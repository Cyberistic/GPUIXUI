# COMPONENTS.md — inventory, status, limitations

The inventory is a **target**, not permission to fake unsupported things. A row
may only move to `done` when the component has: code, a test appropriate to its
behaviour, at least one working example, a docs page, and a verified interaction
in the real runtime (or a documented, evidenced limitation).

Status: `todo` · `wip` · `done` · `blocked (reason)` · `unsupported (evidence)`

Every row also records **GPUix support** and, when it is not `yes`, the evidence
and the strongest honest alternative.

> **Editing this file.** The `Tier 1`–`Tier 5` tables are parsed by the docs site
> (`apps/docs/src/lib/inventory.ts`), which renders `/docs/layouts`,
> `/docs/data-display` and `/docs/workspace` from them. A row keeps exactly four
> columns — `Component | Status | GPUix support | Notes / limitations` — under its
> `Tier N` heading, one table per heading. A fifth column, or a second table under
> one heading, silences every row on those pages;
> `apps/docs/src/lib/inventory.test.ts` fails first and names the line.
> The design-system table is held to its own contract by
> `packages/tokens/src/inventory.test.ts`: four columns, the declared status
> vocabulary, and a `done` row that names an existing test file.

All 31 rows below live in `packages/primitives` (icons in `packages/icons`). Each
has: source, a unit suite, an example in `examples/` mounted by
`runtime/examples.runtime.test.tsx`, a page in `packages/primitives/docs/`, and a
runtime-verified interaction measured in the `TestRenderer` on the pinned 0.11.0
(plan `041` §9, plan `055` §7 — 13 files, 119 tests). "GPUix support" is the
verdict for the pinned runtime, not for the reference clone. Where the runtime has no API for a
capability, the row names the alternative in use — nothing here is a decorative
placeholder.
