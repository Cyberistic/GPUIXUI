# COMPONENTS.md — inventory, status, limitations

The inventory is a **target**, not permission to fake unsupported things. A row
may only move to `done` when the component has: code, a test appropriate to its
behaviour, at least one working example, a docs page, and a verified interaction
in the real runtime (or a documented, evidenced limitation).

Status: `todo` · `wip` · `done` · `blocked (reason)` · `unsupported (evidence)`

Every row also records **GPUix support** and, when it is not `yes`, the evidence
and the strongest honest alternative.

> **Editing this file.** The `Tier 1`–`Tier 5` tables are parsed by the docs site
> (`apps/docs/src/lib/inventory.ts`), which renders `/docs/layouts`,
> `/docs/data-display` and `/docs/workspace` from them. A row keeps exactly four
> columns — `Component | Status | GPUix support | Notes / limitations` — under its
> `Tier N` heading, one table per heading. A fifth column, or a second table under
> one heading, silences every row on those pages;
> `apps/docs/src/lib/inventory.test.ts` fails first and names the line.
> The design-system table is held to its own contract by
> `packages/tokens/src/inventory.test.ts`: four columns, the declared status
> vocabulary, and a `done` row that names an existing test file.

### Declined and covered catalogue entries

Plan 600 §2 lists **47** primitives. Thirty-four rows above implement 33 of them
(`Reveal` is the row `fade` and `slide` both resolve to), 6 resolve to a primitive
that already ships, and 8 cannot be painted honestly on `@gpuix/native@0.11.0`.
Each of the fourteen is recorded here, so the catalogue reads complete and a
declined entry is not mistaken for unstarted work. The evidence is the capability
record (`docs/gpuix-capabilities.md`) and the pinned typings;
`src/catalogue.test.ts` holds this list to plan 600's own names.

- `blur` — **declined** — no `filter`: `StyleDesc` has no CSS filter or backdrop filter, and a stack of translucent copies is a dim, not a blur (`docs/gpuix-capabilities.md` §3).
- `zoom` — **declined** — no `transform`: a zoom is a scale and the runtime has no `transform` (upstream issue #102); `Reveal` offers the entry it can paint instead of imitating one.
- `tilt` — **declined** — no `transform`: a tilt is a rotation and numeric insets cannot lean a plate; `Magnetic` is the honest neighbour, because a lean is an offset rather than a translate.
- `flip-button` — **declined** — no `transform`: a flip is a rotation about one axis, so it would be two fades pretending to be a turn.
- `hole` — **declined** — two-stop: a soft-edged hole is a **radial** gradient, and the runtime's whole gradient grammar is one linear angle with exactly two stops (no radial, conic, repeating or multi-stop gradient, `docs/gpuix-capabilities.md` §3); stacking rings bands visibly, so `Gradient` or one of the fields is the honest alternative.
- `morphing-text` — **declined** — no `filter`: a morph is a blur plus a scale and the runtime has neither; `RollingText` is the honest substitution for a value that changes.
- `click` — **declined** — measured: a wrapper press effect needs the press point, and a pointer click reaches only the element that was hit (two nested handlers report the inner one), so `RippleButton`, which owns the action, is the honest form.
- `github-stars` — **declined** — out of scope: plan 600 defers it until a consumer needs it, and it is a network block rather than a motion primitive.
- `fade` — **covered** by `Reveal` — the house entrance is an opacity run plus a few pixels of travel, on mount or on an `open` change.
- `slide` — **covered** by `Reveal` — `from` names the edge the content arrives from, so one row paints both catalogue names.
- `highlight` — **covered** by `Highlight text` — the runtime's own `highlight` layer is swept one code point at a time.
- `icon-button` — **covered** by `IconButton` in `@gpuixui/primitives` — a press target, not an animated primitive; `Copy button` and `Theme toggler` compose it and animate their glyph.
- `swapping-text` — **covered** by `Rolling text` and `Sliding text` — the vertical and horizontal swaps share one state machine in `internal/text-swap.ts`, and a third component would be the copy the boundaries forbid.
- `scrolling-number` — **covered** by `Sliding number` and `Counting number` — the odometer and the tweened reading are the catalogue's scrolling/sliding/counting number triple.

## Blocked by the runtime

A row whose GPUix support reads `partial` ships and works; one capability the
component would use is missing from the pinned `@gpuix/native@0.11.0`. Every
partial row names its own gap in one line; this table is the one place the gaps
are explained. The verdict and the evidence for each are in
`docs/gpuix-capabilities.md`. `#102`–`#109` are the filed upstream issues; a gap
with no filed issue is marked `unfiled` and lives in that capability record
instead.

The rest of the filed set does not block a row: `#103` grid span (`Grid` ships equal tracks), `#104` IME (native text hosts keep it), `#105` physical key `code` (chords read `key` and `modifiers`), `#106` relaunch, `#107` delta updates and `#108` rollback.

| Capability | Issue | What the library does instead |
| ---------- | ----- | ----------------------------- |
| Per-element `transform` (`rotate`, `scale`, `translate`, `skew`) | #102 | animate numeric insets (`left`, `top`, `width`, `height`, `borderRadius`) and `opacity`; `@gpuixui/motion` drives the same fields |

`onFocus` / `onBlur` are delivered only for an **active** window. The automation
window never becomes active, so `tabs-lifecycle` and `tooltip-lifecycle` read
`focuses=0` and `blur-delivery-lifecycle` finds no focus line: a component paints
its focus cue at rest and gives a focus-only surface a press path, rather than
treating the missing event as a runtime rule.
