# COMPONENTS.md — inventory, status, limitations

The inventory is a **target**, not permission to fake unsupported things. A row
may only move to `done` when the component has: code, a test appropriate to its
behaviour, at least one working example, a docs page, and a verified interaction
in the real runtime (or a documented, evidenced limitation).

Status: `todo` · `wip` · `done` · `blocked (reason)` · `unsupported (evidence)`

Every row also records **GPUix support** and, when it is not `yes`, the evidence
and the strongest honest alternative.

## How the two evidence columns are decided

The **GPUix support** column answers *does GPUix already provide this
primitive?* — `yes`, `?` (unknown or partly documented) or `unsupported` — read
from the published `@gpuix/react` / `@gpuix/native` 0.10.0 types and recorded,
row by row with evidence and workarounds, in
[`docs/gpuix-capabilities.md`](docs/gpuix-capabilities.md) (plan `203`). It
describes the runtime's API surface, not our status. **Read that document before
citing a capability here**: it separates the published 0.10.0 surface from the
features documented on `references/gpuix` `main`, which is ahead of the release.

**Measured native evidence** is separate, and it is what a `done` row needs. It
comes from the native smoke suite in this repo, run **on this host** against a
`@gpuix/native@0.10.0` built from source with `gpui_macos/runtime_shaders`
(ADR 0003). **Provenance caveat (plan `529`):** the artifact this table was first
measured on was compiled from the `references/gpuix` **`main`** tree, not the
published 0.10.0 release tag (`9fcd6288…`), so a verdict read from it described
GPUix's current source, not necessarily what a consumer installs. Plan `529`
records the measured deltas.
The artifact in the shared store is now the **release-tag** build (plan `529`;
`strings` reports `focusVisible=0`). It delivers **no `onFocus`/`onBlur`**
(measured, plan `583`). Since plan `590`, `ThemeProvider` mounts a native-focus
tracker that samples `getFocusedElementId()` every 50 ms, so the focus rings
still paint on the release runtime (up to one tick late) and the focus matrix
passes there after `settleFocus`. What the tracker cannot restore is a
runtime-internal focus behaviour: the headless `Tooltip`'s open-on-focus still
depends on the missing events.
The Tier 1 rows below stay `wip` until their suite passes on a runtime a
consumer installs. It has now been run on the release-tag build: the focus
rings are green after plan `590`, and the whole runtime suite — **80 files** —
passes after plan `597` corrected the published box model (a
plain `div` reports from its content origin, a `Button` from its border box;
`paintBounds` is the opt-in correction), plan `598` corrected a scroller's
own report (it slides by the scroll offset, so `paintBounds` is its visible
box), and plan `599` replaced `Select`'s off-by-one `scrollIntoView` reveal with
a measured `scrollTo`. Plan `602` closed the last focus-lifetime gap on this
build (`RangeSlider`'s thumb ring), and plan `603` holds every focusable Tier 1
control to `ring while focused / none after leaving` in one table, and plan `636`
carries that reveal through nested regions. The remaining
reporting limit is recorded in
`docs/gpuix-capabilities.md` §4. The rows stay `wip` for the
provenance reason above, not for a red suite. Reproduce it with:

```sh
nub run --filter playground build && nub apps/playground/dist/smoke/run.js
```

The suite is **20/20 green here** (exit `0`, `.artifacts/smoke-report.json`).
What it settled, and what changed the plans: focus/blur events **do** work on
0.10.0 (they never did on 0.5.1); component code **can** move native focus
through `useGpuix().renderer.focusElement`, and `focusNextWithin` /
`focusPreviousWithin` cycle within a container, which is the dialog's Tab trap
(the trap wraps: `content → a → b → open-popover → close → content`);
Escape in a nested layer closes only that layer; **`<anchored align="center">`
is off by half the panel size** (it ends the panel at the anchor's centre line)
and `fit="snap"` clamps a layer inside the window **without flipping it**, so a
bottom-side menu can cover its trigger; synthetic wheel scrolling
**does** work
(`deltaY` negative scrolls down, the opposite of the DOM); a `<virtual-list>`
**retains** every row but **paints** a window (~9 of 5 000); an `<anchored>`
paints no surface of its own, so overlay handlers belong on the content div;
`autoFocus` takes native focus without dispatching `onFocus`; and the app-level
window key handler (`render({ onKeyDown })`) receives a keystroke after the
focused element's `onKeyDown` — the command-palette / application-menu path.
`shell-navigation` adds the shell's own rule: a flex child needs `minHeight: 0`
before `overflowY: "scroll"` can make it scroll, which is what keeps the
15-entry sidebar reachable in the 720px window.

`verified 0.5.1` (the published 0.5.1 binding, the last `darwin-x64` release,
run by `apps/playground/legacy-probe`; ADR 0002) and `docs` (the upstream
README/types document it, but no run has confirmed it here).

provide** — the rows that need real implementation, not API-shape work over an
existing host element.

## Tier 1 — foundational

**Why every row below is `wip`:** each one has code, a behaviour test, a mounted
example, an in-package docs page and a measured runtime interaction on the
release-tag build — the `done` bar above. The status stays `wip` for two
reasons, and neither is a failing suite:

- **Provenance.** The native evidence comes from a **source build of the
  published `0.10.0` tag** on Intel macOS, not from a published prebuilt binary
  (ADR `0003`). The gold-standard CI run on a published binary is the playground
  workstream's task. The runtime suite passes on that build (see §"How the two
  evidence columns are decided" above).
- **Docs site.** Seven public parts still have no page on the Fumadocs site —
  `IconButton`, `ToggleGroup`, `CheckboxGroup`, `Grid`, `InfoTip`,
  `ThemeProvider` and `Surface` — because that site is a separate deliverable with its own
  workstream (`TODO.md` records the list). Every part has an in-package page
  today.

**Inert and invalid states are announced (plans `810`, `812`).** 0.10.0 has
neither `aria-disabled`, `aria-readonly` nor `aria-invalid`, and an emulated
state is invisible to assistive technology: measured, every disabled control's
node was byte-identical to its enabled twin, `Click` action included, and an
invalid field reported no description while it painted its error boundary. One
`stateWords`/`describeState` rule now puts `unavailable` (disabled), `read only`
(read-only) or `invalid` (a failed validation) in front of every named control's
description — the channel this table has always named as the ARIA workaround — so
every row below carries it. `Label`'s `invalid` stays paint-only: it is a
caption, and the control it names owns the node and the state. The action list is
unchanged (an `aria-disabled` control keeps its action too); the handler's guard
refuses the press.

The published box model is **not** a remaining gap: plans `597`/`598` replaced
the content-origin reading with `paintBounds` and corrected a scroller's own
offset, and the suite has been green since. Flipping a row to `done` is a
deliberate ledger change; the two items above are why it has not happened.

sixteen controls that take a `disabled` prop to the other keyboard invariant:
**a control that cannot act is not a tab stop, and a control that can act is
reached.** Each control runs twice between two focusable sentinels — enabled, the
next Tab lands inside it; disabled, the next Tab lands on the element after it.
32 cases; both failure directions were measured (a `Checkbox` that kept its stop
fails the disabled half, one that dropped it fails the enabled half).

**Disabled after focus (332):** `runtime/disabled.runtime.test.tsx` guards the
state transition the tab-order matrix cannot see. Native focus **outlives** a
`disabled` prop change — measured on thirteen controls, the runtime never blurs a
host element whose tab stop disappears — so a form that disables its controls
while saving leaves the keyboard on a control that now claims to be disabled.
Thirteen controls must act while enabled, keep focus across the disable, and
report nothing afterwards; fifteen must paint exactly one ring while enabled and
none once disabled. The two defects that found: `CheckboxGroup`'s row guarded the
pointer but not the keys (its `onValueChange` reported a second toggle), and ten
action/selection controls kept the ring while the five fields had always dropped
it. The ring rule now has one owner, `controlFocusStyle`, plus the four painters
that do not use it (`selectionBoxStyle`, `switchTrackStyle`, `sliderThumbStyle`,
`ratingStarStyle`); no caller re-tests `disabled`. 29 runtime cases plus four
core/element cases; reverting the row's guard fails one activation case, and
reverting a painter fails its ring case by name.

**Accessible-name matrix (093):** `runtime/name.runtime.test.tsx` is the third
cross-control invariant. Three shipped defects were one class — a control that
painted, took focus and worked but reached assistive technology with no role or
no name (plans 057, 058, 071, 073) — and only per-component assertions existed.
One table now proves the documented role and exact name of 28 name-bearing
Tier 1 nodes (including `Slider`, `TextArea`, `NumberField`, `Switch` and every
group row that had no role/name assertion), a composed scene proves no
interactive node is unnamed, and the presentational primitives prove they invent
no role. Measured: a `TextArea` is `MultilineTextInput`, not `TextInput`;
removing `Switch`'s label fails the table and the closure, and removing
`Slider`'s role leaves no node at all.

**Blank labels (026):** plans `396`/`399` made a blank label absent on
`Button`/`Toggle`/`ScrollArea`/`Icon`, but every other named surface still wrote
the raw string into `aria-label`. One `ariaName` rule now trims a real label and
omits a blank one on all seventeen remaining surfaces; `Spinner` keeps its
documented `"Loading"` fallback, an OTP cell falls back to `"Code"`, and a range
thumb is unnamed rather than `"   minimum"`. Measured on the pre-fix tree: 18
offline cases fail across every surface, and the runtime reported `Status:""`
for a blank spinner (its default erased), no `"Code digit 1"` cell, and
`['minimum','maximum']` thumbs. `runtime/blank-name.runtime.test.tsx` (6 cases)
guards the tree the runtime builds; the per-component element-tree suites guard
the props.

**Blank descriptions (586):** the same rule had not reached the public
`aria-description` prop a slot trigger adds — measured, ten surfaces published
`description: "   "` verbatim and a busy `Button` composed `"Loading.    "`.
Every forwarded description now goes through `ariaName` (trim or absent), and
the busy button announces `"Loading"` or `"Loading. <tip>"`, never a dangling
separator. `src/components/description.test.tsx` (33 cases, including a
file-level source guard) and `runtime/description.runtime.test.tsx` (5 cases)
hold the rule; 23 offline and 4 runtime cases fail without it.

**Validation matrix (351):** `runtime/invalid.runtime.test.tsx` guards the state
that produced two shipped defects — `RadioGroup` had no `invalid` at all (plan
`061`) and `Rating` accepted it and painted nothing (plan `070`). Thirteen cases,
one per control that declares the prop (`Checkbox`, `CheckboxGroup`, `Input`,
`Label`, `NumberField`, `OTPField`, `RadioGroup`, `RangeSlider`, `Rating`,
`Select`, `Slider`, `Switch`, `TextArea`), mount each with and without `invalid`
in fresh windows and require the theme's destructive role to appear only in the
first. The scan is whole-tree because the state lands on a border, a tint or a
text colour depending on the control, and the defect class is "paints nothing";
each control's own suite still asserts where it lands. All three mutation
directions (drop Rating's, drop the field chrome's, hard-code the switch's) fail
by case name.

**Style order (097):** `src/components/style-order.test.tsx` holds the other
written promise — *a caller's `style` wins last* — over every one of the 29
`render*` functions that take one. It walks the whole decoded tree and requires
each caller property to survive on some painted element; `Progress`'s forced
row (`display`, `flexDirection`) and `TextArea`'s row re-base (`height`,
padding) were the two exceptions and are merged before the caller now. Both
directions were measured: reverting either merge order fails the guard by
property name.

**API contract (090):** `src/contract.test.ts` is the Tier 1 half of the accepted
Tier 1–2 contract (`docs/component-api.md`, ADR `0004`). It records one part per
public component — page and the state types its `style` props accept — and
fails by name for an unrecorded export, a recorded part that is not a component,
a `render*`/`*Parts` seam in the package root, an undeclared state type, a page
missing its state name or a required section, and any ARIA prop outside the
verified 0.10.0 subset. Five deliberate mutations failed it (a dropped table row,
a re-exported `renderIconButton`, a deleted `## Keyboard`, a renamed
`ButtonState`, an added `aria-checked`); the fixes were one demoted `IconButton`
seam and this record. The four shipped parts missing from the contract doc's own
Tier 1 table are a cross-team `TODO.md` row.

**Composed app (327):** `examples/basic-app` — the settings workflow that uses
the whole Tier 1 set — now mounts in the real `TestRenderer`
(`nub run --filter @gpuixui/basic-app test:runtime`, 7 tests): the skeleton hands
over to the form, the consent row paints its own label and is clickable, Save is
refused until it is accepted and stays refused for an invalid email, the save
lifecycle runs, and the Select paints its option's label. Its consent control is
a one-row **`CheckboxGroup`**, because a standalone `Checkbox`'s `label` is only
an accessible name: measured, the app painted an empty box under a caption that
never named the agreement (the `Label`-beside-a-box class of plan `087`). The
form is taller than its scroll region, so the suite wheels the region to the row
and asserts it is reachable. The first field takes `autoFocus` after the
skeleton: measured, a field mounted after the first render **does** take native
focus (plan `584`); plan `327`'s empty `runtime.focused()` was a locator
artifact, not a runtime limitation. On the release-tag build the suite is
**7/7**, including the consent row's reachability after a real wheel (plan
`598`).

**Both themes (021/042/352):** every painted colour in the Tier 1 scene comes from
the active palette, and re-rendering with the dark palette repaints every asserted
role (plan 042 §8). Since plan 021 the palettes are the shipped `lightTheme` /
`darkTheme` from `@gpuixui/tokens`, not test doubles. Plan `352` adds the
**both-theme matrix over all 31 public components**: each is mounted in its
smallest honest shape under both palettes, every colour inside the case must be
a palette value, and a case that paints anything must paint a *different* set in
light than in dark — so a hard-coded literal or a component the provider never
reached fails by case name. The plan names the four mutation directions that
fail it.

**No row is `done`** until the published-binary run lands and the docs site
(docs-site workstream) has its page. The in-package docs page and the mounted
example exist for every row (plan 047); the runtime column is the honest
locally-built-binding result.
