# COMPONENTS.md — inventory, status, limitations

The inventory is a **target**, not permission to fake unsupported things. A row
may only move to `done` when the component has: code, a test appropriate to its
behaviour, at least one working example, a docs page, and a verified interaction
in the real runtime (or a documented, evidenced limitation).

Status: `todo` · `wip` · `done` · `blocked (reason)` · `unsupported (evidence)`

Every row also records **GPUix support** and, when it is not `yes`, the evidence
and the strongest honest alternative.

> **Editing this file.** The `Tier 1`–`Tier 5` tables are parsed by the docs site
> (`apps/docs/src/lib/inventory.ts`), which renders `/docs/layouts`,
> `/docs/data-display` and `/docs/workspace` from them. A row keeps exactly four
> columns — `Component | Status | GPUix support | Notes / limitations` — under its
> `Tier N` heading, one table per heading. A fifth column, or a second table under
> one heading, silences every row on those pages;
> `apps/docs/src/lib/inventory.test.ts` fails first and names the line.
> The design-system table is held to its own contract by
> `packages/tokens/src/inventory.test.ts`: four columns, the declared status
> vocabulary, and a `done` row that names an existing test file.

| Image zoom | done | partial | `ImageZoom` is a clipped frame whose picture magnifies and pans under the pointer: the `<img>` host scales its own buffer to its box (measured by the `chart-raster` probe), so growing `width`/`height` magnifies and moving `left`/`top` pans — the runtime has no `transform` (upstream issue #102), so this is not a scaled layer, and a clipped box really does clip its content (`motion-geometry`). The pan keeps the pointer's share of the frame under the pointer, and a pointer near an edge pins that edge of the picture to the frame's, so the picture always covers the frame and the page never shows through (`image-zoom/logic.ts`). The frame keeps its caller-given size, so a gallery does not reflow while one picture is explored; `scale` is held to `1…4` and `1` turns the zoom off, a frame side below one pixel falls back to the house 240 × 160 rather than clipping the picture to nothing, and a `NaN` magnification falls back to 1.6. The **magnification is content, not journey**, so `MotionProvider preference="reduced"` keeps it and drops only the tween; `level` picks the pan duration (`normal`, 200 ms by default). The picture is the content, so `alt` is required and the frame publishes no node of its own; the picture takes no tab stop, and there is no wheel, pinch or drag-to-pan gesture because the runtime exposes none. The pan is read against the frame's **current** origin through the same one-pixel probe `Magnetic` uses (`internal/surface-box.tsx`), because `onLayout` reports a size change rather than the move a pane or a scroll makes. The window measured the rule with the playground's `surface-origin` probe (15 checks, 0.11.0): a 120 pt panel above delivered no report, the nudged probe re-reported 88 → 208, and the same window point stayed the local `120,30` where the stale report read `120,150`. 10 native behaviour tests. |
| Motion grid | done | partial | `MotionGrid` is a grid whose cells **travel to their new slots** when the order changes: each cell is an absolutely positioned box whose `left`/`top` are a motion target, so a reorder retargets the cells that moved from the box on screen and leaves the ones whose slot did not change where they are. Absolute placement is what makes the movement possible — the runtime has no `transform` (upstream issue #102), so this is inset geometry rather than a translated layer — and its cost is that **no cell sizes its row**: `columns`, `cellWidth`, `rowHeight` and `gap` are the caller's, the frame is arithmetic over them (`motion-grid/logic.ts`), every measure is a whole number of pixels, and an unreadable one falls back instead of reaching the runtime as `null`. The frame reserves every declared column, so filtering a cell out moves the survivors without resizing the box under them, and the frame's own height is a motion target, so a grid that gains a row grows with the cells instead of jumping a row ahead of them. A cell's key is its `id`, so an appended cell mounts alone and fades in at the slot it is arriving into, while the boxes around it travel; a removed cell does not replay the rest. The wrapper paints nothing and clips nothing — a card's radius, border and shadow are the content's — and content inside a cell keeps its presses at the box it is painted in. The frame publishes no accessibility node unless `label` names it, at which point it is a `role="group"`; the reading order is the array's order. `MotionProvider preference="reduced"` paints every new slot in the frame the order changes, and a mounted cell is already opaque. 9 native behaviour tests. |
| Sliding text | done | partial | `SlidingText` is the horizontal sibling of `RollingText`: a value leaves towards one edge and the next one arrives from the other, as a relative `left` inside a box that clips — because the runtime has no `transform` (upstream issue #102) and keeps every inset a **number**, never a percentage of the parent, so the travel is the box's own width. The width arrives from `onLayout` after the first paint; a change in the frame before that fades in place rather than travelling a guessed distance (a `NaN` inset would reach the runtime as `null`). `direction="forward"` reads left to right and `"back"` mirrors both halves, `level` splits one house duration across the two halves (`normal` = 100 ms out + 100 ms in), and a value changed mid-exit replaces the pending one rather than queueing. The swap settles to `rest` when the entry tween reports complete, so the state a `style` callback reads does not stay in `entering`. Only one value is mounted at a time — the swap happens while the clip is empty — because `0.11.0` has no `aria-hidden` to keep the outgoing value out of the accessibility tree (`sliding-text/logic.ts`, `src/internal/text-swap.ts` shares the machine and timing with `RollingText`). The box fills the width it is given and clips: a string wider than the box is cut at the edge it slides past, not wrapped. 9 native behaviour tests. |

### Declined and covered catalogue entries

Plan 600 §2 lists **47** primitives. Thirty-four rows above implement 33 of them
(`Reveal` is the row `fade` and `slide` both resolve to), 6 resolve to a primitive
that already ships, and 8 cannot be painted honestly on `@gpuix/native@0.11.0`.
Each of the fourteen is recorded here, so the catalogue reads complete and a
declined entry is not mistaken for unstarted work. The evidence is the capability
record (`docs/gpuix-capabilities.md`) and the pinned typings;
`src/catalogue.test.ts` holds this list to plan 600's own names.

- `blur` — **declined** — no `filter`: `StyleDesc` has no CSS filter or backdrop filter, and a stack of translucent copies is a dim, not a blur (`docs/gpuix-capabilities.md` §3).
- `zoom` — **declined** — no `transform`: a zoom is a scale and the runtime has no `transform` (upstream issue #102); `Reveal` offers the entry it can paint instead of imitating one.
- `tilt` — **declined** — no `transform`: a tilt is a rotation and numeric insets cannot lean a plate; `Magnetic` is the honest neighbour, because a lean is an offset rather than a translate.
- `flip-button` — **declined** — no `transform`: a flip is a rotation about one axis, so it would be two fades pretending to be a turn.
- `hole` — **declined** — two-stop: a soft-edged hole is a **radial** gradient, and the runtime's whole gradient grammar is one linear angle with exactly two stops (no radial, conic, repeating or multi-stop gradient, `docs/gpuix-capabilities.md` §3); stacking rings bands visibly, so `Gradient` or one of the fields is the honest alternative.
- `morphing-text` — **declined** — no `filter`: a morph is a blur plus a scale and the runtime has neither; `RollingText` is the honest substitution for a value that changes.
- `click` — **declined** — measured: a wrapper press effect needs the press point, and a pointer click reaches only the element that was hit (two nested handlers report the inner one), so `RippleButton`, which owns the action, is the honest form.
- `github-stars` — **declined** — out of scope: plan 600 defers it until a consumer needs it, and it is a network block rather than a motion primitive.
- `fade` — **covered** by `Reveal` — the house entrance is an opacity run plus a few pixels of travel, on mount or on an `open` change.
- `slide` — **covered** by `Reveal` — `from` names the edge the content arrives from, so one row paints both catalogue names.
- `highlight` — **covered** by `Highlight text` — the runtime's own `highlight` layer is swept one code point at a time.
- `icon-button` — **covered** by `IconButton` in `@gpuixui/primitives` — a press target, not an animated primitive; `Copy button` and `Theme toggler` compose it and animate their glyph.
- `swapping-text` — **covered** by `Rolling text` and `Sliding text` — the vertical and horizontal swaps share one state machine in `internal/text-swap.ts`, and a third component would be the copy the boundaries forbid.
- `scrolling-number` — **covered** by `Sliding number` and `Counting number` — the odometer and the tweened reading are the catalogue's scrolling/sliding/counting number triple.
