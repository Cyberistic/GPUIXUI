## Finding

**Four fixed marks were only `positive`.**
`dimensions.toastToneBarWidth`, `notificationUnreadDotSize`,
`carouselIndicatorSize` and `avatarPresenceDotSize` pass every check at `0.1`,
a mark thinner than the theme's own hairline. The timeline marker already has
the rule (plan 604): a mark thinner than the rail it marks does not read. The
same argument applies to a tone bar, an unread dot, a carousel indicator and a
presence dot — at a tenth of a pixel the mark aliases to a faint smear.

```ts
const faded = extendTheme(getTheme("light"), {
  dimensions: { toastToneBarWidth: 0.1 },
});
themeMetricFailures(faded); // []
```

The rule is `usableBound(mark) ? atLeast(mark, borderWidth.thin) : []`, so a
zero/negative/non-finite mark keeps its one `positive` diagnostic and a
borderless theme (`thin: 0`) invents no bound. Every shipped set ships `thin: 1`
and the four marks at 3/6/8/10, so no value moves.
