# tokens-theme — audit after plan 641 (2026-10-19, sixteenth tick)

## Scope

Every remaining `[ ]` row in `TODO.md` is a cross-team handoff or the
upstream-blocked `registerFont` (052), so this tick re-audited the numeric
contract — `themeMetricFailures` — against the runtime's actual paint.

## What was checked

- **The ten checks over all 24 shipped sets** — `themeFailures` returns `[]`.
- **Every elevation rule**: the per-shape finite, non-negative and alpha-fraction
  rules; the `sm`/`md`/`lg` at-least-one rule; the reserved empty `overlay`; the
  defined-`overlay` feather ladder; the contrast walk.
- **The shipped-only guard** `elevation.test.ts` — it walks all four identity
  sets and asserts `length <= 1` per level.
- **`elevationShadow` and `elevationShadows`** — the former reads the first
  entry only; the latter resolves the list for a web renderer.

## Finding

**A level with two shapes returns `[]` and paints one.**
`themeMetricFailures` requires `sm`/`md`/`lg` to hold **at least** one shape but
never held the count at the other end. The native runtime paints one shadow per
element and `elevationShadow` destructures `[shape]`, so a copied theme loses
the rest silently:

```ts
const shape = { offsetX: 0, offsetY: 1, blurRadius: 2, spreadRadius: 0, alpha: 0.08 };
const doubled = extendTheme(getTheme("light"), {
  elevation: { sm: [shape, { ...shape, offsetY: 2 }] },
});
themeMetricFailures(doubled); // []
themeFailures(doubled);       // []
elevationShadow(doubled, "sm"); // the first shape only
```

Every field of both shapes is finite and in range, so no per-shape rule fires.
`elevation.test.ts` asserts the one-entry rule on the **shipped** themes, not on
an edited one, so the copy is outside every guard. The documentation already
tells the reader that a second entry is discarded, but the editable-theme
guarantee returns `[]` while half the declared elevation paints — the same
class plan 641 closed for a bound the runtime ignores.

The count is already a metric: an empty `sm` reports `{ rule: "at-least",
actual: 0, bound: 1 }`. The missing half is `at-most 1`, expressible with the
existing helper and rule.

## Decision

Add one `atMost("elevation", level, shapes.length, 1)` per level, `overlay`
included, compose it with the existing count and shape rules, and extend the
elevation JSDoc. Plan 642 carries the exact edit, a nine-case suite (five fail
on the pre-fix tree) and the four document updates. `elevationShadows` stays as
the web list; the native contract simply names a multi-entry theme as outside
its guarantee.

## Not changed

- Any colour, pair, floor, figure or shipped metric.
- `elevationShadows`, the `Elevation` list type or the web rationale.
- The per-shape rules and the feather ladder.
- The shipped `elevation.test.ts` guard, which keeps its own job.
