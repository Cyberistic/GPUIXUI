# tokens-theme — audit before plan 646 (2026-10-19, nineteenth tick)

## Scope

Every remaining `[ ]` row in `TODO.md` is a cross-team handoff or the
upstream-blocked `registerFont` (052). This tick audited the numeric contract's
`finite` rule against the number the renderer actually receives, reading the
pinned GPUix source at `references/gpuix` (read-only) as evidence.

## What was probed

The contract used `Number.isFinite`, which is true for a JavaScript number far
beyond `f32`'s range. The renderer casts every style metric with an unchecked
`value as f32` (`packages/native/src/renderer.rs`, `el.p(gpui::px(p as f32))`),
and the runtime's own metric override names the consequence
(`packages/native/src/theme.rs`, `Metrics::apply`): a value that overflows `f32`
becomes an infinity Taffy rejects and gpui renders nothing, silently.

Each theme below returned `[]` from `themeMetricFailures` and `themeFailures` on
the pre-fix tree with `huge = 1e39`:

| Group | Member | Painted result |
| ----- | ------ | -------------- |
| `spacing` | `5xl` | the ladder's last step, never compared onwards |
| `radius` | `full` | excluded from the radius ladder |
| `borderWidth` | `strong` | `positive` and `at-least` both pass |
| `iconSize` | `xl` | the ladder's last step, `positive` passes |
| `avatarSize` | `lg` | the ladder's last step, `positive` passes |
| `dimensions` | `toastWidth` | `positive` passes, the chrome bound passes |
| `typography` | `display.fontSize` / `lineHeight` | `positive` and the line rule pass |
| `elevation` | `md[0].offsetY` | offsets are only sign-checked |
| `motion` | `slow` | `non-negative` passes |

The mirror case is underflow: `Math.fround(1e-50) === 0`, so a positive surface
size passed `positive` and painted at size zero.

A huge dependent value also cascaded. `density.rowHeight: 1e39` produced four
`at-least` failures for `overlayMaxHeight`, `notificationListMaxHeight`,
`chatViewportMinHeight` and `drawerHeightSm`, blaming the rows and surfaces for
the one broken number — against the contract's rule that a value the `finite`
rule rejects is not compared by a bound.

## Finding

`finite` must mean finite **after the renderer's cast**, and the sign rules must
read the painted value. Plan 646 adds one predicate,
`paints = Number.isFinite(Math.fround(value))`, and routes every bound, ladder,
sign rule, usable fit bound and theme extreme through it, so one unpaintable
number keeps one diagnostic. Every shipped metric is a small positive integer,
so no shipped value, colour, pair, floor, figure or metric moves.

## Not changed

- any colour, pair, floor, figure or shipped metric;
- a component or primitive source file — the contract follows the geometry the
  renderer already paints;
- the rule or group indexes, the public API, or the number of checks;
- `zero`/`fraction`/`easing` semantics beyond waiting for a paintable value.
