# tokens-theme — audit before plan 645 (2026-10-19, eighteenth tick)

## Scope

Every remaining `[ ]` row in `TODO.md` is a cross-team handoff or the
upstream-blocked `registerFont` (052). This tick audited the numeric contract's
fixed-surface bounds against the chrome the consumer components actually paint,
using the component trees at `workspaces/components/packages/components/src` as
read-only evidence.

## What was probed

Each theme below returned `[]` from both `themeMetricFailures` and
`themeFailures` on the pre-fix tree:

| Theme | Painted chrome it leaves out |
| ----- | ---------------------------- |
| `chatViewportMinHeight: 32` | `chat.tsx` paints `spacing.md` padding and two borders around the viewport; the signed bound only required one `density.rowHeight` |
| `previewCardMinWidth: 10` | `preview-card.tsx` paints `spacing.lg` padding inside two borders; the bound only required positive and below the maximum |
| `overlayMinWidth: 57, overlayWidth: 58` | `menu/surface.tsx` and `combobox.tsx` paint `spacing.xs` surface padding around the row the bound measures |
| `chipMinWidth: 10, fieldMinWidth: 79` | `search-input.tsx` paints the field's two borders; the query branch of the field bound omitted them while the chip branch charged them |
| `spacing: { "2xl": 16 }, dialogWidthSm: 70` | `dialog.tsx`/`drawer.tsx` place a square `controlHeight.sm` close control at `spacing.lg` from the right edge; the bound reserved `2 * spacing["2xl"]` |

The dialog case is the visible one: when `spacing.lg + controlHeight.sm` is
larger than `2 * spacing["2xl"]`, a one-glyph title can sit under the close
control while the shell width passes.

## Finding

The five bounds are under-counted; they are the same class plans 384/627
already fixed for the control, field, Toast, inbox and shell chrome. Plan 645
charges the missing padding, border and close-control reach. Every shipped
theme is far above the new minima, so no shipped pixel moves.

## Not changed

- any colour, pair, floor, figure or shipped metric;
- `dimensions`, `Dimensions`, `metricMembers`, `metricGroups` or `metricRules`;
- a component or primitive source file — the contract follows the geometry the
  components already paint;
- the existing positive, finite, ladder and `usableBound` rules.
