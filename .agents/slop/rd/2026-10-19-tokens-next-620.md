## Finding

**The three fixed surfaces whose horizontal chrome never wraps were ungoverned.**
`dimensions.toastWidth`, `dimensions.notificationPanelWidth` and
`dimensions.overlayMinWidth` were held only to `positive` (or only ordered
against a sibling), so a copied platform style could ship:

- a 20px toast card — narrower than its own `spacing.lg` padding, `md` tone
  icon and `bodyStrong` title;
- a 20px notification inbox — narrower than a row's padding, unread dot and
  title;
- a 20px overlay minimum — narrower than a menu row's insets, leading icon and
  label;

and `themeMetricFailures` / `themeFailures` returned `[]`. No shipped component
reads the token yet (the migration is already recorded in `TODO.md` for
`components`), so no shipped composition breaks today; the defect is that the
guarantee a brand is told to rely on is incomplete.

## Plan 620 — the fixed surfaces hold their own chrome

- Three `at-least` rules derive each bound from the theme's own metrics:
  `toastWidth` = `2·spacing.lg + iconSize.md + spacing.lg +
  typography.bodyStrong.fontSize`; `notificationPanelWidth` = `2·spacing.lg +
  notificationUnreadDotSize + spacing.sm + typography.bodyStrong.fontSize`;
  `overlayMinWidth` = `2·spacing.md + iconSize.md + spacing.md +
  typography.label.fontSize`.
- Each rule waits for a usable value (zero/non-finite stays the sign rule's one
  diagnostic), matching the established dependent-fit pattern.
- `fixed-surface-fit.test.ts` states the bug in its header and covers the
  shipped pass, the three narrowed themes, the derivation from the theme's own
  spacing, and the total check. It fails 5/7 on the pre-fix tree and passes 7/7
  after.
- The catalogue, design system and ledger name the rule; `docs.test.ts` derives
  the quoted headroom (`5.76× / 6.40× / 3.40×`).
