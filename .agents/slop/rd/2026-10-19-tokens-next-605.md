# tokens-theme — next-unit audit after plan 605 (2026-10-19)

## What landed

- **605** closed the last interaction state that had no public resolver. The
  disabled state shipped as roles in plan 306 and was documented by copying
  `disabled-state.example.ts`, while `filledControl`, `softAction`, `focusRing`,
  `selectionStyle`, `nativeFieldTheme` and `statusTone` each resolve their state
  in one call. `disabledControl(theme)` and `DisabledControlStyle` now return
  `opacity: 1`, the `disabled` fill, the `disabledForeground` label and the
  `border` edge.
- The example is a runnable consumer now: `disabledButtonStyle` spreads the
  helper and adds the density height, padding and `radius.md`, and the suite
  imports it (the `examples.test.ts` rule).
- The helper's label and edge are held to the inactive and divider floors on
  every shipped set; the equality case is the guard that it did not silently
  choose a different designed pair. The catalogue type index, value coverage,
  rule 8, the design system, the package README and the ledger name it.
- 157 files / 6,005 tests green; `check`, `lint` and `test` pass. No colour,
  pair, floor, metric or shipped pixel moves.
- Both directions verified by hand: with the helper returning `opacity: 0.5`
  the equality case fails; with `disabledControl` removed from `docs/tokens.md`
  the namespace value-coverage case fails. Each restores green.

   secondary Button ladder, pressed list row, menu glyphs and bar, avatar,
   timeline and notification marks, ColorPicker and DatePicker rings, selected
   Tabs trigger, disabled `opacity: 0.5`, the Toast tone and groove, and every
   new dimension migration.
2. **A new contract pair** still needs a failing plant. The probes run after 605
   (text roles across fill surfaces, ring/boundary roles across fills) found no
   plausible shipped composition below its floor that is not already a
   cross-team row, so do not add a pair that only blesses a composition no
   consistent palette fails.
3. **Runtime reach** left: `HighlightSpec.radius` is a fixed 2px the bridge does
   not set. It is a chrome default, not a measured failure; leave it until a
   consumer needs a themed highlight radius or the runtime exposes more.
4. **Decoration metrics**: `notificationUnreadDotSize` has only a positive rule,
   unlike the timeline marker. It is a candidate if the token-owned numeric
   surface is reopened, but the 604 audit's caution stands — it prevents a
   clipped mark, it does not fix a shipped defect.
