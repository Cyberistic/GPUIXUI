# tokens-theme — audit after plan 617 (2026-10-19, second tick)

## Scope

Plan 617 closed the ledger's check counts. Every remaining `[ ]` row in
`TODO.md` is a cross-team handoff or the upstream-blocked `registerFont`, so this
tick re-audited the one contract this workstream owns end to end: the level →
palette → elevation chain in `applyPlatformStyle`, now that plans 373, 505 and
541 have each changed one link of it.

## What was checked

- **The ten checks over all 24 shipped sets** — `themeFailures` returns `[]`.
- **Every `PlatformStyle` field and every requested level** against plan 373
  (whole default palette), 505 (AAA dark tint and alphas), 541 (the level owns
  the name/declaration/opacity) and 551 (`undefined` colour segments).
- **Copied styles that omit a group**, the "copy a file and edit it" path the
  docs teach, rather than the shipped styles, which name every elevation level.

## Finding

**A `"default"` request over an AAA base kept the base's elevation.** The
`"default"` branch of `platformOverrides` returned `style.elevation[base.mode]`,
which `extendTheme` merged over the **base** — still the AAA theme. Plan 373
replaced the palette as a set, but only the colours; every elevation level the
style did not name kept the AAA shape and alpha.

A valid copied style that names one colour and no elevation, applied to
`getTheme("dark", "high")` with `"default"`, returned:

- the default palette and its black `shadow` tint,
- the AAA alphas `0.10 / 0.14 / 0.18` instead of the default dark set's
  `0.40 / 0.65 / 0.80`,
- `themeFailures(result)` — **15 elevation pairs** under the 1.05:1 floor, worst
  **1.0175:1** (`sm` on the canvas). The library's own checker rejected a theme
  the library produced from a valid style.

The docs already claimed the palette decides the elevation opacity (plans 541,
505, 373), so this is a truth gap, not a design change. Every shipped style names
`sm`/`md`/`lg` in both modes, so no shipped value moved.

## Plan 618 — the default request owns its elevation

- The default branch merges the style's levels over `palette.elevation`, the same
  owner the `high` branch already uses; a named level still wins, and a
  same-level base (`palette === base`) keeps its edits.
- `applied-level-elevation.test.ts` states the bug in its header and covers five
  compositions: no named level, one named level, a same-level edit, a `"high"`
  request, and the light AAA set (which already carries the default alphas, so it
  documents the asymmetry).
- `applied-level.example.ts` gains the colour-only style and the
  `defaultFromHighContrast` composition, imported by the suite so the snippet
  runs.
- The rule is stated in `docs/tokens.md`, `docs/design-system.md`, the package
  README, the `applyPlatformStyle` JSDoc and the ledger's platform row.
