# tokens-theme — audit after plan 638 (2026-10-19, fifteenth tick)

## Scope

Every remaining `[ ]` row in `TODO.md` is a cross-team handoff or the
upstream-blocked `registerFont` (052), so this tick re-audited what an edited
theme reports, the direction plan 532 started with non-finite metrics.

## What was checked

- **The ten checks over all 24 shipped sets** — `themeFailures` returns `[]`.
- **Every dependent fit in `themeMetricFailures`**: which reads a bound from
  another metric, and whether that bound is guarded by `usableBound`.
- **Every `atMost` rule**: only three, all size fits.

## Finding

**A negative or zero bound blames the metric that fits inside it.**
`atMost` already skips a non-finite bound (`Number.isFinite(bound)`), the half
plan 532 added. `usableBound` — `finite && > 0` — exists for the zero/negative
half and is used by the largest-corner bounds, the presence dot and the date
field, but three fits never call it:

```ts
const clipped = extendTheme(getTheme("light"), {
  typography: { caption: { lineHeight: -1 } },
});
themeMetricFailures(clipped);
// caption.lineHeight at-least (correct) + iconSize.xs at-most 12 ≤ -1 (false)

const crampedRow = extendTheme(getTheme("light"), {
  density: { rowHeight: -1 },
});
themeMetricFailures(crampedRow).filter((f) => f.group === "avatarSize");
// [{ member: "xs", rule: "at-most", actual: 20, bound: -1 }] (false)
```

The three unguarded rules are `iconSize.xs` against `caption.lineHeight`,
`iconSize.sm` against `label.lineHeight` and `avatarSize.xs` against
`density.rowHeight` — plans 521 and 522. A consumer following the report would
shrink a correct icon or avatar while the line or row that broke stays broken.

`label.lineHeight: -1 | 0` and `density.rowHeight: 0` reproduce the same class;
every shipped set keeps usable bounds (12/14/20 against 16/18/32), so no value
moves.

## Decision

Guard the three `atMost` fits with `usableBound`, extend the helper's JSDoc, and
add an eight-case suite whose five defect cases fail on the pre-fix tree. The
control cases keep a usable bound reporting a real overflow, so the fix cannot
silently disable plan 521/522. Plan 641 carries the exact edits, documents the
rule in the catalogue and leaves every sign and finite diagnostic unchanged.

## Not changed

- Any colour, pair, floor or shipped metric.
- The `atLeast` fits: a negative bound cannot false-report a positive actual,
  and a negative actual is the same member's own defect.
- The sign and finite rules, including `-Infinity` reporting both (plan 532).
