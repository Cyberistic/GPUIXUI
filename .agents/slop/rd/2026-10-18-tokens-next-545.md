# tokens-theme — next-unit audit after plan 545 (2026-10-18)

## What landed

- **545** closed the false name in the applied theme. `platformOverrides` named
  its result `${palette.name} · ${label}`, and a same-level base keeps its own
  palette (plan 373), so applying the style a theme already carried appended
  the label again: `Light · Windows` became `Light · Windows · Windows`, a
  palette the package does not ship, printed by the preview `Theme.name` exists
  for. A probe found the second application deep-equal to the first in every
  field except `name`, so the composition was already idempotent and only the
  label drifted.

  One helper, `appliedStyleName`, appends a label only when the name does not
  already end with it. `applyPlatformStyle` and the deprecated `platformTheme`
  bridge share it. A different style still appends its own label once, which
  records provenance rather than accumulation: Windows → macOS reads
  `Light · Windows · macOS` because the second style names only the roles it
  owns (plan 374). `applied-style-name.test.ts` (five cases) fails pre-fix in
  all five; the executed `acmeWindowsReapplied` example runs in
  `applied-level.test.ts`; the catalogue, README and design system state the
  rule and `docs.test.ts` holds all three (proved by breaking the sentence).

  131 files / 5639 tests green (+1 file, +6 cases); `check`, `lint` and `test`
  pass. No public value, colour, pair, floor, metric, platform style or recipe
  moved, so no `COMPONENTS.md` row changes beyond the Theme extension clause.
