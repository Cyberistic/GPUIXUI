# tokens-theme — audit before plan 658 (2026-10-19, twenty-fifth tick)

## Scope

Every remaining `[ ]` row in `TODO.md` is a cross-team handoff or the
upstream-blocked `registerFont` (052), so this tick audited the copy-and-own
story: does every documented theme edit produce a theme the package accepts?

## What was probed

Plan `656` made every copyable block self-contained and plan `355` checks the
names a block imports. Neither runs a block that **builds** a theme. The
`documentedBrands` cases in `snippets.test.ts` hold the brand and builder maps
to `themeFailures`, but they select blocks by `brandTheme =` (docs/README) or a
`colors:` in a `theme.ts @example`, so the recipe section's block — a spread of
`platformRecipes.aero` with a nested `colors.dark` — was never executed.

Running it:

```ts
const mine = applyPlatformStyle(getTheme("dark"), {
  ...platformRecipes.aero,
  colors: {
    ...platformRecipes.aero.colors,
    dark: { ...platformRecipes.aero.colors.dark, primary: "#1F6FB5" },
  },
});
```

`themeFailures(mine)` returns seven entries:

| Pair | Class | Floor | Ratio |
| ---- | ----- | ----- | ----- |
| `primaryForeground` on `primary` | secondary | 4.5 | 3.999 |
| `primary` on `card` | mark | 3 | 2.696 |
| `primary` on `popover` | mark | 3 | 2.696 |
| `primary` on `muted` | mark | 3 | 2.696 |
| `primary` on `input` | mark | 3 | 2.696 |
| `primary` on `track` | mark | 3 | 2.882 |
| `primary` on `hover` | mark | 3 | 2.233 |

The page's own rule, one section above: "A style that names only the fill
inherits a foreground designed for another fill; that is the 2.96:1 failure plan
`310` fixed." The recipe block demonstrated the anti-pattern it warns about.

## Other probes, and why they are not plans

- **Marks on row washes**: `primary` on `active`/`selected` fails 3:1 on
  `Dark · macOS` (2.836 / 2.748). That is the shipped notification unread dot,
  already a cross-team row with the `primaryText` replacement; the other mark
  roles clear every row wash in every shipped set. The contract deliberately
  treats `primary` as a fill and `xText` as the row-safe tone (plans 332, 651).
- **Fills on row washes**: a filled secondary control on an `accent`/`selected`
  row matches the wash in several sets, but the secondary control paints a
  `border` edge on the same fill, and that edge is measured (`controlFillRoles`
  and the selected-row pair, plans 318 and 335). The one same-role collision is
  an accent toggle on an accent row, which is transient and self-referential.
- **Marks on soft fills**: `primary`/`success`/`destructive`/`info` clear 3:1 on
  all four soft fills in all 24 shipped sets; no shipped composition paints a
  solid mark there (`xText` and `xSoftForeground` are the roles), so adding the
  pairs would guard nothing.
- **The press row's inactive label**: `disabledForeground` on `selectedActive`
  is measured at rest by `selectionPressPairs` (plan 651). `inactiveSurfaces`
  does not own it, but the press list owns every text role on that transient
  fill by design; a second owner would report one composition twice.

## Finding

The copyable guarantee is only as wide as its guard, again: a block that builds
a theme must be *built*. Plan `658` gives the recipe edit the whole Contoso
primary family on the Aero dark base, ships it as `recipe-edit.example.ts`, holds
it to `themeFailures`, and makes `snippets.test.ts` parse the documented nested
map, compare it to the example and build it. The pre-fix one-role edit is
reconstructed in the tests as the can-fail fixture.

## Not changed

- `packages/components`, `packages/primitives` and `apps/*`;
- the platform-section snippet, which already moves the whole family (plan 310).
