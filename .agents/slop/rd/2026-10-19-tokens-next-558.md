# tokens-theme — next-unit audit after plan 558 (2026-10-19)

## What landed

- **558** closed a contradiction between the two halves of the editable-theme
  guarantee. Plan 540's `themeOpacityFailures` accepts an opaque role written
  `#RRGGBBFF` ("it paints the same colour either way") and `themeColorFailures`
  agreed, but `contrastRatio`, `relativeLuminance` and `compositeOver` parsed
  only six digits. A theme with `foreground: "#191D25FF"` returned `[]` from both
  format checks and **35** failures from `themeFailures` (23 contrast pairs plus
  the hierarchy cases, all ratio `NaN`); dark `card` returned **67** (62
  contrast). The opaque parser accepts a fully opaque `FF` byte, a partial alpha
  keeps failing, and `opaque-suffix.test.ts` proves both directions: reverting
  the parser fails three cases; a permissive parser fails the partial-alpha case
  and `contrast.test.ts`'s `NaN` case. No colour, pair, floor, metric, theme,
  platform style or recipe value moves. 139 files / 5,713 tests; `check`, `lint`
  and `test` green.

## Candidates, re-checked

1. **`ColorForm` is the last bare exported union.** Plan 305 gave every union an
   ordered index and a narrowing guard; `ColorForm` shipped later in plan 540 as
   `"opaque" | "translucent"` with no `colorForms` index and no `isColorForm`.
   It is a diagnostics payload (`OpacityFailure.expected`), not a stored choice,
   so the value is lower than 305's persisted axes — a small follow-up if the
   pattern is to stay total.
2. **An extra colour role a copied theme carries.** `extendTheme` keeps an
   unknown member in `colors`, but `themeColorFailures` and
   `themeOpacityFailures` walk the closed `colorRoles` list; plans 552/554 made
   the numeric equivalents total over the theme's own group. The colour side is
   deliberately closed ("if a token is not here, it is not public"), so this is
   a contract decision before it is a defect.
3. **Opaque `FF` spellings in platform styles and recipes.** Covered by 558's
   parser; no shipped style uses the spelling, and every shipped set still
   returns `[]`.
4. **Consumer handoffs.** Another workstream's tree; the remaining migrations
   (secondary/List press fills, field dimensions, native field theme) have rows.

## Order

558 template is another useful one: when two checks disagree about the same
authored value, the defect is in the reader, not in either documented rule.
