## Finding

**The date field's disclosure glyph was charged as caption type.** Plan 601
introduced `dateFieldWidth`'s bound and plan 627 added its two borders, but the
last term was `typography.caption.fontSize` while the trigger paints an icon:

```ts
// metrics.ts, as of plan 631
dateFieldWidth ≥
  3 * spacing.md + 2 * borderWidth.thin +
  typography.label.fontSize + typography.caption.fontSize;
// = 24 + 2 + 13 + 12 = 51 at the shipped identity
```

The trigger needs one more two-pixel step for the `sm` icon:

```ts
const tight = extendTheme(getTheme("light"), {
  dimensions: { dateFieldWidth: 52 },
});
```

returned **`[]`** from `themeMetricFailures` and `themeFailures` while the
trigger needed `24 + 2 + 13 + 14 = 53`. The shipped `220` hid the gap under the
old rule, but the guarantee an edited theme is told to rely on was 2px short. A
coherent theme that lifted the icon tier (`sm: 16`, `md: 18`, `lg: 22`,
`xl: 26`) and kept `dateFieldWidth: 54` also returned `[]` while the need was
`55`: the rule never read the tier the component paints.
