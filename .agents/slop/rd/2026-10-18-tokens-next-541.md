# tokens-theme — next-unit audit after plan 541 (2026-10-18)

Where the workstream stands after plan 541.

## What landed

- **541** made the requested contrast level total. `applyPlatformStyle` derived
  four level-dependent outputs from three inputs — the palette from the style's
  colours, the name from the base, the elevation opacity from the `contrast`
  argument, the declaration from the palette — so three documented calls returned
  a theme that lied about itself:
  - a `"high"` request on a default base returned a `default` theme while
    `themeContrastFailures(result, "high")` reported **180** pairs (the
    accessibility level was silently not honoured);
  - a `"default"` request on an AAA base returned the default palette under the
    name **"High contrast light · macOS"**;
  - a shape-only style kept the AAA palette (plan 301) and painted the style's
    default-level alpha — **`#FFFFFFA6`**, the near-white halo plan 505 forbids —
    with every check returning `[]`.

  The level now decides the palette, and the palette decides the name, the
  declaration and the elevation's opacity. A same-level base keeps its own
  palette, name and edits; a shape-only style keeps the base's level; a high
  request always builds the AAA set, which a platform's colours never repaint.
  `platform-claim.test.ts`'s "cannot claim high when only shape was applied" case
  became "builds the AAA palette for a high request instead of refusing it": the
  plan-301 principle (a declaration follows the palette) is preserved, and the
  composition now supplies the palette it declares. No shipped name, colour, pair,
  floor or metric moved.

## Candidates, re-checked

1. **`ContrastPairClass` is the last exported union without an ordered index.**
   Every sibling owns one (`themeModes`, `metricRules`, `motionLevels`,
   `typefaceRoles`, `translucentRoles`, …), and two guards hand-order these eight
   classes: `docs.test.ts`'s `rowFor` is type-exhaustive (a ninth class fails to
   compile), while `inventory.test.ts`'s `floorRow` builds the ledger's floor
   table from eight named fields and would silently under-report a ninth. A
   guard-only unit, like plans 372 and 501.
2. **The catalogue's "every present-tense figure" claim is split across two
   suites.** `docs/tokens.md` attributes the whole table to `figures.test.ts`, but
   several present-tense figures (the field edge's 1.25:1 on Linux dark, the
   `primaryText` row values) are pinned in `docs.test.ts` instead. The guarantee
   holds; the sentence names one owner. A wording change, not a defect.
3. **Fills on row washes (recorded, not fixed).** A probe over the 24 shipped
   sets shows `secondary` on `hover` at **1.000:1** in the identity light and dark
   sets and `accent` on `hover` at 1.000:1 light, so a neutral filled control or
   an accent toggle inside a hovered row has no shape against the wash. The
   contract measures fills against the four panels, not the row washes (plan 309),
   and the shipped secondary control's own `secondary` → `hover` → `active` step
   is already the plan-357 cross-team row; adding the pair today would fail the
   gate on values the `components` migration is going to change, so it waits for
   that migration or for a documented composition.
4. **A re-applied style names itself twice** (`"Light · Windows · Windows"`),
   because `applyPlatformStyle` appends the label to the palette's name. Cosmetic,
   and the name now carries the palette's level, which is the meaning worth
   keeping. Recorded, not fixed.
5. **The consumer handoffs.** Another workstream's tree.
