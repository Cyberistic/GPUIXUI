## Finding

**The row press had a distance but no direction.** Plan 619 published
`rowPressStepPairs` — `active` one 1.05:1 step from the `accent` hover a
selectable row paints — but `stateLadders`, the list `themeDirectionFailures`
walks, named only the filled families, the panel action, the generic wash and
the selected step.

A contrast ratio is symmetric, so a copied dark theme whose row presses
**darker** than its hover passes the step, every on-colour pair, every edge and
every metric. The planted theme used in the suite:

| Role | Value | What it paints |
| ---- | ----- | -------------- |
| `accent` | `#393939` | the hover wash a selectable row paints |
| `active` | `#333333` | the press, darker than the hover in a dark theme |
| `hover` | `#2C2C2C` | the generic wash, darker than the press, so that ladder passes |
| `selected` | `#3F3F3F` | one step past `accent`, so the selection ladder passes |
| `border` | `#414A57` | the divider stays visible on the selected fill |

`contrastRatio(active, accent)` is **1.094:1**, above the 1.05 step floor, and
`themeFailures(theme)` returned **`[]`**. The press moved toward the canvas while
the contract said nothing.

## Plan 622 — the selectable row's press direction

- `stateLadders` gains `{ name: "rowPress", roles: ["accent", "active"] }` after
  the selection ladder. The name matches `rowPressStepPairs`; the ladder follows
  the `accent` hover, not the generic `hover` wash.
- The new suite derives the ladder from the published pair (`[to, from]` →
  `[from, to]`) so a future edit to the distance cannot leave the direction
  behind. The existing "publishes a distance for every ladder step" case in
  `state-direction.test.ts` gains `rowPressStepPairs`, which is what makes the
  two lists coupled.
- `row-press.example.ts` is the executed inversion, imported by the suite and
  linked from the catalogue.
- Every shipped set already steps away from the canvas on `accent` → `active`,
  so no token value moves.
