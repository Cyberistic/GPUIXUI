## Candidates, re-checked

1. **A platform style cannot own density metrics (not planned).**
   `PlatformStyleStructure.density` is `DensityName`, while every other numeric
   group accepts partial overrides (plan 389). A consumer who copies
   `platform-styles/macos.ts` can name `compact` but cannot raise a control
   height or a row height inside the file they own; `platform-extension.example.ts`
   is named `contosoDensityPlatformStyle` and carries no density at all. The
   widening is type-only at runtime — `extendTheme` already merges
   `DensityOverrides` size by size — so the two-direction proof is the
   `check-types` gate plus a runtime case. It needs a decision on preset +
   overrides: the union `DensityName | DensityOverrides` merges overrides over
   the **base** preset, which loses a style's own preset choice; a
   `{ preset, overrides }` shape keeps both but widens the public surface.
2. **Marks on row washes (deferred again).** The combobox row highlights with
   `hover` only (`combobox.tsx:196-214`), so no shipped composition paints a
   `primary` check on `active`, `accent` or `selected`. `markPairs` already
   covers the plain surfaces, `input` and the combobox check on `hover`.
   Revisit when a component adopts one.
3. **Elevation over the content fills.** A probe over `primary`, the four solid
   status chips and the four soft fills found only the AAA dark `sm` level under
   1.05:1 (1.0396–1.0483 on `info`, `success`, `warning`, `primary`). A resting
   card's `sm` shadow does not land on a solid chip or an action in any shipped
   composition, so this is not a pair yet.
4. **Component literals the tokens can already satisfy.** The cross-team rows
   name the exact sites (drawer widths/heights, `overlayWidth`,
   `overlayMaxHeight`, `keycapSize`, field adornment and chat viewport). Tokens
   side ships the values.
