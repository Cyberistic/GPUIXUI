# tokens-theme — audit before plan 650 (2026-10-19, twenty-first tick)

## Scope

Every remaining `[ ]` row in `TODO.md` is a cross-team handoff or the
upstream-blocked `registerFont` (052). This tick audited the inactive half of
the contrast contract against the state the catalogue teaches: a disabled
field painted with `disabledControl(theme)`.

## What was probed

`disabledControl(theme)` (plan 605) returns `opacity: 1`, the `disabled` fill,
the `disabledForeground` label and the `border` edge, and
`src/disabled-state.example.ts` builds a Button from it. `docs/tokens.md` says a
disabled field is out of scope for the body pairs because the designed state
reads `disabledForeground`, "which `inactivePairs` measures", and records the
old 50% dim's measured cost on the macOS light `input` fill.

But `inactiveBaseSurfaces` was `disabled`, `background`, `card`, `popover`,
`muted`, `hover`, `active`, `accent`, `selected` plus the four soft status
fills — no `input`. A field keeps its `input` fill in the designed state, so the
label the catalogue promises is measured is not.

A probe built a theme that edits the field fill and everything painted on it
coherently. On the pre-650 tree it returned `[]` from all ten checks:

```ts
const planted = extendTheme(getTheme("light"), {
  colors: {
    input: "#B0B0B0",
    inputForeground: "#0D0F13",
    placeholder: "#404040",
    mutedForeground: "#2A2A2A",
    disabledForeground: "#6A6A6A",
    borderStrong: "#4A4A4A",
    primary: "#1B45A8",
    primaryHover: "#163C95",
    primaryActive: "#12327D",
    destructive: "#A32017",
    destructiveHover: "#8B1B13",
    destructiveActive: "#75160F",
    infoText: "#0E356E",
    successText: "#0A3F2A",
    warningText: "#4A3000",
    destructiveText: "#5A1116",
    primaryText: "#241C5C",
  },
});
```

`contrastRatio(disabledForeground, input)` is **2.494:1**, under the 3:1
inactive floor. Through the `selection` wash it is lower still. `input` is
already one of the nine `selectionSurfaces`, so the washed ground is measured;
only the two inactive pairs were missing.

The probe also walked the thirteen pre-650 surfaces at rest and washed: every
one clears 3:1 for the fixture, which is why the old checker accepted it.

Every shipped set already passes the missing pairs:

| measurement | tightest |
| ----------- | -------- |
| `disabledForeground` on `input` | 6.610:1 (Dark · Linux) |
| the same through `selection` | 4.944:1 (Light · Windows) |

## Finding

The field's `input` fill belongs to `inactiveBaseSurfaces`, the one owner both
inactive lists derive from. Plan 650 adds it: `inactivePairs` and
`selectionInactivePairs` each grow 13 → 14, `contrastPairs` 421 → 422,
`selectionWashPairs` is unchanged, and no colour moves.

## Not changed

- any shipped colour, role, floor, figure or metric;
- `selectionWashPairs` — `input` is already a `selectionSurface`;
- the body pairs — a disabled field still reads the designed role, not a
  faded `inputForeground`;
- a component or primitive source file;
- the check-kind count or the public export list.
