- **585** closed the last promise the native-text bridge made without a type.
  The documents told a brand to set the runtime's two token-less chrome metrics
  "on the returned object", but `NativeTextMetrics` declared neither
  `codeGutterMinWidth` nor `diffAccentBarWidth`, so the documented literal failed
  `check-types` with TS2561. Both are optional members now, `metricsOf` leaves

  `docs/design-system.md` §10, the interface JSDoc, the README and the ledger

## Candidates, re-checked

1. **Derive the two runtime metrics.** `codeGutterMinWidth` is a floor the
   computed width already exceeds as the type grows; scaling it with
   `codeBlock` would make a large code role's one-digit gutter enormous.
   `diffAccentBarWidth` has no token source (a 3px chrome bar, not a border).
   Optional passthrough is the honest answer, and now it type-checks.
2. **A mark helper for row washes.** The notification dot shows the real
   composition, but the measured answer is `primaryText`, which the text
   contract already holds at 4.5:1/7:1 on all four washes; a new helper would
   add API without a new guarantee.
3. **Fills on row washes (`secondary` on `hover` at 1.000:1 in the identity).**
   Still the plan-357/334 consumer ladder; waits for `components`.
4. **CSS-wide family keywords (`inherit`, `initial`, `unset`, `revert`).** Not
   CSS Fonts 4 generic family keywords, so adding them to
   `cssGenericFamilies` would falsify its claim.
5. **The consumer handoffs.** Another workstream's tree.
