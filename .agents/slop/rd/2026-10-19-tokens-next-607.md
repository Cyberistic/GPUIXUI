# tokens-theme — next-unit audit after plan 607 (2026-10-19)

## What landed

- **607** closed the last painted corner the theme did not own. The pinned
  runtime's `HighlightSpec.radius` defaults to a 2px literal, and
  `nativeHighlight` returned only the two washes, so a copied platform style
  with `radius.sm: 0` still painted a rounded find match. The helper now
  returns `radius: theme.radius.sm` — the inline-mark step inline code already
  uses (`mdInlineCodeRadius`).
- The identity, macOS and Linux sets move their match corner from 2px to their
  own 4px step; Windows and the XP/Aero recipes already ship `sm: 2`, so their
  paint is unchanged. A square theme now paints a square match.
- The suite derives the field from every shipped theme and proves it follows a
  squared and a widened copied step; the opaque equality case includes it, the
  example asserts it, and a docs case holds the catalogue, design system and
  README to the sentence.
- 157 files / 6,007 tests green; `check`, `lint` and `test` pass. No colour,
  pair, floor, metric or check moves.
- Both directions verified by hand: with `radius: 2` the derivation and example
  cases fail (3 cases); with `inline-mark` removed from `docs/tokens.md` the
  document case fails. Each restores green.

## Queue state

- Every `[ ]` row in `TODO.md` outside the phase headers is a cross-team
  handoff (`components`, `primitives`, `docs-site`, `playground`, licensing,
  repo tooling). None is in this workstream's paths.
- BLOCKERS B1 and B2 are not in this workstream's paths.
- With the highlight corner owned, the bridge now populates every field the
  pinned runtime reads for a native text document, a native text field and a
  find bar. No runtime-exposed style field is left at a literal.
