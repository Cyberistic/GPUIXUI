# 348 — A package manifest must declare every module its source imports

**Phase:** G (release readiness) · **Owner:** primitives · **Depends on:**
`021`, `024`, `030`, `031`, `203` · **Status:** planned

## 1. The defect

`packages/primitives` and `packages/icons` both import **`effect` at runtime**,
but both `package.json` files list it only under `devDependencies`:

```jsonc
// packages/primitives/package.json
"dependencies": { "@gpuixui/icons": "workspace:*", "@gpuixui/tokens": "workspace:*" },
"devDependencies": { "effect": "catalog:", /* … */ }
```

```jsonc
// packages/icons/package.json
"dependencies": { "@gpuixui/tokens": "workspace:*" },
"devDependencies": { "effect": "catalog:", /* … */ }
```

The shipped source is not type-only:

| Package | File | Import | Used at runtime |
| ------- | ---- | ------ | --------------- |
| primitives | `src/core/keyboard.ts` | `effect/Array`, `effect/Option` | `Arr`, `Option` |
| primitives | `src/core/selection.ts` | `effect/Array`, `effect/Option` | both |
| primitives | `src/core/state.ts` (and 9 more core modules) | `effect/…` | yes |
| primitives | `src/components/Select.tsx`, `Spinner.tsx`, … | `effect/Array`, `effect/Option` | yes |
| icons | `src/registry.ts` | `effect/Record` | `R.map` builds the registry |

A consumer that installs `@gpuixui/primitives` (or `@gpuixui/icons`) therefore
does **not** get `effect`; the first import of the package fails to resolve
`effect/Array`. The docs site found the primitives half while deriving dependency
lists from the manifests (its plan `428`); the icons half is the same defect and
was not recorded.

Why no gate caught it: `nub run check` / `nub run test` run inside the workspace,
where `effect` is hoisted from the dev dependency, so resolution never fails.
Only a clean consumer install would, and no test reads the manifest.

This is a release requirement (`MISSION.md` "clear install … instructions",
Phase G "clean-environment install and public-export checks") and a truth defect
in two files whose whole job is to say what the package needs.

## 2. The fix

### 2.1 Manifests

Move `effect` from `devDependencies` to `dependencies` in **both** packages,
keeping the catalog specifier (`"effect": "catalog:"`). Nothing else changes:

- `@gpuix/react` stays a `peerDependency` — it is the host runtime, supplied once
  by the application, and duplicating it is worse than requiring it;
- `react` stays a `peerDependency`;
- `@gpuixui/tokens` / `@gpuixui/icons` stay workspace `dependencies`.

`nub install` regenerates `nub.lock`; the expected diff is the two workspace
importers' dependency lists, nothing else.

### 2.2 The guard

A new test, `packages/primitives/src/package-manifest.test.ts`, scans the
**shipped** source of both packages and asserts every bare module specifier is
declared in `dependencies` or `peerDependencies` of that package's manifest.

- Both packages are scanned from one test because both are owned by this
  workstream and the alternative is the same scanner twice — the precedent is
  `src/docs-theme-paths.test.ts` (plan `333`), whose header says exactly this.
- The scan reads files with Effect `FileSystem`/`Path` and Node layers, matching
  `src/capabilities.test.ts` and `src/docs-theme-paths.test.ts`.
- Scope: `packages/<name>/src/**/*.ts(x)` minus `*.test.ts(x)` and minus any
  `testing/` directory (`src/testing/**`, `src/components/testing/**`), which
  are test-only subpaths and import `vitest`/`@gpuix/react/testing`.
- Specifier → package: `@scope/pkg/sub` → `@scope/pkg`, `pkg/sub` → `pkg`;
  relative specifiers and `node:*` builtins are skipped.
- Matching covers `from "…"` and side-effect `import "…"`.
- Declared = `dependencies` ∪ `peerDependencies`. A module in `devDependencies`
  only is reported as the failure, naming the package, the module and the file.
- Liveness: the scan must find a non-trivial number of imports (> 20) and must
  find `effect` in the runtime imports of **both** packages, so a broken
  specifier regex fails loudly instead of passing vacuously.

## 4. Test plan

The guard must fail without the fix, in independent directions.

| Mutation (apply, run, revert) | Must fail |
| --- | --- |
| put `effect` back in `devDependencies` in `packages/primitives/package.json` | one case naming `@gpuixui/primitives`, `effect` and `src/core/keyboard.ts` (or the first importing file) |
| put `effect` back in `devDependencies` in `packages/icons/package.json` | one case naming `@gpuixui/icons`, `effect` and `src/registry.ts` |
| break the specifier regex (e.g. require a leading space) | the liveness case |
| delete `src/registry.ts`'s `effect/Record` import and leave the manifest as is | liveness case for icons |

The first two are the regression directions (the bug being guarded); the last two
prove the guard is not vacuous.

## 5. STOP conditions

Stop and report with the measurement rather than improvise if:

- a bare specifier found by the scan is genuinely dev-only (a shipped file
  imports `vitest` or another test API) — that means a test harness has leaked
  into the shipped surface; report the file instead of adding it to an allowlist;
- moving `effect` to `dependencies` changes any resolved version in `nub.lock`
  (the catalog must keep `effect` at one version);
- `nub install` reports a peer/version conflict;
- any existing test fails (the manifests do not change resolution inside the
  workspace, so nothing should).

## 6. Acceptance

- Both manifests declare `effect` in `dependencies`; `nub.lock` reflects it.
- `src/package-manifest.test.ts` fails when either package lists a runtime
  import only as a dev dependency, and fails when its scanner matches nothing.
- `nub run check`, `nub run lint`, `nub run test` are green, and both packages'
  own suites pass.
- `TODO.md` and the plan index record the task; the plan's Result section records
  the measured before/after and the two mutation proofs.

## 7. Result

Landed on `agent/primitives`, 2026-10-18.

### 7.1 What changed

| File | Change |
| ---- | ------ |
| `packages/primitives/package.json` | `effect` moved from `devDependencies` to `dependencies` |
| `packages/icons/package.json` | same |
| `nub.lock` | the two workspace importers' dependency lists (6 insertions / 6 deletions); no version changed — still `4.0.5` |
| `packages/primitives/src/package-manifest.test.ts` | new guard: two per-package cases + one liveness case |

The guard strips comments before matching specifiers, because the first draft
matched prose: `core/keyboard.ts`'s `from "unhandled"` (a docstring sentence) and
`core/value.ts`'s `from "stay where you are"` were reported as modules. That is
recorded here because a text scanner over source must earn its matches.

### 7.2 Both-direction proofs (each mutation measured, then reverted)

| Mutation | Failing test |
| --- | --- |
| `effect` back in `devDependencies` in `packages/primitives/package.json` | `@gpuixui/primitives declares every module its shipped source imports` — 1 failed, reporting `primitives: effect (src/components/Button.tsx)` and the rest of the files |
| `effect` back in `devDependencies` in `packages/icons/package.json` | `@gpuixui/icons declares every module its shipped source imports` — 1 failed, `icons: effect (src/registry.ts)` |
| break the specifier regex (`/ZZZ(?:from\|import)…/`) | `scans the real imports of both packages` — the liveness case (both per-package cases pass vacuously, which is exactly why it exists) |

The planned fourth mutation — delete `registry.ts`'s import and keep the manifest
— was attempted and discarded: removing the import makes `registry.ts` throw at
module load, so the whole suite fails before the guard runs and the result proves
nothing about the guard. The regex mutation is the honest non-vacuity proof.

### 7.4 Deviations

- The plan expected **two** guard cases (`572` tests); the liveness case makes
  **three** (`573`).
- The scan excludes any `testing/` path segment as well as `*.test.ts(x)`, which
  the plan described only for `src/testing/**`; `src/components/testing/element.ts`
  is the same kind of harness and imports `vitest`.
- `scanPackage`'s error channel is `PlatformError | Schema.SchemaError` — the
  manifest is decoded with `Schema.fromJsonString` (EF-19), which can fail with a
  schema error, so the type says so.
- The liveness threshold is a total over both packages (> 50 imports), not a
  per-package count: icons only has ~16 imports, so a per-package `> 20` would
  fail a healthy package. Both packages still assert a real `effect` and
  `@gpuixui/tokens` import by module name.

The docs site derives its dependency tables from `package.json`, so the
primitives row there will now list `effect` without a docs edit. No docs-site
path was touched.
