# 047 — Tier 1 docs pages and runnable examples (primitives workstream)

- **Phase:** C. **Owner:** primitives workstream.
- **Depends on:** `030-primitives-package.md`, `031-icons-package.md`,
  `040-phase-c-tier1.md`, `041-tier1-runtime-verification.md`.
- **Status:** implemented — 21 primitives pages, the icons page, six examples, and
  a seven-test runtime suite that mounts every example. Evidence in §8.
- **Why now:** plan 040 §5 and AGENTS.md §4 require **code + a test that can
  fail + an example + a docs page + an inventory row** per component. Code, unit
  tests and the runtime suites exist; the examples and docs pages are the two
  remaining halves. `examples/basic-app` composes the set once, but a component
  is not demonstrated by one screen that uses it, and there is no page a consumer
  can read before copying the source.

## 1. What this plan delivers

Co-located documentation and examples inside the packages this workstream owns,
so the source, its example and its page cannot drift:

| Path | What it is |
| ---- | ---------- |
| `packages/primitives/docs/<name>.mdx` | one page per Tier 1 component (21 pages) |
| `packages/primitives/docs/README.md` | the page index and the page contract |
| `packages/primitives/examples/<family>.example.tsx` | six realistic examples covering every component (including the icon gallery) |
| `packages/primitives/examples/index.ts` | `id → example` registry for `apps/playground` |
| `packages/icons/docs/icon.mdx` | the icon page |
| `packages/primitives/runtime/examples.runtime.test.tsx` | mounts every example in the real renderer and proves it paints |

The docs site is a separate workstream: `apps/docs` consumes the prop types from
source (plan 411). These pages are the in-package source of truth it can copy or
link; nothing here pretends the browser can render a GPUix tree.

## 2. The page contract

Every page uses the same sections, in this order. A page that cannot fill a
section says so; it does not omit the section silently.

1. **Frontmatter** — `title`, `description`.
2. **What it is** — one paragraph, including what it is *not*.
3. **Usage** — a compiling TSX snippet importing from the public package root.
4. **Variants / sizes / states** — a table, from the real unions in source.
5. **API** — a prop table generated by reading the component's exported
   interface: name, type, default, and the consequence of setting it.
6. **Keyboard** — the contract from `core/keyboard.ts`, or "not focusable".
7. **Accessibility** — role, `aria-*` actually supported by GPUix 0.10.0, and
   what cannot be expressed.
8. **Theming** — which semantic roles the resolver reads; no literals.
9. **Limitations** — measured GPUix gaps with the evidence already recorded in
   `COMPONENTS.md` (never "coming soon").
10. **Verification** — the test files and the exact command that ran them.
11. **Related** — two or three sibling components by name.

Pages are 50–90 lines. They must be true: every claim is either in the source,
in `COMPONENTS.md`'s `Runtime (041)` notes, or in plan 041 §9. Do not invent a
prop, a state or a capability.

## 3. The examples

Five files, each a realistic workflow rather than a gallery. Every example is a
plain React component that renders inside a `ThemeProvider` supplied by its host
(the playground, the runtime suite, `examples/basic-app`).

| File | Covers | The workflow |
| ---- | ------ | ------------ |
| `layout.example.tsx` | Box, Stack, Grid, Separator, Spacer, ScrollArea | an inspector sidebar: header, separated sections, a scrolling property list, a fixed footer |
| `typography.example.tsx` | Text, icons | a change-log entry: heading, body, caption, code role, muted metadata, an inline icon |
| `form.example.tsx` | Label, Input, TextArea, Select, Button, ButtonGroup, Progress | a project-settings form: controlled fields, a save/cancel group, an upload progress bar |
| `selection.example.tsx` | Checkbox, RadioGroup, Switch | notification preferences with an indeterminate "all channels" parent |
| `feedback.example.tsx` | Tooltip, Skeleton, Spinner | a slow-loading metric card: skeleton rows, a busy header button with a tooltip |
| `icons.example.tsx` | Icon | a status strip and the five-step size scale |

Requirements for every example:

- imports only `@gpuixui/primitives`, `@gpuixui/icons`, `effect`, `react`;
- no colour, spacing or radius literal — take them from `useTheme()`;
- `testId` on the root and on any node the runtime suite must find;
- a distinctive headline string the runtime suite can assert was painted;
- controlled state where the control supports it, so the example demonstrates
  the real API rather than only its defaults;
- JSDoc header stating what the example demonstrates.

## 4. The runtime proof

`packages/primitives/runtime/examples.runtime.test.tsx` imports each example and
one `it` per example:

1. mount it in `Surface` (the shared themed frame);
2. assert the distinctive headline is in `paintedText()`/`allText()`;
3. assert the root `testId` was retained by the renderer;
4. for `form.example.tsx`, type into a field and assert the controlled value
   reached the frame; for `selection.example.tsx`, click the switch and assert
   `aria-valuetext` flipped.

This is the half the element-tree suites cannot reach: it proves the examples are
not decorative source that has never been mounted. It is an opt-in command
(`test:runtime`), because it needs the native binding (plan 041 §2.1).

It must be able to fail: deleting a component from an example (or breaking the
wiring) must make its `it` fail. The executor records the two-direction run in
§8 below.

## 6. Commands and expected results

Run from the worktree root, in this order:

```sh
nub run check
# expect: check-tests, lint, fmt and check-types all pass; 0 errors.

nub run --filter @gpuixui/primitives test
# expect: 153 tests pass (the existing suites; this plan adds no src test).

nub run --filter @gpuixui/icons test
# expect: 18 tests pass.

nub run --filter @gpuixui/primitives test:runtime
# expect: 7 files, 54 + N tests pass, where N is one per example.

nub run --filter @gpuixui/primitives check-types
# expect: examples and runtime suite included, 0 errors.

rg 'aria-checked|aria-valuenow|aria-labelledby' packages/primitives/docs
# expect: only the "not supported" sentences mention them.
```

## 7. STOP conditions

- An example cannot render without a capability GPUix does not have → do not
  fake it; document the limitation on the page and use the strongest honest
  alternative.
- A docs claim cannot be traced to source, `COMPONENTS.md` or plan 041 §9 →
  delete the claim rather than guess.
- The runtime example suite fails because the binding is absent → stop and
  report; do not weaken the suite or skip it.
- `nub run check` cannot be green → stop; do not weaken the gate.

### §8.1 Two-direction proof (measured 2026-10-17)

The suite had to be able to fail before it could be called a test. The probe:

1. **Break** — replace the form example's `onActivate={() => setSaving(true)}`
   with `onActivate={() => {}}` and run
   `nub run --filter @gpuixui/primitives test:runtime -- runtime/examples.runtime.test.tsx`.
   Result: **1 failed | 5 passed** —
   `creates through the form example's busy action` failed with
   `AssertionError: expected undefined to be '62%'` (no progress bar was created).
2. **Restore** — revert the line and rerun the same command.
   Result: **6 passed (6)**.

Full runs after the change:

```text
nub run check                         → check-tests, lint, fmt, check-types: pass
nub run test                          → 3 + 16 files, 18 + 153 tests: pass
nub run --filter @gpuixui/primitives test:runtime
                                      → 7 files, 60 tests: pass
```

The six example tests are: every registered example mounts and paints its
headline; the layout example keeps its scrolling property list; the form's save
produces the `62%` progress; the selection switch flips its announced value; the
feedback tooltip opens on hover; the icons example announces its labelled status
icon as an `Image`.

### §8.2 Deviation from §5

The icon gallery lives at `packages/primitives/examples/icons.example.tsx`, not
in `packages/icons/examples/`. The example needs `useTheme()` for its tints, and
`@gpuixui/icons` deliberately has no theme dependency; putting the example there
would either duplicate a palette or make the icon package depend upwards. The
runtime suite that mounts it already lives in `primitives` for the same reason
(plan 041 §2.2).
