# 623 — The per-part state table is generated from the package

**Phase:** F · **Owner:** docs-site · **Status:** implemented
**Depends on:** 410, 411, 415, 419, 431, 482, 504, 587, 610, 622

## 1. Why this plan exists

Plan 622 fixed the false claim on `/docs/component-api#state-aware-styles` and
recorded the measured shape of the state surface: **25** exported `*State`
interfaces with **27** distinct fields, parsed from `packages/components/src`.
The paragraph now names the ownership rule and five examples, but a reader who
styles `InlineEdit` by `editing` or `MessageScroller` by `pinned` still cannot
see the field list, and `TabsTriggerState` is only findable as prose.

`TODO.md` carries the follow-up: a generated per-part table needs a generated
module, an index document and a search entry (D32). This plan delivers those
three, with the same guards as the other generated tables:

- every row comes from the package, never from a hand-written list;
- a stale generated file fails by name;
- the table is indexed in `/api/search` and distinctive type names are promoted
  (D47), so `InlineEditState` reaches the table while plain fields stay prose.

## 2. Decisions

1. **One generated module, one renderer, one index document.** The data lives in
   `src/lib/part-states.generated.ts`; `<PartStates />` renders it; the search
   entry derives from the same array. No layer retypes a row.
2. **Rows are the whole state, not a vocabulary.** Each row is one exported
   `*State` interface with its declared fields, in source order. Fields are
   listed as-is; the page does not classify them as "recurring" or "specific" a
   second time (the prose above already carries that reading).
3. **Only type names are promoted, and they match whole only.** `TabsTriggerState`,
   `InlineEditState`, `MessageScrollerState` and the rest are distinctive
   camelCase names, so a query for one outranks prose. A field (`editing`,
   `pinned`, `status`) is indexed by the document's content but never promoted,
   because a plain word already has an owner elsewhere (D47, plan 569). The
   entry sets `exactNamesOnly` because token matching made
   `MenuCheckboxItemState` outrank the exported `checkboxState` helper on
   `/docs/api-values` — measured while landing this plan; a state type is a
   precise symbol, not a phrase.
4. **The source reader stays out of the browser.** `part-states.ts` stays pure
   (plan 622); a new `part-states-source.ts` owns `node:fs` and is imported only
   by the generator script and tests. The component imports the generated data.
5. **The anchor is `#every-state-type`.** The section heading is
   `### Every state type`; the search URL and the page test use that id.

## 4. The generated module

`src/lib/part-states.generated.ts`:

```ts
// Generated by `nub run --filter docs part-states` from
// `packages/components/src` (plan 623). Do not edit: the guard fails when this
// file is stale.
import type { PartState } from "./part-states.js";

export const stateTypes: readonly PartState[] = [
  {
    name: "TabsTriggerState",
    file: "packages/components/src/tabs.tsx",
    fields: ["active", "disabled", "focused"],
  },
  // …
];
```

`part-states-source.ts`:

```ts
import { readdirSync, readFileSync } from "node:fs";
import { join } from "node:path";
import { partStates, type PartState } from "./part-states";

const isSource = (name: string): boolean =>
  /\.(ts|tsx)$/.test(name) &&
  !/\.test\.(ts|tsx)$/.test(name) &&
  !name.startsWith("behaviour/");

/** Every exported state interface under `packages/components/src`, by path. */
export const readPartStates = (root: string): ReadonlyArray<PartState> => {
  const sourceRoot = join(root, "packages/components/src");
  const sources = readdirSync(sourceRoot, { recursive: true, encoding: "utf8" })
    .filter(isSource)
    .sort()
    .map((name) => ({
      path: `packages/components/src/${name}`,
      text: readFileSync(join(sourceRoot, name), "utf8"),
    }));
  return partStates(sources);
};

/** The committed module, with the command that regenerates it. */
export const renderPartStatesModule = (
  states: ReadonlyArray<PartState>,
): string => `// Generated by \`nub run --filter docs part-states\` …
`;
```

The renderer writes `JSON.stringify(state, null, 2)`-shaped rows but must print
`readonly PartState[]`, so use an explicit template per row (the other generated
modules follow the same style).

`scripts/part-states.ts` mirrors `scripts/api-values.ts`: derive, refuse to
write when the list is empty or a name repeats, otherwise `writeFileSync` and
log `part-states: 25 state types, 27 fields`.

## 5. The table and the page

`<PartStates />` renders:

- a summary line: `25 exported state types across N files.` (derived);
- a scrollable table (`role="region"`, `aria-label`, `tabIndex={0}` like the
  other wide tables) with columns **State type**, **Fields**, **Declared in**;
- one row per generated state, `data-state-type={name}`, fields as inline code.

The page section, directly after plan 622's paragraph:

```mdx
### Every state type

The table below is generated from every exported `*State` interface in
`@gpuixui/components`; run `nub run --filter docs part-states` after changing a
part's state. A row's fields are the fields its `style` function receives.

<PartStates />
```

## 6. The search entry

`part-states-search.ts`:

```ts
import { isDistinctiveName, type GeneratedSearchEntry } from "./generated-search";
import { stateTypes } from "./part-states.generated";

export const partStatesSearchEntry: GeneratedSearchEntry = {
  exactNamesOnly: true,
  names: stateTypes.map((state) => state.name).filter(isDistinctiveName),
  index: {
    title: "Part states",
    description:
      "Every exported state type in @gpuixui/components and the fields it declares.",
    content: stateTypes
      .map((state) => `${state.name} (${state.file}): ${state.fields.join(", ")}`)
      .join("\n"),
    url: "/docs/component-api#every-state-type",
    breadcrumbs: ["Component API"],
    keywords: stateTypes
      .flatMap((state) => [state.name, ...state.fields])
      .join(" "),
  },
};
```

Add the row to `indexedSurfaces` in `search-docs.ts` (the guard compares the two
lists exactly) and add a `smoke:build` search check:

  what: "a state type named by the generated part-state table" },

## 9. Two-direction proofs

Record each measured run in §10.

1. Remove one row from `part-states.generated.ts` → the staleness test fails by
   the missing name.
2. Rename a `*State` interface in `packages/components/src` (temporary) → the
   staleness test fails; restore and re-run.
3. Delete `<PartStates />` from `component-api.mdx` → the page test fails by
   name.
4. Drop one type from the search entry's promoted names → the entry test fails.
5. Point the entry's URL at `#state-types` → `smoke:build`'s
   `InlineEditState` query fails by name (the anchor and the index disagree).
6. Add a new exported `*State` interface in a temporary component file →
   `nub run --filter docs part-states` changes the file, and the stale test
   fails until it is regenerated; delete the file afterwards.
7. **The measured regression this plan found:** before `exactNamesOnly`, the
   full docs suite failed `finds a helper on the generated values page` with
   `checkboxState` → `/docs/component-api#every-state-type`; after the flag the
   value index keeps `/docs/api-values`, and the new unit case pins both
   directions.

## 11. STOP conditions

- Stop if `packages/components/src` stops declaring top-level exported
  `*State` interfaces; adapt the parser first (plan 622 §9), not the renderer.
- Stop if the generated module would need a runtime import from
  `packages/components`; the docs app must not depend on the native package.
- Do not promote a field name; if `editing` needs promotion, the alias/roadmap
  mechanism is the wrong tool too — revisit with a measured query first.
- Stop if `smoke:build` exits `2`.

## 12. Acceptance

- `/docs/component-api#every-state-type` renders one row per exported state type
  and its fields, derived from the package, with a stated regeneration command.
- `InlineEditState`, `MessageScrollerState` and every other state type reach the
  table from ⌘K first; `editing` still reaches the component that owns it.
- The staleness, render, page and search guards fail in both directions.
- `nub run --filter docs test`, `check-types`, `smoke:build`, `nub run check`,
  `lint` and `test` pass; §10 records the counts and proofs.
