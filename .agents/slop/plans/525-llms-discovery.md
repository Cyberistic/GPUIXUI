# 525 — Machine discovery: `/llms.txt` and `/llms-full.txt`

**Status:** implemented
**Phase:** F (docs information architecture)
**Depends on:** 410, 418, 439, 510, 524
**Owns:** `apps/docs/src/lib/llms.ts`, `apps/docs/src/routes/llms[.]txt.ts`,
`apps/docs/src/routes/llms-full[.]txt.ts`, `apps/docs/src/lib/llms.test.ts`,
`apps/docs/content/docs/meta.json`, `apps/docs/scripts/smoke-build.ts`,
`apps/docs/README.md`

## 1. Why

The site has one machine-readable index today: `/sitemap.xml`. It is enough for
a crawler, and nothing else. A reader that is not a browser — an editor, an
agent, a CLI — has no single URL that lists the documentation, and no URL that
returns it as Markdown. `MISSION.md` asks for structured metadata and navigation
that is generated consistently; the page tree already owns that structure, so
the missing piece is an output, not a new source of truth.

Fumadocs ships the generator (`llms()` in `fumadocs-core/source`) and the docs
loader already sets `postprocess: { includeProcessedMarkdown: true }`, which is
what `page.data.getText("processed")` reads. No dependency is added.

The failure this guards is a page the site builds and a machine cannot find, or
a discovery document that lists a URL the sitemap does not serve. **Plan 524 is
the prerequisite:** before it, the test-time source listed 15 of 94 pages, so an
index test would have passed over a fraction of the site.

## 2. Exact changes

### 2.1 `apps/docs/src/lib/llms.ts` (new)

```ts
import { llms } from "fumadocs-core/source";
import { SITE_URL, absoluteUrl } from "./site";
import { source } from "./source";

/** `llms()` writes page-relative links; the file is read outside the site. */
const absoluteLinks = (document: string): string =>
  document.replaceAll("](/", `](${SITE_URL}/`);

/** `/llms.txt`: the page tree's titles, summaries and links. */
export const renderLlmsIndex = (): Promise<string> =>
  Promise.resolve(absoluteLinks(llms(source).index()));

/** `/llms-full.txt`: every page as the Markdown the site renders. */
export const renderLlmsFull = (): Promise<string> =>
  llms(source, {
    renderPage: async (page) => {
      const description = page.data.description ?? "";
      return [
        `# ${page.data.title}`,
        description.length > 0 ? `> ${description}` : null,
        `Source: ${absoluteUrl(page.url)}`,
        await page.data.getText("processed"),
        "",
      ]
        .filter((line): line is string => line !== null)
        .join("\n");
    },
  }).full();
```

The index is the **page tree**, so its order and group titles are the sidebar's.
A page missing from `meta.json` is already a `content.test.ts` failure; the
index does not invent a second navigation.

### 2.4 `apps/docs/src/lib/llms.test.ts` (new)

Header comment states the bug guarded. Five tests:

1. **every page is linked once, absolutely** — for each `source.getPages()`
   entry, `](${absoluteUrl(page.url)})` occurs exactly once, and the document
   contains no `](/`.
2. **the index opens with the site's name and the tree's summary** — starts
   `# GPUIXUI`, contains `\n> `, is not HTML.
3. **the full document renders every page** — for each page,
   `Source: ${absoluteUrl(page.url)}\n` occurs exactly once (the newline keeps
   `/docs` from matching every `/docs/…`).
4. **the document fits one response** — measured 2 493 666 bytes (~2.5 MB)
   against a 10 MiB STOP threshold.
5. **authored prose, not the MDX source** — `## Usage` and the Button page's
   prose sentence are present; the frontmatter block is not.

Processed Markdown keeps data-driven MDX blocks as component tags
(`<ComponentState … />`, `<CapabilityMatrix … />`), because they are React, not
prose. The test asserts author-visible text rather than pretending those blocks
became Markdown.

## 4. Test plan (two directions)

Measured in this worktree:

1. **Relative links:** `renderLlmsIndex` without `absoluteLinks` → test 1 fails
   on the first page (assertion at `llms.test.ts:22`), restore.
2. **A missing page:** render `indexNode(pageTree.children[0])` instead of the
   whole tree → test 1 fails on the first absent page, restore.
3. **A dead link:** append a hard-coded `- [Ghost](/docs/ghost)` to the index →
   `smoke:build` exits `1` with
   `FAIL /llms.txt: links /docs/ghost, which the sitemap does not serve`,
   restore (the restored run is green at 95 sitemap pages).
4. **A page missing from the shipped index** is covered by test 1 iterating the
   real 94-page source (plan 524).

## 5. STOP conditions

- `page.data.getText("processed")` is unavailable or empty for most pages → stop
  and report the loader shape; the index route may ship alone.
- `llms-full.txt` exceeds 10 MiB → stop and report the measured size.
- `llms()` links a path the sitemap does not serve → stop; report the tree
  mismatch instead of loosening the smoke.
