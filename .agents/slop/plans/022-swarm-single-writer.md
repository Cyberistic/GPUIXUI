# 022 — One writer per worktree: the swarm is running duplicate agents

**Phase:** cross-cutting (swarm infrastructure). **Found by:** primitives
workstream. **Owner of the fix:** `scripts/` in the shared checkout — outside
every workstream's paths, so it needs a coordinator or the human.
**Depends on:** nothing. **Status:** `BLOCKER (B3) — measured 2026-10-17 07:40`

> The primitives workstream stopped writing the moment this was confirmed. Read

## 2. Why it happens

The runner generated by `scripts/swarm-supervisor.sh` (`write_runner`) is:

```sh
while :; do
  model=$("$MODELS" current)
  "$OPENCODE" run --model "$model" --auto --title "swarm:$ws" "$PROMPT" | tee "$out"
  # …classify / advance / sleep 20…
done
```

`opencode run` **creates a new session every iteration and does not own the
turn**. When the CLI returns — a fast failure, a dropped stream, a limit — the
server-side turn keeps running against the same directory, and the loop starts
another one on top of it. Nothing in the loop stops, awaits or replaces the
previous session.

The signature is in the timestamps: on 2026-10-17 the primitives loop created a
session every ~20–120 s (07:02:13, 07:02:34, 07:04:14, 07:04:35, 07:05:51,
07:06:13) while every earlier session was still live, then a rung-1 session at
07:12:12 that is still running now. `--title` is set, but a title is not an
identity: `opencode run` has no `--session`, so there is nothing for the loop to
resume or to refuse.

`agent_alive` in the supervisor only checks the **runner pid**
(`ps -p "$pid" -o command= | grep -q "run-$1.sh"`). It cannot see a turn that
outlived its CLI call, so the supervisor believes the workstream is healthy and
keeps every duplicate alive. `MIN_AGENTS` therefore never trips.

## 3. Impact — why every workstream must pause

- **Work is destroyed, not duplicated.** Four agents edit the same files with
  no locking. The winner is whichever wrote last, and the losers' tests then
  fail against their own assumptions, which they "fix" by writing again.
- **The gates lie.** `nub run check` / `nub run test` results are meaningless
  while a file can change between the compiler reading it and the assertion.
- **`TODO.md` / `COMPONENTS.md` / the plan index** are edited by every
  duplicate, so the swarm's "source of truth" is itself racy.
- **Cost and limits.** Five concurrent sessions per workstream burn the same
  model quota the fallback chain is trying to conserve.

A workstream that keeps writing under these conditions is not making progress;
it is manufacturing a half-merged tree.

## 4. Immediate mitigation — stop the damage first

Before any workstream writes again, leave **exactly one** live session per
worktree: the oldest, which holds the most context. For each directory, list the
live sessions (§1) and delete the extras:

```sh
/Users/cyberistic/.opencode/bin/opencode session delete <sessionID>
```

Then confirm the invariant in §6 for every workstream. Resuming the queue before
this is done reproduces the situation within one tick.

> Deleting a live session discards its in-flight (uncommitted) work. Capture the
> tree first: `git -C workspaces/primitives status --short` and commit or stash
> anything worth keeping before deleting.

## 5. The permanent fix (choose one, then verify)

**5.1 Pin one session per workstream (recommended).** Give the runner a stable
session id and always continue it, so a second run *joins* the first instead of
forking it:

```sh
"$OPENCODE" run --session "swarm-$ws" --model "$model" --auto "$PROMPT"
```

`opencode run --session <id>` "continues the session … or creates it if it does
not exist", which is exactly the resume-or-start semantics a loop needs. A
stable id also makes the runner idempotent across ticks: two supervisors racing
produce one session, not two.

**5.2 Abort-or-await before starting.** If a pinned id is not adopted, make the
loop refuse to start while a turn for its directory is live: query the session
store for live sessions in `$dir` (or the server API) and wait for one, never
start a second.

**5.3 Fix the liveness check.** `agent_alive` must also count live
server-side sessions for the worktree directory, so a workstream whose runner
died but whose turn is still generating is reported unhealthy **once**, not
restarted into a duplicate.

**5.4 Never probe with a model that cannot answer.** Sessions were created on
`opencode-go-braven/does-not-exist-xyz` minutes before the duplicate storm.
`swarm-model.sh` classifies "model unavailable" as a spent rung and moves on —
correct — but a probe must still not leave a run loop respawning every 20 s.
Whichever of 5.1–5.3 lands, the loop must be unable to fork.

## 6. Verification — the test that must fail now and pass after

The invariant is "one writer per tree". Check it for every workstream, twice,
one tick apart:

```sh
for ws in primitives tokens-theme components docs-site playground; do
  n=$(sqlite3 ~/.local/share/opencode/opencode.db \
      "select count(*) from session_v2
        where directory like '%/workspaces/$ws'
          and time_idle is null;")
  printf '%-14s live-sessions=%s\n' "$ws" "$n"
done
```

- **Now:** `primitives 5`, `components 5`, `docs-site 6`, `playground 6`,
  `tokens-theme 2` — the test cannot fail.
- **After the fix:** every line prints `1`, and still prints `1` after the next
  supervisor tick.
- **Guard against regression:** commit the loop above as
  `scripts/check-single-writer.sh` and run it from the supervisor tick, so a
  duplicate is detected instead of discovered by a clobbered agent. That is the
  regression test this fix must land with (AGENTS.md §3: a fix with no test is
  unfinished).

## 7. STOP conditions

Stop and escalate rather than improvise if:

- the fix requires editing anything under `packages/primitives` or
  `packages/icons` — it must not; this is a runner problem;
- deleting a duplicate session would destroy work that is not committed *and*
  not reproducible from the remaining session's context;
- after applying 5.1 the same directory still shows more than one live session
  over two ticks — then the CLI's `--session` does not do what its help text
  says, and the honest answer is 5.2 plus an upstream bug report.

## 8. What the primitives workstream did about it

Nothing in its own tree. `packages/primitives` and `packages/icons` were left
untouched from the moment the duplicate writers were confirmed, and this plan
plus the `TODO.md` entry are the only writes. Editing either package would have
clobbered four other sessions mid-turn, which AGENTS.md §6 forbids ("one writer
per tree") and which no amount of local test-passing can repair.

The duplicate sessions, if the coordinator keeps them, also own the current
`packages/primitives` work — `src/core/*` is theirs, mid-flight. Whoever applies
§4 should preserve that tree before deleting anything.
