---
title: Expandable rows
description: A table row that opens a detail panel under itself.
---

`TableExpandableRow` is a row that opens a panel under itself; the composition is
two rows — the row and a `TableDetailRow` sibling.

## Usage

```tsx
import {
  Table,
  TableBody,
  TableExpandableRow,
  TableHeader,
  TableHeaderCell,
  TableRow,
  TableViewport,
} from "@gpuixui/data";
import { useState } from "react";

const [open, setOpen] = useState<string | null>(null);

<Table height={300} aria-label="Files with details">
  <TableViewport>
    <TableHeader>
      <TableRow>
        <TableHeaderCell width={32} />
        <TableHeaderCell width={200}>Name</TableHeaderCell>
      </TableRow>
    </TableHeader>
    <TableBody>
      {files.map((file) => (
        <TableExpandableRow
          key={file.id}
          expanded={open === file.id}
          onToggle={() => setOpen(open === file.id ? null : file.id)}
          cells={<TableCell width={200}>{file.name}</TableCell>}
          detail={<KeyValue entries={detailOf(file)} />}
        />
      ))}
    </TableBody>
  </TableViewport>
</Table>;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `expanded` | `boolean` | `false` | the panel under the row paints |
| `onToggle` | `() => void` | — | the row's press, and the activation its Enter/Space makes; the caller flips `expanded` |
| `cells` | `ReactNode` | — | the row's cells, after the expander track |
| `detail` | `ReactNode` | — | the panel painted under the row while it is open |
| `toggleWidth` | `number` | `32` | the expander track's width |
| `detailTestId` | `string` | — | the panel's test id |
| `tabIndex` | `number` | `0` | the row's place in the Tab order; a disabled row takes `-1` |
| `disabled` | `boolean` | `false` | refuses the press and the keys, and paints no pointer state |

## Keyboard

The row is the disclosure's **control**, so it is a stop in the Tab order and
answers Enter and Space to toggle the panel; a caller's `onKeyDown` still runs.
A focusable `div` has no activation of its own — only the pointer path runs
`onClick` — so a row that answered the press alone would leave a keyboard reader
no way to open a panel.

The key is answered **only while the row itself holds focus**. A key is
dispatched along the focus path, so a field inside the row's cells still reaches
the row's handler (`press-routing-lifecycle`'s `field-cell` route) — an
unguarded row opened its panel while the reader typed a space into the field.
The runtime builds the payload for the handler's own element, so the row reads
the renderer's focused element instead.

A disabled row answers neither the pointer nor the key. It takes `tabIndex` `-1`
rather than leaving the chain entirely: the runtime orders a negative index
before the zero stops, so programmatic focus can still reach the row.

## Limitations

- One panel per row; two rows can be open at once.
- No animation of the panel's height.
- A windowed table cannot use it; use the plain table or the list's children mode.
- The docs site cannot render this component live.
