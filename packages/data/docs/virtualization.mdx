title: Virtualization
description: A long list and table that mount one window of rows.
---

GPUix publishes `<virtual-list>`; `@gpuixui/data` composes it as `VirtualList`
and `VirtualTable`, with the window arithmetic from `@tanstack/virtual-core`.

## Usage

```tsx
import { VirtualList } from "@gpuixui/data";

<VirtualList height={320} aria-label="Files">
  {rows.map((row) => (
    <div key={row.id} style={{ height: 32 }}>
      <text>{row.label}</text>
    </div>
  ))}
</VirtualList>;
```

## API

`VirtualList`:

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `height` | `number` | caller's layout | a definite viewport height |
| `children` | `ReactNode` | — | the rows |
| `itemCount` | `number` | children mode | switches to the windowed mode |
| `estimatedItemHeight` | `number` | — | required with `itemCount`; a height the runtime cannot lay out is read as the shipped row's own (`37`) |
| `windowStart` | `number` | `0` | the first rendered slice's index |
| `onVisibleRange` | `(range: VisibleRange) => void` | — | the built window |
| `overdraw` | `number` | — | rows built beyond the viewport |
| `ref` | `Ref<PublicInstance>` | — | the list's instance, for `scrollToItem` |

`VirtualTable` and `VirtualTableBody`:

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `count` | `number` | — | the logical row count; a fraction, a negative or an unreadable count is the whole, non-negative rows the table holds (`0` paints `empty`) |
| `rowHeight` | `number` | — | every row must paint exactly this height; a height the window cannot divide is read as the shipped row's own (`37`) |
| `row` / `renderRow` | `(index: number) => ReactNode` | — | paints one absolute row index |
| `height` | `number` | measured body | a definite table (or body) height |
| `header` | `ReactNode` | — | the header row's cells |
| `empty` | `ReactNode` | `No rows` | painted inside a `TableEmpty` row when `count` is `0`; a string paints as its own text element |
| `caption` | `ReactNode` | — | the line below the frame; a string paints as its own text element |
| `overdraw` | `number` | `4` | rows mounted beyond the viewport on each side |
| `reveal` | `VirtualReveal` | — | `{ index }`; the window moves, then the body scrolls |
| `onVisibleRange` | `(range: VisibleRange) => void` | — | the runtime's lagging report |

`useVirtualRows({ count, rowHeight, viewportHeight, overdraw, initialOffset, reveal })` returns the window state a consumer needs to render it themselves.

An empty set paints `empty` inside a `TableEmpty` row: the message is a cell of
the grid, not a loose label under the body's row group — the same shape the
plain table's empty state has. A **string** is painted as the cell's own
`<text>`, because the runtime reaches its accessibility tree only through text
elements: a raw string in a box paints and is never announced.

`count={0}` is an empty set, not a load. A windowed table with no `empty` node
used to fall through to the body's no-children branch and paint the **loading
skeleton** — three rows of placeholder bars — so a caller who said there were no
records was told the first page was still arriving. It paints
`DEFAULT_EMPTY_MESSAGE` (`No rows`) instead; pass `empty` to choose the words.

`count` is read **once**, as the whole non-negative number of rows the table
holds: a fraction of a row cannot exist, and a count the table cannot read
(`NaN`, an infinity, a negative) is `0`, so it paints the empty state rather
than a header above a blank body. That one number drives the runtime list's
`itemCount`, the window arithmetic and the empty state, so the list and its
window cannot disagree about how many rows exist. A caller waiting on a total
passes `0` and its own `empty` (a `Spinner`, a message) until the response
arrives, rather than an unresolved arithmetic result.

**A row height is read once too.** `rowHeight` (and the list's
`estimatedItemHeight`) is often computed — the density's step, a viewport divided
by the rows it should show, a measurement taken before the first layout — and a
value the window cannot divide is not a height. The estimate, the scroll
anchor's arithmetic and a reveal all read one number: a finite height above
zero, or the height this package's own row paints (`DEFAULT_ROW_HEIGHT`, 37 —
its `text-sm` line inside `py-2` plus the row's rule, measured by
`behaviour/rowheight.test.tsx`). Before that rule, a `NaN` height reached all
three: the window mounted a row per pixel (204 rows of a thousand in a 240px
viewport), the anchor's `index × NaN` clamped the offset to `0`, and a
thousand-row table painted nothing past its first window for ever. A caller
whose rows paint another height declares it; the fallback is an estimate, not a
measurement of the caller's row.

## Limitations

- One row height: the windowed mode positions rows from `estimatedItemHeight`.
- `onVisibleRange` is not a window source: it lags the paint by one gesture.
- `itemCount` mode has no row span; an expanding row belongs in children mode.
- The window is app state; the docs site cannot render this component live.
