---
title: Virtual trees
description: A hierarchy of thousands of rows that retains and paints only one window, with the tree keyboard, roving tab stop and reveal rules the plain tree already measured
---

## Usage

```tsx
import { VirtualTree, useExpandedRows } from "@gpuixui/data";

const tree = useExpandedRows({ roots: files, keyOf, childrenOf, labelOf });

<VirtualTree
  aria-label="Workspace files"
  height={320}
  rows={tree.rows}
  cursor={tree.cursor}
  onCursorChange={tree.setCursor}
  labelOf={labelOf}
  onActivate={(row) => open(row.node)}
/>;
```

## API

### `VirtualTree`

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `rows` | `TreeRow<T>[]` | — | the **whole** flattened set, in paint order |
| `labelOf` | `(node: T) => string` | — | the row's accessible name and what type-ahead matches |
| `cursor` | `TreeCursor` | — | the caller's cursor; omit it for an uncontrolled tree |
| `onCursorChange` | `(cursor: TreeCursor) => void` | — | reports every cursor a key, a press or a window move produces |
| `defaultCursor` | `TreeCursor` | nothing open | the uncontrolled tree's start |
| `onActivate` | `(row: TreeRow<T>) => void` | — | a press or Enter on a row |
| `renderRow` | `(row: TreeRow<T>) => ReactNode` | `labelOf` as text | paints a row's content after its inset and chevron |
| `height` | `number` | the bounded column's height | the viewport height; a height the layout cannot paint is **no height**, so the tree fills the column and windows against the height it measured |
| `rowHeight` | `number` | the density's `rowHeight` | every row paints exactly this height |
| `overdraw` | `number` | `4` | rows mounted beyond the viewport on each side |
| `onVisibleRange` | `(range: VisibleRange) => void` | — | the runtime's lagging report, for a readout or pagination |
| `instanceRef` | `(instance: PublicInstance \| null) => void` | — | the list's painted element, for a probe that reads its scroll anchor |
| `className` | `string` | — | joined after the recipe |
| `testId` | `string` | — | the tree; each row is `${testId}-row-${key}` and its chevron slot `${testId}-row-${key}-slot` |

## Limitations

- **One row height**: `rowHeight` positions rows; use `VirtualList` for variable heights.
- **A window needs a height**: given a paintable `height` the window is computed from it; a height the layout cannot paint is no height, so the tree fills its bounded column and windows against the height it measured. The runtime's `<virtual-list>` paints no surface and reports no `onLayout`, so an unbound tree measures the column it fills instead (measured on 0.11.0; `behaviour/paintable-height.test.tsx` holds a 320px pane to the 10 rows a `height={320}` tree paints). An auto-height or non-flex parent gives the tree no viewport, and it paints no rows.
- **A scrolling window moves the cursor**: the focused row can unmount.
- **One active row**; no multi-select tree.
