title: Charts
description: Bar, stacked, line, area, pie, donut, radar, radial, treemap, sankey, sunburst and sparkline charts
---

A chart is a **scene**, and the scene is compiled by
[TanStack Charts](https://github.com/TanStack/charts). The compiler is a pure
function over a definition and a size — no DOM, no `document`, no `window` —
and the scene it returns carries every series' own colour, so one element
paints the whole plot.

The paint route is `setImage`: the chart's SVG document is decoded by the
runtime's own renderer and painted as one image, which is why a chart can hold
two colours in one element and a real gradient under an area. The axis,
labels, legend and the hover readout are text and boxes beside the plot, so
every chart inherits the surface it sits on. The paint is window-verified by
`chart-surface-lifecycle`.

## Usage

```tsx
import {
  AreaChart,
  BarChart,
  ChartLegend,
  ComposedChart,
  DonutChart,
  LineChart,
  PieChart,
  RadarChart,
  RadialChart,
  Sparkline,
  StackedBar,
} from "@gpuixui/data";

<BarChart
  aria-label="Revenue against cost by quarter"
  labels={["Q1", "Q2", "Q3", "Q4"]}
  series={[
    { key: "revenue", label: "Revenue", values: [32, 48, 41, 60] },
    { key: "cost", label: "Cost", values: [18, 22, 26, 24] },
  ]}
  width={320}
  height={140}
/>;
```

Every cartesian chart shares the frame's options: `grid`, `tooltip`, `colors`,
`legend`, `axis`, `xLabels`, `ticks` and `valueFormat`. Hovering a column shows
each series' value; `tooltip={false}` turns it off.

## API

### `BarChart`

```tsx
<BarChart
  aria-label="Signups by month"
  labels={MONTHS}
  series={[{ key: "signups", label: "Signups", values: SIGNUPS }]}
  orientation="horizontal" // vertical by default
  radius={4}
  valueLabels
  valueLabelFormat={(value, series) => `${series.label} ${value}`}
/>;
```

Negative values stand below the axis; a zero paints no bar but keeps its slot.


| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `orientation` | `"vertical" \| "horizontal"` | `"vertical"` | bars grow up, or right from the axis |
| `radius` | `number` | `3` | the bar's corner, clamped to half its width and height |
| `valueLabels` | `boolean` | `false` | each bar's value prints above it |
| `valueLabelFormat` | `(value, series, category) => string` | `valueFormat`, then the value | what a bar's label says |

### `StackedBar`

```tsx
<StackedBar
  aria-label="Revenue and cost"
  labels={QUARTERS}
  series={[revenue, cost]}
  percent // each category reads as 100%
/>;
```


| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `radius` | `number` | `3` | the segment's corner, clamped to the bar |
| `percent` | `boolean` | `false` | values become shares of each category's total, on a 0–100 axis |

### `LineChart`

```tsx
<LineChart
  aria-label="Churn"
  labels={QUARTERS}
  series={[churn]}
  curve="smooth" // linear, smooth or step
  dots
  showLabels
  dotIcons={["check", "info", "bell", "circle"]}
  lineWidth={2}
/>;
```


| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `curve` | `"linear" \| "smooth" \| "step"` | `"linear"` | a spline through every point, or a held step |
| `dots` | `boolean` | `false` | a dot paints on every point |
| `dashed` | `boolean` | `false` | the line paints dashes |
| `lineWidth` | `number` | `2` | the stroke's weight, in pixels |
| `showLabels` | `boolean` | `false` | each point's value paints above it |
| `dotIcons` | `IconName[]` | none | an icon per category paints on each point |
| `pointTooltip` | `boolean` | `false` | a hit zone on every point shows that datum |
| `dotIcons` | `IconName[]` | none | an icon per category paints on each point |

### `ScatterChart`

```tsx
<ScatterChart
  aria-label="Response time against load"
  labels={LOADS}
  series={[{ key: "latency", label: "Latency", values: [12, 30, 58] }]}
/>;
```

One point per datum, and no line between them: a point sits where its value
sits, so a point outside the range is clipped to the plot's edge rather than
drawing outside the frame. A datum with no number paints no point.

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `radius` | `number` | `3` | each point's radius, in pixels |

### `CandleChart`

```tsx
<CandleChart
  aria-label="Daily prices"
  labels={DAYS}
  series={[]}
  candles={[
    { open: 10, high: 20, low: 5, close: 18 },
    { open: 18, high: 19, low: 12, close: 13 },
  ]}
/>;
```

The open, high, low and close of each period. A candle that closed **above**
its open paints in the `upColor` and one that closed at or below it in the
`downColor`, so a reader who cannot separate two hues still reads the
direction.

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `candles` | `Candle[]` | — | the open, high, low and close of each period, one per category |
| `width` | `number` | `6` | each candle's body width, in pixels |
| `upColor` | `string` | the theme's `success` | the colour an up day paints |
| `downColor` | `string` | the theme's `destructive` | the colour a down day paints |

### `FunnelChart`

```tsx
<FunnelChart
  aria-label="Signups"
  labels={["Visit", "Sign up", "Buy"]}
  series={[]}
  stages={[100, 60, 20]}
/>;
```

A stage per datum, each a share of the **first**. The stages are centred and
narrow, so a funnel reads as a funnel rather than as bars of different widths
stacked to one side.

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `stages` | `number[]` | — | each stage's value; the first is the widest |
| `stageLabels` | `string[]` | the categories | the names the stages answer to |

### `TreemapChart`

```tsx
<TreemapChart
  aria-label="Where the time goes"
  nodes={[
    { path: "engineering", value: 60 },
    { path: "design", value: 25 },
    { path: "operations", value: 15 },
  ]}
/>
```

A hierarchy as nested rectangles, each area its value's share of the whole.
The cells are **squared** by the compiler, so a large value is a wide cell
rather than a tall one — the shape reads as the value's shape.

A node's **path** is its route through the tree: `"root/engineering"` is a
node named `engineering` under `root`. The list may name only the leaves — a
root is added when the list names none — and a node that carries no value of
its own holds its subtree's.

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `nodes` | `{ path: string; value?: number }[]` | — | the hierarchy, one row per node |
| `size` | `number` | `200` | the plot's size, in pixels |
| `method` | `"squarify" \| "binary" \| "dice" \| "slice" \| "slice-dice"` | `"squarify"` | how the cells are squared |
| `ratio` | `number` | the compiler's | the target aspect ratio of a cell |
| `paddingInner` | `number` | `0` | the gap between adjacent cells |
| `paddingOuter` | `number` | `0` | the gap between a parent's edge and its children |
| `colors` | `string[]` | the theme's series scale | the categorical palette |
| `nodeColors` | `Map<string, string>` | — | a node's own colour, by its path |
| `legend` | `boolean` | `true` | the legend paints under the cells |
| `valueFormat` | `(value: number) => string` | — | how a value prints in the legend |
| `testId` | `string` | — | the chart's test id; a cell is `${testId}-cell-${path}` |
| `label` | `string` | the chart's own name | the name the document announces |

### `RadialBarChart`

```tsx
<RadialBarChart
  aria-label="The letters"
  data={[
    { key: "E", label: "E", value: 40 },
    { key: "T", label: "T", value: 30 },
    { key: "A", label: "A", value: 20 },
  ]}
/>
```

One bar per category, each extending out from the centre. The bar's length
is its value's share of the largest, and the categories own their own slots
around the circle — so a reader compares the lengths and the sectors at
once.

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `data` | `{ key: string; label?: string; value: number }[]` | — | one row per category |
| `size` | `number` | `200` | the plot's size, in pixels |
| `radiusRatio` | `number` | `0.8` | the share of the plot the bars' ring occupies |
| `bandPadding` | `number` | `0.12` | the share of each category's slot left empty |
| `colors` | `string[]` | the theme's series scale | the categorical palette |
| `legend` | `boolean` | `true` | the legend paints under the bars |
| `valueFormat` | `(value: number) => string` | — | how a value prints in the legend |
| `testId` | `string` | — | the chart's test id; a cell is `${testId}-cell-${path}` |
| `label` | `string` | the chart's own name | the name the document announces |

### `SankeyChart`

```tsx
<SankeyChart
  aria-label="The pipeline"
  nodes={[
    { id: "visits", name: "Visits" },
    { id: "signups", name: "Signups" },
    { id: "buys", name: "Buys" },
  ]}
  links={[
    { source: "visits", target: "signups", value: 60 },
    { source: "signups", target: "buys", value: 20 },
  ]}
/>
```

A flow between nodes, each ribbon's thickness its value. A link naming a node
the graph does not hold is **dropped**: the compiler rejects such a link, and
a reader who drew a flow to a node that is not there would rather see the
flow that is.

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `nodes` | `{ id: string; name?: string }[]` | — | the nodes the flow runs through |
| `links` | `{ source: string; target: string; value: number }[]` | — | the edges the flow runs along |
| `size` | `number` | `200` | the plot's size, in pixels |
| `nodeWidth` | `number` | the compiler's | a node's width, in pixels |
| `nodePadding` | `number` | the compiler's | the gap between same-column nodes |
| `colors` | `string[]` | the theme's series scale | the categorical palette |
| `nodeColors` | `Map<string, string>` | — | a node's own colour, by its id |
| `legend` | `boolean` | `true` | the legend paints under the flow |
| `valueFormat` | `(value: number) => string` | — | how a value prints in the legend |
| `testId` | `string` | — | the chart's test id; a cell is `${testId}-cell-${path}` |
| `label` | `string` | the chart's own name | the name the document announces |

### `SunburstChart`

```tsx
<SunburstChart
  aria-label="The store"
  nodes={[
    { path: "root/engineering", value: 60 },
    { path: "root/design", value: 25 },
    { path: "root/operations", value: 15 },
  ]}
/>
```

The same hierarchy a treemap draws, as **concentric rings**: each arc's angle
is its value's share of its parent, and the rings are drawn from the centre
out. A hierarchy deeper than `visibleDepth` is not drawn.

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `nodes` | `{ path: string; value?: number }[]` | — | the hierarchy, one row per node |
| `size` | `number` | `200` | the plot's size, in pixels |
| `innerRadius` | `number` | the compiler's | the hole at the centre, as a share of the outer radius |
| `ringPadding` | `number` | `0` | the gap between the rings, in pixels |
| `visibleDepth` | `number` | every ring | how many rings of the hierarchy are drawn |
| `colors` | `string[]` | the theme's series scale | the categorical palette |
| `nodeColors` | `Map<string, string>` | — | a node's own colour, by its path |
| `legend` | `boolean` | `true` | the legend paints under the rings |
| `valueFormat` | `(value: number) => string` | — | how a value prints in the legend |
| `testId` | `string` | — | the chart's test id; a cell is `${testId}-cell-${path}` |
| `label` | `string` | the chart's own name | the name the document announces |

## Tooltip

```tsx
<BarChart
  aria-label="Revenue"
  labels={QUARTERS}
  series={[revenue, cost]}
  tooltipIndicator="line"
  labelFormat={(label) => `Quarter ${label}`}
  valueFormat={(value) => `${value}k`}
  activeBand
/>;
```

The readout follows the pointer inside a column. `tooltipIndicator` marks each
row with a dot, a line or nothing; `labelFormat`
rewrites the category's name and `valueFormat` rewrites every value.

## Legend

```tsx
<BarChart
  aria-label="Revenue"
  labels={QUARTERS}
  series={[revenue, cost]}
  legend="top"
  legendShape="line"
/>;

<ChartLegend
  shape="dot"
  items={[
    { key: "revenue", label: "Revenue", color: series1, value: "181k" },
    { key: "cost", label: "Cost", color: series2, value: "90k" },
  ]}
/>;
```

`legendShape` draws a square, a dot or a line before each row; a row with a
`value` prints it after its label.

## Zoom and pan

```tsx
<BarChart
  aria-label="Revenue"
  labels={QUARTERS}
  series={[revenue]}
  view={view} // controlled: drag the strip to pan, wheel to zoom
  zoom
  onViewChange={setView}
/>;
```

`view` is a **continuous** window in category units: an edge of `1.5` puts
category 1 half off the plot's left edge, and a span of two shows two
categories. `zoom` paints the navigation strip; dragging it pans and the wheel
zooms around the window's centre. Its **Reset** control returns `[0, labels]`.

## Brush

```tsx
<BarChart
  aria-label="Revenue"
  labels={QUARTERS}
  series={[revenue]}
  domain={window} // controlled: the drag reports into it
  brush
  onDomainChange={setWindow}
/>;
```

`brush` paints a strip under the plot; dragging across it reports
`onDomainChange` for the categories it covers, and the controlled `domain` is
what the plot paints. `domain` is the same window as `[start, end)` indexes;
the chart paints only those categories and measures its axis over them. A stored window that is
reversed, fractional or past the end is normalized to whole indexes inside the
list, and a window that leaves nothing paints the whole chart.

## Animation

```tsx
<BarChart
  aria-label="Revenue"
  labels={QUARTERS}
  series={[revenue, cost]}
  animate
  animationDuration={320}
/>;
```

`animate` tweens a data change from the values on screen to the new ones;
`animationDuration` is that run in milliseconds. A chart with a
`MotionProvider preference="reduced"` above it paints the new values at once —
the resting frame is the same one the tween lands on.

## How a chart is painted

A chart is **a scene**, and the scene is compiled by
[TanStack Charts](https://github.com/TanStack/charts) — MIT, and the one chart
library whose compiler runs without a DOM.

| Stage | What it does |
| --- | --- |
| `sceneRows` | the caller's series become **flat** rows: one field per series, keyed by the series' own key |
| `sceneDefinition` | the rows become a definition: the marks, the ticks and the scales |
| `chartScene` | the definition and the plot's box compile to a `ChartScene` — a value, not a render |
| `sceneSvg` | the scene serialises to **one SVG document** |
| `ChartSurface` | the document is decoded by the runtime's own renderer and painted as one image |

Two properties follow, and neither is available to a chart drawn as a stack of
tinted masks:

- **one element, every colour.** Two series paint in two colours inside one
  element, because the document carries each shape's own fill;
- **a real gradient.** A fade under an area is a `linearGradient`, not a stack
  of nested bands.

The hit test is **geometric**: the scene keeps a point for every datum beside
the painted nodes, so the datum under the pointer is the nearest point, not a
DOM event on a mark. That is what the hover readout asks.

Only the **DOM-free** subpaths are used — `/scene`, `/line`, `/bar`, `/area`,
`/tick`, `/svg` and `/scales/*`. TanStack's DOM renderers (`/canvas`, `/dom`,
`/dom-text`) name `document`, `window`, `HTMLElement`,
`getBoundingClientRect` and `ResizeObserver`, and this runtime has none of
them. Importing by subpath keeps `d3-scale`, `d3-shape` and `d3-selection`
out of the bundle as well: the shipped bundle carries **zero** d3 references.

The scales come from `@tanstack/charts-scales`, a package with no dependencies
of its own.

## Limitations

- A category label wider than its slot is clipped at the slot's edge, so two
  neighbouring categories never paint over each other.
- A hover readout is per category, not per mark: it names every series' value at
  that column rather than the one shape under the pointer.
- The document route paints the marks as one image, so a mark is not an
  accessibility element of its own; the series' values are announced by the
  chart's own description, and the readout is a sibling of the image.
- Zoom, pan and the brush paint their strips as the runtime's own boxes, not
  as scene nodes.
