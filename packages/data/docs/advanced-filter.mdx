## Usage

```tsx
import { AdvancedFilter, emptyTree } from "@gpuixui/data";
import { useState } from "react";

const [tree, setTree] = useState<FilterTree>(emptyTree);

<AdvancedFilter
  fields={[
    { field: "status", label: "Status" },
    { field: "size", label: "Size" },
  ]}
  tree={tree}
  onChange={setTree}
/>;
```

## API

The tree's own readers are exported beside the builder:

| Export | What it does |
| ------ | ------------ |
| `emptyTree` | the empty `all` group, which matches everything |
| `FilterTree` | the schema a stored query is decoded and validated through |
| `isFilterTree(value)` | whether a value is a tree this release can read |
| `readFilterTree(value)` | `Option<FilterTree>`: a stored query, or the refusal |
| `filterByTree(rows, tree, valueOf)` | the rows a tree keeps |
| `matchesTree(tree, row, valueOf)` | whether one row matches |
| `describeTree(tree)` | the sentence a tree reads as |

### `AdvancedFilter`

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `fields` | `AdvancedFilterField[]` | — | the fields a clause may name; a blank label reads as the field's own name, a value that is not a list offers no field, and a list that offers none — or whose entries name a blank `field` — paints no Add control |
| `tree` | `FilterTree` | — | the tree the builder paints |
| `onChange` | `(next: FilterTree) => void` | — | receives every edited tree |
| `title` | `string` | `Filters` | the title above the builder; a blank title reads as `Filters` |
| `className` | `string` | — | joined after the recipe |
| `testId` | `string` | — | the builder's id; a clause is `${testId}-${slot}-…` |

### `AdvancedFilterField`

| Field | Type | Consequence |
| ----- | ---- | ----------- |
| `field` | `string` | the field a clause reads, and the fallback name when the label is blank |
| `label` | `string` | the words the builder shows for it |

## A saved query

A tree is stored data: a saved query outlives the release that wrote it, and a
store or a hand-edited record can hand back a node or a comparison this build
does not carry. Decode it before it reaches a builder or a table:

```ts
const saved = readFilterTree(storedQuery);

Option.match(saved, {
  onNone: () => promptToRebuildTheQuery(),
  onSome: (tree) => setTree(tree),
});
```

A tree this release cannot read is **refused, never approximated**: the table
keeps **no** rows rather than showing every record the query meant to hide, and
`describeTree` answers `a filter this release cannot read`. The builder paints
that sentence with Clear, so a reader can recover from a query whose clauses it
cannot edit. A `null`/`undefined` query is no filter at all — `useTable` and the
builder read it as the empty tree.

A tree the schema **can** read may still name no field: a query saved before its
field was picked carries a blank `field`, which the tree's schema accepts. The
builder does not refuse it — there is a clause to edit — it reads the missing
name as `Field`, so the row is named and its sentence says which part is absent.

## Limitations

- The builder edits a tree; it does not run one — use `filterByTree`.
- `fields` is read as data: a saved record that carried `null` for the
  list offers no field, so a clause falls back to the field's own name. An entry
  that names a **blank** `field` is not a field either — it can never match a
  column id, so it is dropped from the picker and from the list Add reads.
- **Add is offered only while there is a field to name.** A new clause takes the
  first offered field, so a builder with none to offer paints no Add clause and
  no Add group — the press would append a clause over no field, a query that
  narrows nothing. Clear stays. A blank `field` among other entries is skipped,
  so the clause Add composes names the first field it can actually use.
- A clause that names no field — the shape a saved query can carry — reads
  `Field` in its clause row and its sentence, so it is never a nameless picker
  and its sentence never opens on its comparison.
- A `not` holds exactly one child and paints no Add of its own.
- A clause carries Remove only where removing it changes the tree.
- A tree the release cannot read is refused with Clear; it is not migrated into
  the current comparison set.
