---
title: Advanced filtering / query builders
description: A builder over a typed predicate tree.
---

`AdvancedFilter` is a **query builder**: the reader composes clauses, and the
tree combines them with `all`, `any` and `not`. The builder paints the tree it
is handed, adds clauses to any group, and **composes the groups themselves**: a
group's combinator is a menu (`all of`, `any of`, `Negate`), and **Add group**
nests a new one where the reader asked. Every group it can extend paints its
**own Add controls**, so a nested `any` gains a clause or a group in place —
including one inside a `not`. A `not` itself paints none, because it holds one
child; a group inside one is a group like any other, and its clauses remove
individually.

## Usage

```tsx
import { AdvancedFilter, emptyTree } from "@gpuixui/data";
import { useState } from "react";

const [tree, setTree] = useState<FilterTree>(emptyTree);

<AdvancedFilter
  fields={[
    { field: "status", label: "Status" },
    { field: "size", label: "Size" },
  ]}
  tree={tree}
  onChange={setTree}
/>;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `fields` | `AdvancedFilterField[]` | — | the fields a clause may name |
| `tree` | `FilterTree` | — | the tree the builder paints |
| `onChange` | `(next: FilterTree) => void` | — | receives every edited tree |
| `title` | `string` | `Filters` | the title above the builder |
| `testId` | `string` | — | the builder's id; a clause is `${testId}-${slot}-…` |

A clause's `slot` is its path joined with `-` (a root clause is `0`), so a
clause inside a nested group keeps its own locators: `${testId}-${slot}-field`,
`${testId}-${slot}-comparison`, `${testId}-${slot}-value`,
`${testId}-${slot}-remove`, and a group's remove is
`${testId}-${slot}-group-remove`. A group's combinator control is
`${testId}-kind` at the root and `${testId}-${slot}-kind` below it, with
`-kind-all`, `-kind-any` and `-kind-negate` for its menu. The root's Add clause
is `${testId}-add` and its Add group `${testId}-add-group`; a nested group's own
are `${testId}-${slot}-add` and `${testId}-${slot}-add-group`.

The tree's own API, exported beside the builder:

| Export | What it does |
| ------ | ------------ |
| `emptyTree` | the empty `all` group, which matches everything |
| `filterByTree(rows, tree, valueOf)` | the rows a tree keeps |
| `matchesTree(tree, row, valueOf)` | whether one row matches |
| `describeTree(tree)` | the sentence a tree reads as |

## Narrowing a table

The tree is the same one a table runs: `useTable` takes it as `filterTree` and
reads each clause's field through the column whose `id` it names. The tree
narrows the records before the text query does, so the filter field searches the
set the tree kept and a sort orders that same set.

```tsx
const columns = [
  { id: "status", label: "Status", width: 120, valueOf: (row) => row.status },
  { id: "size", label: "Size", width: 90, valueOf: (row) => row.size },
];
const table = useTable({ rows, keyOf: (row) => row.id, columns, filterTree: tree });

<AdvancedFilter fields={FIELDS} tree={tree} onChange={setTree} />;
```

A chosen record the tree hides is released in the same commit (the rule the
text query already follows), and the core keeps the id, so a tree that keeps it
again paints it chosen. A field no column names reads blank, so a saved tree
that mentions a column the caller has since removed narrows to the records it
can decide instead of failing. A controlled consumer that builds the table with
`constructGrid` reads the same seam:
`filterByTree(rows, tree, fieldValueOf(columns))`.

## How a comparison reads a value

The comparisons are literal — a clause's value is never treated as a pattern.
An `equals`/`notEquals` compares the field's text, a `contains` is a
case-insensitive substring, and an order reads **both** sides as numbers, so a
field stored as a number and a clause typed as text still compare.

A side that does not read as a number satisfies no order. That includes the
blank value a clause starts with: the builder appends `value: ""`, and an order
built from it keeps no row rather than treating the blank as `0`. A field the
row does not carry reads as blank too, and text like `wide` never satisfies an
order.

## Composing groups

The tree holds `all`, `any` and `not`, and the builder writes all three. A
group's **combinator** is a menu beside its clauses:

- **Match all** keeps the group's children and requires every one.
- **Match any** keeps them and requires one.
- **Negate** wraps the group, so `not (any of A, B)` reads "neither A nor B";
  the same item un-negates it, so a reader who changes their mind gets the group
  back rather than a second wrapper.

**Add group** appends an `all` group holding one blank clause to the group it
sits on, and the reader switches that group's combinator afterwards. A new group
starts with a clause rather than empty because an empty `any` keeps nothing —
landing a reader in a group whose own explanation is "nothing" would be a trap
the Add control set.

```tsx
const tree: FilterTree = {
  kind: "all",
  children: [
    { kind: "predicate", field: "status", comparison: "equals", value: "tracked" },
    {
      kind: "any",
      children: [
        { kind: "predicate", field: "name", comparison: "contains", value: "readme" },
        { kind: "predicate", field: "name", comparison: "contains", value: "notes" },
      ],
    },
  ],
};
// "tracked AND (readme OR notes)"
```

The reducers behind those controls are exported for a caller that builds a tree
outside the component: `setGroupKind(tree, path, "all" | "any")` keeps a group's
children and changes how they combine, and `negateAt(tree, path)` wraps the
group (a second call gives it back). Both leave the tree alone when the path
names nothing.

## Accessibility

The builder's title is a level-3 `heading`, and the sentence above the clauses,
each group's combinator (`all of`, `any of`, `not`) and the clause controls are
all announced (`surface-a11y.test.tsx`): a reader hears the tree's meaning, not a
row of unlabelled menus. A group's combinator is the **control** that changes
it, named by the words it shows, so the same node a reader hears is the one they
press. A clause's field and comparison triggers are named buttons, and its value
is the primitives' `Input`, named by the field it edits.

## Limitations

- The builder edits a tree; it does not run one — use `filterByTree`.
- A `not` holds exactly one child, so it paints no Add of its own; a group
  inside it paints both Adds, and the `not` itself is removed whole when it sits
  in a group. To negate one clause, add a group holding it and press Negate, or
  build the `not` with `negateAt` directly.
- A clause carries a Remove control only where removing it changes the tree: a
  `not` holds one child and cannot be left empty, so the clause it holds
  directly has no Remove of its own — remove the group whole when it sits in a
  group. A clause inside a group the `not` negates removes like any other. A
  root clause, or a root `not`, is cleared with **Clear**.
- No pattern comparison: a value is compared literally.
