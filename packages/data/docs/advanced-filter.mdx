---
title: Advanced filtering / query builders
description: A builder over a typed predicate tree.
---

`AdvancedFilter` is a **query builder**: the reader composes clauses, and the
tree combines them with `all`, `any` and `not`. The builder paints the tree it
is handed and adds clauses to its root group; a nested `any` or `not` group is
part of the caller's tree (the builder paints and edits it, but does not create
one). Every group it can extend paints its **own Add control**, so a nested
`any` gains a clause in place. A group the tree holds but the builder cannot
safely change — a `not`, or a group inside one — paints none.

## Usage

```tsx
import { AdvancedFilter, emptyTree } from "@gpuixui/data";
import { useState } from "react";

const [tree, setTree] = useState<FilterTree>(emptyTree);

<AdvancedFilter
  fields={[
    { field: "status", label: "Status" },
    { field: "size", label: "Size" },
  ]}
  tree={tree}
  onChange={setTree}
/>;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `fields` | `AdvancedFilterField[]` | — | the fields a clause may name |
| `tree` | `FilterTree` | — | the tree the builder paints |
| `onChange` | `(next: FilterTree) => void` | — | receives every edited tree |
| `title` | `string` | `Filters` | the title above the builder |
| `testId` | `string` | — | the builder's id; a clause is `${testId}-${slot}-…` |

A clause's `slot` is its path joined with `-` (a root clause is `0`), so a
clause inside a nested group keeps its own locators: `${testId}-${slot}-field`,
`${testId}-${slot}-comparison`, `${testId}-${slot}-value`,
`${testId}-${slot}-remove`, and a group's remove is
`${testId}-${slot}-group-remove`. The root's Add is `${testId}-add`; a nested
group's Add is `${testId}-${slot}-add`.

The tree's own API, exported beside the builder:

| Export | What it does |
| ------ | ------------ |
| `emptyTree` | the empty `all` group, which matches everything |
| `filterByTree(rows, tree, valueOf)` | the rows a tree keeps |
| `matchesTree(tree, row, valueOf)` | whether one row matches |
| `describeTree(tree)` | the sentence a tree reads as |

## How a comparison reads a value

The comparisons are literal — a clause's value is never treated as a pattern.
An `equals`/`notEquals` compares the field's text, a `contains` is a
case-insensitive substring, and an order reads **both** sides as numbers, so a
field stored as a number and a clause typed as text still compare.

A side that does not read as a number satisfies no order. That includes the
blank value a clause starts with: the builder appends `value: ""`, and an order
built from it keeps no row rather than treating the blank as `0`. A field the
row does not carry reads as blank too, and text like `wide` never satisfies an
order.

## Accessibility

The builder's title is a level-3 `heading`, and the sentence above the clauses,
each group's combinator (`all of`, `any of`, `not`) and the clause controls are
all announced (`surface-a11y.test.tsx`): a reader hears the tree's meaning, not a
row of unlabelled menus. A clause's field and comparison triggers are named
buttons, and its value is the primitives' `Input`, named by the field it edits.

## Limitations

- The builder edits a tree; it does not run one — use `filterByTree`.
- The builder never writes an `any` or a `not` and never changes a group's
  combinator: a group the caller's tree holds is painted and edited, its Add is
  offered where the append lands, and a negated group is removed whole. Use
  `appendAt(tree, path, clause)` directly to build a group the tree does not
  hold yet.
- A clause carries a Remove control only where removing it changes the tree: a
  `not` holds one child and cannot be left empty, so a clause inside one has no
  Remove of its own — remove the group whole when it sits in a group. A root
  clause, or a root `not`, is cleared with **Clear**.
- No pattern comparison: a value is compared literally.
