## Usage

```tsx
import { InlineEdit } from "@gpuixui/components";

<InlineEdit label="Workspace name" value={name} onCommit={setName} />;
```

## API

| Prop | Type | Default |
| ---- | ---- | ------- |
| `value` | `string` (required) | — |
| `onCommit` | `(value: string) => void` | — |
| `label` | `string` | — |
| `placeholder` | `string` | `"—"` |
| `disabled` | `boolean` | `false` |
| `editing` | `boolean` | — |
| `defaultEditing` | `boolean` | `false` |
| `onEditingChange` | `(editing: boolean) => void` | — |
| `style` | `StateStyle<InlineEditState>` | — |

The host input's handlers are composed rather than replaced: `onChange`,
`onFocus`, `onBlur` and `onSubmit` reach the caller on whichever element is
focused (the display or the editor), and each runs after the component's own
decision — so `onSubmit` fires once per Enter, after the commit.

**A disabled control refuses the edit in both phases.** It opens nothing, and a
control a consumer disables mid-edit discards that draft — on `Enter`, on the
host's submit, and on blur — so no path writes a value into an inert control.
The editor stays `readOnly` until the caller frees it.

### Blur commits, and the host that proves it

The commit runs from the host's `onBlur`, which is the right handler for an
active app. The **offscreen renderer** delivers it: the suite's
`commits a changed draft on blur` case reads `onCommit("blurred")` once the
field loses focus, and that host can fake window activation
(`set_active_for_tests`).

A **live** automation window cannot prove it. GPUI dispatches element focus
listeners only for an **active window**, and the automation window never becomes
one: `blur-delivery-lifecycle` (10 checks, 0.11.0) types into the shipped
`InlineEdit`, moves the real focus away with Tab and presses another control —
the focus id moves to `blur-after`, the typing arrives, and the draft **never
commits**. That is the harness, not the component; no live route on this host
delivers `onBlur`.

If a draft must not be lost without a proven route, take one the harness proves:
`Enter` commits, or the consumer commits on the press that leaves the field
(a caller-owned commit).

## Limitations

- No rich text; the editor is a single-line `<input>`.
- Blur commits in an active app; a live window cannot prove it — use `Enter` or a
  caller-owned commit when the draft must not be lost.
- A consumer wanting blur-to-cancel must not use this part.
- A control disabled mid-edit discards the draft instead of committing it.
- No validation state; `onCommit` is where a caller rejects a value.
- No multi-line editor.
