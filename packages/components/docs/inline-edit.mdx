---
title: Inline edit
description: Rename a value where it is displayed.
---

`InlineEdit` shows a value as text and swaps to an `<input>` in place when the
user activates it. GPUix has no `contenteditable`, so the swap is explicit, not
a styled text field pretending to be editable.

The caller owns the committed value; the component owns only the draft.

## Usage

```tsx
import { InlineEdit } from "@gpuixui/components";

const [name, setName] = useState("Untitled workspace");

<InlineEdit label="Workspace name" value={name} onCommit={setName} />;
```

The runnable build is `examples/inline-edit.example.tsx`, registered in
`examples/index.ts` and mounted by the package's native example suite
(`src/behaviour/examples.test.tsx`).

## The commit contract

| Action | Result |
| ------ | ------ |
| Click, `Enter` (press) or `Space` (release) on the display | edit mode; the input is focused |
| `Enter` in the input | commit the draft, return to display, focus the display |
| `Tab` in the input | commit the draft; focus moves on |
| A press outside the field | commit the draft; the display takes focus back when the press did not land on another control |
| Blur | commit the draft, leave focus where the user put it |
| `Escape` | discard the draft, return to display, focus the display; the key is claimed, so an enclosing dialog stays open |
| Commit with an unchanged draft | nothing is called |
| Empty text | a valid value; it clears the field (it is not "cancel") |

Commit is **one rule**, and `Enter` can arrive twice in 0.10.0 (`keyDown` and
`submit`), so the component finishes an edit once per entry. The same guard makes
the runtime's repeated outside-press dispatch harmless.

A live window does **not** deliver React's `onBlur` for a native focus change
(measured by the playground, plan `347` §8.2), so the outside press and `Tab` are
the paths a real user takes. Blur still commits where the host delivers it; it is
not the only way out.

`autoFocus` sets the initial `focused` state, so the display's ring is painted
on the first commit — the runtime applies native focus after React's effects and
never dispatches `onFocus`.

## API

| Prop | Type | Default | Notes |
| ---- | ---- | ------- | ----- |
| `value` | `string` | — | Required; the committed text. |
| `onCommit` | `(value: string) => void` | — | Called on a changed Enter/blur commit. |
| `label` | `string` | — | The accessible name of the display and the input. |
| `placeholder` | `string` | `"—"` | Shown in `mutedForeground` while the value is empty. |
| `disabled` | `boolean` | `false` | Leaves the tab order, ignores activation, paints no hover and no ring (including from `autoFocus`). |
| `editing` | `boolean` | — | Controlled edit state. |
| `defaultEditing` | `boolean` | `false` | Uncontrolled starting state. |
| `onEditingChange` | `(editing: boolean) => void` | — | Fired when the edit state changes. |
| `style` | `StateStyle<InlineEditState>` | — | `{ editing, disabled }`. |

`InlineEdit` takes the GPUix input props (`testId`, `placeholder`, `aria-*`) and
merges `style` last. A caller `onMouseDownOutside` composes with the component's
own leave-the-field handler, but that handler sits on the wrapper element around
the input: 0.10.0 never delivers the event to an `<input>` itself.

## Theming

The display uses `label` type, `foreground`/`mutedForeground` and an `accent`
hover; the input uses `controlHeight(theme, "md")`, `background`,
`inputForeground`, `border` and `focusRing(theme)`. A custom theme changes both
states with no code change — see [Theming](/docs/theming).

## Accessibility

- The display is a `role="button"` named by `label`; the input is a real input
  with the same name.
- Focus is moved with the renderer's `focusElement`; `autoFocus` alone does not
  follow a replaced element.
- `@gpuix/native@0.10.0` has no `aria-invalid` or `aria-describedby`, so a
  rejected value needs the consumer's own message (pair it with `Field`).
- Disabled is `tabIndex={-1}` with no handlers, plus dimming; there is no
  `aria-disabled` in 0.10.0.

## Limitations

- No rich text; the editor is a single-line `<input>`.
- Commit and cancel cover Enter, Escape, `Tab` and a press outside the field. A
  native focus change does not run React's `onBlur` in a live window, so blur is
  a headless-only extra path — it is not how a live user leaves the editor.
- No validation state of its own; `onCommit` is where a caller rejects a value,
  and the component will still have closed the edit.
- No multi-line editor in v1; `Textarea`-based inline editing is a future variant.

## Verification

`src/behaviour/inline-edit.test.tsx` runs in the real GPUix renderer (17 tests):
display mode, click-to-edit with focus, keyboard entry with Space starting on
release, Enter commit with focus return, Escape discard, blur commit, an outside
press that commits and restores the display, a press on another control that
keeps its focus, a `Tab` commit, an inside press that must not commit, the
unchanged/disabled guards, a controlled edit state, the caller's display
(`onClick`/`onKeyDown`) and field (`onChange`/`onSubmit`/`onFocus`/`onBlur`/
`onMouseDownOutside`) handlers composing with the swap and the commit contract,
a disabled display that paints neither a hover fill nor a ring, and an Escape
that cancels the edit without closing the dialog around it.

```sh
nub run --filter @gpuixui/components test:behaviour
```

It needs a host with a GPUix native binding — macOS arm64, Linux x64, Windows
x64, or this Intel Mac, where plan 140's locally built `darwin-x64` binding is
installed.
