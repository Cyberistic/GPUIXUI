title: Context menu
description: The shared menu rows, positioned at the pointer or opened from the keyboard.
---

`ContextMenu` is the right-click counterpart of **Dropdown menu**. It uses the
same rows, submenus, highlight rules and keyboard handling; only the positioning
differs — the surface is placed at the pointer in window coordinates rather than
anchored to a control.

```tsx
import {
  ContextMenu,
  ContextMenuContent,
  ContextMenuItem,
  ContextMenuSeparator,
  ContextMenuSub,
  ContextMenuSubContent,
  ContextMenuSubTrigger,
  ContextMenuTrigger,
} from "@gpuixui/components/context-menu";

<ContextMenu>
  <ContextMenuTrigger>
    <text>GPUIXUI</text>
  </ContextMenuTrigger>
  <ContextMenuContent label="Project actions">
    <ContextMenuItem onSelect={open}>Open</ContextMenuItem>
    <ContextMenuItem onSelect={copyPath}>Copy path</ContextMenuItem>
    <ContextMenuSeparator />
    <ContextMenuItem tone="destructive" onSelect={remove}>
      Delete…
    </ContextMenuItem>
  </ContextMenuContent>
</ContextMenu>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `ContextMenu` | open state, the pointer point, the dismiss layer |
| `ContextMenuTrigger` | the area whose right click or `Shift+F10` opens the menu |
| `ContextMenuContent` | the surface at the pointer, rendered while open |
| `ContextMenuItem` / `ContextMenuCheckboxItem` | the shared rows |
| `ContextMenuRadioGroup` / `ContextMenuRadioItem` | the shared exclusive choice |
| `ContextMenuSeparator` / `ContextMenuLabel` / `ContextMenuGroup` | the shared structure |
| `ContextMenuSub` / `ContextMenuSubTrigger` / `ContextMenuSubContent` | one secondary level |

The radio group and row are the shared exclusive choice: controlled `value` /
`onValueChange`, one marked row, and the menu stays open after choosing. The
[Dropdown menu](./dropdown-menu) page has the long form.

## Right click

`@gpuix/native@0.10.0` has no `onContextMenu`. A non-primary click arrives as
`onAuxClick`, and the payload's `isRightClick` says whether it was the right
button (`mutations.ts` maps `onAuxClick` → `"auxClick"`). The trigger stores
`{ x, y }` from that event and opens.

A second right click elsewhere **on the trigger** closes the old surface and
opens a new one at the new point; a right click outside the trigger area closes
the menu but cannot open another, because the trigger is what listens. That is a
deliberate scope, not a portal.

## Positioning

`ContextMenuContent` renders an `anchored` element with the pointer as its
`position`. `anchored position` is **window coordinates**, independent of the
mount parent — measured in a nested container (plan 112 §1c) — so the point is
passed through unchanged. `FloatingLayer` is anchor-relative and cannot take a
pointer point, which is why this component uses `anchored` directly.

## Keyboard and dismissal

| Key | Result |
| ---- | ------ |
| `Shift+F10` / Menu key | opens at the trigger's bottom-left; focus enters the menu |
| any right click on the trigger | opens at the pointer |
| `ArrowDown` / `ArrowUp` | next/previous enabled row, wrapping |
| `Home` / `End` | first/last enabled row |
| `Enter` / `Space` | runs the highlighted row and closes |
| `ArrowRight` on a submenu trigger | opens it and focuses its first row |
| `ArrowLeft` inside a submenu | closes that level and returns focus to its trigger |
| Letter keys | jumps to the next enabled row whose label starts with the typed prefix |
| `Escape` | closes; a keyboard-opened menu returns focus to the trigger |
| `Tab` | closes and moves on |

The trigger is a tab stop (unless disabled). The surface takes focus on open. The
highlighted row is the focused row, exactly as in **Dropdown menu**. An outside
press closes the menu without running anything. Type-ahead follows the same rules:
a 500 ms, case-insensitive prefix search over enabled labels (see **Dropdown
menu → Type-ahead**).

Focus returns to the trigger on `Escape` and on activation only when the menu was
opened from the keyboard; a pointer-opened menu leaves focus where the pointer
put it.

## Submenus

A submenu groups actions behind one secondary level, using the same parts as
**Dropdown menu**:

```tsx
<ContextMenuSub>
  <ContextMenuSubTrigger>Share</ContextMenuSubTrigger>
  <ContextMenuSubContent label="Share">
    <ContextMenuItem onSelect={copyLink}>Copy link</ContextMenuItem>
    <ContextMenuItem onSelect={email}>Email</ContextMenuItem>
  </ContextMenuSubContent>
</ContextMenuSub>;
```

The trigger is an ordinary row: arrows and type-ahead reach it, and clicking,
`Enter`, `Space`, `ArrowRight` or hovering opens the submenu and focuses its first
row. A submenu may contain another; the rules are the same at every depth, and a
row in an enclosing submenu stays clickable while a deeper level is open. The
surface uses the same measured placement as the Dropdown menu's submenus: its
right edge when that fits, otherwise its left edge, decided once per open. Only
one submenu is open at a time. `Escape` and `ArrowLeft` close one level and
return focus to the sub-trigger; choosing a row (by keyboard or pointer) runs it
once, closes every level, and a pointer-opened menu leaves focus where the click
put it. Leaving the submenu row and its panel also closes that level after
`closeDelay` (default 150 ms), with focus back on the row; a `disabled` row opens
nothing, by hover or by key. A press outside every menu surface closes all levels.

`autoFocus` sets the initial `focused` state, so the trigger's ring is painted
on the first commit — the runtime applies native focus after React's effects and
never dispatches `onFocus`.

## API

The trigger, surface and rows merge `style` last. The row parts share one prop set: `onSelect?: ()
=> void`, `disabled?: boolean`, `tone?: "default" | "destructive"` (default
`"default"`), `leading?: ReactNode`, `trailing?: ReactNode`, `textValue?:
string`, `closeOnSelect?: boolean` (default `true`) and `style?:
StateStyle<{ disabled: boolean; highlighted: boolean }>`.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `ContextMenu` | provider (no host element) | `open?: boolean`, `defaultOpen?: boolean` (default `false`), `onOpenChange?: (open: boolean) => void` |
| `ContextMenuTrigger` | `div` (the right-click target) | `disabled?: boolean` (default `false`) |
| `ContextMenuContent` | anchored surface | `label?: string` (default `"Context menu"`), `testId?: string` (default `"context-menu"`) |
| `ContextMenuItem` | `div` (`role="menuitem"`) | the shared row props |
| `ContextMenuCheckboxItem` | `div` (`role="menuitem"`) | `checked: boolean` (required), `onCheckedChange: (checked: boolean) => void` (required), plus the shared row props |
| `ContextMenuRadioGroup` | `div` (`role="group"`) | `value: string \| null` (required), `onValueChange: (value: string) => void` (required), `label?: string` |
| `ContextMenuRadioItem` | `div` (`role="menuitemradio"`) | `value: string` (required), plus the shared row props except `leading`, `closeOnSelect` and `style` (`style?: StateStyle<MenuRadioItemState>`) |
| `ContextMenuGroup` | `div` (`role="group"`) | — |
| `ContextMenuLabel` | `text` | — |
| `ContextMenuSeparator` | `div` (`role="separator"`) | — |
| `ContextMenuSub` | provider (no host element) | `closeDelay?: number` (default `150`) |
| `ContextMenuSubTrigger` | `div` (`role="menuitem"`, `aria-expanded`) | the shared row props except `onSelect`, `closeOnSelect` and `tone` |
| `ContextMenuSubContent` | anchored surface | `label?: string` |

## Theming

The surface and rows are the shared menu look: `colors.popover`, `radius.md`,
`borderWidth.thin` in `colors.border`, the `md` elevation, `spacing.xs` padding;
rows use `colors.hover` with a 2px `colors.accent` bar. The trigger is a card-like
box in `colors.card` with a border and `spacing.md` padding; pass `style` to
match the row it represents.

## Style by state

The rows are the shared menu parts: `ContextMenuItem.style` takes a
`MenuItemState` (`{ disabled, highlighted }`), `ContextMenuCheckboxItem.style`
a `MenuCheckboxItemState` (`{ checked, disabled, highlighted }`) and
`ContextMenuRadioItem.style` a `MenuRadioItemState`
(`{ checked, disabled, highlighted }`). The
[Dropdown menu](./dropdown-menu) page has the same section.

## Accessibility and limitations

Disabled controls announce **Disabled** through `aria-description`; 0.10.0 has no
`aria-disabled` semantics (plan 516).

- `role="menu"` on the surface, `menuitem`/`menuitemcheckbox`/`menuitemradio` on
  rows and `group` on a group; a checkbox or radio row carries `aria-selected`
  because 0.10.0 has no `aria-checked`. No
  `aria-haspopup` on the trigger (not available in 0.10.0), so the keyboard route
  is documented rather than announced.
- There is no portal. The surface is a sibling of the trigger painted at window
  coordinates, so it is correct visually but not clipped by a scroll container.
- Nested submenus are exercised to two levels, including a row of an enclosing
  submenu chosen while a deeper level is open. A submenu trigger announces
  `aria-expanded` only — 0.10.0 has no `aria-haspopup`.
- `Shift+F10` opens at the trigger's bottom-left, not at a text caret; a
  keyboard-opened menu returns focus to its trigger on Escape and activation.

## Verification

`src/behaviour/context-menu.test.tsx` runs in the real GPUix renderer (21 tests):
a left click doing nothing, a right click opening a `menu` surface, the surface
landing within 12px of the pointer, a selected action running once and closing,
a second right click moving the surface, Escape closing, a disabled trigger not
opening, `Shift+F10` opening at the trigger's bottom-left with focus in the menu,
keyboard activation running a row, Escape returning focus to the trigger, a
disabled trigger ignoring `Shift+F10`, type-ahead jumping to a row, the
submenu rules — `ArrowRight` opening and focusing the first row, a pointer click
running a row and closing both levels, one-level Escape/ArrowLeft, a right-edge
menu whose submenu opens to the left, and an enclosing-submenu row chosen while a
nested level is open — and a radio row selected from the pointer that keeps the
menu open. Hover open, the delayed close on a leave (one level, focus back on the
row) and a `disabled` row that opens nothing are shared with the Dropdown menu's
submenus and proven by `src/behaviour/dropdown-menu.test.tsx`; this suite does not
repeat them.

```sh
nub run --filter @gpuixui/components test:behaviour
```
