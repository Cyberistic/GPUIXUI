---
title: Counting number
description: A number that counts to its value on the physics clock, not a jump cut.
---

`CountingNumber` interpolates a number and paints each sampled value as text. The
runtime can tween a numeric style value but not the digits of a text node, so
`@gpuixui/motion`'s tween does the interpolation and the component owns the
string.

## Usage

```tsx
import { CountingNumber } from "@gpuixui/components";

<CountingNumber value={1284} from={0} role="display" />;
```

On mount the number counts from `from` to `value`. With no `from` the number
paints at rest — the component is not a mount decoration, and a panel that
re-renders must not re-count a metric the reader was already looking at.

A later `value` **retargets from the number on screen**, so a live metric that
updates mid-tween continues from where the reader saw it. That holds after the
number has come to rest too: the hook samples once before retargeting, so a
value that waited a while still counts over the full duration instead of
counting the pause as elapsed motion and landing in one frame.

## Formatting

The default text is `value.toFixed(decimals)` with `decimals` defaulting to `0`
and clamped to the 0–20 digits `toFixed` accepts. A `format` callback owns the
string whole, which is what a currency or a suffix needs:

```tsx
<CountingNumber
  value={0.42}
  from={0}
  decimals={1}
  format={(value) => `${value.toFixed(1)}%`}
/>
```

`countedText` prints an unreadable value (`NaN`, `Infinity`) as `0`, so a metric
fed a broken calculation reads as empty rather than "NaN".

## Motion and reduced motion

The count runs on the hook's real-time clock. Under
`MotionProvider preference="reduced"` the target paints on the first frame, and
`durationMs={0}` does the same without a provider. A non-finite or negative
duration falls back to the `slow` motion level (320 ms) instead of a tween that
never settles.

The accessible name is the **target**, never the frame: a screen reader hears
"42%" once rather than every tick.

## API

| Prop | Type | Default | Notes |
| ---- | ---- | ------- | ----- |
| `value` | `number` | — | Required. The number to count to. |
| `from` | `number` | `value` | The first run's start. Pass `0` to count up on mount. |
| `durationMs` | `number` | `320` | One run's span in milliseconds. |
| `decimals` | `number` | `0` | Digits after the point in the default text. |
| `format` | `(value: number) => string` | — | Replaces the text whole; `decimals` no longer applies. |
| `label` | `string` | the target's text | The accessible name. |
| `role` | `TextRole` | `"body"` | Any theme type role (`display`, `h2`, `bodyStrong`, …). |
| `className` | `string` | — | Joined after the resting style, so it wins conflicts. |
| `style` | `StateStyle<CountingNumberState>` | — | `CountingNumberState` is `{ value, counting, reducedMotion }`. |

`CountingNumber` renders one `<text>` host and takes the GPUix host props
(`testId`, `role`, `aria-*`); `style` merges last and sees each sampled value.

## Limitations

- The digits are re-rendered text, not a rolling reel: the runtime has no
  `transform`, so there is no per-digit slide or odometer.
- One tween per value change, with `easeOut`; no spring, stagger or delay.
- The clock is real time, not the renderer's motion clock, so the count is not
  frame-locked to a surface tween.
- No grouping separator or locale formatting in the default text; pass `format`
  for that.

## Verification

`src/behaviour/counting-number.test.tsx` renders the component in the real GPUix
renderer (7 tests): a count from `from` to the target, a rest paint with no
`from`, an intermediate value proving it does not jump, a retarget from the
number on screen, a retarget after the count has rested, the reduced preference
painting the target at once, and a formatted text whose accessible name is the
target from the first frame. The formatting and duration rules are the unit
suite beside the logic (`src/counting-number/logic.test.ts`).
