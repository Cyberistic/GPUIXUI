---
title: Notification centre
description: A bell-shaped inbox with a derived unread count, grouped rows and app-owned read state.
---

`NotificationCentre` is the durable half of feedback: a trigger that carries the
unread count, and a non-modal panel that lists notifications newest-first. It is
not a toast — a toast is transient, a notification stays until it is read.

## Usage

```tsx
import {
  NotificationCentre,
  NotificationCentreClear,
  NotificationCentreContent,
  NotificationCentreHeader,
  NotificationCentreList,
  NotificationCentreMarkAll,
  NotificationCentreTitle,
  NotificationCentreTrigger,
} from "@gpuixui/components";

<NotificationCentre
  notifications={items}
  onRead={(id) => markRead(id)}
  onMarkAllRead={() => markAllRead()}
  onClear={() => clear()}
>
  <NotificationCentreTrigger>Inbox</NotificationCentreTrigger>
  <NotificationCentreContent>
    <NotificationCentreHeader>
      <NotificationCentreTitle />
      <NotificationCentreMarkAll>Mark all</NotificationCentreMarkAll>
      <NotificationCentreClear />
    </NotificationCentreHeader>
    <NotificationCentreList />
  </NotificationCentreContent>
</NotificationCentre>;
```

The runnable build is `examples/notification-centre.example.tsx`, registered in
`examples/index.ts` and mounted by the package's native example suite
(`src/behaviour/examples.test.tsx`).

## The read model

The caller owns the data. The component never stores a notification, a read flag
or an unread count:

- `unreadCount` is derived from `read !== true` on every render.
- A row press, `Enter` or `Space` on the active row calls `onRead(id)`. A button
  activates `Space` on release, so its press does nothing and a held key cannot
  read twice. Call it twice and the second request is idempotent only if your
  data says so — the component reports what happened, it does not toggle.
- Opening the panel never marks anything read, so the count cannot drift from a
  glance at the inbox.
- `onMarkAllRead` and `onClear` are requests; omit either handler and its
  control is not rendered. That is deliberate: a dead button is worse than no
  button.
- Closing and reopening changes nothing, because the flags live in the caller.

## Groups

Supply the notifications **newest first**; the component preserves your order.
A group is a **contiguous** run of items with the same `group` label:

```ts
[
  { id: "a", title: "Deploy finished", group: "Today" },
  { id: "b", title: "Review requested", group: "Today" },
  { id: "c", title: "Invite accepted", group: "Earlier" },
];
```

`Today` is painted once before `a`, `Earlier` once before `c`. An item with no
`group` gets no heading. A group label repeated after another run gets its own
heading, so a filtered list never renames a section. Each label is a real
heading (`groupLevel`, default `4`, one below the title's default `3`), so a
reader can jump between groups; the rows are not wrapped in a labelled group,
because 0.10.0 has no `aria-labelledby` to associate them.

## Keyboard

The panel is focused when it opens. `ArrowDown` / `ArrowUp` move the active row
over notifications only — headings are skipped and the ends clamp. The feed
scrolls the active row into view with an 8 px margin, so the reading cursor
never leaves the panel. `Enter` and `Space` (on release) request a read for the
active row. Arrow keys, `Enter` and `Space` belong to the panel surface and its
rows: while a header action holds focus, `Enter` runs that action and the arrows
leave the reading cursor where it is, and `Space` runs that action instead of
reading a row. If the row the reader is on disappears (a read, a clear, a live
feed), the cursor and native focus move to the first live row instead of being
stranded; a removal while another control holds focus leaves that focus alone.
`Escape` closes the panel and returns focus to the trigger. The
panel is **non-modal**, so `Tab` leaves it rather than trapping focus.

## API

| Part | Renders | Props |
| ---- | ------- | ----- |
| `NotificationCentre` | the positioning root; owns open state and the derived rows | `notifications`, `onRead?`, `onMarkAllRead?`, `onClear?`, `open?`, `defaultOpen?`, `onOpenChange?`, `label?`, `empty?`, children |
| `NotificationCentreTrigger` | the button, its label and the derived badge | Button props, `children?` (visible label only), `showBadge?` |
| `NotificationCentreContent` | the anchored, non-modal panel, `role="region"` | `label?`, `side?` (default `bottom`), `align?` (default `end`), `sideOffset?`, `alignOffset?`, `collisionPadding?`, `autoFocus?`, children |
| `NotificationCentreHeader` | the title/actions row | children, host props |
| `NotificationCentreTitle` | the panel heading, `role="heading"` | children (defaults to the root `label`), `level?` (default `3`), host props; a raw `aria-level` is honoured |
| `NotificationCentreMarkAll` | a ghost button bound to `onMarkAllRead` | Button props except `variant`/`size`; renders only with a handler |
| `NotificationCentreClear` | a ghost button bound to `onClear` | Button props except `variant`/`size`; renders only with a handler |
| `NotificationCentreList` | grouped rows, a scrolling viewport, or the empty state | `emptyTitle?`, `emptyDescription?`, `groupLevel?` (default `4`), host props |

`notifications` is the only required prop. A row's data is `{ id, title,
description?, timestamp?, group?, read? }`; an absent `read` means unread.

### Trigger naming

The trigger's accessible name is `"{label}, {n} unread"` (default
`Notifications, 3 unread`), and `aria-expanded` follows the panel. A caller's
authored `aria-label` (a Button prop) replaces that whole name, trimmed — the
count is derived only when the name is. A blank or whitespace-only value is not
a name and falls back to the derived one. The panel keeps the root `label`, so
renaming the trigger never renames the region. The badge is hidden at zero, but
the derived name still says `0 unread`, so the count is never a colour-only
signal. `children` replaces the visible label (use it for a bell glyph); the
badge and the derived name still follow the data.

### Row naming

0.10.0 reports no accessible name from a text child, so each row is named
`"{title}, unread"` or `"{title}, read"`. The unread dot is decorative; the name
carries the state.

### Headings

The panel's title is `role="heading"` with `level` (default `3`) — the same rule
as Card, Dialog and Empty state — and a raw `aria-level` is honoured when no
typed level is passed. Each group label is a heading one level below it
(`groupLevel`, default `4`), so move both together if you move the title: an
outline where a group outranks its panel is worse than the default. The header
and the title take host props, so `testId="inbox-title"` addresses the title
like any other part.

## Placement

The panel uses the shared measured placement rule: `side="bottom"`,
`align="end"`, an 8 px side offset and an 8 px collision margin. A surface that
would snap over its trigger flips once per open, and `align="center"` is
corrected from the measured panel — the same rule as Popover, Dropdown menu and
Preview card.

## Theming

The panel uses `popover`/`popoverForeground`, `border`, `radius.lg` and the
medium elevation. The badge is the theme's `primary`; the active row is
`accent`, with the token focus ring; group headings and metadata use
`mutedForeground`. A custom theme restyles the whole centre with no code change.

## Limitations

- **Every row renders.** The published `<virtual-list>` host takes `itemCount`
  and requires the app to window its own children (0.10.0 ships no wrapper), so
  v1 uses a plain scrolling viewport. For a typical inbox (tens to low hundreds
  of rows) that is the honest choice; a later plan can add windowing without
  changing the API. The scroll container keeps its pixel offset, so the list
  re-anchors a prepend itself: a notified arrival above a scrolled viewport
  leaves the row the reader was on in place (measured shift 0, not the old
  44 px).
- **No bell icon in v1.** `@gpuixui/icons` has no `bell`, so the trigger is a
  text button with the badge. Pass a custom child when the icon set gains one;
  no icon was copied into this package.
- **No `aria-live` in 0.10.0**, so an arrival while the panel is closed is not
  announced. The trigger's accessible name carries the count.
- **Non-modal**: no focus trap and no `aria-modal`; `Tab` leaves the panel.
- **No `aria-activedescendant`**, so the active row is a painted accent fill and
  ring; native focus follows it through `focusElement` on a best-effort basis,
  and the feed scrolls it into view (plan 644). The row the reader is on is
  remembered while it exists, so a data update that removes it hands focus to
  the first live row only when nothing else holds native focus — a host cannot
  be read after it is gone (plan 746).
- State is app-owned: a remount resets nothing you persist, and nothing you do
  not persist.
- **A group label is a heading, not a labelled region:** 0.10.0 has no
  `aria-labelledby`, so a group's rows are not associated with its heading by
  anything the runtime can announce.
- No per-notification actions menu, bulk selection or toast bridge in v1. The
  centre is durable; a toast is transient.

- Focus cues are seeded by `autoFocus`; the runtime does not reliably deliver
  React `focus`/`blur`, so a ring may not paint when focus moves by code
  (plans 390/603/605).

## Verification

`src/behaviour/notification-centre.test.tsx` runs in the real GPUix renderer (32 tests):
closed by default with the derived count in the trigger's name, open and named
by a press, a caller-authored trigger name winning whole (trimmed, with a blank
one falling back to the derived name and the panel keeping the root label), opening that marks nothing read, contiguous grouping in the
caller's order, unread dots and row names, one read request from a press with
the panel staying open and the dot clearing on the next data update, mark-all
and clear, Escape and an outside press, a **held** trigger press closing on
release, arrow movement skipping headings with
Enter reading the reached row, Space reading it on release while its press reads
nothing, a header action owning its Space as well as its Enter, the arrow
revealing an off-screen row in both directions, a header action that runs
without reading a row,
a header action that keeps the reading cursor and focus in place, arrows and
Enter still reaching the row that holds focus, a prepend that leaves the reader's
row where it was, the light theme's roles, and a controlled close the caller
refuses leaving the panel and focus where they are. The panel title and each
group label are headings with caller-owned levels, and the header and the title
take a caller's `testId` and `style`. Removing the focused row
hands focus to the first live row while a removal under the trigger's focus (or
another row's) leaves it alone. The pure grouping
and count rules live in `src/notification-centre/model.test.ts` (5 tests).
