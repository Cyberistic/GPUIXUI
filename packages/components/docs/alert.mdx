---
title: Alert
description: A persistent, in-flow message about the current context.
---

`Alert` reports something about the state the user is looking at: a warning about
missing data, a failure with an action, a notice that stays until the condition
changes. It is **in the flow** — it occupies its own place in the layout.

Choose by lifetime, not by looks:

| Surface | Lifetime | Where it lives |
| ------- | -------- | -------------- |
| `Alert` | until the state changes | in the layout, where the problem is |
| Toast | a few seconds, or until dismissed | floating, over the corner |
| Dialog | until the user answers | modal, blocking everything |

## Usage

`Alert` is a compound: the root paints the tone and owns `role="alert"`, and the
parts fill it.

```tsx
import {
  Alert,
  AlertContent,
  AlertDescription,
  AlertTitle,
} from "@gpuixui/components/alert";

<Alert tone="warning">
  <AlertContent>
    <AlertTitle>3 tokens are missing</AlertTitle>
    <AlertDescription>
      The platform themes fall back to the default palette.
    </AlertDescription>
  </AlertContent>
</Alert>;
```

Add the icon and the dismiss control only when the message needs them:

```tsx
<Alert tone="info">
  <AlertIcon>i</AlertIcon>
  <AlertContent>
    <AlertTitle>Update available</AlertTitle>
    <AlertDescription>0.11.0 is ready. Installing restarts the app.</AlertDescription>
  </AlertContent>
  <AlertDismiss onDismiss={() => setDismissed(true)} />
</Alert>
```

`AlertDescription` is a container, so an action belongs inside it:

```tsx
<Alert tone="danger">
  <AlertContent>
    <AlertTitle>Upload failed</AlertTitle>
    <AlertDescription>
      <Button onClick={retry}>Try again</Button>
    </AlertDescription>
  </AlertContent>
</Alert>
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `Alert` | the root: `role="alert"`, the tone surface, the row layout and the tone context |
| `AlertIcon` | the leading glyph, in the tone's readable colour |
| `AlertContent` | the growing column between the glyph and the dismiss control |
| `AlertTitle` | the heading, `bodyStrong` in the tone's colour |
| `AlertDescription` | body prose in the page foreground; may hold an action |
| `AlertDismiss` | the focusable dismiss button |

## Tones

| `tone` | Surface | Heading |
| ------ | ------- | ------- |
| `info` (default) | `infoSoft` | `infoSoftForeground` |
| `success` | `successSoft` | `successSoftForeground` |
| `warning` | `warningSoft` | `warningSoftForeground` |
| `danger` | `destructiveSoft` | `destructiveSoftForeground` |

The tone paints the surface, the border and the heading; the **description stays
in the page's foreground colour**, because body prose has to stay readable rather
than match the tone. Badge, Alert and the toast viewport read the same
`statusTone` roles from `@gpuixui/tokens` (plan 157), so a status cannot look
different in two places.

## API

Every part takes the GPUix host props (`style`, `testId`, `role`, `aria-*`,
pointer and key handlers) and **merges `style` last**.

| Part | Prop | Type | Default |
| ---- | ---- | ---- | ------- |
| `Alert` | `tone` | `"info" \| "success" \| "warning" \| "danger"` | `"info"` |
| `AlertIcon` | — | — | — |
| `AlertContent` | — | — | — |
| `AlertTitle` | — | — | — |
| `AlertDescription` | — | — | — |
| `AlertDismiss` | `onDismiss` | `() => void` (required) | — |
| `AlertDismiss` | `label` | `string` | `"Dismiss"` |

A part rendered outside `Alert` throws `Alert parts must be used inside Alert` —
the tone context is the contract. (The test renderer catches render errors, so
this is a code guarantee rather than a behaviour-suite assertion.)

## Accessibility

- The root is `role="alert"` — a live region, announced when it appears. An alert
  that appears out of nowhere mid-sentence should be used sparingly.
- The dismiss control is a focusable `role="button"` with `label` as its
  accessible name, activated by Enter or Space as well as a click. Its `testId` is
  `alert-dismiss`.
- `AlertIcon` is decorative: it is not announced, so the title must say what the
  state is.
- Colour is never the only signal — every alert has an `AlertTitle`.
- A part outside its root fails loudly instead of rendering with the wrong tone.

## Limitations

- **The live-region announcement itself cannot be verified here.** The test
  renderer exposes the accessibility tree (the suite asserts `role="alert"`), but
  a real screen reader's announcement needs a real window.
- The dismiss control is this package's local button stand-in.
  `@gpuixui/primitives` now ships its own `Button`, but primitives read a second
  theme context, so the stand-in is replaced when that provider and
  `@gpuixui/tokens/react` are one (`TODO.md` → Interlocks).
- No automatic timeout: an alert stays until the state changes or the user
  dismisses it. That is deliberate — a message that vanishes on its own is a
  toast.
- The docs site cannot render this component live. The code above is the real
  source.

- Focus cues are seeded by `autoFocus`; the runtime does not reliably deliver
  React `focus`/`blur`, so a ring may not paint when focus moves by code
  (plans 390/603/605).

## Verification

`src/behaviour/alert.test.tsx` runs in the real GPUix renderer (12 tests): the
parts render in order inside one alert region, every tone paints its root surface
and title colour, the description keeps the page foreground, the icon takes the
tone colour and is optional, the theme is read rather than a constant, there is no
dismiss control unless `AlertDismiss` is composed, a click and an Enter fire it
once, its accessible name is the default or `label`, an action in the description
receives its click, a consumer `style` wins, and a caller `onClick` composes with
`onDismiss`.

```sh
nub run --filter @gpuixui/components test:behaviour
```
