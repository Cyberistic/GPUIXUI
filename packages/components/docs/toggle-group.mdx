## Usage

```tsx
import {
  ToggleGroup,
  ToggleGroupItem,
} from "@gpuixui/components/toggle-group";

<ToggleGroup type="single" label="Alignment" defaultValue="left">
  <ToggleGroupItem value="left" label="Align left">
    Left
  </ToggleGroupItem>
  <ToggleGroupItem value="centre" label="Align centre">
    Centre
  </ToggleGroupItem>
</ToggleGroup>;

<ToggleGroup type="multiple" label="Formatting" defaultValue={["bold"]}>
  <ToggleGroupItem value="bold" label="Bold">
    Bold
  </ToggleGroupItem>
  <ToggleGroupItem value="italic" label="Italic">
    Italic
  </ToggleGroupItem>
</ToggleGroup>;
```

`type="single"` keeps at most one mode on and clears it when the live option is
pressed again; `type="multiple"` lets any number stay on. The group is one tab
stop: the arrow keys move focus between options without pressing them.

## Keyboard

| Key | Effect |
| --- | ------ |
| `ArrowRight` / `ArrowLeft` | move focus along a horizontal group |
| `ArrowDown` / `ArrowUp` | move focus along a vertical group |
| `Home` / `End` | the first or last enabled option |
| `Enter` / `Space` | press the focused option |

## Accessibility

- The group is a named `group` node; each option is a `button`.
- Each option announces its state through `aria-valuetext`, because 0.11.0
  publishes no `aria-pressed`.
- One option holds the tab stop — the focused one, or the selected one while
  nothing holds focus — so Tab enters and leaves the toolbar once.
- `label` on an item is the accessible name even when `children` paints richer
  content, so a glyph-only option is still named.

## Limitations

- **No `aria-pressed`** on an option.
- No attached `spacing={0}` variant: the options keep the theme's `xs` gap
  because the runtime's flex layout has no negative margin to close it.
- An option a stored list marks `disabled` leaves the tab and arrow rotation
  but keeps its place in the drawing.
