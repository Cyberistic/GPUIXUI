## Usage

```tsx
import {
  Carousel,
  CarouselControl,
  CarouselIndicators,
  CarouselSlide,
  CarouselTrack,
} from "@gpuixui/components";

<Carousel label="Workspace previews" value={index} onValueChange={setIndex} loop>
  <CarouselTrack>
    <CarouselSlide>…</CarouselSlide>
    <CarouselSlide>…</CarouselSlide>
  </CarouselTrack>
  <CarouselControl direction="previous" />
  <CarouselControl direction="next" />
  <CarouselIndicators />
</Carousel>;
```

## Composition

```text
Carousel
├── CarouselTrack
│   └── CarouselSlide
├── CarouselControl
└── CarouselIndicators
```

Only the slide on screen is mounted. `CarouselSlide` returns `null` for every
other index, so the track lays out one slide and nothing hidden can paint or take
a tab stop — the pinned runtime ignores `display: none`, so a mounted spare slide
would paint beside the active one with its controls still reachable. The cost is
stated where it is paid: **a slide's local state does not survive a visit** (a
form on slide two is empty when the reader returns).

## API

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Carousel` | `role="group"` named by `label`, `tabIndex={0}` | `label` (required), `value?`, `defaultValue?` (0), `onValueChange?`, `loop?` |
| `CarouselTrack` | the slide row | children (slides must be direct) |
| `CarouselSlide` | one slide, or nothing while another is on screen | `style?: StateStyle<CarouselSlideState>` (`{ index }`) |
| `CarouselControl` | button | `direction: "previous" \| "next"`, `label?`, `disabled?` |
| `CarouselIndicators` | `role="group"` of named dots | `label?`, `style?: StateStyle<CarouselIndicatorsState>` |

## Limitations

- The track does not travel; the frame is sized by the slide on screen.
- No swipe, drag or scroll snap.
- No auto-advance or thumbnails.
- Only the slide on screen is mounted, so its local state is lost when the reader
  leaves it. That is the honest hiding word: the runtime ignores `display: none`,
  so a kept slide would paint and keep its tab stops.
