---
title: Carousel
description: Discrete slide stepping, with every slide kept mounted.
---

`Carousel` steps through a fixed set of slides with previous/next controls,
indicator dots and the arrow keys. It is **discrete**, not sliding: GPUix `motion` animates width,
left and opacity only — no transform — and scroll snap is unavailable, so a
translating track is not honestly expressible.

Every slide stays mounted and only the active one is painted and hit-testable:
an inactive slide is `visibility: hidden` with a collapsed box, so it keeps its
component state (a form on slide two is not reset by visiting slide three) while
taking no layout space and staying outside the tab order. GPUix 0.10.0 ignores
`display: none`, which is why the mechanism is visibility (plan 365).

## Usage

```tsx
import {
  Carousel,
  CarouselControl,
  CarouselIndicators,
  CarouselSlide,
  CarouselTrack,
} from "@gpuixui/components";

<Carousel label="Workspace previews" value={index} onValueChange={setIndex} loop>
  <CarouselTrack>
    <CarouselSlide>…</CarouselSlide>
    <CarouselSlide>…</CarouselSlide>
  </CarouselTrack>
  <CarouselIndicators />
  <div style={{ display: "flex", gap: 8 }}>
    <CarouselControl direction="previous" />
    <CarouselControl direction="next" />
  </div>
</Carousel>;
```

The runnable build is `examples/carousel.example.tsx`, registered in
`examples/index.ts` and mounted by the package's native example suite
(`src/behaviour/examples.test.tsx`).

**Declare slides directly inside `CarouselTrack`.** The track reads its direct
children to number them; wrapping them in a component or a fragment gives every
slide the same index.

## Behaviour

| Action | Result |
| ------ | ------ |
| `next` / `previous` | moves one slide; a no-op at an edge unless `loop` |
| indicator press, or `Enter`/`Space` on a focused dot | jumps to that slide |
| `loop` | wraps in both directions |
| `ArrowRight` / `ArrowLeft` (carousel focused) | same as the controls |
| `Home` / `End` | first / last slide |
| `value` controlled | the caller's index wins; the control still reports |

The root is focusable and named by `label`. The active index is clamped to the
slide count, so a controlled value past the end cannot blank the carousel.

## API

Every part takes the GPUix host props (`style`, `testId`, `role`, `aria-*`) and
merges `style` last.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Carousel` | `role="group"` with `aria-label`, `tabIndex={0}` | `label` (required), `value?`, `defaultValue?` (0), `onValueChange?`, `loop?`, children |
| `CarouselTrack` | the slide row | children |
| `CarouselSlide` | one slide, inactive ones hidden with `visibility` and a collapsed box | `style?: StateStyle<CarouselSlideState>`, children |
| `CarouselControl` | button | `direction: "previous" \| "next"`, `label?`, `disabled?` |
| `CarouselIndicators` | `role="group"`, one button per slide | `label?` (default "Choose slide"), `indicatorStyle?: StateStyle<CarouselIndicatorState>` |

`CarouselSlideState` is `{ active, index }`; `CarouselIndicatorState` is the same
shape.

## Theming

The track uses `card` with a `border` edge and `radius.lg`; controls use the
local Button roles. The active dot is an 18×8 `primary` pill; the others are
8×8 `border` dots. Slides have no surface of their own. A custom theme changes
the frame with no code change — see [Theming](/docs/theming).

## Accessibility

- The root is a named `group` and takes focus for the arrow keys.
- Controls are buttons named "Previous slide" / "Next slide"; a control at an
  edge is disabled (out of the tab order, dimmed) unless `loop`.
- Each indicator is a button named "Go to slide N"; the active one carries
  `aria-selected`. Every dot is a tab stop, and `Enter`/`Space` jump to it.
- Inactive slides stay in the tree (their state survives) but are
  `visibility: hidden` with no layout box: they paint nothing, take no click and
  leave the native tab order.
- There is no `aria-roledescription="carousel"` or slide-position announcement
  in `0.10.0`.

## Limitations

- **No slide animation** (no transform in `motion`).
- **No swipe/drag** (no drag host feature).
- No auto-advance or thumbnails.
- Slides must be direct children of the track.
- Inactive slides stay mounted and are still reconciled: many heavy slides cost
  render time even though only one paints.

## Verification

`src/behaviour/carousel.test.tsx` runs in the real GPUix renderer (15 tests):
exactly one slide painted, an inactive slide with no layout box, the active slide
taking a click the inactive one used to take, a hidden slide keeping its state
across a step, control stepping, edge clamping, loop wrapping, arrows and
Home/End, a controlled carousel, region naming and disabled edges, one named
indicator per slide with the active one marked (press and `Enter`/`Space` both
jump), and a style callback receiving `{ active, index }` in both themes.

```sh
nub run --filter @gpuixui/components test:behaviour
```

It needs a host with a GPUix native binding — macOS arm64, Linux x64, Windows
x64, or this Intel Mac, where plan 140's locally built `darwin-x64` binding is
installed.
