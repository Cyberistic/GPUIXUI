---
title: Mention input
description: `@name` autocompletion in a text field.
---

`MentionInput` opens a ranked suggestion list when the text contains an open
`@` token and inserts the chosen name. The token rules are pure
(`src/mention/logic.ts`); the field owns the text and the highlight, and the
consumer declares the candidate `MentionInputItem`s.

## Usage

```tsx
import {
  MentionInput,
  MentionInputItem,
  MentionInputList,
} from "@gpuixui/components";

<MentionInput
  label="Comment"
  value={comment}
  onValueChange={setComment}
  onMention={(name) => notify(name)}
>
  <MentionInputList>
    {people.map((person) => (
      <MentionInputItem key={person} value={person} />
    ))}
  </MentionInputList>
</MentionInput>;
```

The runnable build is `examples/mention-input.example.tsx`, registered in
`examples/index.ts` and mounted by the package's native example suite
(`src/behaviour/examples.test.tsx`).

## Token rules

| Text | Result |
| ---- | ------ |
| `"@"` | opens with an empty query |
| `"hi @"` | opens with an empty query |
| `"hi @an"` | query `"an"` |
| `"email@example"` | no mention (no whitespace before `@`) |
| `"@a b"` | no mention (whitespace ends the token) |
| `"@a @b"` | the last token |

Ranking is case-insensitive: **prefix matches first**, then substring matches,
each in declaration order, capped by `maxVisible` (default 6). A non-finite
`maxVisible` is **no cap**, so a malformed bound lists every match rather than
none. Insertion replaces the `@query` token with `@value` plus one space, and
reports both `onValueChange` and `onMention`.

The highlight always starts at the first ranked match. Extending the query
restarts it there (plan 765), so `Enter` confirms the best match for what is
currently typed rather than an index left over from a wider query.

## Key and pointer behaviour

| Action | Result |
| ------ | ------ |
| `ArrowDown` / `ArrowUp` | moves the highlight, wrapping |
| Typing more of the query | restarts the highlight at the first match (plan 765) |
| `Enter` | inserts the highlighted name (arrives as the input's submit event) |
| Click a row | inserts that name on the release; a press dragged off the row inserts nothing |
| `Enter` / `Space` on a focused row | inserts that row's name — `Enter` on press, `Space` on release (plan 759) |
| `Escape` | closes the list, text unchanged — from the field or a focused row |
| Typing a query with no matches | closes the list |
| `Tab` | not claimed: the platform moves focus out of the field |

`Escape` closes the list and claims the event, so inside a dialog the first
press closes the list and the next closes the dialog.

## API

| Part | Renders | Props |
| ---- | ------- | ----- |
| `MentionInput` | a `role="group"` field wrapping a real `<input>` | `label` (required), `value?`, `defaultValue?`, `onValueChange?`, `onMention?`, `maxVisible?`, `disabled?`, children |
| `MentionInputList` | anchored suggestion surface, labelled "Mentions" | children (`MentionInputItem`s) |
| `MentionInputItem` | a selected button row | `value` (required), `label?` (defaults to `@value`), `style?` |

The list renders nothing while there is no query or no match.

With a `testId`, the input is that id and the group surface that paints the ring
is `<testId>-group`, so a harness can measure the focused field surface.

## Theming

The field uses `background`, `border`, `radius.md`, `controlHeight(theme, "md")`
and `focusRing`; the list uses `popover`, `border` and `radius.md`; the
highlighted row uses `accent`/`accentForeground`. A custom theme changes both —
see [Theming](/docs/theming).

## Accessibility

Disabled controls announce **Disabled** through `aria-description`; 0.10.0 has no
`aria-disabled` semantics (plan 516). A disabled field is also read-only, leaves
the tab order (`tabIndex -1`), ignores `autoFocus` and paints no focus ring, so it
never looks editable or focused (plan 527).

- The field is a real input named by `label`, so typing, selection and focus are
  native.
- Suggestion rows are buttons with `aria-selected` on the highlighted one; the
  surface is a named group.
- `role="listbox"` and `role="option"` are **dropped** by
  `@gpuix/native@0.10.0`'s accessibility dump (measured), so the list is not
  announced as a listbox. There is no `aria-activedescendant` either.
- Rows are focusable (`tabIndex=0`), so `Tab` then `Enter` or `Space` can pick a
  row; the input's `Tab` behaviour is the platform's. A focused row paints the token ring
  from the renderer's focused host (plan 754) even when it is not the
  highlighted row, and a field with `autoFocus` seeds the group ring (plan 522).

## Limitations

- **The query comes from the text, not the caret.** `0.10.0` exposes no caret
  position, so the component assumes typing at the end. Mid-string editing is not
  supported; an `@` inside a word is deliberately ignored.
- **A space typed while the list is open is consumed by the runtime** before the
  field sees it (measured in the test renderer). Escape or picking a row closes
  the list; there is no "type a space to dismiss" path.
- No async or remote candidates — the items you declare are the candidate set.
- No `role="listbox"`/`option` in the dump, no `aria-activedescendant`.
- Fixed `"Mentions"` label for the surface.

- Focus cues are seeded by `autoFocus` and then follow the renderer's focused
  host (a 50 ms sample while the field is enabled): a suggestion row's ring and
  the **group** ring paint on a `Tab` entry, a programmatic move or a press, and
  clear when focus leaves; the seed stands only until a host is reported (plans
  390/603/605, 754, 755).

## Verification

`src/behaviour/mention-input.test.tsx` runs in the real GPUix renderer (22 tests):
opening, narrowing, arrow movement, the highlight restarting when the query
narrows, Enter insertion, a clicked row, a press
dragged off a row inserting nothing, `Space` inserting on release rather than on
press, Escape from the field and from a focused row, one surface per Escape
inside a dialog, no-match closing, a non-finite `maxVisible` listing every match,
the two callbacks firing once, a focused row's ring, the group
ring a field's `autoFocus` seeds, a disabled field that ignores `autoFocus`, stays
out of the tab order and paints no ring, and the caller's
`onKeyDown`/`onFocus`/`onBlur` and row handlers composing with the component's
own action.

`src/mention/logic.test.ts` (13 pure tests) covers query detection, replacement
and ranking.
