<ComponentPreview name="drawer-sides" />

The drawing opens on the surface: the frame is the window, the panel is flush to
the edge it names, and the edge buttons re-open it.

## Usage

```tsx
import {
  Drawer,
  DrawerClose,
  DrawerContent,
  DrawerDescription,
  DrawerFooter,
  DrawerHeader,
  DrawerTitle,
  DrawerTrigger,
} from "@gpuixui/components";

<Drawer>
  <DrawerTrigger>Filters</DrawerTrigger>
  <DrawerContent side="right" size="md" label="Filters">
    <DrawerHeader>
      <DrawerTitle>Filters</DrawerTitle>
      <DrawerDescription>Narrow the result set.</DrawerDescription>
    </DrawerHeader>
    <DrawerFooter>
      <DrawerClose>Cancel</DrawerClose>
    </DrawerFooter>
  </DrawerContent>
</Drawer>;
```

## The surface

The shipped surface is vaul's drawer more than a docked column: the **inner
corners** are rounded (`radius.xl`) while the window edge it opens from stays
flush, the frame's `elevation.lg` lift is the theme's own, and a `top` or
`bottom` sheet paints the **grabber** — the 40×4 handle at its inner edge. The
grabber is decoration: `0.11.0` has no drag host, so no gesture follows it, and
`grabber={false}` removes it.

## Motion

<ComponentPreview name="drawer-workflow" />

The panel **slides its own span** in from the edge it names — a right `md` drawer
starts a whole 400px to the right of its resting place — and the veil (the
window-sized box) clips it while it travels. The runtime has no `transform`, so
the movement is a numeric `left`/`top` offset on the surface's box rather than a
scaled or translated element; the surface's content keeps its layout because a
relative offset moves the box, not the flow. It runs on the `slow` level
(320 ms), and the grabber and the close control ride the same box.

`MotionProvider preference="reduced"` paints the settled frame at once. A
dismissed panel stays painted for its exit without taking a press.

## Composition

```text
Drawer
├── DrawerTrigger
└── DrawerContent
    ├── DrawerHeader
    │   ├── DrawerTitle
    │   └── DrawerDescription
    ├── DrawerFooter
    │   └── DrawerClose
    └── (close control)
```

The close control is painted in the box around the surface's own scroller, not
inside it, so a body longer than the drawer scrolls under the control instead of
carrying the one visible way out of the panel (`src/behaviour/drawer.test.tsx`
scrolls a 30-row body and holds the control's box).

## API

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Drawer` | nothing; owns open state | `open?`, `defaultOpen?`, `onOpenChange?`, `dismissible?`, `children` |
| `DrawerTrigger` | button | button props |
| `DrawerClose` | button | button props |
| `DrawerContent` | veil + `role="dialog"` surface | `side`, `size`, `label` (required), `showClose`, `grabber`, `initialFocus`, `className`, `children` |
| `DrawerHeader` | heading block | `className?`, `children` |
| `DrawerTitle` | level-2 heading | text props, `className?` |
| `DrawerDescription` | muted copy | text props, `className?` |
| `DrawerFooter` | right-aligned actions | `children`, `className?` |

## Limitations

- **Measured in a window**: the playground's `drawer-lifecycle` (34 checks,
  0.11.0) mounts the shipped Drawer and reads the surface flush to the edge it
  names — `500,0,400,520` for a right `md` column, `340,0,560,520` for a right
  `lg`, `0,0,400,520` for a left `md`, and `0,100,900,420` for a bottom `lg` —
  over a veil that measurably dims the page it leaves uncovered. A press is
  hit-tested: one inside the surface keeps the drawer open, while the veil's
  dismisses it, reports the close and returns the focus to the opener. The Tab
  trap is the window's own traversal, so the opener is never a stop while the
  drawer is open, and `dismissible={false}` removes Escape and the veil while
  the close control still works.
- **Slides its own span** from the named edge — a numeric `left`/`top` offset,
  not a `transform` — and fills the window's other axis. It is still not a
  full-width column on a vertical edge.
- No swipe-to-dismiss, no snap points: `0.11.0` has no drag host, so the grabber
  cannot be dragged and the surface cannot follow the pointer.
- The veil is the page's own background at 55% (a wash). **The 6px blur shadcn's
  veil carries is drawing-only**: `StyleDesc` has no `filter`/`backdrop-filter`,
  so the native veil cannot blur what is behind it.
- No `aria-modal` or `aria-labelledby` in 0.11.0: the surface is named by its own
  `label`, and the Tab traversal is the containment a reader gets.
- Not portalled; painted at window coordinates.
- Sizes are layout constants, not tokens.
- A `side` restored from persisted state that the union does not name opens the
  house `right` edge, and travels in from it; the box, the layout and the entry
  frame read one edge, so a panel never opens from an edge it is not on.
- A `size` restored from persisted state that the union does not name paints the
  house `md` box; the table lookup never hands the renderer an `undefined`, so a
  renamed or dropped size cannot shrink the panel to its content.
- A dismissed drawer stays painted for its exit and takes no presses; the two
  close actions the component paints — the top-right control and a
  `DrawerClose` in the body — leave the Tab order for that window, while a
  control you compose yourself keeps its stop until the runtime publishes an
  inherited `inert`.
