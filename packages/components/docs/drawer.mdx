---
title: Drawer
description: A modal panel anchored to a window edge.
---

`Drawer` is a dialog that opens from an edge: filters on the right, navigation on
the left, a details sheet at the bottom. It shares Dialog's rules — a window veil,
the topmost dismiss layer, focus in and back, and a Tab trap — and differs only in
where the surface sits.

## Usage

```tsx
import {
  Drawer,
  DrawerClose,
  DrawerContent,
  DrawerDescription,
  DrawerFooter,
  DrawerHeader,
  DrawerTitle,
  DrawerTrigger,
} from "@gpuixui/components";

<Drawer>
  <DrawerTrigger>Filters</DrawerTrigger>
  <DrawerContent side="right" size="md" label="Filters">
    <DrawerHeader>
      <DrawerTitle>Filters</DrawerTitle>
      <DrawerDescription>Narrow the result set.</DrawerDescription>
    </DrawerHeader>
    <DrawerFooter>
      <DrawerClose>Cancel</DrawerClose>
    </DrawerFooter>
  </DrawerContent>
</Drawer>;
```

The runnable build is `examples/drawer.example.tsx`, registered in
`examples/index.ts` and mounted by the package's native example suite
(`src/behaviour/examples.test.tsx`).

## Sides and sizes

| `side` | Surface |
| ------ | ------- |
| `"right"` (default) | full-height column at the right edge |
| `"left"` | full-height column at the left edge |
| `"bottom"` | full-width sheet at the bottom |

`size` is `"sm" | "md" | "lg"`: 320 / 400 / 560 px wide for left and right, and
240 / 320 / 420 px tall for the bottom sheet. A surface never exceeds the window.
The numbers are layout constants — tokens carry no drawer-size role — and are
capped by the window size.

## Dismissal and focus

A press inside a nested surface that extends beyond the drawer's edge belongs to
that surface, not to the drawer (plan 816).

- The trigger opens and closes the drawer and reports `aria-expanded`.
- Focus moves into the surface; `Tab` and `Shift+Tab` wrap inside it.
- `Escape` closes and returns focus to the trigger; an outside press closes.
  The opener is captured before the surface mounts, so an auto-focused control
  inside the content does not become the saved opener (plan 638).
- `dismissible={false}` ignores both Escape and an outside press.
- A drawer opened inside a dialog pushes its own layer, so one Escape closes
  the drawer first (the shared dismiss stack, plan 112).
- Layer order and focus entry follow the nesting, not the open order: a
  confirmation mounted together with the drawer is still the top layer, holds
  focus, and hands it back to the drawer surface when it closes (plan 730).

## Motion

The veil fades in 100 ms (`dialogMotion(theme)`) and the surface fades and slides
in 300 ms from its own edge, from the shadcn sheet recipe compiled by
`@gpuixui/tw`. GPUix's motion animates `top` / `left` as relative offsets, so the
surface moves without reflowing its content; the slide is measured in the native
suite rather than only configured.

A closing drawer stays painted for its 300 ms exit, with the veil inert
(`pointerEvents: none`), so it cannot be clicked while it leaves. Focus has
already returned at close, exactly as before. `zoom-*` and `transform` stay
unsupported and are not faked.

## API

Every part takes the GPUix host props (`style`, `testId`, `role`, `aria-*`) and
merges `style` last.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Drawer` | nothing; owns open state and the dismiss layer | `open?`, `defaultOpen?`, `onOpenChange?`, `dismissible?`, children |
| `DrawerTrigger` | button | `onClick`, button props |
| `DrawerClose` | button | `onClick`, button props |
| `DrawerContent` | veil + `role="dialog"` surface | `side?`, `size?`, `label` (required), `showClose?`, `initialFocus?`, children |
| `DrawerHeader` | heading block | children |
| `DrawerTitle` | heading (level 2 by default) | `level?: 1 \| 2 \| 3 \| 4 \| 5 \| 6`, text props |
| `DrawerDescription` | muted copy | registers its plain text as the drawer's `aria-description` |
| `DrawerFooter` | right-aligned actions | children |

`DrawerContent` renders nothing while the drawer is closed and through its exit
motion, then unmounts.

## Theming

The surface uses `popover` / `popoverForeground`, `border`, `radius` and the
largest elevation; the veil is `overlay`; spacing and sizes come from the theme's
scale (widths are the documented constants). A custom theme changes the drawer
with no code change — see [Theming](/docs/theming).

## Accessibility

- `DrawerContent` is a `dialog` named by the required `label`; `0.10.0` has no
  `aria-modal` or `aria-labelledby`, and its title is a heading, not the dialog's
  accessible name.
- `DrawerDescription` is announced as the drawer's description through
  `aria-description`, because `0.10.0` also has no `aria-describedby`. An explicit
  `aria-description` on `DrawerContent` wins over the registered part.
- `DrawerTitle`'s `level` is the caller's, defaulting to 2; a raw `aria-level`
  is still honoured when no `level` is given, and an explicit `level` wins.
- Focus enters the surface and returns to the opener. `initialFocus` can put it
  on a specific control after the surface takes focus.
- A disabled `dismissible={false}` drawer cannot be escaped by keyboard or
  pointer; make sure such a drawer has a visible close control.

## Limitations

- **No swipe-to-dismiss**: `0.10.0` has no drag host feature.
- **No portal**: the veil is an `<anchored>` element at window coordinates, as in
  Dialog. A drawer mounted inside a scrolled container is still painted at the
  window origin, not inside that container.
- Sizes are layout constants, not tokens.
- The animated edge-surface wrapper carries `<testId>-surface`
  (`drawer-content-surface` by default), while the dialog keeps `testId`
  (plan 597).
- The close control uses the `x` icon from `@gpuixui/icons`.

- Focus cues are seeded by `autoFocus`; the runtime does not reliably deliver
  React `focus`/`blur`, so a ring may not paint when focus moves by code
  (plans 390/603/605).

## Verification

`src/behaviour/drawer.test.tsx` runs in the real GPUix renderer (18 tests): open
lifecycle, dialog naming and `aria-expanded`, the description announced through
`aria-description`, the title's default and caller-set
heading levels, full-window veil, focus in/return — including when the content
contains an auto-focused field (plan 638) —
backdrop dismissal, the Tab trap, all three sides and sizes, both themes, an
uninterruptible drawer, a controlled drawer that stays closed, a confirmation
mounted with the drawer keeping focus and the top layer (plan 730), and the
motion — entry props, the measured slide on both axes, and a closing surface
that stays painted but inert until it unmounts.

The four modal rules were extracted from Dialog into `internal/modal.ts` with no
behaviour change; Dialog and Confirmation dialog keep their own suites as the
guard (18 tests).

```sh
nub run --filter @gpuixui/components test:behaviour
```

It needs a host with a GPUix native binding — macOS arm64, Linux x64, Windows
x64, or this Intel Mac, where plan 140's locally built `darwin-x64` binding is
installed.
