The drawing opens on the surface: the frame is the window, the panel is flush to
the edge it names, and the edge buttons re-open it.

## Usage

```tsx
import {
  Drawer,
  DrawerClose,
  DrawerContent,
  DrawerDescription,
  DrawerFooter,
  DrawerHeader,
  DrawerTitle,
  DrawerTrigger,
} from "@gpuixui/components";

<Drawer>
  <DrawerTrigger>Filters</DrawerTrigger>
  <DrawerContent side="right" size="md" label="Filters">
    <DrawerHeader>
      <DrawerTitle>Filters</DrawerTitle>
      <DrawerDescription>Narrow the result set.</DrawerDescription>
    </DrawerHeader>
    <DrawerFooter>
      <DrawerClose>Cancel</DrawerClose>
    </DrawerFooter>
  </DrawerContent>
</Drawer>;
```

## The surface

The shipped surface is vaul's drawer more than a docked column: the **inner
corners** are rounded (`radius.xl`) while the window edge it opens from stays
flush, the frame's `elevation.lg` lift is the theme's own, and a `top` or
`bottom` sheet paints the **grabber** — the 40×4 handle at its inner edge. The
grabber is decoration: `0.11.0` has no drag host, so no gesture follows it, and
`grabber={false}` removes it.

## Motion

<ComponentPreview name="drawer-workflow" />

The panel **slides its own span** in from the edge it names — a right `md` drawer
starts a whole 400px to the right of its resting place — and the veil (the
window-sized box) clips it while it travels. The runtime has no `transform`, so
the movement is a numeric `left`/`top` offset on the surface's box rather than a
scaled or translated element; the surface's content keeps its layout because a
relative offset moves the box, not the flow. It runs on the `slow` level
(320 ms), and the grabber and the close control ride the same box.

`MotionProvider preference="reduced"` paints the settled frame at once. A
dismissed panel stays painted for its exit without taking a press.

## Composition

```text
Drawer
├── DrawerTrigger
└── DrawerContent
    ├── DrawerHeader
    │   ├── DrawerTitle
    │   └── DrawerDescription
    ├── DrawerFooter
    │   └── DrawerClose
    └── (close control)
```

The close control is painted in the box around the surface's own scroller, not
inside it, so a body longer than the drawer scrolls under the control instead of
carrying the one visible way out of the panel (`src/behaviour/drawer.test.tsx`
scrolls a 30-row body and holds the control's box).

## API

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Drawer` | nothing; owns open state | `open?`, `defaultOpen?`, `onOpenChange?`, `dismissible?`, `children` |
| `DrawerTrigger` | button | button props |
| `DrawerClose` | button | button props |
| `DrawerContent` | veil + `role="dialog"` surface | `side`, `size`, `label` (required), `showClose`, `grabber`, `inset`, `initialFocus`, `className`, `children` |
| `DrawerHeader` | heading block | `className?`, `children` |
| `DrawerTitle` | level-2 heading | text props, `className?` |
| `DrawerDescription` | muted copy | text props, `className?` |
| `DrawerFooter` | right-aligned actions | `children`, `className?` |

## A Mac sheet

On macOS a sheet drops from under the window's toolbar. Give a top sheet the
toolbar's height as `inset`, and it hangs that far below the window's top,
centred and at most the window's width less 80:

```tsx
<DrawerContent side="top" inset={TOOLBAR_HEIGHT.unified} label="New release">…</DrawerContent>
```
