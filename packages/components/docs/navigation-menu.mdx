---
title: Navigation menu
description: A horizontal nav whose items open one anchored panel at a time.
---

`NavigationMenu` is a navigation region: triggers in a row, exactly one anchored
panel open, and links inside it. It is not a dropdown menu — the panel holds
navigation, and the trigger row takes arrow keys as a group.

## Usage

```tsx
import {
  NavigationMenu,
  NavigationMenuContent,
  NavigationMenuItem,
  NavigationMenuLink,
  NavigationMenuList,
  NavigationMenuTrigger,
} from "@gpuixui/components";

<NavigationMenu label="Product">
  <NavigationMenuList>
    <NavigationMenuItem value="platform">
      <NavigationMenuTrigger>Platform</NavigationMenuTrigger>
      <NavigationMenuContent>
        <NavigationMenuLink onSelect={() => go("overview")}>
          Overview
        </NavigationMenuLink>
      </NavigationMenuContent>
    </NavigationMenuItem>
  </NavigationMenuList>
</NavigationMenu>;
```

The runnable build is `examples/navigation-menu.example.tsx`, which the native
playground mounts.

## Behaviour

| Action | Result |
| ------ | ------ |
| Resting on a trigger | opens that item's panel after `openDelay` (default 150 ms) |
| Moving between triggers | switches the open panel; the first closes |
| Leaving the trigger and panel | closes after `closeDelay` (default 150 ms) |
| Press or `Enter`/`Space` on a trigger | toggles that item's panel |
| `ArrowDown` on a trigger | opens its panel and moves focus to the panel surface |
| `ArrowLeft` / `ArrowRight` on a trigger | moves focus between triggers; does not open |
| `Home` / `End` on a trigger | first / last trigger |
| `Escape` | closes the panel and returns focus to its trigger |
| Outside press | closes the panel |
| Choosing a link | calls `onSelect` once and closes the panel |
| A second trigger | closes the first panel; one open at a time |

The open item is `value` (`string | null`, `null` = closed), controllable with
`onValueChange`. A controlled nav that ignores the change stays closed.

Hover is one policy, not two: an explicit press or key cancels a pending hover
timer, and a panel closed by a press does not spring back open while the pointer
rests on its trigger. A pointer that crosses the 4 px gap between trigger and
panel is inside both surfaces for the purpose of the close timer, so the panel
does not flicker shut on the way in.

## API

Every part takes the GPUix host props (`style`, `testId`, `role`, `aria-*`) and
merges `style` last.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `NavigationMenu` | `role="navigation"` named by `label`, the dismiss layer | `label` (required), `value?`, `defaultValue?`, `onValueChange?`, `openDelay?`, `closeDelay?`, children |
| `NavigationMenuList` | `role="list"` row | children |
| `NavigationMenuItem` | `role="listitem"`; owns its value | `value` (required), children |
| `NavigationMenuTrigger` | button with `aria-expanded`; `disabled` leaves the tab order and opens nothing | button props |
| `NavigationMenuContent` | anchored `role="group"` panel, mounted through its exit tween | children |
| `NavigationMenuLink` | a full-width button row | `onSelect?`, button props |

## Theming

The panel uses `popover` / `popoverForeground`, `border`, the registry's fixed
8px corner (`rounded-lg`, ADR 0006) and the medium elevation; links use the
ghost-button roles with an `accent` hover. Items
sit `spacing["2xs"]` apart. A custom theme changes it with no code change — see
[Theming](/docs/theming).

## Motion

The panel fades and travels 4px out from its trigger's side (`normal`, 200 ms),
and stays mounted for its exit tween: a dismissal is immediate in state (the
trigger reports `aria-expanded: false`, focus returns) while the box fades out,
and the panel takes no presses while it leaves, so a control underneath keeps
them. `MotionProvider preference="reduced"` supplies the reduced-motion
preference (the runtime exposes none), which paints the resting frame with no
travel — see `docs/component-api.md` §11.

## Accessibility

- The nav is a named `navigation` region; the trigger row is a `list`.
- A trigger reports `aria-expanded`; the open state is one value, so two panels
  cannot both claim to be open.
- `Escape` uses the shared dismiss stack: a nav inside a dialog closes first, and
  focus returns to the trigger that opened it.
- Hover is an accelerator, never the only path: every panel opens from the
  keyboard, and a press on an open trigger closes it.
- Links are buttons with `onSelect`; `0.11.0` has no anchor element or `href`.
- `0.11.0` has no `aria-haspopup`, so the trigger does not announce that it owns
  a panel.

## Limitations

- **No `href`:** `NavigationMenuLink` is a button; navigation is the consumer's
  `onSelect`.
- **Hover is a timer policy:** `0.11.0` has no pointer-type signal, so touch
  opens by press and there is no "coarse pointer" variant.
- **`ArrowDown` focuses the panel surface**, not the first link; one `Tab` then
  reaches the links.
- No `aria-haspopup` in `0.11.0`.
- No nested menus or columns inside a panel beyond whatever children you place.

## Verification

`src/behaviour/navigation-menu.test.tsx` runs in the real GPUix renderer
(21 tests): declaration order, press-to-open with `aria-expanded`, a disabled
trigger that opens nothing on hover, press or key, one panel at a
time, Enter/ArrowDown with panel focus, Left/Right/Home/End between triggers,
Escape with focus return, outside-press dismissal, a link running once and
closing, a controlled nav staying closed, both themes, the pointer policy —
open only after the delay, survival across the trigger-to-panel gap, switching
panels by moving between triggers, an explicit key beating a pending hover open,
and a pressed-closed panel staying shut — and the panel's motion: the 4px entry
travel, the exit tween with its press passing through, and the reduced-motion
resting frame.

One measured implementation fact: the trigger registry updates its ordered key
list only when the key sequence changes. An always-new array (or a ref callback
that detaches on every render) caused React's update-depth error.

A second measured fact: the runtime delivers a press on the open trigger as a
mouse-down *outside* the panel, and then the trigger's click. Treating that
mouse-down as a dismissal closes the panel and the click reopens it, so a
pressed-open panel could never be toggled shut. The panel therefore ignores an
outside press that lands on one of the nav's own triggers (`isTriggerPoint`).
