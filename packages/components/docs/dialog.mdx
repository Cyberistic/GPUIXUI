## Usage

```tsx
import {
  Dialog,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
  DialogTrigger,
} from "@gpuixui/components/dialog";

<Dialog>
  <DialogTrigger>Delete workspace</DialogTrigger>
  <DialogContent label="Delete workspace">
    <DialogHeader>
      <DialogTitle>Delete this workspace?</DialogTitle>
      <DialogDescription>
        The workspace and its 42 files are removed for everyone.
      </DialogDescription>
    </DialogHeader>
    <DialogFooter>
      <DialogClose>Cancel</DialogClose>
      <Button variant="danger">Delete workspace</Button>
    </DialogFooter>
  </DialogContent>
</Dialog>;
```

## Composition

```text
Dialog
├── DialogTrigger
└── DialogContent
    ├── DialogHeader
    │   ├── DialogTitle
    │   └── DialogDescription
    ├── DialogFooter
    │   └── DialogClose
    └── (close control)
```

The close control is painted in the box around the surface's own scroller, not
inside it, so a body longer than the dialog scrolls under the control instead of
carrying the one visible way out of the surface (`src/behaviour/dialog.test.tsx`
scrolls a 30-row body and holds the control's box).

## Limitations

- No `aria-modal` or `aria-labelledby`; the name is `label`.
- The veil is an anchored layer at window coordinates, not a portal.
- Not resizable, draggable or multi-window.
- A dismissed dialog stays painted for its 320 ms exit and takes no presses; the
  two close actions the component paints — the top-right control and a
  `DialogClose` in the body — leave the Tab order for that window, while a
  control you compose yourself keeps its stop until the runtime publishes an
  inherited `inert`.
- A `size` restored from persisted state that the union does not name paints the
  house `md` width (480px); the lookup never hands `Math.min` an `undefined`, so
  a renamed or dropped size cannot shrink the surface to its content.
