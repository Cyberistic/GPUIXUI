---
title: Dialog
description: A modal surface that takes the window until it is dismissed.
---

`Dialog` is the modal primitive: it dims and blocks the window, moves focus into
its surface, keeps Tab inside it, and returns focus to whatever opened it. Compose
it from a trigger, a content surface and the header/description/footer parts.

```tsx
import {
  Dialog,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
  DialogTrigger,
} from "@gpuixui/components/dialog";
import { Button } from "@gpuixui/primitives";

<Dialog>
  <DialogTrigger>Delete workspace</DialogTrigger>
  <DialogContent label="Delete workspace">
    <DialogHeader>
      <DialogTitle>Delete this workspace?</DialogTitle>
      <DialogDescription>
        The workspace and its 42 files are removed for everyone.
      </DialogDescription>
    </DialogHeader>
    <DialogFooter>
      <DialogClose>Cancel</DialogClose>
      <Button variant="danger">Delete workspace</Button>
    </DialogFooter>
  </DialogContent>
</Dialog>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `Dialog` | owns `open`/`defaultOpen`/`onOpenChange`, pushes the dismiss layer |
| `DialogTrigger` | a button that toggles the dialog, `aria-expanded` included |
| `DialogContent` | the veil and the surface: focus, Tab, Escape and outside press |
| `DialogHeader` | title + description block, with room for the close control |
| `DialogTitle` | the heading (level 2 by default, or the caller's `level`) |
| `DialogDescription` | one paragraph of supporting copy |
| `DialogFooter` | right-aligned actions |
| `DialogClose` | a button that closes the enclosing dialog |

`DialogContent` takes `size` (`sm` 360px, `md` 480px, `lg` 640px), the required
`label` — the accessible name — `showClose` (default `true`) and `initialFocus`,
a function returning the native id focus should land on after the surface itself.

## Controlled and uncontrolled

```tsx
// Uncontrolled: the dialog remembers.
<Dialog defaultOpen>…</Dialog>;

// Controlled: the app remembers, which async work needs.
<Dialog open={open} onOpenChange={setOpen}>…</Dialog>;
```

The controlled form is authoritative: `onOpenChange` still fires, but the dialog
does not change its own state. In uncontrolled mode it stores the value itself.

## Dismissal

`dismissible` (default `true`) controls both Escape and an outside press. A dialog
doing uninterruptible work sets `dismissible={false}` and re-enables it when the
work settles.

Open dialogs share one dismiss stack (`src/internal/dismiss-layer.ts`): Escape and
outside presses are consumed by the **topmost** overlay only, so a popover inside a
dialog closes the popover first. One event cannot close two layers, however many
surfaces enclose it (a submenu, its menu and the dialog around both — plan 669).
The runtime hands each handler its own payload copy, so consumption is keyed on
the event's fields (the same claim the menus use), never on object identity. A
claim lives one task rather than one microtask, because a live window delivers a
nested layer's handler and its parent's across a microtask (plan 587); every
enclosing handler reads it, and a genuinely new event is a new task.

## Keyboard

| Key | Effect |
| --- | ------ |
| `Tab` | move to the next focusable inside the surface, wrapping at the end |
| `Shift+Tab` | move to the previous focusable, wrapping at the start |
| `Escape` | close, when `dismissible`; focus returns to the opener |
| `Enter` / `Space` | activate the focused action |

A nested surface that handles `Tab` itself owns that press: a `Popover` inside
the content walks its own controls and the trap resumes once its panel closes
(plan 719), and a modal opened from the content — a `ConfirmDialog`, another
`Dialog` — traps its own `Tab` while the enclosing dialog yields (plan 728).
Every other `Tab`, and the caller's own `onKeyDown`, behaves as before.

Nesting, not open order, decides which layer a key reaches: a modal opened in the
same commit as the dialog around it is still the top layer, holds initial focus,
and returns focus to the enclosing surface when it closes (plan 730).

The opener is captured before the surface mounts, so a control inside the
content that carries `autoFocus` (a form field, say) does not become the saved
opener. The promise holds for that content too (plan 638).

## Sizing and theming

The surface paints `colors.popover` / `colors.popoverForeground` with
`radius.xl`, `borderWidth.thin` in `colors.border` and the `lg` elevation. The veil
paints `colors.overlay`. The surface caps its height at the window minus two
`spacing["3xl"]` and scrolls interior overflow, so a long body cannot push the
actions off screen.

## Motion

`DialogContent` runs `dialogMotion(theme)` from `@gpuixui/tw` through
`AnimatePresence`: a 100 ms opacity fade on open and close. The surface stays
mounted for the exit and is inert while it leaves (`pointerEvents: none`), so
focus, Tab and dismissal end at close. `zoom-in-95`/`zoom-out-95` are recorded
as unsupported: GPUI has no transform, so no scale is faked.

## Accessibility and limitations

- `role="dialog"` with the required `label` as its accessible name.
- `DialogDescription` is announced as the dialog's description through
  `aria-description`, because `0.10.0` has no `aria-describedby`. An explicit
  `aria-description` on `DialogContent` wins over the registered part.
- Focus enters the surface on open and returns to the opener on close.
- **No `aria-modal` and no `aria-labelledby`.** `@gpuix/native@0.10.0` exposes
  only `aria-label`, `aria-description`, `aria-expanded`, `aria-selected`,
  `aria-valuetext` and `aria-level` on a host element (see `HostProps` in
  `@gpuix/native/dist/host.d.ts`), so the dialog's *name* is `label` and its title
  is a separate heading. Screen readers hear the name, not the heading, as the
  dialog's label.
- `DialogTitle`'s `level` is the caller's, defaulting to 2. A raw `aria-level`
  is still honoured when no `level` is given, and an explicit `level` wins.
- **The veil is an `anchored` layer at window coordinates.** 0.10.0 ships no
  portal, and `position:"absolute"` resolves against the mount parent, so a dialog
  must be mounted at (or near) the root of the tree. It then paints over the whole
  window; it does not participate in a scrolling parent's clip.
- The top-right close control uses the `x` icon from `@gpuixui/icons`.
- A dialog is not resizable, draggable or multi-window. One dialog per surface.
- The dismiss stack orders layers by the commit that opens them. A nested overlay
  (a popover or menu) that mounts **open in the same commit** as its dialog joins
  the stack below it, so the first Escape closes the dialog first; opening the
  nested overlay through interaction puts it on top as expected.

- Focus cues are seeded by `autoFocus`; the runtime does not reliably deliver
  React `focus`/`blur`, so a ring may not paint when focus moves by code
  (plans 390/603/605).

## API

| `Dialog` prop | Type | Default |
| ------------- | ---- | ------- |
| `open` | `boolean` | — (uncontrolled) |
| `defaultOpen` | `boolean` | `false` |
| `onOpenChange` | `(open: boolean) => void` | — |
| `dismissible` | `boolean` | `true` |

| `DialogContent` prop | Type | Default |
| -------------------- | ---- | ------- |
| `label` | `string` (required) | — |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` |
| `showClose` | `boolean` | `true` |
| `initialFocus` | `() => number \| null` | — |

`DialogHeader`, `DialogDescription` and `DialogFooter` take the host props and
children; they draw no state of their own.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `DialogHeader` | `div` | — |
| `DialogTitle` | `text` with `role="heading"` | `level?: 1 \| 2 \| 3 \| 4 \| 5 \| 6` (default `2`) |
| `DialogDescription` | `text` | — (registers its plain text as the dialog's `aria-description`) |
| `DialogFooter` | `div` | — |

`DialogTrigger`, `DialogClose` and `DialogTitle` take the GPUix host props where
they render one host element plus, for the buttons, the `variant`/`size` of the
button. Every part merges `style` last.

## Verification

`src/behaviour/dialog.test.tsx` runs in the real GPUix renderer (21 tests): the
veil measured at the window bounds, a click on a control behind it blocked, focus
entering and returning — including when the content contains an auto-focused
field (plan 638) — Escape and backdrop dismissal, a popover inside the dialog
closed by the first Escape with the dialog kept open, a menu's submenu inside the
dialog closing one layer per Escape (plan 669), Tab wrapping at both ends,
`role`/`aria-label` in the accessibility dump, the description announced through
`aria-description` (with an authored content value winning), the title's default
and caller-set heading levels, both themes reading
`colors.popover`/`colors.overlay`, a non-dismissible dialog ignoring both
dismissals, a controlled dialog staying closed, the caller's own close control,
a caller content `ref`, the 100 ms enter recipe, and the surface remaining for
its exit before it unmounts. Plus `src/internal/dismiss-layer.test.ts` for the
stack's own rules, including one keystroke arriving as two payload copies.

```sh
nub run --filter @gpuixui/components test:behaviour
```
