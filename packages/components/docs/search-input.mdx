title: Search input
description: A single-line search field with a clear affordance.
---

`SearchInput` is the field a filter bar uses: a leading icon, the text, and a
clear control that appears only when there is something to clear. It reports
every keystroke and never debounces.

```tsx
import { SearchInput } from "@gpuixui/components/search-input";

<SearchInput
  placeholder="Filter files…"
  onValueChange={setQuery}
  onSubmit={runSearch}
  onClear={() => setQuery("")}
/>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| the field | text editing; `onChange` and `onValueChange` fire on every edit |
| the icon | a static search marker, not interactive |
| the clear control | `aria-label="Clear search"`, shown only when the text is non-empty |

There is no separate label part: put a **Field** around it when the search needs
a visible label, or pass `aria-label` for a filter bar.

## Keyboard

| Key | Result |
| ---- | ------ |
| any character | updates the text and calls `onValueChange` |
| `Enter` | calls `onSubmit(currentText)` |
| `Escape` | clears when non-empty and calls `onClear`; does nothing on an empty field, so it does not swallow the key from an enclosing dialog |

`Enter` arrives as the input's `submit` event, not a key-down — measured in
`@gpuix/native@0.11.0`.

## Controlled and uncontrolled

```tsx
<SearchInput defaultValue="card" />;                       // remembers
<SearchInput value={query} onValueChange={setQuery} />;     // app remembers
```

A controlled field whose consumer ignores the change keeps showing the prop
value, while `onValueChange` still fires — the classic contract, tested.

## Clearing

Clicking the clear control (or pressing Escape) empties the field, calls
`onClear`, and returns focus to the input so typing can continue immediately.

## Disabled

A disabled field is `readOnly`, painted at 50% opacity, and **out of the tab
order**: 0.11.0 publishes no `disabled` on a host input, so `readOnly` is what
stops typing and `tabIndex: -1` is what keeps the field and its clear target out
of a `Tab` traversal.

Every edit path is refused while it is disabled. The field's own guard runs
before the clear, so `Escape` does nothing and neither `onValueChange` nor
`onClear` fires. A read-only host still receives keys, which is why the guard
sits on the edit path rather than on the host: a field disabled while it holds
the focus keeps that focus, and a key must not become an edit again.

The clear target stays painted — the field still shows its query — but it
advertises no press it would refuse: no hover wash, no keyboard outline, and a
`not-allowed` cursor, the rule `internal/button.tsx` states for a disabled
action.

## API

`SearchInput` takes the input's own `aria-*` and key handlers and merges `style`
last.

| Prop | Type | Default |
| ---- | ---- | ------- |
| `value` / `defaultValue` | `string` | — / `""` |
| `onValueChange` | `(value: string) => void` — every edit, including the clear and Escape paths | — |
| `onSubmit` | `(value: string) => void` — Enter, with the current text | — |
| `onClear` | `() => void` — the clear control and Escape on a non-empty field | — |
| `placeholder` | `string` | `"Search…"` |
| `disabled` | `boolean` | `false` |
| `style` | `StateStyle<SearchInputState>` — `{ disabled, focused }` | recipe |

## Theming

The container paints `colors.background`, a `borderWidth.thin` border in
`colors.border`, a **6px radius** and **8px** horizontal padding from the
recipe's fixed shadcn metrics (ADR 0006), and its height follows
`controlHeight(theme, "md")` — so a platform style repaints and re-heights the
field but never rounds or pads it differently. The clear control paints a 24px
square (the pressable-target floor — the `sm` glyph inside is 14px) with a 4px
radius and a `colors.accent` hover; it declares the same keyboard outline the
input does, and neither the hover nor the outline while the field is disabled.
Focus is the runtime's `focusVisible` outline in `colors.ring`, declared at rest,
so a Tab paints it and a mouse press does not.

## Style by state

`SearchInput.style` takes a `StyleDesc` or a function of `SearchInputState`
(`{ disabled, focused }`); the style is applied to the field surface, not the
inner `<input>`.

`focused` reaches a press, a click and a programmatic focus — but not a `Tab`
traversal: the runtime focuses the element without running its `onFocus` on
0.11.0 (`tabs-lifecycle` reads `focuses=0`; `tooltip-lifecycle` does not open its
tip, re-measured 2026-10-22). The ring declared at rest is still the keyboard
cue: the flag is presentational, and nothing here depends on the event
(`docs/component-api.md` §3).

```tsx
<SearchInput style={(state) => ({ opacity: state.disabled ? 0.5 : 1 })} />
```

## Accessibility and limitations

- The input carries the caller's `aria-label` (or the field's label); the clear
  control is a labelled button.
- A disabled field and its clear target leave the tab order and both answer
  nothing (see [Disabled](#disabled)).
- **No debounce.** Debouncing is the consumer's: fire the query from
  `onValueChange` through your own Effect schedule. A component-level timer would
  both hide the policy and break the repo's clock rule.
- No search history, no suggestions and no shortcut binding (`⌘F` belongs to the
  app).
- The leading mark and the clear control are `@gpuixui/icons` glyphs; the icon
  set owns their size and stroke.

## Verification

`src/behaviour/search-input.test.tsx` runs in the real GPUix renderer (10 tests):
real keystrokes reaching `onValueChange`, the clear control appearing only with
text, clearing and returning focus, Enter submitting, Escape clearing once, the
controlled contract, a caller `ref` composed with the internal one, a disabled
field and its target leaving the tab order, and the disabled field refusing both
its clear target and Escape. `src/search-input-page.test.ts` holds this page's
metrics and disabled rule to the compiled recipe and the source.

The field merges its own focus ref with the caller's, so `ref` receives the same
`<input>` instance that clearing focuses.

```sh
nub run --filter @gpuixui/components test:behaviour
```
