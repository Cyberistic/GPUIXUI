---
title: Search input
description: A single-line search field with a clear affordance.
---

`SearchInput` is the field a filter bar uses: a leading search icon, the text,
and a clear control that appears only when there is something to clear. It
reports every keystroke and never debounces.

```tsx
import { SearchInput } from "@gpuixui/components/search-input";

<SearchInput
  placeholder="Filter files…"
  onValueChange={setQuery}
  onSubmit={runSearch}
  onClear={() => setQuery("")}
/>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| the field | text editing; `onChange` and `onValueChange` fire on every edit |
| the icon | a static `search` mark, not interactive |
| the clear control | `aria-label="Clear search"`, shown only when the text is non-empty |

There is no separate label part: put a **Field** around it when the search needs
a visible label, or pass `aria-label` for a filter bar.

## Keyboard

| Key | Result |
| ---- | ------ |
| any character | updates the text and calls `onValueChange` |
| `Enter` | calls `onSubmit(currentText)` |
| `Space` on the clear control | clears on release; key down alone does nothing |
| `Escape` | clears when non-empty and calls `onClear`, claiming the key so an enclosing dialog stays open; on an empty field it does nothing and leaves the key to the dialog |

`Enter` arrives as the input's `submit` event, not a key-down — measured in
`@gpuix/native@0.10.0`.

## Controlled and uncontrolled

```tsx
<SearchInput defaultValue="card" />;                       // remembers
<SearchInput value={query} onValueChange={setQuery} />;     // app remembers
```

A controlled field whose consumer ignores the change keeps showing the prop
value, while `onValueChange` still fires — the classic contract, tested.

## Clearing

Clicking the clear control (or pressing Escape) empties the field, calls
`onClear`, and returns focus to the input so typing can continue immediately.
The Escape that clears is claimed, so a search field inside a dialog clears and
leaves the dialog open; an empty field has nothing to clear and passes Escape on
(plan `514`).

## API

`SearchInput` is one part; it takes the host input props and adds:

| Prop | Type | Default |
| ---- | ---- | ------- |
| `value` | `string` | — (uncontrolled) |
| `defaultValue` | `string` | `""` |
| `onValueChange` | `(value: string) => void` | — |
| `onSubmit` | `(value: string) => void` | — |
| `onClear` | `() => void` | — |
| `placeholder` | `string` | `"Search…"` |
| `disabled` | `boolean` | `false` |
| `style` | `StateStyle<{ disabled: boolean; focused: boolean }>` | — |

`disabled` makes the field `readOnly`, dims it, drops the focus ring and hides
the clear control; Escape and Enter are inert too. A field the user cannot type
into must not offer any way to change or submit it.

## Theming

The container paints `colors.background`, a `borderWidth.thin` border in
`colors.border`, `radius.md`, `spacing.md` horizontal padding and
`controlHeight(theme, "md")`. The clear control is 18×18 with `radius.sm` and a
`colors.accent` hover. Focus draws the zero-blur `colors.ring` ring, because
0.10.0 has no `outline`.

## Style by state

`SearchInput.style` takes a `StyleDesc` or a function of `SearchInputState`
(`{ disabled, focused }`); the style is applied to the field surface, not the
inner `<input>`.

```tsx
<SearchInput style={(state) => ({ opacity: state.disabled ? 0.5 : 1 })} />
```

`autoFocus` sets the initial `focused` state, so the ring is painted on the
first commit — the runtime applies native focus after React's effects and never
dispatches `onFocus`.

## Accessibility and limitations

Disabled controls announce **Disabled** through `aria-description`; 0.10.0 has no
`aria-disabled` semantics (plan 516).

- The input carries the caller's `aria-label` (or the field's label); the clear
  control is a labelled button.
- **No debounce.** Debouncing is the consumer's: fire the query from
  `onValueChange` through your own Effect schedule. A component-level timer would
  both hide the policy and break the repo's clock rule.
- No search history, no suggestions and no shortcut binding (`⌘F` belongs to the
  app).

- Focus cues are seeded by `autoFocus`; the runtime does not reliably deliver
  React `focus`/`blur`, so a ring may not paint when focus moves by code
  (plans 390/603/605).

## Verification

`src/behaviour/search-input.test.tsx` runs in the real GPUix renderer (13 tests):
real keystrokes reaching `onValueChange`, the clear control appearing only with
text and never on a disabled field, a disabled field ignoring Escape and Enter, clearing and returning focus, clearing from the keyboard on Space
release, Enter submitting, Escape clearing once, the clear keeping its dialog
open while an empty field's Escape closes it, the controlled contract, and a
caller `ref` composed with the internal one.

The field merges its own focus ref with the caller's, so `ref` receives the same
`<input>` instance that clearing focuses.

```sh
nub run --filter @gpuixui/components test:behaviour
```
