---
title: Dropdown menu
description: A list of actions anchored to the control that opened it.
---

`DropdownMenu` shows a short list of actions next to its trigger. The surface is
an anchored GPUix layer, which snaps inside the window but does not flip; the
component opens it on the opposite side when snapping would cover the trigger,
centres a requested surface from measured bounds, and owns the open state, the
highlight, the dismissal rules and focus return.

```tsx
import {
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuItem,
  DropdownMenuSeparator,
  DropdownMenuTrigger,
} from "@gpuixui/components/dropdown-menu";

<DropdownMenu>
  <DropdownMenuTrigger>Actions</DropdownMenuTrigger>
  <DropdownMenuContent label="File actions">
    <DropdownMenuItem onSelect={rename}>Rename</DropdownMenuItem>
    <DropdownMenuItem disabled>Duplicate</DropdownMenuItem>
    <DropdownMenuSeparator />
    <DropdownMenuItem tone="destructive" onSelect={remove}>
      Delete
    </DropdownMenuItem>
  </DropdownMenuContent>
</DropdownMenu>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `DropdownMenu` | open state, the dismiss layer, the positioning root |
| `DropdownMenuTrigger` | a button that toggles the menu, `aria-expanded` included |
| `DropdownMenuContent` | the floating `role="menu"` surface, rendered while open |
| `DropdownMenuItem` | one action; `onSelect` runs, then the menu closes |
| `DropdownMenuCheckboxItem` | an on/off row that stays open after toggling |
| `DropdownMenuRadioGroup` | one exclusive value across its radio rows |
| `DropdownMenuRadioItem` | one choice in a radio group; stays open after choosing |
| `DropdownMenuSub` | a group of actions behind a secondary level |
| `DropdownMenuSubTrigger` | the row that opens the submenu |
| `DropdownMenuSubContent` | the floating second level, rendered while open |
| `DropdownMenuSeparator` | a hairline between groups |
| `DropdownMenuLabel` | a small heading over a group |
| `DropdownMenuGroup` | a labelled group of rows |

`DropdownMenuContent` takes `side` (`top`/`right`/`bottom`/`left`, default
`"bottom"`), `align` (`start`/`center`/`end`, default `"start"`), `sideOffset`
(default `4`) and `collisionPadding` (default `8`, the margin kept from the
window edge when the surface snaps). A surface that snaps over its trigger is
opened on the opposite side when that side has room, otherwise on the roomier
side. `align="center"` is exact and measured; `alignOffset` is added on top if
the caller needs its own adjustment. `label` is the menu's accessible name.

## Highlight is focus

The highlighted row **is** the focused row. Every arrow move calls the renderer's
`focusElement`, and every row that takes focus becomes the highlight, so a row
can never look selected while Enter would activate a different one. A pointer
hover does not highlight the row it is over; clicking activates. Hovering a
submenu row opens that submenu and focuses its first row, as the submenu section
describes.

## Keyboard

| Key | Result |
| ---- | ------ |
| `Enter` / `Space` on the trigger | opens on the first enabled row, or closes when open |
| `ArrowDown` on the trigger | opens on the first enabled row |
| `ArrowUp` on the trigger | opens on the last enabled row |
| `ArrowDown` / `ArrowUp` | moves to the next/previous enabled row, wrapping |
| `Home` / `End` | first/last enabled row |
| `Enter` / `Space` | runs the highlighted row and closes |
| Letter keys | jumps to the next enabled row whose label starts with the typed prefix |
| `Escape` | closes and returns focus to the trigger |
| `Tab` | closes and lets focus move on — a menu is not modal |
| `ArrowRight` on a submenu trigger | opens it and focuses its first row |
| `ArrowDown` / `ArrowUp` on an open submenu trigger | enters the submenu at its first/last row |
| `ArrowLeft` or `Escape` inside a submenu | closes that level and returns focus to its trigger |

A keyboard open lands on a row, so a second `Enter` runs the first action without
an extra arrow press. A pointer click leaves focus on the menu surface with no
row highlighted, which is the desktop menu convention; the first arrow key then
picks the first enabled row.

Disabled rows are skipped by every arrow key, by `Home`/`End` and by type-ahead,
and a click on one does nothing. A **disabled trigger** opens nothing: the
button's press is muted and the trigger's own arrow keys are inert, while a
caller's `onKeyDown` still runs.

## Type-ahead

Typing a letter jumps to the next enabled row whose label starts with the typed
prefix, so `Re` reaches **Rename** and `De` reaches **Delete**. The prefix is
case-insensitive, ignores surrounding whitespace and is matched from the start of
the label — not as a fuzzy substring.

- The prefix lives for **500 ms** after the last keystroke. A later letter starts
  a fresh search instead of extending an old one.
- Typing the same letter again within the window advances to the next row that
  starts with it, wrapping at the end — so `D`, `D`, `D` cycles every D row.
- A prefix that matches nothing leaves the highlight where it was and clears the
  buffer, so the next letter searches afresh.
- A row whose `children` is not a plain string (a label with a badge beside it)
  is matched through `textValue`:

```tsx
import { Badge } from "@gpuixui/components/badge";

<DropdownMenuItem textValue="Rename" onSelect={rename}>
  Rename <Badge>draft</Badge>
</DropdownMenuItem>;
```

The window is a timestamp comparison, not a `setTimeout`: the buffer records the
monotonic time of its last keystroke and the next keystroke decides whether it has
expired. Nothing has to run while the menu is idle, so the component owns no
timer and no provider.

## Dismissal

Pressing outside, pressing the open trigger, `Escape` and choosing a row all
close the menu. Menus are layers in the same dismiss stack as `Dialog` and
`Popover`, so a menu opened inside a dialog closes first and leaves the dialog
open.

A press on the menu's own trigger is not an outside press: the menu's dismiss
layer claims the press (so an enclosing dialog stays open) and the click that
follows closes the menu. The runtime delivers that click in a later task than the
press, which is why the rule reads the press position instead of marking the
next click.

## Checkbox rows and tones

```tsx
<DropdownMenuCheckboxItem
  checked={showHidden}
  onCheckedChange={setShowHidden}
>
  Show hidden files
</DropdownMenuCheckboxItem>
```

A checkbox row does not close the menu — toggling several settings in one visit
is the point. It shows a check icon when checked and carries `aria-selected`.

`tone="destructive"` paints the row in `colors.destructive`. It is a visual
signal, not a confirmation step: pair a destructive row with **Confirmation
dialog** when the action cannot be undone.

## Radio rows

A radio group expresses one exclusive setting — sort order, view mode, density:

```tsx
<DropdownMenuRadioGroup
  label="Sort by"
  value={sort}
  onValueChange={setSort}
>
  <DropdownMenuRadioItem value="name">Name</DropdownMenuRadioItem>
  <DropdownMenuRadioItem value="modified">Modified</DropdownMenuRadioItem>
  <DropdownMenuRadioItem value="size">Size</DropdownMenuRadioItem>
</DropdownMenuRadioGroup>;
```

The group is controlled: it renders `value` and reports the chosen row through
`onValueChange`; it never changes its own mark. Choosing the row that is already
marked reports nothing. A radio row keeps the menu open —
choosing a setting is not an action — and the leading dot marks exactly one row
in the group. The group is a `role="group"`; `label` names it, or a
`DropdownMenuLabel` above it does. A disabled row is skipped by arrows and
type-ahead and cannot be chosen.

The same group and row work inside a `DropdownMenuSubContent`, so a submenu can
carry the setting too.

## Submenus

A submenu groups actions behind one secondary level:

```tsx
<DropdownMenuSub>
  <DropdownMenuSubTrigger>Share</DropdownMenuSubTrigger>
  <DropdownMenuSubContent label="Share">
    <DropdownMenuItem onSelect={copyLink}>Copy link</DropdownMenuItem>
    <DropdownMenuItem onSelect={email}>Email</DropdownMenuItem>
  </DropdownMenuSubContent>
</DropdownMenuSub>;
```

The trigger is an ordinary menu row: arrows and type-ahead reach it, and
clicking, `Enter`, `Space`, `ArrowRight` or hovering opens the submenu. Opening a
submenu focuses its first row, so the next `Enter` runs the first action without
an extra arrow press. Only one submenu per menu is open at a time; moving onto
another row closes the open one. Leaving the row **and** its panel also closes
that level, after `closeDelay` (default 150 ms) so the pointer can cross the gap
into the surface; focus returns to the row and the parent menu stays open. A
`disabled` row opens nothing, by hover or by key.

A submenu may itself contain a submenu. The rules are the same at every depth,
and a row in an enclosing submenu stays clickable while a deeper level is open:
the deeper layer treats a press inside any enclosing surface as inside the menu
tree, so the click reaches the row and that row's action closes the levels above
it.

The surface's side is decided once per open from measured bounds: it opens at
the trigger row's right edge when it fits there, otherwise at the row's left
edge. A surface taller than the room below is bottom-aligned to its row, so it
never covers the row it belongs to. A surface wider than either side of the
window is still clamped by GPUix's `fit="snap"`, and the roomier side wins. A
press on a submenu surface is geometrically outside the parent surface, so the
runtime reports it to the parent's outside handler first; the submenu's dismiss
layer recognises a press inside its own or any enclosing surface and lets it
reach the row. A press outside every menu surface closes the whole menu.

A row is chosen by pointer as well as by keyboard: clicking it runs the action
once and closes every level.

`Escape` and `ArrowLeft` close **one** level: the submenu disappears, focus
returns to its trigger, and the parent menu stays open. Choosing a submenu action
closes both levels and returns focus to the dropdown trigger. An outside press
also closes both.

## Controlled and uncontrolled

```tsx
<DropdownMenu defaultOpen>…</DropdownMenu>;                        // remembers
<DropdownMenu open={open} onOpenChange={setOpen}>…</DropdownMenu>;  // app remembers
```

## API

The trigger, surface and rows merge `style` last. The row parts share one prop set: `onSelect?: ()
=> void`, `disabled?: boolean`, `tone?: "default" | "destructive"` (default
`"default"`), `leading?: ReactNode`, `trailing?: ReactNode`, `textValue?:
string`, `closeOnSelect?: boolean` (default `true`) and `style?:
StateStyle<{ disabled: boolean; highlighted: boolean }>`.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `DropdownMenu` | provider (no host element) | `open?: boolean`, `defaultOpen?: boolean` (default `false`), `onOpenChange?: (open: boolean) => void` |
| `DropdownMenuTrigger` | `div` (`role="button"`, `aria-expanded`) | the button's `variant`, `size` and `disabled` |
| `DropdownMenuContent` | anchored surface | `label?: string`, `side?: "top" \| "right" \| "bottom" \| "left"` (default `"bottom"`), `align?: "start" \| "center" \| "end"` (default `"start"`), `sideOffset?: number` (default `4`), `alignOffset?: number` (default `0`) |
| `DropdownMenuItem` | `div` (`role="menuitem"`) | the shared row props |
| `DropdownMenuCheckboxItem` | `div` (`role="menuitem"`) | `checked: boolean` (required), `onCheckedChange: (checked: boolean) => void` (required), plus the shared row props |
| `DropdownMenuRadioGroup` | `div` (`role="group"`) | `value: string \| null` (required), `onValueChange: (value: string) => void` (required), `label?: string` |
| `DropdownMenuRadioItem` | `div` (`role="menuitemradio"`) | `value: string` (required), plus the shared row props except `leading`, `closeOnSelect` and `style` (`style?: StateStyle<MenuRadioItemState>`) |
| `DropdownMenuGroup` | `div` (`role="group"`) | — |
| `DropdownMenuLabel` | `text` | — |
| `DropdownMenuSeparator` | `div` (`role="separator"`) | — |
| `DropdownMenuSub` | provider (no host element) | `closeDelay?: number` (default `150`) |
| `DropdownMenuSubTrigger` | `div` (`role="menuitem"`, `aria-expanded`) | the shared row props except `onSelect`, `closeOnSelect` and `tone` |
| `DropdownMenuSubContent` | anchored surface | `label?: string` |

## Theming

The surface paints `colors.popover` / `colors.popoverForeground`, `radius.md`,
`borderWidth.thin` in `colors.border`, the `md` elevation and `spacing.xs` padding,
with a 180px minimum width. Rows are `controlHeight(theme, "sm")` tall, use the
`label` type role, and highlight with `colors.hover` plus a 2px left bar in
`colors.accent`.

## Style by state

A row takes a `StyleDesc` or a function of its state: `MenuItemState`
(`{ disabled, highlighted }`), `MenuCheckboxItemState`
(`{ checked, disabled, highlighted }`) or `MenuRadioItemState`
(`{ checked, disabled, highlighted }`). `highlighted` is the row the menu's real
focus is on.

```tsx
<DropdownMenuItem
  style={(state) => ({ opacity: state.disabled ? 0.4 : 1 })}
>
  Rename
</DropdownMenuItem>
```

## Accessibility and limitations

Disabled controls announce **Disabled** through `aria-description`; 0.10.0 has no
`aria-disabled` semantics (plan 516).

- `role="menu"` on the surface, `role="menuitem"` / `role="menuitemcheckbox"` /
  `role="menuitemradio"` on rows, `role="group"` on a group, `aria-expanded` on
  the trigger, and `aria-selected` for a checkbox or radio row's state.
- A row's accessible name comes from its plain-text child; a row composed from
  elements must pass `aria-label`, because 0.10.0 does not lift the child text
  into the name.
- **No `aria-haspopup`, `aria-controls`, `aria-checked` or `aria-activedescendant`**
  in `@gpuix/native@0.10.0`: `HostProps` exposes only `aria-label`,
  `aria-description`, `aria-expanded`, `aria-selected`, `aria-valuetext` and
  `aria-level`. The checkbox and radio rows therefore use `aria-selected`, and the
  link between trigger and surface is positional. A submenu trigger announces
  `aria-expanded` but not `aria-haspopup`.
- Nested submenus are exercised to two levels, including a row of an enclosing
  submenu chosen while a deeper level is open. Placement, hover travel and
  dismissal follow the same rule at every depth.
- Submenus open to the right when they fit and otherwise to the left of their
  row, from one measurement per open; a submenu wider than both sides is still
  clamped by `fit="snap"`.
- The root surface flips once per open, from measured bounds. A surface taller
  than both sides can still cover its trigger, and `align="center"` is clamped by
  the snap margin near a window edge.
- Type-ahead is a prefix match with no fuzzy scoring, and it ignores a label that
  is not plain text unless `textValue` is set.
- A hover does not preview a highlight; the pointer activates on click.
