## Usage

```tsx
import {
  ChatComposer,
  ChatMessages,
  ChatRoot,
  MessageContent,
  MessageRoot,
  chatMove,
} from "@gpuixui/components";

<ChatRoot
  status={status}
  onStatusChange={setStatus}
  onSubmit={send}
  onStop={stop}
  onRetry={retry}
>
  <ChatMessages>
    {messages.map((message) => (
      <MessageRoot key={message.id} variant={message.role}>
        <MessageContent>{message.body}</MessageContent>
      </MessageRoot>
    ))}
  </ChatMessages>
  <ChatComposer hint="Enter sends · Shift+Enter adds a line" />
</ChatRoot>;
```

## Composition

```text
ChatRoot
├── ChatMessages

```

## API

| Part | Renders | Props |
| ---- | ------- | ----- |
| `ChatRoot` | `role="region"` named by `label` | `status?`, `defaultStatus?`, `onStatusChange?`, `onSubmit` (required), `onStop?`, `onRetry?`, `error?`, `label?` |
| `ChatMessages` | the transcript viewport and empty panel | `empty?`, `emptyTitle?`, `emptyDescription?` |
| `ChatComposer` | a field and its Send/Stop control | `value?`, `defaultValue?`, `onValueChange?`, `label?`, `placeholder?`, `submitLabel?` (default `"Send"`), `stopLabel?` (default `"Stop"`), `hint?`, `attachments?` (a row above the field), `disabled?` |

## While a reply is open

Send becomes Stop, and `Enter` is refused by the same machine rule that hides
Send — `chatMove(status, "submit")` emits nothing while `submitting` or
`streaming`. A refused send keeps the draft in the field, so the words nobody
received are not cleared and the reader can send them when the reply ends.

## Limitations

- The transport is yours; the component never calls a model.
- No streaming API; drive the status with `chatMove`.
- No `aria-live`; new rows are not announced.
- The transcript is not virtualized.
