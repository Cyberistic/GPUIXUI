MessageScroller is the transcript. It follows new rows and a growing streamed
reply while the reader is at the end; the moment they scroll away it stops, keeps
their position and offers the way back with the number of rows that arrived
unseen.

## Installation

```bash
nub add @gpuixui/components
```

## Usage

```tsx
import {
  MessageScroller,
  MessageScrollerContent,
  MessageScrollerItem,
  MessageScrollerJumpToLatest,
  MessageScrollerViewport,
} from "@gpuixui/components";

<MessageScroller label="Conversation" streaming={streaming}>
  <MessageScrollerViewport style={{ height: 320 }}>
    <MessageScrollerContent>
      {messages.map((message) => (
        <MessageScrollerItem key={message.id}>
          <text>{message.body}</text>
        </MessageScrollerItem>
      ))}
    </MessageScrollerContent>
  </MessageScrollerViewport>
  <MessageScrollerJumpToLatest />
</MessageScroller>;
```

## Composition

```text
MessageScroller
├── MessageScrollerViewport
│   └── MessageScrollerContent
│       └── MessageScrollerItem
└── MessageScrollerJumpToLatest
```

## The height contract

The viewport is the flexible middle of the scroller: it grows, may shrink and
never makes the frame taller. The jump control owns a **reserved rail** below
it, so showing it does not take height from the viewport or move anything below
the scroller. Give the scroller a bounded height (directly, or through a sized
flex parent) because a viewport with no height has nothing to scroll.

## Following and releasing

- A reader inside `threshold` (default 24px) of the tail is at the end. New rows
  and a reply that grows keep the tail visible.
- Scrolling away releases the view: appends and growth change nothing, and the
  rail's control counts the rows that arrived.
- Jump to latest returns to the end and re-pins.
- A row that grows through its own state is still followed while pinned: the 1px
  tail sentinel's `onLayout` is the measurement, so no React render is needed.
- An observation the scroller cannot read (`NaN`) is ignored; the pin state is
  kept.

## Turn anchoring

`MessageScrollerItem scrollAnchor` places a newly mounted row near the top with
`previousItemPeek` of the row above still visible, but only while the reader is
pinned. It is opt-in: a Chat that appends a user row and a reply should mark the
user row as the anchor if it wants shadcn's turn behaviour. An unpinned reader
is never moved.

## API

| Part | Renders | Props |
| ---- | ------- | ----- |
| `MessageScroller` | `role="group"` named by `label` | `label` (required), `threshold?`, `previousItemPeek?`, `pinned?`, `defaultPinned?`, `onPinnedChange?`, `streaming?`, `className?`, `children` |
| `MessageScrollerViewport` | the scroll container and its tail sentinel | `style`, `onScroll?`, `onLayout?`, `ref?`, `className?`, `children` |
| `MessageScrollerContent` | the rows column; publishes `aria-busy` | `className?`, `children` |
| `MessageScrollerItem` | one row, no surface | `scrollAnchor?`, `className?`, `children`, `ref?` |
| `MessageScrollerJumpToLatest` | a secondary control in a reserved rail | `label?`, `className?`, `style?` |

## Limitations

- Not virtualized; every row renders. `<virtual-list>` takes an item count
  rather than compound children.
- The jump control travels inside the rail, not over the viewport's corner:
  `position: absolute` resolves against the mount parent in `0.11.0`.
- No `aria-live` role, so new rows are not announced; the control's count is
  painted and the content publishes `aria-busy` while a reply is streaming.
- Turn anchoring has no follow-output handoff: after a new turn is anchored, the
  reader is away from the tail until they jump back. shadcn resumes following
  once the reply fills the viewport; this release keeps the reader's position.
