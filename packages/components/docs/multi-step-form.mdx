## Usage

```tsx
import { MultiStepForm } from "@gpuixui/components";
import * as Option from "effect/Option";

<MultiStepForm
  label="Create a workspace"
  steps={[
    {
      id: "name",
      title: "Name",
      content: <WorkspaceNameField value={name} onChange={setName} />,
      gate: () =>
        namePattern.test(name)
          ? Option.none()
          : Option.some("Use 3 to 24 lowercase letters, digits or hyphens"),
    },
    {
      id: "port",
      title: "Port",
      content: <PortField value={port} onChange={setPort} />,
      gate: () =>
        portUsable(port) ? Option.none() : Option.some("Enter a port from 1024 to 65535"),
    },
    {
      id: "review",
      title: "Review",
      content: <Review draft={{ name, port }} />,
      gate: () =>
        accepted ? Option.none() : Option.some("Accept the checklist first"),
    },
  ]}
  onSubmit={create}
/>;
```

## Steps

Each entry of `steps` is a `MultiStep`:

| Field | Type | Default | Notes |
| ----- | ---- | ------- | ----- |
| `id` | `string` | required | The step's stable key, shared with its indicator row. |
| `title` | `string` | required | The step's name in the indicator and in the content's announcement. |
| `description` | `string` | — | One line of supporting copy in the indicator. |
| `content` | `ReactNode` | required | Mounted only while the step is current. |
| `gate` | `() => Option.Option<string>` | — | Runs before the step moves and before the last step submits; the message it returns keeps the reader put. |

## API

| Prop | Type | Default |
| ---- | ---- | ------- |
| `steps` | `ReadonlyArray<MultiStep>` | required |
| `onSubmit` | `() => void` | required |
| `step` | `number` | — (uncontrolled) |
| `defaultStep` | `number` | `1` |
| `onStepChange` | `(step: number) => void` | — |
| `pending` | `boolean` | `false` |
| `submitLabel` | `string` | `"Submit"` |
| `nextLabel` | `string` | `"Next"` |
| `backLabel` | `string` | `"Back"` |
| `label` | `string` | — |
| `className` | `string` | — |
| `style` | `StyleDesc` | — |

## Limitations

- **The draft is the caller's**: the component stores the step index and a
  refusal per step `id`, so a caller that reorders `steps` never paints one
  step's message under another.
- **No free navigation**: `Back` and the gates are the only moves.
- A step gate is not the record decode; decode the whole draft in `Form`.
