`MultiStepForm` is the orchestration a multi-step form would otherwise repeat
per screen: the current step, a **gate** that may refuse to leave it, the
shipped `Stepper` indicator, and one submit that only the last step offers. The
draft stays the caller's — the same contract `Form` has.

```tsx
import { MultiStepForm } from "@gpuixui/components";
import * as Option from "effect/Option";

<MultiStepForm
  label="Create a workspace"
  steps={[
    {
      id: "name",
      title: "Name",
      content: <WorkspaceNameField value={name} onChange={setName} />,
      gate: () =>
        namePattern.test(name)
          ? Option.none()
          : Option.some("Use 3 to 24 lowercase letters, digits or hyphens"),
    },
    {
      id: "port",
      title: "Port",
      content: <PortField value={port} onChange={setPort} />,
      gate: () =>
        portUsable(port) ? Option.none() : Option.some("Enter a port from 1024 to 65535"),
    },
    {
      id: "review",
      title: "Review",
      content: <Review draft={{ name, port }} />,
      gate: () =>
        accepted ? Option.none() : Option.some("Accept the checklist first"),
    },
  ]}
  onSubmit={create}
/>;
```

## Two gates, two jobs

A wizard's validation is not one check:

- a **step gate** answers "may the reader leave this step?" — it runs on `Next`
  and again on the last step's `Submit`, and its message is painted beside the
  content until the step moves;
- the **record decode** is `Form`'s: the whole draft (including the review
  step's acceptance) is decoded once on submit. Wrap the content in a `Form`
  whose `onSubmit` is this component's `onSubmit`, or pass the decoded call as
  `onSubmit` yourself.

A gate returns `Option<string>`: `Option.none()` allows the move, `Option.some(message)`
refuses with that sentence. The refusal is remembered with the step it was
raised on, so a controlled `step` change never shows one step's message under
another's content.

## Steps

Only the current step's `content` is mounted. That is the honest trade for a
wizard whose draft lives above it: a field's own transient state (an IME
composition, a scroll offset) does not survive a step change, and a hidden step
never leaves controls in the tab order. Keep the draft in the caller.

`steps` with no entries paints nothing. A `step` outside `1…steps.length` reads
as the nearest real step — `0` is the first, `99` is the last.

## Controlled or not

| Mode | Props |
| ---- | ----- |
| uncontrolled | `defaultStep?` (default `1`) |
| controlled | `step`, plus `onStepChange` |

`onStepChange` fires in both modes with the accepted step. A controlled `step`
is authoritative: `Next` reports and repaints only when the caller passes a new
step.

## Keyboard and focus

The actions are the shipped `Button`s, so a click and the platform's activation
keys (Enter, Space on release) both work, and a disabled action leaves the tab
order. The indicator is read-only: `Stepper` installs no key handler and no tab
stop. Moving a step unmounts the previous content, so focus returns to the
document; a wizard that must keep focus on a field should focus it after the
step's content mounts.

## API

| Prop | Type | Default |
| ---- | ---- | ------- |
| `steps` | `ReadonlyArray<MultiStep>` | required |
| `onSubmit` | `() => void` | required |
| `step` | `number` | — (uncontrolled) |
| `defaultStep` | `number` | `1` |
| `onStepChange` | `(step: number) => void` | — |
| `pending` | `boolean` | `false` |
| `submitLabel` | `string` | `"Submit"` |
| `nextLabel` | `string` | `"Next"` |
| `backLabel` | `string` | `"Back"` |
| `label` | `string` | — |
| `className` | `string` | — |
| `style` | `StyleDesc` | — |

A `MultiStep` is `{ id, title, description?, content, gate? }`, where `gate` is
`() => Option<string>`.

## Limitations

- **The draft is the caller's.** The component stores the step index and a
  refusal; it never reads or copies the record.
- **No free navigation.** The indicator does not jump; `Back` and the gates are
  the only moves. That is `Stepper`'s contract.
- **The last step's gate is not the record decode.** A gate is a cheap "may I
  leave?" answer; a schema that must see the whole record belongs to `Form`.
- **A step change unmounts its content.** Field-local state does not survive it.
