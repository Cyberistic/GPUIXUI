title: Combobox
description: A searchable single- or multi-select over a ranked option list.
---

`Combobox` combines a field-like trigger with a searchable popup. It wraps
GPUix's headless combobox — focus, the active row and the keyboard stay the
runtime's — and adds our option shape, ranking, row look and value semantics.

```tsx
import {
  Combobox,
  ComboboxContent,
  ComboboxEmpty,
  ComboboxInput,
  ComboboxList,
  ComboboxTrigger,
} from "@gpuixui/components/combobox";

<Combobox
  options={[
    { value: "ada", label: "Ada Lovelace", description: "Engineering" },
    { value: "grace", label: "Grace Hopper", description: "Compilers" },
  ]}
  onValueChange={(value) => setReviewer(typeof value === "string" ? value : null)}
>
  <ComboboxTrigger label="Assign reviewer" />
  <ComboboxContent>
    <ComboboxInput label="Search reviewers" />
    <ComboboxList label="Reviewers" />
    <ComboboxEmpty />
  </ComboboxContent>
</Combobox>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `Combobox` | the headless root: ranking, selection, open state and focus restore |
| `ComboboxTrigger` | the field-shaped control: selected labels or `placeholder`, `role="button"`, `aria-expanded`, a chevron |
| `ComboboxContent` | the anchored popup surface |
| `ComboboxInput` | the search field; Escape asks the root to restore focus |
| `ComboboxList` | the ranked listbox, one `ComboboxItem` per visible option |
| `ComboboxItem` | one row: label, optional description, a check icon while selected |
| `ComboboxEmpty` | shown only when no option matches; children replace the default |

Single mode selects one value and closes. Multiple mode keeps the popup open,
toggles the row, and reports the selected values in the order they were chosen.

The root owns the state because ranking and the selection payload need the whole
option set; the parts own their own labels and place. `ComboboxItem` is exported
so a caller can compose the rows of a custom list from the same root.

## Values, not labels

`onValueChange` receives the option **value** (`"ada"`), never the display label
(`"Ada Lovelace"`). The adapter maps values to labels only for display, which is
why a rename never changes the stored data.

The public shape is:

```ts
value?: string | ReadonlyArray<string>;                 // controlled
onValueChange?: (value: string | null | ReadonlyArray<string>) => void;
```

`null` is "nothing selected" in single mode; `undefined` means uncontrolled.

## Creating values

A picker whose options come from a fixed list can still accept a new name. Pass
`onCreate`; while the trimmed query matches no option exactly, one create row is
appended after the ranked matches.

```tsx
<Combobox
  options={projects}
  onCreate={(query) =>
    setProjects((current) =>
      current.some((option) => option.value === query)
        ? current
        : [...current, { value: query, label: query }],
    )
  }
  onValueChange={(value) =>
    setProject(typeof value === "string" ? value : null)
  }
>
  <ComboboxTrigger label="Project" />
  <ComboboxContent>
    <ComboboxInput label="Search projects" />
    <ComboboxList label="Projects" />
  </ComboboxContent>
</Combobox>
```

| Prop | Meaning |
| ---- | ------- |
| `onCreate?: (query: string) => void` | Called once with the trimmed query after the create row is selected. |
| `createLabel?: (query: string) => string` | The row's text. Default `Create “<query>”`. |

The row appears only when the trimmed query is non-empty and no option's label or
value already equals it (case-insensitive). In single mode selecting it reports
the trimmed query as the value, closes the popup and returns focus to the
trigger, exactly like a real option. In multiple mode it adds the trimmed query
to the selection once and keeps the popup open. The synthetic row never reaches
`onValueChange`: the callback sees the query, never an internal value.

Creation is synchronous. `onCreate` is the caller's cue to append the option (or
persist it). Rows fetched remotely are a separate concern: see
[Remote options](#remote-options).

## Ranking

The filter is our pure `combobox/logic.ts`, not GPUix's order-preserving
predicate:

| Rank | Rule |
| ---- | ---- |
| 0 | the label starts with the query |
| 1 | a word inside the label starts with the query |
| 2 | the label contains the query |
| 3 | the description contains the query |

Ties keep declaration order. Matching is case-insensitive and an empty query
shows everything. Disabled options stay visible but cannot be selected by click,
arrow or Enter.

> **Adapter note.** GPUix's `filter` is a predicate applied to `items`, so it can
> only remove rows, never reorder them. The adapter therefore passes an
> already-ranked `items` array with `filter={null}` and controls `inputValue`.
> This is plan 116 §3's documented fallback; a predicate could not express the
> ranking. `combobox.test.tsx` asserts the order.

## Remote options

When the options come from a server, the wrapper must not filter them: the rows
it would keep are exactly the ones the caller's search already discarded. Two
props hand the search over, and one reports that rows are on their way.

| Prop | Meaning |
| ---- | ------- |
| `onQueryChange?: (query: string) => void` | `""` when the popup opens, then once per edit the user types. The label a selection writes back into the field is **never** reported. |
| `shouldFilter?: boolean` | Default `true`. `false` shows `options` exactly as given — membership and order — so the caller's result is not re-filtered or re-ranked. |
| `loading?: boolean` | Default `false`. While no row is shown, the default `ComboboxEmpty` text reads `Loading…` instead of `No matches`. |

```tsx
const [rows, setRows] = useState(allPeople);
const [pending, setPending] = useState(false);

<Combobox
  options={rows}
  shouldFilter={false}
  loading={pending}
  onQueryChange={(query) => {
    // The fetch belongs here, not in the component.
    setRows(searchPeople(query));
  }}
  onValueChange={(value) => setPerson(typeof value === "string" ? value : null)}
>
  <ComboboxTrigger label="Assign reviewer" />
  <ComboboxContent>
    <ComboboxInput label="Search people" />
    <ComboboxList label="People" />
    <ComboboxEmpty />
  </ComboboxContent>
</Combobox>;
```

The component never fetches, debounces or cancels a request. `onQueryChange`
fires once per edit, so a caller with a network round trip debounces it and
drops stale responses itself. `loading` only changes the empty slot: a caller
that keeps the previous rows visible while the next request is in flight gets
no built-in indicator, and should render its own.

The `examples/combobox.example.tsx` directory picker is this shape: the example
filters a local array in `onQueryChange`, which is where a request would go.

## Keyboard

| Key | Result |
| ---- | ------ |
| click / Enter / Down on the trigger | opens the popup |
| typing | filters; the first enabled match is highlighted |
| `ArrowDown` / `ArrowUp` | moves the highlight, wrapping and skipping disabled rows |
| `Enter` | selects the highlighted row |
| `Escape` | closes and returns focus to the trigger |
| outside press | closes without stealing focus back |

The search input keeps focus; the highlighted row is visual. **No
`aria-activedescendant`** exists in 0.10.0, so assistive technology does not get
the input→row relationship; `aria-selected` on the rows is the supported signal.

The trigger is a `button` node named by `label` (or its text) with a live
`aria-expanded`, so the open state is announced even though 0.10.0 has no
`aria-haspopup` (see [Limitations](#limitations)).

## API

`ComboboxOption` is `{ value: string; label: string; description?: string;
disabled?: boolean }`; `ComboboxSelection` is `string | null |
ReadonlyArray<string>`. Every part merges `style` last where it takes one.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Combobox` | GPUix's headless combobox root | `options: ReadonlyArray<ComboboxOption>` (required), `value?: string \| ReadonlyArray<string>`, `defaultValue?: string \| ReadonlyArray<string>`, `onValueChange?: (value: ComboboxSelection) => void`, `multiple?: boolean` (default `false`), `disabled?: boolean`, `onQueryChange?: (query: string) => void`, `shouldFilter?: boolean` (default `true`), `loading?: boolean`, `onCreate?: (query: string) => void`, `createLabel?: (query: string) => string` |
| `ComboboxTrigger` | headless trigger (`role="button"`, `aria-expanded`) | `placeholder?: string` (default `"Select…"`), `label?: string`, `testId?: string` (default `"combobox-trigger"`) |
| `ComboboxContent` | anchored popup | `side?: "top" \| "right" \| "bottom" \| "left"` (default `"bottom"`), `align?: "start" \| "center" \| "end"` (default `"start"`), `sideOffset?: number` (default `4`), `alignOffset?: number` (default `0`) |
| `ComboboxInput` | `input` | `placeholder?: string` (default `"Search…"`), `label?: string` (default `"Search options"`), `onChange?: (event: EventPayload) => void` |
| `ComboboxList` | GPUix's listbox | `label?: string` (default `"Options"`), `itemStyle?: StateStyle<ComboboxItemState>` |
| `ComboboxItem` | GPUix's option row | `value: string` (required), `style?: StateStyle<ComboboxItemState>` |
| `ComboboxEmpty` | GPUix's empty slot | `children?: ReactNode` |

## Theming

The trigger paints `colors.background`, a `borderWidth.thin` border in
`colors.borderStrong`, `radius.md`, `controlHeight(theme, "md")` and
`colors.mutedForeground` for the placeholder. The popup paints
`colors.popover`, `radius.md`, the `md` elevation, a `maxHeight` of 280 with
scrolling, and rows highlight with `colors.hover`. The selected check is
`colors.primary`.

## Style by state

Rows take a `StyleDesc` or a function of `ComboboxItemState`
(`{ selected, highlighted, disabled }`, GPUix's own type). The list renders the
rows, so pass it as `ComboboxList.itemStyle`; `ComboboxItem.style` accepts the
same shape for a row composed by hand.

```tsx
<ComboboxList
  itemStyle={(state) => ({ opacity: state.disabled ? 0.4 : 1 })}
/>
```

## Limitations

- No grouping headers in v1. Create-new is a synchronous caller callback
  (`onCreate`), not a persistence layer.
- No built-in debounce or request cancellation: `onQueryChange` fires per edit
  and the caller owns the transport ([Remote options](#remote-options)).
- No separate loading row: `loading` changes the empty slot only. Rows kept
  visible from the previous query stay on screen until the caller replaces them.
- The popup is an anchored layer, not a portal. The runtime snaps it inside the
  window but does not flip it, so the component opens it on the opposite side
  when snapping would cover the trigger; `align="center"` is measured from the
  trigger rather than using the runtime's containing-block centre.
- `align="center"` is clamped by the snap margin near a window edge.
- The trigger is a `div` with button semantics (the `@gpuixui/primitives`
  stand-in), not a native button element.

## Verification

`src/behaviour/combobox.test.tsx` runs in the real GPUix renderer (28 tests):
open + input focus, a centred popup and a near-bottom popup that opens above its
trigger, the trigger exposed as a button with its expanded state, filtering,
ArrowDown + Enter selecting the **value**, the empty state,
single replacement (including the selected row's `aria-selected`), multi
add/remove with order, the disabled row, Escape restoring focus,
prefix-before-substring ranking, both themes, the pointer path — selecting an
option, toggling several while skipping a disabled one, closing on an outside
press — a caller-supplied empty state, the trigger's placeholder/name coming
from the part, the create row: its position after the matches, its absence
for an exact option, Enter and pointer selection with focus return, multiple
selection without the sentinel, and a caller-supplied label — plus the reported
query (including that a selection's label write is not reported), caller-owned
filtering, a caller replacing the options for a query, and the loading empty
state in both directions.

`src/combobox/logic.test.ts` covers the ranking table, `labelOf`,
`toggledSelection`, `visibleOptions`, and the create rules (`canCreate` plus
the synthetic value's round-trip).
