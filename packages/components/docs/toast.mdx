---
title: Toast
description: A bounded, auto-dismissing notification stack backed by an Effect store.
---

`ToastProvider` creates one Effect runtime and one toast store; `useToast()`
pushes and dismisses; `ToastViewport` paints the stack. The queue is a
`SubscriptionRef`, the auto-dismiss timers are a `FiberMap`, and React only sees
the resulting array.

```tsx
import {
  ToastProvider,
  ToastViewport,
  useToast,
} from "@gpuixui/components/toast";

<ToastProvider>
  <App />
  <ToastViewport />
</ToastProvider>;

const toast = useToast();
toast.push({
  title: "Changes published",
  description: "The site rebuilds in about a minute.",
  tone: "success",
});
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `ToastProvider` | the `ManagedRuntime`, the store, the React subscription — the package's **only** `runtime.run*` boundary |
| `useToast()` | `{ toasts, push, dismiss, dismissAll, pause, resume, actionFor }`; throws outside the provider |
| `ToastViewport` | the stack in `position`'s corner (bottom-right by default); `role="group"` named Notifications, with each card its own status |

Render the viewport **last** in the app root: GPUix has no `zIndex`, so overlays
stack in paint order. The viewport is `pointerEvents: "none"` and each card turns
pointer events back on, so a toast never blocks the page underneath.

## Behaviour

| Rule | Value |
| ---- | ----- |
| stack size | 3 by default (`max`); pushing a fourth drops the oldest, a finite cap is truncated and floored at 1, and a non-finite one keeps the default instead of removing the bound |
| auto-dismiss | 5 seconds by default (`defaultDuration`) |
| custom duration | `duration: Duration.seconds(6)` |
| zero or infinite duration | never auto-dismisses; the card stays until dismissed |
| ids | monotonic (`"1"`, `"2"`, …), never reused |
| hovering a card or one of its controls | pauses its clock; leaving resumes with the **remaining** time |
| focusing a card's controls | pauses its clock; moving focus away resumes with the **remaining** time |
| an action | one labelled control; pressing it runs the handler once and dismisses the toast |
| dismissing a card | its dismiss control or its action dismisses that card and hands focus to the next live card's dismiss control (the card below it, else the one above); the last card leaves focus alone |
| progress | a positive finite `duration` paints a 2px bar across the card bottom; it shrinks every 100 ms, freezes during a pause and resumes with the same remainder |
| placement | `position` picks `top-left`, `top-right`, `bottom-left` or `bottom-right` (default); the oldest toast is topmost and the stack hugs the named horizontal side in every corner |

A dismissed toast's timer is cancelled with it, so a stale timer can never remove
the next toast. That regression is guarded in `toast/store.test.ts` with
`TestClock`; the store suite also proves the stack bound and the id order.

Pause/resume is also on `useToast()` for a consumer that wants its own hold
affordance (a button, a hover target, a focus ring). The viewport holds a card's
clock while the pointer is on it **or** focus is inside it, and resumes only when
both have left; the pause keeps the remaining time, so the two reasons compose
without restarting the countdown.

The same hold freezes the progress bar: the store publishes the running deadline
or the paused remainder as `ToastTiming`, and the card ticks that value locally
every 100 ms. The visual tick is not the dismissal clock — the store still drops
the toast at the exact deadline. A zero or infinite duration has no timer, so it
draws no progress bar.

Tones are `info` (default), `success`, `warning` and `danger`; each paints the
3px left bar and a matching `@gpuixui/icons` mark (`info`, `success`, `warning`,
`error`).

## Actions

A toast may carry one action, such as Undo. The **label** is data in the draft,
so it decodes and validates like the title; the **handler** is supplied beside
the draft, because a function cannot cross the schema boundary:

```tsx
toast.push(
  {
    title: "Message archived",
    action: { label: "Undo" },
    duration: Duration.seconds(8),
  },
  { onAction: () => restore() },
);
```

- An action label with **no handler draws nothing** — never a dead control.
- Pressing the action runs the handler once and dismisses the toast, the same
  contract as Radix/shadcn; the handler may push another toast.
- A toast has at most one action. More than one is a composition decision, not a
  hidden array.
- Keyboard focus on the action holds the auto-dismiss clock exactly like the
  dismiss control; the two controls share one hold count, so moving focus between
  them does not resume the timer.
- `useToast().actionFor(id)` returns the handler as an `Option`, for a consumer
  that renders its own content.

## Controlled by whom

The queue belongs to the provider, not to the calling component. Any component
inside the provider can push; the viewport is the single place that renders.
There is no per-toast React state to keep in sync.

## API

`ToastDraft` is `{ title: string; description?: string; action?: { label:
string }; tone?: "info" | "success" | "warning" | "danger"; duration?: Duration }`.
`ToastTiming` is `{ id, totalMs, remainingMs, paused }`.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `ToastProvider` | provider (no host element) | `max?: number` (default `3`; a finite value truncates and floors at 1, a non-finite value is the default), `defaultDuration?: Duration.Input` (default `5 seconds`), `children?: ReactNode` |
| `ToastViewport` | `div` (`role="group"`, `aria-label="Notifications"`, `testId="toast-viewport"`) | `position?: "top-left" \| "top-right" \| "bottom-left" \| "bottom-right"` (default `"bottom-right"`), `children?: ReactNode` (an optional element before the toasts, e.g. "Dismiss all") |
| `useToast` | hook | returns `{ toasts, push(draft, { onAction }?), dismiss(id), dismissAll(), pause(id), resume(id), actionFor(id), timingFor(id) }`; `timingFor` is `Option<ToastTiming>` and is absent for a toast with no timer |

## Motion

Cards enter and leave through `AnimatePresence` with `toastMotion(theme)` from
`@gpuixui/tw`: 500 ms with `cubic-bezier(0.22, 1, 0.36, 1)`, fading opacity
only. The card stays mounted for the exit, so a dismissal is visible rather than
an instant pop, while the store's queue drops immediately. 0.10.0 exposes no
reduced-motion preference, so the recipe is not switchable.

## Theming

Cards paint `colors.popover` with `colors.popoverForeground`, a
`borderWidth.thin` border in `colors.border`, `radius.md`, the `md` elevation and
`spacing.lg` padding. The bar and icon take the tone's colour (the same status
palette Alert and Badge use). Width is 380px; the viewport keeps `spacing.xl`
from its two pinned edges.

## Accessibility and limitations

- Each card is a `role="status"` region whose accessible name is its message
  (`title: description`), so the content that changed is the status content; the
  viewport is a `role="group"` named `Notifications`. Each card's dismiss control
  is a labelled button, addressed as `toast-<id>-dismiss`; a card with an action
  addresses it as `toast-<id>-action` (plan 770 — the cards used to share one
  handle, so no two cards' controls could be told apart).
- Dismissing a card from one of its own controls hands focus to the next live
  card's dismiss control, because the control unmounts with its card and would
  otherwise leave focus on nothing while other notifications remain. Dismissing
  the only card leaves focus alone: a toast is pushed programmatically and has no
  trigger to return to, so the viewport does not invent one (plan 770).
- **No `aria-live` and no `aria-atomic`** in `@gpuix/native@0.10.0`; a named
  status region is the supported announcement, and the runtime exposes no
  live-region concept beyond it.
- The progress bar is presentational: it has no role, no tab stop and no pointer
  events, so the card remains the single named status region. It ticks at 100 ms
  for a smooth-enough visual; the dismissal itself is exact.
- Hovering a card pauses its clock, and so does keyboard focus on either of its
  controls; the clock resumes with the remaining time once both the pointer and
  focus have left. The keyboard reason is measured from the renderer's focused
  host, sampled every 50 ms, because `@gpuix/native@0.10.0` delivers no React
  `focus`/`blur` for a native focus change (plans 536/540, 743); the card holds
  while the focused host is its own action or dismiss control, and it never
  expires underneath one. A control inside the card reports its own pointer
  crossing through the shared hover group, because GPUix hover is per element:
  moving from the card body onto `Undo` or the dismiss control keeps the hold
  instead of resuming the clock under the pointer. A consumer that needs a
  custom hold can call `pause`/`resume` from `useToast()`.
- No portal: the viewport is an absolutely positioned element in its parent, so
  put it at the app root.
- The animated card wrapper carries `toast-<id>-surface`, while the card itself
  is `toast-<id>`; the wrapper is how a native suite addresses the exit ghost
  (plan 597).
- Disposal is deferred one microtask (`toast/lifecycle.ts`) so a React
  StrictMode mount/unmount/remount does not dispose the runtime the remount
  keeps using. The native test renderer does not reproduce StrictMode's double
  effect invocation, so that rule is a pure suite rather than a component test.

- Focus cues are seeded by `autoFocus`; the runtime does not reliably deliver
  React `focus`/`blur`, so a ring may not paint when focus moves by code
  (plans 390/603/605).

## Verification

- `src/toast/store.test.ts` — queue, ids, `max`, dismiss, `dismissAll`,
  `TestClock` auto-dismiss, the stale-timer regression, custom durations,
  rejected input, pause/resume with the remaining time, the published
  `ToastTiming` (start, elapsed, paused, removed, absent for an infinite timer),
  the timing stream and action decoding (present, absent, empty label). The
  malformed-cap guard proves `NaN` and `Infinity` each keep the newest three.
- `src/toast/timing.test.ts` — six pure cases for the percentage, clamping, the
  zero-total guard, one running tick, a paused tick and the final zero.
`src/behaviour/toast.test.tsx` runs in the real GPUix renderer (28 tests): push
and the card's status name, stacking order, dismissing one card, the per-card
control handles, focus handed to the next card (below, and above when the last
one goes) by a dismiss control and by an action, `dismissAll`,
the page staying clickable
through the viewport, both themes, the queue still working after a dismiss,
hover pausing a card's auto-dismiss, keyboard focus pausing it through the
sampled native focus (the queue and its timer are asserted, so the painted exit
ghost cannot stand in for a hold), focus holding through the pointer leaving,
the clock resuming once native focus leaves the card, the clock holding while
the pointer rests on the action or the dismiss control and resuming when it
leaves the action, the shrinking progress
bar and its hover hold, no bar for a
persistent toast, the action running once and dismissing, no control for an
unhandled label, no control without an action, the action holding focus, the
500 ms enter recipe, the card remaining through its exit before it leaves, and
