---
title: Toast
description: A bounded, auto-dismissing notification stack backed by an Effect store.
---

`ToastProvider` creates one Effect runtime and one toast store; `useToast()`
pushes and dismisses; `ToastViewport` paints the stack. The queue is a
`SubscriptionRef`, the auto-dismiss timers are a `FiberMap`, and React only sees
the resulting array.

```tsx
import {
  ToastProvider,
  ToastViewport,
  useToast,
} from "@gpuixui/components/toast";

<ToastProvider>
  <App />
  <ToastViewport />
</ToastProvider>;

const toast = useToast();
toast.push({
  title: "Changes published",
  description: "The site rebuilds in about a minute.",
  tone: "success",
});
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `ToastProvider` | the `ManagedRuntime`, the store, the React subscription — the package's **only** `runtime.run*` boundary |
| `useToast()` | `{ toasts, push, dismiss, dismissAll, pause, resume, actionFor }`; throws outside the provider |
| `ToastViewport` | the bottom-right stack; `role="status"` |

Render the viewport **last** in the app root: GPUix has no `zIndex`, so overlays
stack in paint order. The viewport is `pointerEvents: "none"` and each card turns
pointer events back on, so a toast never blocks the page underneath.

## Behaviour

| Rule | Value |
| ---- | ----- |
| stack size | 3 by default (`max`); pushing a fourth drops the oldest |
| auto-dismiss | 5 seconds by default (`defaultDuration`) |
| custom duration | `duration: Duration.seconds(6)` |
| zero or infinite duration | never auto-dismisses; the card stays until dismissed |
| ids | monotonic (`"1"`, `"2"`, …), never reused |
| hovering a card | pauses its clock; leaving resumes with the **remaining** time |
| focusing a card's controls | pauses its clock; moving focus away resumes with the **remaining** time |
| an action | one labelled control; pressing it runs the handler once and dismisses the toast |

A dismissed toast's timer is cancelled with it, so a stale timer can never remove
the next toast. That regression is guarded in `toast/store.test.ts` with
`TestClock`; the store suite also proves the stack bound and the id order.

Pause/resume is also on `useToast()` for a consumer that wants its own hold
affordance (a button, a hover target, a focus ring). The viewport holds a card's
clock while the pointer is on it **or** focus is inside it, and resumes only when
both have left; the pause keeps the remaining time, so the two reasons compose
without restarting the countdown.

Tones are `info` (default), `success`, `warning` and `danger`; each paints the
3px left bar and a matching `@gpuixui/icons` mark (`info`, `success`, `warning`,
`error`).

## Actions

A toast may carry one action, such as Undo. The **label** is data in the draft,
so it decodes and validates like the title; the **handler** is supplied beside
the draft, because a function cannot cross the schema boundary:

```tsx
toast.push(
  {
    title: "Message archived",
    action: { label: "Undo" },
    duration: Duration.seconds(8),
  },
  { onAction: () => restore() },
);
```

- An action label with **no handler draws nothing** — never a dead control.
- Pressing the action runs the handler once and dismisses the toast, the same
  contract as Radix/shadcn; the handler may push another toast.
- A toast has at most one action. More than one is a composition decision, not a
  hidden array.
- Keyboard focus on the action holds the auto-dismiss clock exactly like the
  dismiss control; the two controls share one hold count, so moving focus between
  them does not resume the timer.
- `useToast().actionFor(id)` returns the handler as an `Option`, for a consumer
  that renders its own content.

## Controlled by whom

The queue belongs to the provider, not to the calling component. Any component
inside the provider can push; the viewport is the single place that renders.
There is no per-toast React state to keep in sync.

## Theming

Cards paint `colors.popover` with `colors.popoverForeground`, a
`borderWidth.thin` border in `colors.border`, `radius.md`, the `md` elevation and
`spacing.lg` padding. The bar and icon take the tone's colour (the same status
palette Alert and Badge use). Width is 380px.

## Accessibility and limitations

- The viewport is `role="status"` with `aria-label="Notifications"`; each card's
  dismiss control is a labelled button.
- **No `aria-live` and no `aria-atomic`** in `@gpuix/native@0.10.0`; a status
  region is the supported announcement.
- **No progress indicator** for the remaining time; the store knows the deadline
  but the card does not animate it.
- Hovering a card pauses its clock, and so does keyboard focus on either of its
  controls; the clock resumes with the remaining time once both the pointer and
  focus have left. A consumer that needs a custom hold can call
  `pause`/`resume` from `useToast()`.
- No portal: the viewport is an absolutely positioned element in its parent, so
  put it at the app root.
- Disposal is deferred one microtask (`toast/lifecycle.ts`) so a React
  StrictMode mount/unmount/remount does not dispose the runtime the remount
  keeps using. The native test renderer does not reproduce StrictMode's double
  effect invocation, so that rule is a pure suite rather than a component test.

## Verification

- `src/toast/store.test.ts` — queue, ids, `max`, dismiss, `dismissAll`,
  `TestClock` auto-dismiss, the stale-timer regression, custom durations,
  rejected input, pause/resume with the remaining time, and action decoding
  (present, absent, empty label).
`src/behaviour/toast.test.tsx` runs in the real GPUix renderer (14 tests): push,
stacking order, dismissing one card, `dismissAll`, the page staying clickable
through the viewport, both themes, the queue still working after a dismiss,
hover pausing a card's auto-dismiss, focus pausing it, focus holding through the
pointer leaving, the action running once and dismissing, no control for an
unhandled label, no control without an action, and the action holding focus.

```sh
nub run --filter @gpuixui/components test
nub run --filter @gpuixui/components test:behaviour
```
