## Installation

```bash
nub add @gpuixui/components
```

## Usage

```tsx
import {
  ToastProvider,
  ToastViewport,
  useToast,
} from "@gpuixui/components/toast";

<ToastProvider>
  <App />
  <ToastViewport />
</ToastProvider>;

const toast = useToast();
toast.push({ title: "Changes published", tone: "success" });
```

## Composition

```text
ToastProvider
└── ToastViewport
```

## API

| Part | Prop | Type | Default |
| ---- | ---- | ---- | ------- |
| `ToastProvider` | `max` | `number` | `3` |
| `ToastProvider` | `defaultDuration` | `Duration.Input` | `5 seconds` |
| `ToastViewport` | `children` | `ReactNode` | — |
| `useToast()` | `push` | `(draft: ToastDraft, options?) => void` | — |
| `useToast()` | `dismiss` / `dismissAll` | `(id: string) => void` / `() => void` | — |
| `useToast()` | `pause` / `resume` | `(id: string) => void` | — |

`max` bounds the queue: a count the store cannot measure — a `NaN` from a width
calculation that never arrived, or an `Infinity` — reads as the default 3, and a
finite count below one keeps one card. An unbounded queue would retain a card
and its auto-dismiss timer for every toast ever pushed.

## Motion

The stack moves on its own timing, not a shared level: a card rises 16px into
place (220 ms) and leaves by fading while it slides 16px to the right (180 ms).
A dismissed card stays painted for that exit, so the card keeps the content it
was dismissed with.

Hovering any card fans the stack — each card that is not the newest lifts 8px,
widening the gap — and holds every auto-dismiss clock; leaving the stack resumes
each with the time it had left. `MotionProvider preference="reduced"` removes
the travel and paints the resting frame at once.

## Limitations

- No `aria-live` or `aria-atomic`; a status region is the announcement.
- No progress indicator for the remaining time.
- A traversal does not hold the clock; use `duration: 0` for an actionable toast.
- Not portalled; put the viewport at the app root.
- A dismissed card stays painted for its exit and keeps the content it was
  dismissed with — its action stays visible but inert, because the seam's
  `PresenceShield` takes the press rather than the action running after close.
