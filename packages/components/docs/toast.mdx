## Installation

```bash
nub add @gpuixui/components
```

## Usage

```tsx
import {
  ToastProvider,
  ToastViewport,
  useToast,
} from "@gpuixui/components/toast";

<ToastProvider>
  <App />
  <ToastViewport />
</ToastProvider>;

const toast = useToast();
toast.push({ title: "Changes published", tone: "success" });
```

## Composition

```text
ToastProvider
└── ToastViewport
```

## API

| Part | Prop | Type | Default |
| ---- | ---- | ---- | ------- |
| `ToastProvider` | `max` | `number` — cards kept before the oldest drops | `3` |
| `ToastProvider` | `defaultDuration` | `Duration.Input` | `5 seconds` |
| `ToastViewport` | `swipe` | `boolean` — sideways drag to dismiss | `true` |
| `ToastViewport` | `children` | `ReactNode` | — |
| `ToastViewport` | `className` | `string` | — |
| `useToast()` | `push` | `(draft, options?) => void` | — |
| `useToast()` | `promise` | `(p, { loading, success, error }) => Promise` | — |
| `useToast()` | `dismiss` / `dismissAll` | `(id: string) => void` / `() => void` | — |
| `useToast()` | `pause` / `resume` | `(id: string) => void` | — |
| `useToast()` | `hold` | `(held: boolean) => void` — the stack's clock | — |

A draft is `{ title, description?, tone?, duration?, action?, phase? }`. `tone`
is `"info" | "success" | "warning" | "danger"`, `duration: 0` keeps the card, and
`action` is a label whose handler travels beside the draft
(`toast.push(draft, { onAction })`); a label with no handler paints nothing.

## Behaviour

- **Stack.** Up to three cards show while the stack rests: the newest is full
  and the two behind are short, inset peeks of the card's own top. The viewport
  keeps `max` cards, so a fourth push expires the oldest; the leaving card fades
  and closes its row without re-slotting, so a push animates the card that
  arrived and nothing else.
- **Expand.** Hovering or focusing the stack unfolds the peeks into a column of
  full cards with one shared gap; leaving folds them back. Every clock pauses
  while the pointer or a focus is in the stack and resumes with the time it had
  left, so a card pushed during the hold starts paused.
- **Swipe.** A horizontal drag moves the card; past 40 px, or a fast 12 px flick,
  the release dismisses it toward the edge it travelled. Under that it springs
  back.
- **Promise.** `toast.promise(p, { loading, success, error })` queues one
  loading card, then updates that same row when the promise settles. `success`
  and `error` may be a draft or a function of the answer. The caller's promise
  is returned unchanged.
- **Action.** One action per card runs once and dismisses it.
- **Close.** The X dismisses; both controls are labelled buttons.

## Motion

A card fades and slides 16 px in from the right once its height is known, and
leaves by fading while it slides 16 px toward the edge it was dismissed from.
Everything the stack does to itself — a rank change, an unfold, a closing row, a
swipe returning — runs on one movement: 260 ms of Base UI's
`[0.22, 1, 0.36, 1]` curve. The arrival is 240 ms and the exit 180 ms. The card
is kept painted for that exit and takes no presses; **its action and dismiss
controls drop out of the Tab order for the same window**, so a reader
Tab-browsing cannot land on a control that is about to unmount.
`MotionProvider preference="reduced"` snaps every frame and keeps the resting
appearance.

## Limitations

- No `aria-live` or `aria-atomic`; a card paints `role="status"` (`alert` for the
  destructive tone), so new rows are not announced.
- A traversal does not hold the clock; use `duration: 0` for an actionable toast.
- No progress indicator for the remaining time.
- The runtime has no `transform`, so nothing scales and a tween cannot
  overshoot: a peek is a clip of a full card, and a swipe-back returns fast and
  settles rather than springing past the edge.
