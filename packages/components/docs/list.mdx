---
title: List
description: A vertical collection of rows, optionally single- or multi-selectable.
---

`List` presents rows. With `selectionMode="single"` it becomes a `listbox`: arrow
keys move a roving tab stop, a click selects, and the list behaves as a single tab
stop instead of one per row. `selectionMode="multiple"` keeps that keyboard model
and adds the desktop selection modifiers. In both modes, typing the first letters
of a row jumps to it.

```tsx
import {
  List,
  ListItem,
  ListItemDescription,
  ListItemTitle,
} from "@gpuixui/components/list";

<List selectionMode="single" defaultValue="readme">
  <ListItem value="readme" textValue="README.md">
    <ListItemTitle>README.md</ListItemTitle>
    <ListItemDescription>~/GPUIXUI</ListItemDescription>
  </ListItem>
  <ListItem value="list" textValue="list.tsx">
    <ListItemTitle>list.tsx</ListItemTitle>
  </ListItem>
</List>;
```

## Modes

| `selectionMode` | Role | Tab stop | Keyboard |
| --------------- | ---- | -------- | -------- |
| `none` (default) | `list` / `listitem` | none — rows are not focusable | none |
| `single` | `listbox` / `option` | exactly one row | see below |
| `multiple` | `listbox` / `option` | exactly one row | see below |

## Keyboard (single mode)

| Key | Effect |
| --- | ------ |
| `↓` | focus the next enabled row, wrapping |
| `↑` | focus the previous enabled row, wrapping |
| `Ctrl+N` / `Ctrl+P` | the desktop equivalents of `↓` / `↑` |
| `Home` | focus the first enabled row |
| `End` | focus the last enabled row |
| `Enter` / `Space` | select the focused row |
| Letter keys | jump to the next enabled row whose `textValue` starts with the typed prefix |

A disabled row is skipped by the arrow keys, by `Home`/`End` and by clicks; it can
never be selected.

## Keyboard (multiple mode)

Movement works exactly as in single mode. Selection differs:

| Key | Effect |
| --- | ------ |
| `Space` / `Enter` | toggle the focused row, keeping the rest |
| `Shift+↓` / `Shift+↑` | move focus and select the range from the anchor |
| `↓` / `↑` (no shift) | move focus and re-anchor; the selection stays |
| `Cmd+A` / `Ctrl+A` | select every enabled row; focus stays put |

Select-all becomes the new anchor at the first enabled row, so a following
`Shift`+click extends from the top of the list. Single-mode lists ignore the key.
Type-ahead works here too: a typed jump moves focus and re-anchors without
changing the selection, so a following `Shift`+click extends from the row reached.

## Type-ahead

Type the first letters of a row to jump to it. Matching is a case-insensitive
**prefix** (not fuzzy), reads `ListItem`'s `textValue`, and searches the rows
after the current one, wrapping to the first match. A repeated letter therefore
cycles through the rows that start with it, the desktop convention. Disabled rows
and rows without `textValue` are skipped.

```tsx
<List selectionMode="single">
  <ListItem value="readme" textValue="README.md">
    <ListItemTitle>README.md</ListItemTitle>
  </ListItem>
  <ListItem value="design" textValue="Design notes">
    <ListItemTitle>Design notes</ListItemTitle>
  </ListItem>
</List>
```

Typing `d` focuses “Design notes”; typing `d` again stays there (one match).
Typing `r` from “Design notes” wraps back to “README.md”.

The typed prefix lives for 500ms. The window is a lazy comparison against
Effect's monotonic clock, not a timer: nothing runs while the list is idle, and a
prefix that matches nothing is cleared so the next letter starts a fresh search.

## Selection

Controlled and uncontrolled both work, like every stateful component here:

```tsx
// Uncontrolled: the list remembers.
<List selectionMode="single" defaultValue="a" onValueChange={log} />;
<List
  selectionMode="multiple"
  defaultValue={["a"]}
  onValueChange={log}
/>;

// Controlled: the app remembers.
<List selectionMode="single" value={selected} onValueChange={setSelected} />;
<List
  selectionMode="multiple"
  value={assigned}
  onValueChange={setAssigned}
/>;
```

In controlled mode the list reports the change and leaves `aria-selected` where
the consumer put it — a suite asserts exactly that, because silently updating
would be the classic controlled-component bug.

### Multiple selection

| Pointer | Effect |
| ------- | ------ |
| click | select only that row; it becomes the anchor |
| `Cmd`/`Ctrl`+click | toggle that row, keeping the rest; it becomes the anchor |
| `Shift`+click | select the enabled range from the anchor to that row |

A range never includes a disabled row. Values are reported in the order they were
selected, without duplicates. Selecting the same set again reports nothing new.
Single mode still has no second click that clears the value; a multiple list
clears by toggling its last selected row.

**Not built**: no drag reorder and no `aria-multiselectable` (see Accessibility).

## API

`List` and `ListItem` take the GPUix host props and merge `style` last.

| `List` prop | Type | Default |
| ----------- | ---- | ------- |
| `selectionMode` | `"none" \| "single" \| "multiple"` | `"none"` |
| `value` / `defaultValue` | `string` (single) · `ReadonlyArray<string>` (multiple) | — / `""` · `[]` |
| `onValueChange` | `(value: string) => void` (single) · `(values: ReadonlyArray<string>) => void` (multiple) | — |
| `dense` | `boolean` | `false` |

The value type follows the mode: a `single` list cannot be given an array and a
`multiple` list cannot be given a string — the props are a discriminated union,
so the compiler enforces it.

| `ListItem` prop | Type | Default |
| --------------- | ---- | ------- |
| `value` | `string` (required) | — |
| `textValue` | `string` — the text type-ahead matches; omit and the row is not searched | — |
| `disabled` | `boolean` | `false` |
| `leading` | `ReactNode` | — |
| `trailing` | `ReactNode` | — |

`ListItemTitle` is the row's one line; `ListItemDescription` is its second, muted
and ellipsised.

`ListItem` used outside `List` throws — a programming error at the boundary, not a
runtime state to recover from.

## Sizing

A row is `density.rowHeight + spacing.md` tall (40px on the default comfortable
density) and `density.rowHeight` when `dense` (32px). Selection paints
`colors.selected` / `colors.selectedForeground`; hover paints `colors.accent`;
a disabled row is drawn at 50% opacity.

## Accessibility

- `role="list"`/`"listitem"` without selection and `listbox`/`option` with it, so
  assistive technology reads a list of rows either way.
- `aria-selected` is set on every row in both selectable modes, so the selection
  (including each member of a multiple selection) is announced rather than only
  painted.
- **`aria-multiselectable` cannot be declared.** `@gpuix/native@0.10.0`'s
  `HostProps` has no such attribute, so assistive technology learns the mode from
  the per-row `aria-selected` values, not from the listbox itself.
- **The active row's focus ring shows for a click too.** `@gpuix/native@0.10.0`
  has no `focusVisible`, so a keyboard-only ring cannot be declared; the ring is
  the runtime's honest maximum.
- Rows are reached as one list; Tab does not stop at every row.

## Limitations

- No drag reorder, no group headers, no nested rows.
- Type-ahead searches `textValue`, not the rendered `ListItemTitle`: the row is a
  composition, so the list cannot read its text. An omitted `textValue` makes the
  row unsearchable rather than guessing.
- No `aria-multiselectable` in 0.10.0 (see Accessibility).
- No virtualisation: a `List` renders every row. Long collections belong in
  `virtual-list`, which is a separate component with its own API.
- The rows are not accessible by index: the API is `value`-based.

## Verification

`src/behaviour/list.test.tsx` runs in the real GPUix renderer (29 tests) plus
`src/internal/collection.test.ts` for the navigation arithmetic,
`src/internal/typeahead.test.ts` for the shared prefix matching, and
`src/list/selection.test.ts` for the multiple-selection rules: the modes and
their roles, the absence and uniqueness of the tab stop, selection by click and by
key, a disabled row rejecting both, real focus moving with wrap-around past a
disabled row, `Home`/`End`, the accent hover on a real mouse move, the dense
height, the controlled list not moving its own selection, type-ahead jumping and
cycling while skipping disabled and unlabelled rows, and — in multiple mode —
plain/`Cmd`/`Shift` clicks, `Space` toggling, `Shift+Arrow` ranges, `Cmd`/`Ctrl`+A
selecting every enabled row, and a disabled row never entering a selection.

```sh
nub run --filter @gpuixui/components test:behaviour
```
