## Usage

```tsx
import {
  List,
  ListItem,
  ListItemDescription,
  ListItemTitle,
} from "@gpuixui/components/list";

<List selectionMode="single" defaultValue="readme">
  <ListItem value="readme" textValue="README.md">
    <ListItemTitle>README.md</ListItemTitle>
    <ListItemDescription>~/GPUIXUI</ListItemDescription>
  </ListItem>
  <ListItem value="list" textValue="list.tsx">
    <ListItemTitle>list.tsx</ListItemTitle>
  </ListItem>
</List>;
```

## Composition

    └── trailing

## Examples

### Multiple selection

```tsx
<List selectionMode="multiple" defaultValue={["a"]} onValueChange={log}>
  <ListItem value="a" textValue="Alpha">
    <ListItemTitle>Alpha</ListItemTitle>
  </ListItem>
  <ListItem value="b" textValue="Beta">
    <ListItemTitle>Beta</ListItemTitle>
  </ListItem>
</List>;
```

### Activation

```tsx
<List selectionMode="single" onActivate={(id) => openFile(id)}>
  <ListItem value="readme" textValue="README.md">
    <ListItemTitle>README.md</ListItemTitle>
  </ListItem>
</List>;
```

## Selection

A range press keeps the anchor; a plain or toggle press moves it
(`modifier-select-lifecycle` measured the chord).

The type-ahead rule is published at `@gpuixui/components/typeahead`.

## Hover

A row's pointer feedback is the runtime's **native `hover` refinement**, and its
hovered set is the same hit test the press takes — so a **filled child takes the
row's hover**. `hover-routing-lifecycle` (56 checks, 0.11.0) mounted one row per
child shape:

| Child at the pointer | Row `onMouseEnter` | Child `onMouseEnter` | Row paints `hover` |
| -------------------- | ------------------ | -------------------- | ------------------ |
| an unfilled `<text>` label | **1** | 1 | **yes** |
| a `<text>` label that paints a fill | **0** | 1 | **no** |
| a `<div>` that paints a fill | **0** | 1 | **no** |
| a filled `<div>` with `pointerEvents: "none"` | **1** | 1 | **yes** |

An unfilled label leaves the row both its enter event and its wash; a filled
one takes both. `pointerEvents: "none"` puts the row back in the pointer's path
while the child still hears its own listener, because opting out removes the
fill's hitbox rather than the handler — the shipped `Badge` declares it for this
reason. A row that wants feedback while the pointer is over a badge, a status
marker or a control therefore gives that child `pointerEvents: "none"` when it
is decorative, or the child owns a `hover` paint of its own when it is not.

## API

| `List` prop | Type | Default |
| ----------- | ---- | ------- |
| `selectionMode` | `"none" \| "single" \| "multiple"` | `"none"` |
| `value` / `defaultValue` | `string` (single) · `ReadonlyArray<string>` (multiple) | — |
| `onValueChange` | `(value) => void` | — |
| `onActivate` | `(value: string) => void` | — |
| `dense` | `boolean` | `false` |

| `ListItem` prop | Type | Default |
| --------------- | ---- | ------- |
| `value` | `string` (required) | — |
| `textValue` | `string` | — |
| `disabled` | `boolean` | `false` |
| `leading` | `ReactNode` | — |
| `trailing` | `ReactNode` | — |

| `ListItemTitle` prop | Type | Default |
| -------------------- | ---- | ------- |
| `className` | `string` | — |

| `ListItemDescription` prop | Type | Default |
| -------------------------- | ---- | ------- |
| `className` | `string` | — |

`ListItemTitle` and `ListItemDescription` are the row's two text slots — one
line each, clipped rather than wrapped — and they take the role the row's own
fill was measured with, so a selected row's title keeps its on-colour and its
description keeps the muted role the contract measures on that fill.

## Limitations

- No drag reorder, group headers or nested rows.
- No `aria-multiselectable`; the mode reads from per-row `aria-selected`.
- No virtualisation; a long list renders every row.
- `onActivate` needs a selection mode; `none` is click-only.
