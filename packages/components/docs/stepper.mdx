## Installation

```bash
nub add @gpuixui/components
```

## Usage

```tsx
import { Stepper, StepperStep } from "@gpuixui/components";

<Stepper value={2} label="Checkout">
  <StepperStep value={1} label="Account" description="Email and password" />
  <StepperStep value={2} label="Billing" description="Card and address" />
  <StepperStep value={3} label="Review" />
</Stepper>;
```

## Composition

```text
Stepper
└── StepperStep
```

## API

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Stepper` | `div` with `role="list"` | `value` (required), `orientation?` (default `"horizontal"`; a stored name that is neither axis reads as `"horizontal"`), `label?`, `className?`, `children` |
| `StepperStep` | `div` with `role="listitem"` | `value` (required), `label` (required; a blank one reads as the step's position, `Step 2`), `description?` (a blank one paints no line), `style?`, `className?` |

## Limitations

- Display-only: no step click, disabled policy or `onValueChange`.
- No connector line between steps.
- No `aria-current`; the current step uses `aria-selected`.
- **A blank step title is an absence**: a title read from an i18n table or a
  saved workflow that arrived empty names the step by its position (`Step 2`),
  so no list item is unnamed and no marker paints with a wordless label beside
  it. A blank or whitespace description paints no line. `MultiStepForm` states
  the same rule for the wizard's own content announcement.
- **A stored `orientation` the union does not carry paints the horizontal
  axis**: a workflow a record saved as `"column"` keeps a painted axis and its
  alignment instead of falling back to the runtime's own row.
