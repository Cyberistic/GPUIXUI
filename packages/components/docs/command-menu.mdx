## Usage

```tsx
import {
  CommandMenu,
  CommandMenuEmpty,
  CommandMenuInput,
  CommandMenuList,
} from "@gpuixui/components/command-menu";

<CommandMenu open={open} onOpenChange={setOpen} actions={actions}>
  <CommandMenuInput placeholder="Type a command…" />
  <CommandMenuList />
  <CommandMenuEmpty>No matching commands</CommandMenuEmpty>
</CommandMenu>;
```

## Composition

```text
CommandMenu
├── CommandMenuInput
├── CommandMenuList
│   └── CommandMenuItem
└── CommandMenuEmpty
```

## API

| Part | Renders | Props |
| ---- | ------- | ----- |
| `CommandMenu` | the composed `Dialog` surface | `open` (required), `onOpenChange` (required), `actions` (required), `recents?`, `filter?` |
| `CommandMenuInput` | host `<input>` | `placeholder?`, `label?`, `className?` |
| `CommandMenuList` | the scrolling match column | `className?` |
| `CommandMenuItem` | one runnable row | `action` (required), `className?` |
| `CommandMenuEmpty` | the no-match message | `children?`, `className?` |

## Limitations

- `open` is controlled; the app owns the shortcut that opens it.
- No `aria-activedescendant` or `aria-controls`; the highlight is visual.
- `shortcut` is display only; the component binds no keys.
- `actions` and `recents` read from a saved state are read at the boundary: an `actions` value that is not a list paints the empty state, a `recents` value that is not a list carries no recents, and an entry that is not an id is dropped.
- The palette leaves on the dialog's `slow` exit (320 ms, a fade and an 8px rise). The field it paints is the library's control, so it drops its own Tab stop for that window: pressing Escape and then Tab walks past the field instead of landing on one that is about to unmount. Rows are highlighted, not focused, so they were never stops; a control a caller composes into the palette keeps its stop until the runtime publishes an inherited `inert`.
