title: Command menu
description: A searchable action list in a dialog — the ⌘K palette.
---

`CommandMenu` puts a filterable list of actions in a modal surface. It composes
the parts instead of reinventing them: **Dialog** owns the surface and Escape,
the GPUix `<input>` owns typing, and `menu/logic.ts` owns which row is active.

```tsx
import {
  CommandMenu,
  CommandMenuEmpty,
  CommandMenuInput,
  CommandMenuList,
} from "@gpuixui/components/command-menu";

<CommandMenu open={open} onOpenChange={setOpen} actions={actions}>
  <CommandMenuInput placeholder="Type a command…" />
  <CommandMenuList />
  <CommandMenuEmpty>No matching commands</CommandMenuEmpty>
</CommandMenu>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `CommandMenu` | the dialog, the query and the ranked matches; `open` is controlled |
| `CommandMenuInput` | the search field: typing, arrows, Enter, Escape |
| `CommandMenuList` | the scrolling match column: group headings, rows and the key hint |
| `CommandMenuItem` | one runnable row; the list renders one per match |
| `CommandMenuEmpty` | shown only when nothing matches; its children are the message |

The root owns the query and the matches because ranking needs the whole action
set: `actions` stays a root prop, and the list renders the rows it derives.
`CommandMenuItem` is exported for a caller that composes its own list over the
same ranked matches.

Groups are rendered in the caller's order; a heading appears when `group` changes
between consecutive matches. `shortcut` is **display only** — the component binds
no keys.

## Focus and the highlight

The search input keeps focus the whole time and paints the token focus ring
(plan 523). The active row is **highlighted,
not focused**: focusing a row would take typing away from the input after the
first arrow key. That is why this palette does not reuse the menu registry, only
the pure `menu/logic.ts` arithmetic. The list scrolls the highlighted row into
view as it moves, so `Enter` never runs a row the user cannot see (plan 530).

Closing the palette — `Escape` or running a command — returns focus to the
control that held it before the palette opened, through the dialog's recorded
opener (plan 589).

| Key | Result |
| ---- | ------ |
| type | filters; the highlight resets to the first enabled match |
| `ArrowDown` / `ArrowUp` | move the highlight, wrapping and skipping disabled rows |
| `Enter` | runs the highlighted action and closes |
| `Escape` | closes |
| `Tab` | follows the dialog's trap |

`Enter` arrives as the input's `submit` event, not a key-down — measured in
0.10.0 — which is also why Space types a space instead of activating a row.

## Filtering

The default matcher is a case-insensitive **subsequence**: the query's characters
must appear in order in the label, not necessarily together. Initials work.

| Query | Matches |
| ----- | ------- |
| `opfl` | **Op**en **f**i**l**e — a non-contiguous match |
| `open` | `Open file` ranks above `Reopen file` — a word start beats a mid-word run |
| `of` | `Open file` ranks above `Proofread` — the `f` starts a word |

Scoring is deterministic: ten points per matched character, eight more when the
character starts a word, and two per character in the current consecutive run.
The palette then ranks **within each group** and keeps the caller's group order,
so a heading never repeats because a lower group happened to score higher.
Equal scores keep declaration order; an empty query shows every action in
declaration order.

Pass `filter` to replace all of it with a boolean predicate. A custom filter
receives the action and the raw query, and its accepted rows stay in declaration
order — no hidden fuzzy pass and no reordering. Disabled actions stay visible and
cannot be run by click or `Enter`; the initial highlight lands on the first
enabled match.

## Recent commands

Running an enabled command records it. With an empty query the recent commands
are shown first under `Recent`, in recency order, and each subsequent action
stays in declaration order. Typing a query ranks exactly as before — recents are
not pinned while searching.

```tsx
<CommandMenu
  open={open}
  onOpenChange={setOpen}
  actions={actions}
  recent={recent}
  onRecentChange={setRecent}
  recentLimit={5}
  recentLabel="Recently used"
/>
```

| Prop | Meaning |
| ---- | ------- |
| `recent` | Controlled ids, most recent first. |
| `defaultRecent` | Uncontrolled starting list. |
| `onRecentChange` | Called with the next list after a command runs. |
| `recentLimit` | Entries kept, default `5`, minimum `1`; a non-finite value keeps every entry. |
| `recentLabel` | The group heading, default `"Recent"`. |

Recording is front-inserted, deduplicated, and capped. Running the command
already at the front reports nothing. Disabled commands are never recorded.
Without `recent`, the list is component state for the lifetime of the mounted
palette; there is no renderer storage, so an app that needs recents across a
remount owns the prop (and persists it itself). An id that no longer exists in
`actions` is ignored when the list renders.

## Controlled only

`open` is required. A command palette is opened by an application shortcut
(⌘K, Ctrl+P) rather than by a control inside the component, so ownership of the
state belongs to the app. Render it once at the app root.

## API

`CommandAction` is `{ id: string; label: string; group?: string; shortcut?:
string; disabled?: boolean; perform: () => void }`. Every part merges `style`
last where it takes one.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `CommandMenu` | Dialog-hosted palette | `open: boolean` (required), `onOpenChange: (open: boolean) => void` (required), `actions: ReadonlyArray<CommandAction>` (required), `filter?: (action: CommandAction, query: string) => boolean`, `recent?: ReadonlyArray<string>`, `defaultRecent?: ReadonlyArray<string>`, `onRecentChange?: (recent: ReadonlyArray<string>) => void`, `recentLimit?: number` (default `5`), `recentLabel?: string` (default `"Recent"`) |
| `CommandMenuInput` | `input` | `placeholder?: string` (default `"Type a command…"`), `label?: string` (default `"Search commands"`) |
| `CommandMenuList` | `div` (`role="listbox"`) | `label?: string` (the match column's accessible name, default `"Commands"`), host props; the key hint belongs to the list |
| `CommandMenuItem` | `div` (`role="option"`) | `action: CommandAction` (required) |
| `CommandMenuEmpty` | `text` | `children?: ReactNode` (default `"No matching commands"`) |

## Theming

The surface is the dialog's: `colors.popover`, `radius.xl`, the `lg` elevation.
The input uses `colors.input` / `colors.inputForeground` with a
`borderWidth.thin` border in `colors.border` and `radius.md`. Rows are the shared
menu rows: `colors.hover` for the highlight with the 2px
`colors.popoverForeground` bar (the bar is an ink, not the `accent` wash).

## Accessibility and limitations

- The dialog is named `"Command menu"`; the input is `"Search commands"`; the
  match column is a `role="listbox"` named `Commands` (`label` renames it), each
  contiguous group is a `role="group"` named by its heading, and every row is
  named by its action label (0.10.0 never names an option from its contents —
  plan 783), with `aria-selected` for the highlight.
- **No `aria-activedescendant` or `aria-controls`** in 0.10.0: the relationship
  between the input and the highlighted row is visual only for assistive
  technology.
- The `<input>` is the GPUix host element. `@gpuixui/primitives` now ships its own
  `Input`, but primitives read a second theme context, so the stand-in is
  replaced when that provider and `@gpuixui/tokens/react` are one (`TODO.md` →
  Interlocks).
- Ranking is **per group**, not global: a group's heading stays where the caller
  declared it even when another group holds the best match. Recents are session
  state unless the app owns and persists `recent`; there is no per-query history.
- `Home` and `End` do not reach the palette while the GPUix `<input>` holds
  focus: the host consumes them and no key-down is emitted (measured in 0.10.0;
  the scroll offset does not change). The palette has no branch for them, so the
  arrows are the path to the first and last rows.
- The 320 px list scrolls with the highlight; a row that left the viewport is
  brought back on the next move (plan 530).

- Focus cues are seeded by `autoFocus` and then follow the renderer's focused
  host (a 50 ms sample while the part is enabled), so `Tab`, a programmatic focus
  and a press paint the ring and it clears when focus leaves; the seed stands
  only until a host is reported (plans 390/603/605, 755).

## Verification

`src/behaviour/command-menu.test.tsx` runs in the real GPUix renderer (29 tests):
focus landing on the input, the input's focus ring, closing returning focus to
the control that opened the palette, typing filtering the list while focus stays
put, ArrowDown + Enter running the second match and closing, a clicked row, the
empty label, a custom filter, a disabled action refusing to run, Escape closing,
a non-contiguous query matching initials, ranking deciding the default `Enter`
target, group order surviving ranking, an empty query keeping declaration order,
a caller-supplied empty state, the input's placeholder/name coming from the part,
a caller-composed row running its `onClick` before the action, every row named by
its label, the match column named and renamed by a caller `label`, each
contiguous group named and its six rows inside it, a highlighted row
staying inside the list viewport after 24 arrow presses and returning to the top
as the highlight moves back up, and recents: a run command shown first on reopen,
a non-finite `recentLimit` still recording the run, recency order without a
duplicate row, `defaultRecent`, normal ranking while a query is typed, and a
controlled list that reports without moving.

`src/command-menu/logic.test.ts` covers recording (front insert, dedupe, cap,
non-finite cap as no cap, head no-op) and the empty-query ordering (recent group,
declaration order, unknown ids dropped).

`src/menu/fuzzy.test.ts` (12 tests) covers empty and whitespace queries, case and
trim, word-start versus mid-word scores, separator boundaries, subsequence and
non-subsequence queries, over-long queries, repeated letters, declaration
indices, group order, in-group ranking, stable ties and empty groups.
