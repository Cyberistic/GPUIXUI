## Usage

```tsx
import { ConfirmDialog } from "@gpuixui/components/confirm-dialog";

<ConfirmDialog
  open={open}
  onOpenChange={setOpen}
  title="Archive this project?"
  description="The project leaves everyone's sidebar."
  confirmLabel="Archive project"
  tone="danger"
  loading={saving}
  onConfirm={archive}
/>;
```

## API

| Prop | Type | Default |
| ---- | ---- | ------- |
| `open` | `boolean` (required) | — |
| `onOpenChange` | `(open: boolean) => void` (required) | — |
| `title` | `string` (required) | — |
| `description` | `string` (required) | — |
| `confirmLabel` | `string` | `"Confirm"` (a blank label reads as the default) |
| `cancelLabel` | `string` | `"Cancel"` (a blank label reads as the default) |
| `tone` | `"default" \| "danger"` | `"default"` |
| `loading` | `boolean` | `false` |
| `onConfirm` | `() => void` (required) | — |
| `children` | `ReactNode` | — |

## Limitations

- Cancel holds the initial focus; Enter on an untouched dialog cancels.
- The surface carries `role="alertdialog"` (the runtime maps it to `Role::AlertDialog`), so it is announced as an interruptive dialog; it is named by `aria-label`, because 0.11.0 has no `aria-labelledby`.
- Confirm does not close; the caller runs the work and closes it.
- Controlled only; there is no uncontrolled mode.
- **A blank action label reads as its default**: `confirmLabel` and `cancelLabel`
  are copy from an i18n table or a saved record as often as literals, so an
  empty or whitespace-only one is an absence — the two actions are announced as
  "Confirm" and "Cancel", never as nameless buttons.
