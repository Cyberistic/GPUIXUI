title: Collapsible
description: One section that reveals its body on demand.
---

`Collapsible` is the smallest disclosure: a trigger with `aria-expanded` and a
body that grows to its measured height when opened. Compose it when an accordion
would be overkill — one advanced-options block, one "show details" row.

```tsx
import {
  Collapsible,
  CollapsibleContent,
  CollapsibleTrigger,
} from "@gpuixui/components/collapsible";

<Collapsible defaultOpen={false}>
  <CollapsibleTrigger>Advanced options</CollapsibleTrigger>
  <CollapsibleContent>
    <Option label="Retry budget" value="3 attempts" />
  </CollapsibleContent>
</Collapsible>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `Collapsible` | open state and the column that holds the parts |
| `CollapsibleTrigger` | a button with `aria-expanded`; click, Enter and Space toggle; `disabled` leaves the tab order and the section closed |
| `CollapsibleContent` | the measured-height body; **unmounts after its collapse** |

Unmounting is deliberate: a closed body holds no focus, no subscriptions and no
stale values. The cost is that closing loses local state inside the body. The
body stays painted for its 200 ms collapse, then leaves; it re-measures if its
content grows while it is open.

## Controlled and uncontrolled

```tsx
<Collapsible defaultOpen>…</Collapsible>;                        // remembers
<Collapsible open={open} onOpenChange={setOpen}>…</Collapsible>; // app remembers
```

In controlled mode the trigger reports `onOpenChange` and leaves the body where
the consumer put it.

## API

Every part takes the GPUix host props and merges `style` last.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Collapsible` | `div` column | `open?: boolean`, `defaultOpen?: boolean` (default `false`), `onOpenChange?: (open: boolean) => void` |
| `CollapsibleTrigger` | `div role="button"` with `aria-expanded` | `disabled?: boolean`, `style?: StateStyle<CollapsibleTriggerState>` |
| `CollapsibleContent` | `div`, mounted only while open | `children: ReactNode` |

## Theming

The trigger paints the fixed 14/20 `text-sm` step at weight 500,
`colors.foreground`, `colors.hover` on hover, and a **derived** press wash while
`active` is down: `pointerWash(theme, "active", "hover")` takes the smallest move
toward `foreground` that clears the 1.05:1 perceptibility floor against the wash
it replaces, because Light · macOS's raw `active` sat 1.037:1 from its `hover` —
a header that answered the pointer and then went still. A palette that already
answers is painted as authored. The outline is the keyboard-only one (the
runtime's `focusVisible`, so a press shows no ring). The body
uses `colors.mutedForeground` and the theme's spacing steps; there is no surface
of its own, so it inherits the card or panel around it.

## Style by state

`CollapsibleTrigger` takes a `StyleDesc` or a function of
`CollapsibleTriggerState` (`{ open, closed, focused, disabled }`).

`focused` reaches a press, a click and a programmatic focus — but not a `Tab`
traversal: the runtime focuses the element without running its `onFocus` on
0.11.0 (`tabs-lifecycle` reads `focuses=0`; `tooltip-lifecycle` does not open its
tip, re-measured 2026-10-22). The ring declared at rest is still the keyboard
cue: the flag is presentational, and nothing here depends on the event
(`docs/component-api.md` §3).

```tsx
<CollapsibleTrigger
  style={(state) => ({ opacity: state.closed ? 0.8 : 1 })}
/>
```

## Accessibility and limitations

- `aria-expanded` on the trigger, and real button semantics (Tab reaches it,
  Enter/Space activate it).
- **The first open grows from zero.** The body's height is its own `onLayout`
  measurement, because the runtime can tween a number but not `auto`; the first
  frame paints the clipping box at 0 and retargets as soon as the measurement
  arrives. [Auto height](/docs/components/auto-height) is the primitive, and an
  accordion uses the same rule for its stacked sections.
- The collapse unmounts the body, so state inside it does not survive a close;
  keep the state outside the disclosure when it must.
- No `aria-controls` in 0.11.0 (`HostProps`), so the trigger→body relationship
  is positional.
- A `disabled` trigger leaves the tab order, dims, drops its hover and press
  styles, and refuses the click, Enter and Space paths — so a section cannot be
  opened from a control that reads as unavailable.

## Verification

`src/behaviour/collapsible.test.tsx` runs in the real GPUix renderer (6 tests):
a click opens the body and a second click leaves it painted for its collapse
before it unmounts, `aria-expanded` following the body, Enter/Space activation
on the focused trigger, the disabled trigger staying out of the tab order and
closed on every path, the controlled contract in both directions, and the press
wash derived against the hover it replaces (rendered in Light · macOS, where the
raw role sits under the perceptibility floor).

```sh
nub run --filter @gpuixui/components test:behaviour
```
