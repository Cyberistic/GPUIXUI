title: Collapsible
description: One section that reveals its body on demand.
---

`Collapsible` is the smallest disclosure: a trigger with `aria-expanded` and a
body that is kept mounted while its height reveals from a measurement. Compose it
when an accordion would be overkill — one advanced-options block, one "show
details" row.

```tsx
import {
  Collapsible,
  CollapsibleContent,
  CollapsibleTrigger,
} from "@gpuixui/components/collapsible";

<Collapsible defaultOpen={false}>
  <CollapsibleTrigger>Advanced options</CollapsibleTrigger>
  <CollapsibleContent>
    <Option label="Retry budget" value="3 attempts" />
  </CollapsibleContent>
</Collapsible>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `Collapsible` | open state and the column that holds the parts |
| `CollapsibleTrigger` | a button with `aria-expanded`; click, Enter on press and Space on release toggle |
| `CollapsibleContent` | the body; stays mounted and reveals its measured height |

The body is not unmounted while closed. That keeps the state inside it — a
draft, a scroll position, a running sub-view — but the content is hidden with
`visibility: hidden`, so it leaves the tab order and the accessible tree. The
clip alone is not enough: the runtime refuses the pointer but leaves a clipped
subtree in the keyboard order (measured in plan 372).

The height is measured from the content's own bounds after commit. GPUix 0.10.0
has no layout callback, so the first measurement happens while the body is
already collapsed, the value is kept in state, and later opens use it. The one
remaining gap is a rewrap while closed: the stored height is re-measured on the
next open, not on a width change.

`animate={false}` snaps the height instead of tweening it.

## Controlled and uncontrolled

```tsx
<Collapsible defaultOpen>…</Collapsible>;                        // remembers
<Collapsible open={open} onOpenChange={setOpen}>…</Collapsible>; // app remembers
```

In controlled mode the trigger reports `onOpenChange` and leaves the body where
the consumer put it.

## Keyboard

Tab reaches the trigger, and the open body's own controls follow it in the tab
order. A closed body is skipped: hiding it removes the whole subtree from the
keyboard order. `Enter` toggles on press; `Space` toggles on release, so moving
focus before letting go cancels the change. A held key does not toggle twice.

## API

`style` merges last where the part takes one. The root owns state only.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Collapsible` | `div` | `open?: boolean`, `defaultOpen?: boolean` (default `false`), `onOpenChange?: (open: boolean) => void` |
| `CollapsibleTrigger` | `div` (`role="button"`, `aria-expanded`) | `style?: StateStyle<{ open: boolean; closed: boolean; focused: boolean }>` |
| `CollapsibleContent` | `div` (inside the reveal) | `animate?: boolean` (default `true`) |

`autoFocus` sets the initial `focused` state, so the trigger's ring is painted
on the first commit — the runtime applies native focus after React's effects and
never dispatches `onFocus`.

## Theming

The trigger uses the `label` type role, `colors.foreground`, `colors.hover` on
hover and `colors.active` while pressed, with a focus ring on focus. The body
uses `colors.mutedForeground` and the theme's spacing steps; there is no surface
of its own, so it inherits the card or panel around it.

## Style by state

`CollapsibleTrigger` takes a `StyleDesc` or a function of
`CollapsibleTriggerState` (`{ open, closed, focused }`).

```tsx
<CollapsibleTrigger
  style={(state) => ({ opacity: state.closed ? 0.8 : 1 })}
/>
```

## Accessibility and limitations

- `aria-expanded` on the trigger, and real button semantics (Tab reaches it,
  Enter/Space activate it).
- The body is hidden rather than unmounted: its state survives, and hidden
  content leaves the tab order. During the 200 ms close it is still visible and
  reachable, then it leaves.
- The natural height is re-measured on open, not on a width change, so a rewrap
  while collapsed can correct once on the next open.
- Closing with focus inside the body (for example a controlled close from
  elsewhere) leaves focus on the hidden element: 0.10.0 has no focus-within event
  or `inert`, so the component cannot tell a programmatic close from one where
  focus is already on the trigger. A consumer that closes a section while its
  body owns focus should move focus itself.
- No `aria-controls` in 0.10.0 (`HostProps`), so the trigger→body relationship
  is positional.

## Verification

`src/behaviour/collapsible.test.tsx` runs in the real GPUix renderer (11 tests):
click toggling with the body kept mounted, `aria-expanded` following the body,
Enter on press and Space on release, the controlled contract in both directions,
the closed and open tab order, state surviving a close and a re-open, and the
measured-height tween (plus the `animate={false}` snap).

```sh
nub run --filter @gpuixui/components test:behaviour
```
