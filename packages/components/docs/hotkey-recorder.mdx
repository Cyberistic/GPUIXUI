---
title: Hotkey recorder
description: Capture a keyboard chord and display it as platform keycaps.
---

`HotkeyRecorder` binds a shortcut: click it (or press `Enter`/`Space`), press a
chord, and the component reports it as an accelerator string. Display uses the
same grammar and the same platform glyphs as
[Keyboard shortcuts](/docs/components/keyboard-shortcuts), so a bound chord and a cheat
sheet can never disagree.

## Usage

```tsx
import { HotkeyRecorder } from "@gpuixui/components";

const [hotkey, setHotkey] = useState<string | null>("mod+k");

<HotkeyRecorder
  label="Toggle command palette"
  value={hotkey}
  onChange={setHotkey}
/>;
```

The runnable build is `examples/hotkey-recorder.example.tsx`, which the native
playground mounts.

## Recording contract

| Action | Result |
| ------ | ------ |
| Click, `Enter` or `Space` while idle | starts listening ("Press keys…") |
| Click on the displayed chord | starts listening: the keycaps are out of the pointer, so the press belongs to the box |
| A key with a modifier | captures and reports the chord, stops listening |
| A modifier-only press (`Shift`, `Cmd`…) | ignored; still listening |
| `Escape` while listening | cancels and keeps the bound value |
| Focus leaves | cancels; a half-finished chord is never committed |
| The clear control | clears the binding (`null`) |
| `disabled` | out of the tab order, inert, no clear control |

Captured order is canonical: `mod`, then the secondary modifier (`ctrl` on macOS,
`cmd` elsewhere), then `alt`, then `shift`, then the key. `mod` is the platform's
primary modifier: Command on macOS, Control elsewhere. A **Control** press on
macOS keeps `ctrl` rather than being silently rewritten to `mod`.

## API

| Prop | Type | Default | Notes |
| ---- | ---- | ------- | ----- |
| `label` | `string` | — | The recorder's accessible name. |
| `value` | `string \| null` | `null` | The bound accelerator. |
| `onChange` | `(value: string \| null) => void` | — | A captured chord, or `null` on clear. |
| `placeholder` | `string` | `"Click to record"` | Shown while unbound. |
| `disabled` | `boolean` | `false` | Leaves the tab order and ignores activation. |
| `style` | `StateStyle<HotkeyRecorderState>` | — | `{ recording, disabled }`. |

`HotkeyRecorder` takes the GPUix host props (`testId`, `aria-*`) and merges
`style` last. When `testId` is given, the clear control is
`${testId}-clear`. It paints a 24px square — the pressable-target floor, with a
16px glyph inside — so a dense toolbar cannot shrink the press box under the
floor.

## Theming

The field uses `background`, `border`, the registry's fixed 6px corner
(`rounded-md`, ADR 0006), `controlHeight(theme, "md")` and `focusRing(theme)`;
the clear control takes the smaller fixed 4px step (`rounded-sm`); keycaps use
the shared [`Keycap`](/docs/components/keyboard-shortcuts)
roles; the clear control shows an `accent` hover. A custom theme changes it with
no code change — see [Theming](/docs/theming).

## Accessibility

- The recorder is a `role="button"` named by `label`; the clear control is a
  separately named button, so both are reachable by keyboard.
- Recording is visual ("Press keys…") and the field keeps focus while listening.
- There is no `aria-keyshortcuts` and no `aria-disabled` in `0.11.0`; disabled is
  the tab order plus dimming.

## Limitations

- **A recorded key is swallowed.** While listening the recorder calls
  `preventDefault()`, so a captured chord does not also run the application's own
  binding: `Tab` is recorded and focus stays on the recorder. A shortcut the
  operating system intercepts before the window still fires.
- **Clearing is a control, not `Backspace`.** The test renderer emits no key
  event for Backspace/Delete, so that gesture is not promised.
- No conflict detection against already-bound chords.
- The recorder stores a string; registering the chord with the runtime is the
  application's job.

## Verification

The capture rules and the chord grammar live in `@gpuixui/keyboard`
(`decodeGpuixEvent`, `normalizeHotkey`, `hasNonModifierKey`, `formatSymbols`);
its unit suite covers platform `mod`, a secondary modifier, modifier-only
presses, Enter/Space normalisation, and the physical-vs-produced key decode.
`src/behaviour/hotkey-recorder.test.tsx` (9 native tests) covers the display,
click-to-record, a real captured chord, a captured key's default being swallowed,
Escape, the clear control, blur, disabled, and both themes.

```sh
nub run --filter @gpuixui/components test
nub run --filter @gpuixui/components test:behaviour
```
