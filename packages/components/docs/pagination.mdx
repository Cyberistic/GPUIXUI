---
title: Pagination
description: Previous/next controls around a stable-width page window.
---

`Pagination` is controlled: the app owns the page, the control renders the
window the app's page implies. The arithmetic lives in `pagination/logic.ts` so
the width does not jump as the user pages.

```tsx
import {
  Pagination,
  PaginationList,
  PaginationNext,
  PaginationPrevious,
} from "@gpuixui/components/pagination";

const [page, setPage] = useState(1);

<Pagination page={page} pageCount={9} onPageChange={setPage}>
  <PaginationPrevious />
  <PaginationList />
  <PaginationNext />
</Pagination>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `Pagination` | the `role="navigation"` root, its name, the clamped page and the window |
| `PaginationPrevious` | the "Prev" control with a leading chevron; leaves the tab order on the first page |
| `PaginationList` | the page window: page buttons and the ellipses for gaps |
| `PaginationItem` | one page number; the current page is primary and non-pressable |
| `PaginationNext` | the "Next" control with a trailing chevron; leaves the tab order on the last page |
| `PaginationEllipsis` | the non-focusable `…` that stands in for omitted pages |

The root derives the window once, so a caller never re-implements the stable-width
rule. The parts are still composable: add a `PaginationItem` beside the list for a
"jump to page" shortcut, or put your page-size control between the numbered
window and `PaginationNext`.


## Window rule

| Input | Result |
| ----- | ------ |
| `pageCount <= 0` | nothing rendered |
| a list that fits the maximum window (`2 * siblingCount + 5` or fewer pages) | every page |
| page 1 of 10 | `1 2 3 4 5 … 10` |
| page 4 of 8 | `1 2 3 4 5 … 8` |
| page 5 of 10 | `1 … 4 5 6 … 10` |
| page 10 of 10 | `1 … 6 7 8 9 10` |

`siblingCount` widens the window around the current page (default 1).
`showEdges={false}` drops the first and last page and renders only the siblings.
An out-of-range `page` is clamped; an ellipsis always stands for two or more
pages, while a gap of one renders the page itself.

Both numbers are **whole**: `page` is truncated before it is clamped and
`pageCount` is truncated, so `page={1.9}` of `pageCount={5.9}` is page `1` of
`5`, not a window with no current page and a `6` that does not exist. A
non-finite `pageCount` renders nothing rather than an unbounded list. A
non-finite `siblingCount` is **no cap**: the whole list renders, so a malformed
bound never hides the current page.

## Layout and states

The root lays the parts out in a row. The current page is a button with
`aria-selected` and the primary fill; pressing it does nothing. Previous and Next
leave the tab order at the ends instead of merely looking disabled, and a caller
`disabled` can only add to that rule: passing `disabled={false}` at an edge does
not make the control pressable, and neither control reports a page outside
`1…pageCount`.

## Keyboard

Tab moves through the enabled buttons only. Enter and Space activate the focused
button, through the shared button primitive.

## API

Every part takes the GPUix host props and **merges `style` last**.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Pagination` | `div` (`role="navigation"`, `aria-label="Pagination"`) | `page: number` (required), `pageCount: number` (required), `onPageChange: (page: number) => void` (required), `siblingCount?: number` (default `1`), `showEdges?: boolean` (default `true`) |
| `PaginationPrevious` | `div` (`role="button"`, `aria-label="Previous page"`) | host props; disabled on the first page (or by `disabled`) |
| `PaginationList` | `div` | host props |
| `PaginationItem` | `div` (`role="button"`) | `page: number` (required), `style?: StateStyle<{ active: boolean }>` |
| `PaginationNext` | `div` (`role="button"`, `aria-label="Next page"`) | host props; disabled on the last page (or by `disabled`) |
| `PaginationEllipsis` | `text` (`aria-label="More pages"`) | host props |

## Theming

Page buttons are `controlHeight(theme, "sm")` square, `radius.sm`; the current
page paints `colors.primary` with `colors.primaryForeground`, others are ghost
buttons with `colors.mutedForeground`. The ellipsis uses `colors.mutedForeground`
and a caption type role.

## Style by state

`PaginationItem.style` takes a `StyleDesc` or a function of
`PaginationItemState` (`{ active }`), where `active` is the current page.

```tsx
<PaginationItem
  page={3}
  style={(state) => ({ opacity: state.active ? 1 : 0.8 })}
/>
```

## Accessibility and limitations

Disabled controls announce **Disabled** through `aria-description`; 0.10.0 has no
`aria-disabled` semantics (plan 516).

- `role="navigation"` and a name on the root; `aria-label="Page N"` on every page
  button; `aria-label="More pages"` on each ellipsis.
- **No `aria-current="page"`** in 0.10.0 (`HostProps`): the current page carries
  the supported `aria-selected` instead, plus the primary fill.
- The control is controlled-only by design: the result set and the page usually
  live together, and a second uncontrolled copy would drift.
- No page-size selector; put one beside the control when needed.

- Focus cues are seeded by `autoFocus`; the runtime does not reliably deliver
  React `focus`/`blur`, so a ring may not paint when focus moves by code
  (plans 390/603/605).

## Verification

`src/behaviour/pagination.test.tsx` runs in the real GPUix renderer (18 tests):
disabled edges (including a caller `disabled={false}` that cannot re-enable
them), the page number (not index) reported, the current page no-op,
Previous/Next stepping, a fractional page and page count normalised to whole
numbers and stopped at the real last page, a non-finite `siblingCount` rendering
every page, the ellipsis not being a tab stop, a
single hidden page being rendered instead of an ellipsis, Enter activation,
`pageCount: 0`, the current fill in both themes, the composed part order, an
item outside the list reading the root's page, and a caller `onClick` composing
with each page change (including a click on the current page, which reports the
caller and changes nothing).

`src/pagination/logic.test.ts` covers the window table above, including clamping,
truncation of fractional and non-finite inputs, wide siblings, unique ascending
pages, and the invariant that every ellipsis stands for at least two pages.

```sh
nub run --filter @gpuixui/components test:behaviour
```
