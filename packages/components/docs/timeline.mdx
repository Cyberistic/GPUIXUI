---
title: Timeline
description: A read-only rail of events with an explicit status.
---

`Timeline` shows a history: one event per row, a dot on a vertical rail, an
optional timestamp and description. It is display-only — there is no click, no
selection and no "current index". The consumer that knows the events marks their
status.

## Anatomy

```
09:41  ●  Build started
       │
09:44  ●  Tests passed
       │    412 tests, 0 failures
       │
09:52  ●  Deploying to production      ← current
       │
   —   ●  Smoke checks                 ← no connector after the last event
```

`Timeline` is the list; every row is a `TimelineItem`. The root tells each item
whether it is last, which is where the rail stops.

## Usage

```tsx
import { Timeline, TimelineItem } from "@gpuixui/components";

<Timeline label="Release 2.4.0">
  <TimelineItem title="Build started" timestamp="09:41" status="complete" />
  <TimelineItem
    title="Tests passed"
    description="412 tests, 0 failures"
    timestamp="09:44"
  />
  <TimelineItem title="Deploying" timestamp="09:52" status="current" />
  <TimelineItem title="Smoke checks" status="upcoming" />
</Timeline>;
```

The runnable build is `examples/timeline.example.tsx`, registered in
`examples/index.ts` and mounted by the package's native example suite
(`src/behaviour/examples.test.tsx`).

## Statuses

| `status` | Dot fill | Title |
| -------- | -------- | ----- |
| `complete` (default) | `foreground` | `foreground` |
| `current` | `primary` | `foreground` |
| `upcoming` | `mutedForeground` | `mutedForeground` |

`status` is **passed**, not derived: a timeline has no index to count from. The
current event also carries `aria-selected` because `@gpuix/native@0.10.0` has no
`aria-current`.

`TimelineItemState` is `{ status, last }`, so a style callback can react to
either:

```tsx
<TimelineItem
  title="Deploying"
  status="current"
  style={(state) => ({ opacity: state.last ? 1 : 0.6 })}
/>
```

## API

Every part takes the GPUix host props (`style`, `testId`, `role`, `aria-*`) and
merges `style` last.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Timeline` | `div` with `role="list"` | `label?`, `children` |
| `TimelineItem` | `div` with `role="listitem"` | `title` (required), `description?`, `timestamp?`, `status?`, `style?: StateStyle<TimelineItemState>` |

## Theming

Dots use `foreground`, `primary` and `mutedForeground`; `muted` is a wash and
measures about 1.1:1 on the canvas, so an upcoming event would have no dot. The
connector is a 1px `border`-coloured element (the runtime has no
pseudo-elements); timestamps and descriptions use `mutedForeground`; spacing
comes from the theme's scale. A custom theme changes the rail with no code
change — see [Theming](/docs/theming).

## Accessibility

- The root is a named `list` when `label` is given; every event is a `listitem`
  named by its `title`, so the timestamp and description are not repeated in the
  accessible name.
- Every event announces its state through `aria-description`: **Complete**,
  **Current** or **Upcoming**. A description you author on the item is kept and
  the status is appended after it (`Runs after approval. Upcoming`).
- The current event also carries `aria-selected` (no `aria-current` in 0.10.0).
- The dot is decorative; the three states reach assistive technology through the
  description, so colour is never the only signal.

## Limitations

- **Display-only:** no click, no row activation, no disabled policy.
- **`last` comes from direct children.** Wrap events in a fragment and the whole
  fragment is one child, so every event in it would be treated as last; pass
  items directly.
- No connector styles beyond the single `border`-coloured line.
- No `aria-current`; the current event carries `aria-selected` instead, and all
  three states are described through `aria-description`.
- No grouping or collapsing of old events in v1.

## Verification

`src/behaviour/timeline.test.tsx` runs in the real GPUix renderer (8 tests):
declaration order, list/listitem roles, exactly one selected current event, the
three status descriptions, a caller description joined with the status, the
three dot fills, a connector after every event but the last, and a style callback
receiving `{ status, last }` in both themes.

```sh
nub run --filter @gpuixui/components test:behaviour
```

It needs a host with a GPUix native binding — macOS arm64, Linux x64, Windows
x64, or this Intel Mac, where plan 140's locally built `darwin-x64` binding is
installed.
