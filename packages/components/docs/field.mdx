## Usage

```tsx
import { Field, FieldInput } from "@gpuixui/components/field";

<Field
  label="Workspace URL"
  description="Lowercase words joined by hyphens."
  error={error}
  required
>
  <FieldInput value={slug} onChange={(event) => setSlug(event.value ?? "")} />
</Field>;
```

## Composition

```text
Field
├── FieldLabel

├── FieldError

```

## Examples

### Validation

```tsx
import { validate } from "@gpuixui/components/validation/logic";

const Slug = Schema.NonEmptyString.check(
  Schema.isPattern(/^[a-z0-9]+(-[a-z0-9]+)*$/, {
    identifier: "WorkspaceSlugPattern",
    message: "Use lowercase letters, numbers and single hyphens",
  }),
);

const message = Effect.runSync(validate(Slug)(value));
```

## Undo, and the value you push back

The `<input>` keeps its own undo history, and it recognises the values it
reported: a controlled field that writes back exactly what `onChange` gave it
keeps `cmd-z`. A value the field did not produce — a normalised, masked or
truncated rewrite — arrives as an outside set and **clears both stacks**, so the
history is gone from the second keystroke while `cmd-z` still looks like it
works. **Format on commit, or derive the display**, rather than writing a
rewritten value back while the reader types. A re-render that leaves the value
unchanged is safe, and the chord stays in the field: an app-level undo handler
beside it never sees `cmd-z` while the field has focus.

`FieldInput` renders that host. Measured by `text-undo-lifecycle` (15 checks,
0.11.0): the field restores its snapshot through `onChange`, a pushed value
clears the history, and an unrelated re-render keeps it. Fixture
`apps/playground/src/live/text-undo.ts`.

## API

| ---- | ---- | ---- | ------- |

| `FieldError` | `children` | `ReactNode` | — |

| `FieldInput` | `disabled` | `boolean` | `false` |
| `FieldInput` | `style` | `StateStyle<FieldInputState>` | recipe |

## Limitations

- The error replaces the description rather than stacking under it.
- A `Tab` traversal focuses the input without running its `onFocus`.
- No `aria-describedby`, `aria-invalid` or `aria-required`.
- Not a form library; no value, submit or cross-field rules.
