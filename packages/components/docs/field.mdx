`Field` is the structure around one control: label, input, and one message slot.
`validation/logic.ts` turns a `Schema` into a user-facing message; the caller
decides **when** to run it. There is no auto-validate on every keystroke and no
form library.

```tsx
import { Field, FieldInput } from "@gpuixui/components/field";
import { validate } from "@gpuixui/components/validation/logic";

<Field
  label="Workspace URL"
  description="Lowercase words joined by hyphens."
  error={error}
  required
>
  <FieldInput value={slug} onChange={(event) => setSlug(event.value ?? "")} />
</Field>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `Field` | the column, the label row, the control slot, one message slot |
| `FieldLabel` | the visible label and the `*` marker |
| `FieldDescription` | supporting copy, shown when there is no error |
| `FieldError` | `role="alert"`, destructive text, replaces the description |
| `FieldInput` | a single-line input that knows its field's state |

The error **replaces** the description rather than stacking under it: one
message at a time is what a form row can show without shifting the layout twice.

## Validation

```ts
const Slug = Schema.NonEmptyString.check(
  Schema.isPattern(/^[a-z0-9]+(-[a-z0-9]+)*$/, {
    identifier: "WorkspaceSlugPattern",
    title: "Workspace Slug",
    message: "Use lowercase letters, numbers and single hyphens",
  }),
);

const message: Option.Option<string> = Effect.runSync(validate(Slug)(value));
```

- `validate(schema)` returns the **first** message, or `None` when the value is
  valid.
- `validateAll(schema)` returns every distinct message in issue order (it decodes
  with `errors: "all"`; `validate` uses the runtime default, so the two can
  disagree on purpose).
- Message text is always `SchemaIssue.makeFormatterDefault()`'s, so a check's own
  `message` annotation reaches the user verbatim and a raw issue never does. The
  field's JSON pointer is dropped — the row already says which field it is.

Running the Effect is an **application boundary** decision: a click handler can
`Effect.runSync` it, a larger app can compose it. The component itself is pure
presentation.

## Required

`required` appends a destructive `*` and appends `Required` to the control's
`aria-description`, so the accessible name stays `"Workspace URL"` and the
requirement is still announced. The marker itself carries `aria-label="Required"`.

## Theming

Labels use the `label` type role in `colors.foreground`; descriptions the
`caption` role in `colors.mutedForeground`; errors the `caption` role in
`colors.destructive`. The input paints `colors.input` / `colors.inputForeground`,
a `borderWidth.thin` border in `colors.border`, `radius.md`, and swaps the border
to `colors.destructive` when invalid. A neutral focused input takes the focus
ring; an invalid one keeps the destructive border instead.

## Style by state

`FieldInput.style` takes a `StyleDesc` or a function of `FieldInputState`
(`{ disabled, focused, invalid }`).

```tsx
<FieldInput
  style={(state) => ({ opacity: state.disabled ? 0.5 : 1 })}
/>
```

## Accessibility and limitations

- The input's accessible name is the field's label; the message is passed as
  `aria-description`.
- **No `aria-describedby`, `aria-invalid` or `aria-required`** in
  `@gpuix/native@0.10.0`: the association is a description, and the validity is
  carried by colour and the alert message. This is a real limitation for screen
  readers, not a styling choice.
- The control is the GPUix `<input>` host element until `@gpuixui/primitives`
  lands; `FieldInput` is the stand-in.
- `Field` is not a form library: it owns no value, no submit, no cross-field
  rules and no async validation.

## Verification

`src/behaviour/field.test.tsx` runs in the real GPUix renderer (6 tests): label,
description and control rendering; the error replacing the description with
`role="alert"`; the required marker and clean accessible name; the destructive
border in both themes; typed text reaching `onChange`; and the disabled input
leaving the tab order and accepting no typing.

`src/validation/logic.test.ts` covers the message walk, `errors: "all"`,
deduplication and the valid case.

```sh
nub run --filter @gpuixui/components test:behaviour
```
