---
title: Accordion
description: Stacked sections where one — or several — can be open.
---

`Accordion` is a list of collapsible sections that agree on which ones are open.
The two modes have genuinely different state: a single optional value, or an
ordered set. That is modelled as a tagged union in `accordion/logic.ts`, not as a
list plus a boolean.

```tsx
import {
  Accordion,
  AccordionContent,
  AccordionItem,
  AccordionTrigger,
} from "@gpuixui/components/accordion";

<Accordion type="single" collapsible={false} defaultValue="what">
  <AccordionItem value="what">
    <AccordionTrigger>What is GPUix?</AccordionTrigger>
    <AccordionContent>A native rendering runtime…</AccordionContent>
  </AccordionItem>
</Accordion>;
```

## Anatomy

| Part | Responsibility |
| ---- | -------------- |
| `Accordion` | the open state, the mode rules, the divider order |
| `AccordionItem` | one section, its value and its disabled flag |
| `AccordionTrigger` | a full-width button with `aria-expanded` and a chevron |
| `AccordionContent` | the body; stays mounted and reveals its measured height |

A closed body is hidden with `visibility: hidden`, not unmounted, so its state
survives a switch between sections and it leaves the tab order and the
accessible tree. Hiding by the `overflow` clip alone was not enough: the runtime
refuses the pointer but keeps a clipped subtree in the keyboard order (plan
372). The height is measured from the content's own bounds after commit, and
`animate={false}` snaps instead of tweening.

## The two modes

| Mode | Rules |
| ---- | ----- |
| `type="single"` | opening another section closes the first; toggling the open one is a no-op unless `collapsible` |
| `type="single" collapsible` | toggling the open section closes it, leaving nothing open |
| `type="multiple"` | toggling adds or removes; the order sections were opened in is preserved and duplicates are impossible |

Disabled items are skipped by clicks and keys, and their trigger leaves the tab
order.

## Controlled and uncontrolled

```tsx
<Accordion type="multiple" defaultValue={["one"]}>…</Accordion>;

<Accordion
  type="single"
  collapsible
  value={openSection}                 // `null` means "nothing open"
  onValueChange={setOpenSection}
>
  …
</Accordion>;
```

Single mode reports `string | null` — `null` is how a controlled, collapsible
accordion expresses "closed". `undefined` is reserved for "uncontrolled", which
is why it is not used for the closed state. Multiple mode reports the array.

## Keyboard

The trigger is a button: Tab reaches it, Enter and Space toggle it. A closed
body is skipped by Tab; an open body's own controls follow its header.

| Key | Effect |
| --- | ------ |
| `Enter` | toggle the focused section on press |
| `Space` | toggle the focused section on release |
| `↓` / `↑` | focus the next/previous enabled header, wrapping |
| `Home` / `End` | focus the first/last enabled header |

Arrow movement changes focus only — it never opens or closes a section. Disabled
headers are skipped, and a control inside an open section keeps its own arrow
keys because the handler lives on the trigger, not the accordion root.

## API

Every part takes the GPUix host props (`style`, `testId`, `role`, `aria-*`,
pointer and key handlers) and **merges `style` last**.

| Part | Renders | Props |
| ---- | ------- | ----- |
| `Accordion` | `div` | one of two shapes. Single: `type: "single"`, `collapsible?: boolean` (default `false`), `value?: string \| null`, `defaultValue?: string`, `onValueChange?: (value: string \| null) => void`. Multiple: `type: "multiple"`, `value?: ReadonlyArray<string>`, `defaultValue?: ReadonlyArray<string>`, `onValueChange?: (value: ReadonlyArray<string>) => void` |
| `AccordionItem` | `div` | `value: string` (required), `disabled?: boolean` (default `false`) |
| `AccordionTrigger` | `div` (`role="button"`) | `style?: StateStyle<{ open: boolean; disabled: boolean; focused: boolean }>` |
| `AccordionContent` | `div` | `animate?: boolean` (default `true`) |

`autoFocus` sets the initial `focused` state, so the header's ring is painted on
the first commit — the runtime applies native focus after React's effects and
never dispatches `onFocus`.

## Theming

Triggers use the `label` type role at `controlHeight(theme, "lg")`, with
`colors.foreground` and `colors.primary` on hover. Sections are separated by a
`borderWidth.thin` divider in `colors.border`; the last section draws none. The
indicator is a `chevron-down` / `chevron-up` icon because 0.10.0's `StyleDesc`
has no `transform` — a rotation is not available.

## Style by state

`AccordionTrigger` takes a `StyleDesc` or a function of `AccordionTriggerState`
(`{ open, disabled, focused }`).

```tsx
<AccordionTrigger
  style={(state) => ({ opacity: state.open ? 1 : 0.8 })}
/>
```

## Accessibility and limitations

- `aria-expanded` on each trigger; the trigger names the section.
- **No `aria-controls`** in 0.10.0; the relationship is positional.
- The indicator is decorative: `aria-expanded` on the trigger carries the state.
- Arrow keys move focus between enabled headers; they do not activate them.
- A closed body stays mounted and is hidden, so its state survives a section
  switch and its controls leave the tab order.
- The measured natural height is re-measured on open, not on a width change, so a
  rewrap while collapsed can correct once on the next open.
- Closing a section with focus inside its body (for example a controlled close
  from elsewhere) leaves focus on the hidden element: 0.10.0 has no focus-within
  event or `inert`, so the component cannot tell that case apart from a close
  where focus is already on the header. A consumer that closes a section while
  its body owns focus should move focus itself.

## Verification

`src/behaviour/accordion.test.tsx` runs in the real GPUix renderer (20 tests):
single mode closing the previous section, the non-collapsible no-op, the
collapsible close, multiple mode keeping sections, the disabled section, Enter
activation, Space on release, a held Enter toggling only once, the controlled
contract including the `null` close, arrow / `Home` / `End` movement between
headers (wrapping past a disabled one, without opening it), a caller header
`ref`, the closed/open tab order, state surviving a switch, and the
measured-height tween (plus the `animate={false}` snap).

`src/accordion/logic.test.ts` covers the transition table (15 cases), and
`src/internal/collection.test.ts` covers the shared movement arithmetic.

```sh
nub run --filter @gpuixui/components test:behaviour
```
