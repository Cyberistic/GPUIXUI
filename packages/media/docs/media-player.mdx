## Usage

```tsx
import * as Option from "effect/Option";
import { MediaPlayer, type MediaFrame } from "@gpuixui/media";

// The caller decodes or generates each frame: a file, a stream or a sequence.
const frameAt = (playhead: number): Option.Option<MediaFrame> =>
  Option.some(frames[Math.floor(playhead / 1000)] ?? firstFrame);

<MediaPlayer
  duration={24_000}
  frameAt={frameAt}
  alt="A clip's frame"
  label="Generated clip"
  width={640}
  height={360}
  buffered={18_000}
  qualities={["Auto", "1080p", "720p"]}
  onPlayheadChange={(playhead) => savePosition(playhead)}
/>;
```

## API

| Prop | Type | Default |
| ---- | ---- | ------- |
| `duration` | `number` (milliseconds) | required |
| `frameAt` | `(playhead) => Option<MediaFrame>` (a value that is not a function reads as no source) | — (no picture) |
| `alt` | `string` | required (a blank name reads as the player's own) |
| `label` | `string` | `"Media player"` (a blank name reads as the default) |
| `width` | `number` | `640` |
| `height` | `number` | `360` |
| `buffered` | `number` (milliseconds) | the whole clip |
| `defaultPlayhead` | `number` | `0` |
| `onPlayheadChange` | `(playhead: number) => void` | — |
| `defaultPlaying` | `boolean` | `false` |
| `onPlayingChange` | `(playing: boolean) => void` | — |
| `defaultVolume` | `number` (`0…1`) | `1` |
| `onVolumeChange` | `(volume: number) => void` | — |
| `defaultMuted` | `boolean` | `false` |
| `onMutedChange` | `(muted: boolean) => void` | — |
| `rates` | `ReadonlyArray<number>` | `[0.5, 1, 1.5, 2]` |
| `defaultRate` | `number` | `1` |
| `onRateChange` | `(rate: number) => void` | — |
| `qualities` | `ReadonlyArray<string>` | `[]` (the settings menu offers speed only) |
| `defaultQuality` | `string` | the first quality |
| `onQualityChange` | `(quality: string) => void` | — |
| `tickMs` | `number` | `100` |
| `seekStep` | `number` | `1000` |
| `largeSeekStep` | `number` | `10000` |
| `idleMs` | `number` | `3000` |
| `onFullscreenChange` | `(fullscreen: boolean) => void` | — |
| `playLabel` | `string` | `"Play"` (a blank label reads as the default) |
| `pauseLabel` | `string` | `"Pause"` (a blank label reads as the default) |
| `disabled` | `boolean` | `false` |
| `className` | `string` | — |
| `style` | `StyleDesc` | — |
| `testId` | `string` | `"media-player"` |

A `MediaFrame` is `{ width, height, pixels }`, where `pixels` are straight RGBA
bytes (`width * height * 4`). The player pushes them with
`ImgInstance.setImagePixels` from a layout effect; the route is measured by the
`media-frame-lifecycle` probe. A frame whose box or buffer cannot be laid out
paints no new picture rather than a broken one.

## Keyboard

The player is a focusable group, so its keys work while it, its timeline or any
control inside it holds the focus:

| Key | What it does |
| --- | ------------ |
| `Space` / `K` | play or pause |
| `Left` / `Right` | seek back or forward by `seekStep` |
| `Shift` + `Left` / `Right` | seek back or forward by `largeSeekStep` |
| `J` / `L` | seek back or forward by `largeSeekStep` |
| `Up` / `Down` | raise or lower the volume by five points |
| `Home` / `End` | seek to the clip's start or end (and stop a running clip) |
| `M` | mute or unmute |
| `F` | ask the window for fullscreen |

Every control is a shipped `Button`/`IconButton` with its own name, so Enter and
Space activate the focused control as they do elsewhere in the library.

## Pointer

The timeline is a seek control: a press seeks to the share of the clip the
pointer names, and a drag while the primary button is held scrubs. The painted
rail is 4 points tall with a 12-point thumb, and the hit target is the
**24-point** band around it (`targetSize.minimum`); the rail is
pointer-transparent inside that band. The player reads the band's box from the
renderer at press time — the route the shipped `Slider` uses — so a resize is
picked up without a second measurement. A press outside the band's ends clamps
to 0:00 or the clip's end, a secondary press begins no scrub, and a move that
holds no button ends the gesture.

The bar fades out after `idleMs` without a pointer move, key or focus, and any
of those brings it back. A popup keeps it painted while it is open.

## Limitations

- **No audio, no decoding, no `<video>`.** The runtime declares no `video` or
  `audio` element and no playback verb, so the caller supplies each frame's
  bytes and the app owns the clock. This player is the poster and the transport;
  a clip's frames must arrive from the app, and the volume, rate and quality it
  reports are the app's settings to apply. The paint route is
  `media-frame-lifecycle`'s; the shipped wrapper is measured in a window by
  `media-player-lifecycle` (49 checks, 0.11.0) at 512×288, which reads the
  `0:00 / 0:04` clock, a 496×4 timeline with the buffered share at 248, the
  fill, the seek keys, a press and a drag on the track, the rate menu, the
  faded bar and a disabled player.
- **Fullscreen is the window's.** `F` and the fullscreen control call the
  renderer's `toggleFullscreen`; the player reports the state it asked for, and
  the OS may refuse it. There is no element-level fullscreen on this runtime.
- **The buffered range is the app's answer.** `buffered` is a caller-supplied
  span, because nothing decodes here; the default is the whole clip, the range a
  caller that can answer every frame has in hand. A range behind the playhead
  paints as far as the played fill.
- **A quality is a label the app supplies.** `qualities` is empty by default and
  the settings menu then offers only the playback speed; a chosen quality is
  reported to the app, which owns the rendition.
- **The rate scales the app-owned clock.** `onRateChange` reports the choice and
  the interval advances the playhead by `tickMs × rate`, so the readout and the
  picture agree; there is no decoder whose speed could differ.
- **A disabled player stops.** Its clock is not a background job, and its
  controls leave the tab order while the poster keeps painting.
- **A finished clip restarts on Play.** Pressing Play at the clip's end starts
  from zero, the way a player's own button does.
- **Values that cannot be laid out read as defaults**: a stored `duration` that
  is not positive is a zero-length clip, a stored `rate` that is not positive is
  `1×`, a stored volume outside `0…1` is clamped, and a stored `tickMs`,
  `seekStep`, `largeSeekStep`, `idleMs`, `width` or `height` that is not
  positive reads as its default.
- **A frame source that is not a function is no source.** A player restored with
  a workspace carries `null` for a field its record never held, so only a
  function is a frame source: the poster-less player paints instead of the
  layout effect throwing `frameAt is not a function` (`frameAtOf`).
- **A decoded frame is read structurally.** `frameAt`'s answer is a decoder's
  output, so a frame that arrived without its bytes, with a partial buffer or
  with a box that cannot be laid out paints no picture and keeps the transport
  running — a decoder's failure must not unmount the player (`isFrame`).
- **The timeline announces through `aria-valuetext`**: `@gpuix/native@0.11.0`
  has no `aria-valuenow`/`aria-valuemin`/`aria-valuemax`, so the clock is the
  value a reader hears (the same rule the shipped sliders follow).
