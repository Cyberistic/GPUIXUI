---
title: Progress
description: A determinate or indeterminate progress bar.
---

`Progress` paints a track and a fill. With `value` it is determinate (0–100,
clamped); without it, it is indeterminate and a segment advances through eight
positions on a 120 ms interval. It cannot rotate, and does not try to.

A determinate bar is **static**: the step timer runs only while the bar is
indeterminate, so a form showing 42% schedules nothing and re-renders nothing.

## Usage

```tsx
import { Progress, Stack, Text } from "@gpuixui/primitives";

<Stack direction="column" gap="xs">
  <Text role="caption" tone="muted">Uploading · 42%</Text>
  <Progress value={42} label="Uploading" />
</Stack>;
```

```tsx
<Progress label="Saving" />
```

A bar that stands for a quantity announces the quantity, not only the
percentage:

```tsx
<Progress
  value={(filesCopied / totalFiles) * 100}
  label="Copying files"
  formatValue={() => `${filesCopied} of ${totalFiles} files`}
/>
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `number` | — | 0–100 determinate fill; omit for indeterminate |
| `tone` | `primary \| success \| destructive \| muted` | `"primary"` | the fill's colour role, in both the determinate and the indeterminate bar |
| `size` | `"sm" \| "md"` | `"md"` | track height from `spacing.xs`/`sm` |
| `label` | `string` | none | accessible name, trimmed; a blank label leaves the bar unnamed |
| `formatValue` | `(value: number) => string` | whole percentage | the announced sentence for a determinate bar; receives the clamped percentage, a blank result falls back, and the indeterminate bar ignores it |
| `style` | `StyleDesc` | — | merged last, layout included |
| `testId` | `string` | — | stable locator |

Values outside 0–100 are clamped, so a bar can never paint outside its track.
`NaN` is treated as empty, never as complete. A computed percentage
(`(loaded / total) * 100`) keeps its exact fraction in the fill but is
**announced as a whole percent** — `33.333…` reads `"33%"` — because the value
text is a sentence, not geometry (plan `755`). The indeterminate row layout is
the component's default, not a rule the caller cannot touch: `display` and
`flexDirection` are merged before `style`, so a caller who sets them owns the
consequence. The guard in `src/components/style-order.test.tsx` holds that.

## Keyboard

Not focusable. Progress is status, not a control; there is no slider behaviour.

## Accessibility

- Role: `progressbar` (`ProgressIndicator` in AccessKit).
- The value is announced through **`aria-valuetext`** — `"42%"`, the caller's
  `formatValue` sentence, or `"loading"` — because GPUix 0.10.0 has no
  `aria-valuenow`.
- `formatValue` receives the **clamped percentage** (0–100, the value the fill
  paints), not the caller's raw byte or file count: close over those numbers in
  the formatter. A blank sentence falls back to the whole percentage, and an
  indeterminate bar never calls it (plan `780`).
- A computed value's announcement is rounded to a whole percent (`"33%"` for a
  third) while the fill keeps its exact fraction; `NaN` announces `"0%"` and an
  infinity the bound on its side.
- The name comes from `label`. Without one, a progress bar is an unnamed
  progress bar; give it the task's name ("Uploading", "Saving").

## Theming

`progressTrackStyle` paints `colors.muted`; `progressFillStyle` paints the tone's
role — the indeterminate segment resolves the same `progressToneColor` map, so
`success` means success in both modes. Height is a spacing step and both ends are
`radius.full`, so a density or radius change moves the whole family.

## Limitations

- No `aria-valuenow` (above).
- `formatValue` is given the percentage, not the underlying count: a file or
  byte count is closed over in the formatter rather than passed in.
- The indeterminate segment is a discrete step, not a smooth sweep: the bar is a
  percentage, while a `motion` target is a number, and a looping sweep has no
  `repeat` (plan `329`).
- No buffer/secondary value, no stacked segments, no label inside the track.

## Verification

- `src/core/style.test.ts` — clamping, including `NaN` and infinity, the
  whole-percent announcement of a computed value (plan `755`), and the
  caller-sentence and blank-fallback rules (plan `780`).
- `src/components/Progress.test.tsx` — tree-level track/fill, tone (determinate
  and indeterminate), the value text, including a third that announces `"33%"`
  while its fill stays exact, the caller's sentence, the blank fallback and the
  indeterminate bar that never calls the formatter.
- `src/components/style-order.test.tsx` — the caller's `style`, `display` and
  `flexDirection` included, survives the merged row layout (plan 097).
- `runtime/progress-announcement.runtime.test.tsx` — a computed third announces
  `"33%"` in AccessKit and paints a third of the track (plan `755`); a formatted
  bar announces its sentence and paints its fraction, and an indeterminate one
  stays `"loading"` (plan `780`).
- `runtime/loading.runtime.test.tsx` — announces `"42%"`, clamps 140 to `"100%"`
  and −5 to `"0%"`, the fill tracks the value, the indeterminate segment moves
  over real time and paints its requested tone, and a determinate bar schedules
  no interval while an indeterminate one schedules exactly one (plan 328).
