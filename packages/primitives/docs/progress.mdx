---
title: Progress
description: A determinate or indeterminate progress bar.
---

`Progress` paints a track and a fill. With `value` it is determinate (0–100,
clamped); without it, it is indeterminate and a segment advances through eight
positions on a 120 ms interval. It cannot rotate, and does not try to.

The `tone` paints the fill in **both** states: a moving segment that ignores the
tone would make a destructive task and a successful one look the same until the
value arrived. Only an indeterminate bar runs the step timer — a determinate bar
draws a fixed fill, and a timer that wakes the tree for a segment it never
paints is cost with nothing to show for it.

## Usage

```tsx
import { Progress, Stack, Text } from "@gpuixui/primitives";

<Stack direction="column" gap="xs">
  <Text role="caption" tone="muted">Uploading · 42%</Text>
  <Progress value={42} label="Uploading" />
</Stack>;
```

```tsx
<Progress label="Saving" />
```

The parts compose the bar for a caller who wants the value beside it:

```tsx
import {
  Progress,
  ProgressIndicator,
  ProgressLabel,
  ProgressTrack,
  ProgressValue,
  Stack,
} from "@gpuixui/primitives";

<Progress value={42} label="Uploading">
  <ProgressTrack>
    <ProgressIndicator />
  </ProgressTrack>
  <Stack direction="row" justify="between">
    <ProgressLabel>Uploading</ProgressLabel>
    <ProgressValue />
  </Stack>
</Progress>;
```

## Parts

| Part | Responsibility |
| ---- | -------------- |
| `Progress` | role, accessible name, announced value, the frame |
| `ProgressTrack` | the bar's background, height, radius and overflow clip |
| `ProgressIndicator` | the fill; while indeterminate it is the moving segment |
| `ProgressLabel` | visible task name, defaulting to the root's `label` |
| `ProgressValue` | the clamped percentage, or `loading` with no value |

The default composition is the track and its indicator. A caller's `children`
replace it entirely, and the parts render from the same resolved state the
root uses — there is no second paint path.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `number` | — | 0–100 determinate fill; omit for indeterminate |
| `tone` | `primary \| success \| destructive \| muted` | `"primary"` | the fill's colour role |
| `size` | `"sm" \| "md"` | `"md"` | track height from `spacing.xs`/`sm` |
| `label` | `string` | none | accessible name, and `ProgressLabel`'s default text |
| `children` | `ReactNode` | the track | the parts to draw |
| `style` | `StyleDesc` | — | merged last, on the root frame |
| `className` | `string` | — | Tailwind classes, joined last on the root frame |
| `testId` | `string` | — | stable locator, on the root |

`ProgressTrack` and `ProgressIndicator` accept `style`, `className` and
`testId`; `ProgressTrack` also takes `children`. `ProgressLabel` takes
`children` (visible text) and `testId`; `ProgressValue` takes `testId`. Each
part's `style` is merged last, after the recipe.

Values outside 0–100 are clamped, so a bar can never paint outside its track.
`NaN` is treated as empty, never as complete. The fill and `ProgressValue` read
the same clamped number.

## Keyboard

Not focusable. Progress is status, not a control; there is no slider behaviour.

## Accessibility

- Role: `progressbar` (`ProgressIndicator` in AccessKit).
- The value is announced through **`aria-valuetext`** — `"42%"` or
  `"loading"` — because GPUix 0.10.0 has no `aria-valuenow`.
- The name comes from `label`. Without one, a progress bar is an unnamed
  progress bar; give it the task's name ("Uploading", "Saving").
- `ProgressLabel` is visible text, not a second name: it does not replace the
  root's `label`.

## Theming

`progressTrackClass` paints `colors.muted`; `progressFillClass` paints the
tone's role. Height is a spacing step and both ends are `radius.full`, so a
density or radius change moves the whole family. The label and value parts use
the `caption` type role in the `muted` text tone.

## Limitations

- No `aria-valuenow` (above).
- The indeterminate segment is a discrete step, not a smooth sweep; the runtime
  cannot interpolate position beyond the motion API this package does not import.
- No buffer/secondary value and no stacked segments. The label and value parts
  sit beside the track; painting text *inside* the bar is not a part.

## Verification

- `src/core/style.test.ts` — clamping, including `NaN` and infinity.
- `src/core/loading.test.ts` — the step maths and the rule that only a bar
  without a value animates.
- `src/components/Progress.test.tsx` — the tree-level track/fill, the clamped
  fill width, the value part agreeing with it, the indeterminate lead, the tone
  on both the determinate and the indeterminate fill, a custom composition, and
  the root frame's style merge.
- `runtime/loading.runtime.test.tsx` — announces `"42%"`, clamps 140 to `"100%"`
  and −5 to `"0%"`, the fill tracks the value inside the track, the
  indeterminate segment moves over real time in its own tone, and a step counter
  that is not running stays still.

```sh
nub run --filter @gpuixui/primitives test
nub run --filter @gpuixui/primitives test:runtime
```
