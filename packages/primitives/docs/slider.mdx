---
title: Slider
description: A value on a track, by click, drag or keyboard.
---

`Slider` is one value inside a closed range. GPUix 0.10.0 publishes **no slider
host element** (plan 020 §1.5), so the track, the fill and the thumb are this
package's: a `div` tree, the arithmetic in `core/value.ts` and the paint in
`core/style.ts`. It is not a disguised `<input type="range">` — there is no such
thing in the runtime.

## Usage

```tsx
import { Slider, Stack, Text } from "@gpuixui/primitives";
import { useState } from "react";

const [quality, setQuality] = useState(62);

<Stack direction="column" gap="sm">
  <Text role="caption" tone="muted">Quality · {quality}%</Text>
  <Slider
    label="Quality"
    value={quality}
    onValueChange={setQuality}
    formatValue={(value) => `${value}%`}
  />
</Stack>;
```

Omit `value` to let the slider own its state (`defaultValue` sets the start).

## Values

Out-of-range values are clamped, and a value between stops snaps to the nearest
stop measured from `min` (a tie goes to `max`). **`max` is always a stop**, so a
step that does not divide the span still fills the track: `min 0`, `max 10`,
`step 3` has the stops `0, 3, 6, 9, 10`. `NaN` reads as `min`, never as a full
track. An infinity is simply out of range, so it clamps to its own end:
`+Infinity` reads as `max` and `-Infinity` as `min` (the rule the meter and the
number field follow too).

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `number` | — | controlled value |
| `defaultValue` | `number` | `min` | uncontrolled start |
| `onValueChange` | `(value: number) => void` | — | called only when the value changed |
| `min` / `max` | `number` | `0` / `100` | the closed range |
| `step` | `number` | `1` | quantisation; `0` is continuous (arrows move 1% of the span) |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | thumb `iconSize`, track `density.controlHeight` |
| `disabled` | `boolean` | `false` | out of the tab order, half opacity, no pointer or keys |
| `invalid` | `boolean` | `false` | the destructive role on the fill and thumb border |
| `label` | `string` | none | accessible name, trimmed; a blank label is absent |
| `formatValue` | `(value: number) => string` | `String` | the announced text; a blank result falls back to the value |
| `aria-description` | `string` | none | description announced after the name; trimmed, and a blank value is absent (a `Tooltip` writes its text here) |
| `style` | `StateStyle<SliderState>` | — | merged last, on the track; an object or a state callback |
| `thumbStyle` | `StateStyle<SliderThumbState>` | — | merged last on the thumb; an object or a state callback |
| `testId` | `string` | — | names the track; the thumb becomes `${testId}-thumb` |

## Keyboard

| Key | Effect |
| --- | ------ |
| `ArrowRight` / `ArrowUp` | + one step |
| `ArrowLeft` / `ArrowDown` | − one step |
| `PageUp` / `PageDown` | ± ten steps |
| `Home` / `End` | `min` / `max` |

Any other key is left alone, so a slider inside a form does not swallow it. The
slider is a single tab stop, and the focus ring is painted on the thumb.

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). Role, name, tab order, keyboard operation and activation
  are unaffected.
- Role: `slider` (AccessKit `Slider` — verified in the real renderer).
- The value is announced through **`aria-valuetext`**; GPUix 0.10.0 has no
  `aria-valuenow`, `aria-valuemin` or `aria-valuemax`, so a screen reader hears
  the value but not the range. Give the slider a `label`, and a `formatValue`
  when the number alone is ambiguous (`"62%"`, `"$40"`).
- A disabled slider has no tab stop, so it is skipped rather than announced as
  a control that cannot be used.
- **Slot trigger:** forwards a `Tooltip`'s handlers and `aria-description`, so a
  tip opens on hover and on keyboard focus. The track is always 100 % wide, so a
  `Tooltip` around it needs `style={{ width: … }}` on the tooltip root — the root
  otherwise hugs and the slider collapses (measured, plan `345`).

## Theming

The **rail** is `colors.muted` — the track itself paints no surface at rest, so
a slider does not become a bar as tall as the control. The fill is
`colors.primary` (or `colors.destructive` when invalid), and the thumb
`colors.input` with a `colors.primary` border. The track's height is
`density.controlHeight[size]`, the thumb `iconSize[size]`, its border
`borderWidth.strong`, and the focus ring is `@gpuixui/tokens`' `focusRing`.
Hovering or pressing the track paints a `colors.hover` / `colors.active` wash on
the track itself (rounded by `radius.sm`), and a disabled slider paints neither.
Nothing in the component names a literal.

## Pointer behaviour

A press anywhere on the track moves the value to the point under the pointer —
the usable span is inset by half a thumb at each end, so the thumb's centre lands
exactly on the pointer and on the ends without hanging off the track. Only the
**primary button** starts a gesture: a right or middle click neither moves the
value nor takes focus.

The **track is the hit area, so the track carries the pointer feedback**: the
hover and press wash belongs to the element that owns the gesture. The rail, the
fill and the thumb are all `pointerEvents: "none"` — deliberately, so a press on
the thumb reaches the track — which is why the thumb cannot paint a hover state
of its own, and why the focus ring (on the thumb) and the wash (on the track)
are two signals from one control rather than two controls (plan `361`).

A drag keeps updating **after the pointer leaves the track** — the runtime
captures the pressed element (measured, plan 063) — and clamps at `min`/`max`.
Releasing ends the gesture; a plain hover never moves the value.

## Style by state

`style` takes an object or a callback over `SliderState` — the runtime's own
`StateStyle` type — merged last on the track:

```tsx
<Slider style={(state) => ({ opacity: state.disabled ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | refuses pointer and keys |
| `invalid` | `boolean` | paints the destructive role |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

### Per-item style

`thumbStyle` takes the same `StateStyle` over `SliderThumbState`, merged last on
the thumb:

```tsx
<Slider thumbStyle={(thumb) => (thumb.focused ? { opacity: 1 } : { opacity: 0.9 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `focused` | `boolean` | the slider holds native focus |
| `disabled` | `boolean` | refuses pointer and keys |
| `invalid` | `boolean` | paints the destructive role |

`SliderThumbState` is exported. `RangeSlider` has its own
`RangeSliderThumbState`, which adds `end: "start" | "end"`.

## Limitations


- **No `aria-valuenow`/`min`/`max`** (above).
- The thumb cannot rotate or transform; GPUix has no `transform`, and the
  position is a flex layout, not a `translate`.

  `361`).

  element that owns a pointer gesture changes something on hover and on press,
  and a disabled control changes nothing in either state (plan `361`).

- `runtime/value.runtime.test.tsx` — a real click at 25% reports 25, the thumb is
  centred within 1 px at 0/50/100, the ring follows focus, disabled is skipped

  probes.
