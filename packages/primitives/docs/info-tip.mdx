---
title: InfoTip
description: An information icon whose tooltip explains a nearby term.
---

`InfoTip` is the one accessible shape for an info icon with a tooltip. A
`Tooltip` needs a trigger that is a **focusable host element with a role and a
name**; hand-rolling that per consumer produced a real bug — `examples/basic-app`
wrapped the icon in a `Box`, which forwards no `tabIndex` and no role, so the tip
was hover-only and absent from the accessibility tree (plan 073).

## Usage

```tsx
import { InfoTip, Stack, Text } from "@gpuixui/primitives";

<Stack direction="row" align="center" gap="xs">
  <Text role="h3">Revenue</Text>
  <InfoTip
    content="Booked revenue, net of refunds."
    label="Revenue definition"
  />
</Stack>;
```

`content` is the explanation; `label` is what a screen reader calls the icon.
A blank `content` means there is nothing to explain, so no tip and no description
are painted; a blank `label` falls back to "More information", because the
trigger is a focus stop and an unnamed one is the bug plan 073 fixed.
The icon itself is decorative, so the trigger is a single accessibility node.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `content` | `string` | — | the tip; wraps inside the measured cap; also the trigger's `aria-description` |
| `label` | `string` | `"More information"` when blank | the trigger's accessible name; trimmed |
| `icon` | `IconName` | `"info"` | which icon is painted |
| `side` | `FloatingSide` | `top` | preferred side; flips when it does not fit (plan 067) |
| `testId` | `string` | — | the **trigger's** locator |
| `tipTestId` | `string` | — | the **tip's** locator |
| `style` | `StateStyle<InfoTipState>` | — | merged last on the trigger; an object or a state callback |

`content` is a string on purpose: a non-string tip is painted but has no text to
announce (plan 071), and an info tip is prose. Pass an explicit `tipTestId` when
a test needs the open tip; a derived id would be a second convention.

## Keyboard

`Tab` focuses the trigger, which opens the tip. `Escape` dismisses it (the
published tooltip's own behaviour). There is no activation: the icon describes,
it does not act.

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). **The tip opens on keyboard focus too:** `Tooltip` learns
  its trigger's host through the slot's `ref` (plan `596`), so the tracker drives
  the same open path as the pointer; `InfoTip` carries no open state of its own.
  Role, name, tab order, keyboard operation and activation are unaffected.
The trigger is `role="img"` with `aria-label={label}` and `tabIndex={0}`; the
free-text `content` becomes its `aria-description`, so the explanation is
announced on focus even while the tip is closed. The open tip is a named
`role="tooltip"` node (plan 071). The icon is `presentation`, so one trigger
produces one node, not two.

A blank — empty or whitespace-only — `label` takes the documented
"More information" fallback (plan `573`): a focus stop must be named, and
`ariaName` alone would have left an unnamed `img` in the tree. A blank
`content` is absent: the trigger paints with no description and no tip, instead
of an empty popover named with whitespace.

## Theming

The trigger reads `spacing["2xs"]`, `radius.sm`, `iconSize.sm` and
`colors.mutedForeground`; the focus ring is `focusRing(theme)`. The tip is
`Tooltip`'s popover surface.

## Style by state

`style` is the package's one caller seam, merged **last** on the trigger — the
element this component draws. The state is the trigger's own focus, the same
value the ring is painted from:

```tsx
<InfoTip
  content="Booked revenue, net of refunds."
  label="Revenue definition"
  // the ring is part of the base, so a caller can keep it and add layout
  style={(state) => ({ marginLeft: 4, opacity: state.focused ? 0.9 : 1 })}
/>
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `focused` | `boolean` | the trigger holds native focus |

`InfoTipState` is exported. An object style behaves exactly as before; the
callback's result merges after the component's own chrome and ring, so it wins
per property (returning `{}` keeps the default look). Because the merge is last,
a callback that supplies `boxShadow` replaces the focus ring — the same trade
every other part makes.

## Limitations

- **Focus is painted but not "focus-visible"**: GPUix 0.10.0 has no such state,
  so a mouse press shows the same ring as `Tab`.
- **The tip's own surface is not caller-styled.** `style` reaches the trigger;
  the tip is `Tooltip`'s popover surface, and `Tooltip.style` is the anchoring
  root rather than the tip. A caller who needs a different tooltip surface owns a
  `Tooltip` composition, not an `InfoTip`.
- **No click-to-open.** The published tooltip opens on hover and focus; a
  persistent popover is `Popover`/`Dialog` work in `@gpuixui/components`.
- A long `content` **wraps** inside the room the resolved side and alignment
  have (inherited from `Tooltip`, plans `391` and `393`). Measured: a
  230-character tip paints 1 251 × 40 px — two caption lines — in a 1280 × 800
  window. A single unbreakable token can still paint past the cap, because
  `StyleDesc` has no word-break property. Keep `content` to a sentence or two
  anyway; a long explanation belongs in a popover.
- **A window resize or a moving trigger re-places the tip** (inherited from
  `Tooltip`, plans `604` and `645`). The trigger is re-sampled every 100 ms
  while the tip is open, so a layout change is corrected on the next tick; the
  sampler sleeps while the tip is closed.

## Verification

- `src/components/InfoTip.test.tsx` — the trigger is a named `img` tab stop, the
  icon is `presentation`, and the ring paints only while focused; a blank label
  takes the "More information" fallback (plan `573`); a caller's `style` lands on
  the trigger without changing the role, name or tab stop, the callback receives
  both focus states, and the ring stays in the base unless the caller replaces
  it (plan `695`).
- `runtime/info-tip.runtime.test.tsx` — hover opens the tip; `focusNext` lands on
  the trigger and opens it (the component drives the controlled `open` from its
  tracker state, plan `595`), the `Image` node carries the description and the
  tip is a named `Tooltip`; leaving focus closes it; the painted `boxShadow`
  equals `focusRing(theme)`; a 230-character tip stays inside the window and
  paints more than one line, while a short one paints exactly one (plan `395`);
  a tip that is open while its trigger moves to the top edge flips below the
  trigger on the next follow sample (plan `649`); blank content paints no tip
  and publishes no description (plan `573`); the tracked focus reaches a caller's
  style callback (`opacity 1 → 0.5 → 1`) and a caller's `marginLeft: 12` moves
  the painted trigger by exactly 12 px while the `Image` keeps its name (plan
  `695`).
- `runtime/blank-name.runtime.test.tsx` — a blank `InfoTip` label announces
  "More information" and still takes focus (plan `573`).
- `src/docs-tooltip-wrap.test.ts` — the resolver's capped form is `normal` and
  uncapped form `nowrap`, and no primitives page may claim a mounted tip does
  not wrap (plan `395`).

```sh
nub run --filter @gpuixui/primitives test
nub run --filter @gpuixui/primitives test:runtime
```
