---
title: ButtonGroup
description: Related actions, in one row or one column, attached or separated.
---

`ButtonGroup` lays buttons out along one axis and gives the group `role="group"`.
In `attached` mode the gap is zero and the **group** is rounded and clipped; it
does not reshape individual buttons.

## Usage

```tsx
import { Button, ButtonGroup } from "@gpuixui/primitives";

<ButtonGroup mode="attached" label="Text alignment">
  <Button variant="ghost">Left</Button>
  <Button variant="secondary">Center</Button>
  <Button variant="ghost">Right</Button>
</ButtonGroup>;
```

A column of actions uses the same component with the axis flipped. A vertical
group stretches every button to the group's width, so the stack has one edge:

```tsx
<ButtonGroup mode="attached" orientation="vertical" label="Ownership actions">
  <Button variant="secondary">Transfer ownership</Button>
  <Button variant="destructive">Delete project</Button>
</ButtonGroup>;
```

## Modes

| `mode` | Gap | Shape |
| ------ | --- | ----- |
| `attached` (default) | 0 | group radius `md`, `overflow: hidden`; buttons are square, so the clip supplies the rounded ends |
| `separated` | `gap` step (`sm` default) | buttons keep their own `radius` (`md` by default) |

The runtime has no `:first-child`/`:last-child` selector and a component cannot
restyle a child without cloning it, so `attached` cannot round only the ends. It
asks every `Button` to be **square** through a React context and rounds and clips
the **group** instead: the clip supplies the outer corners, and two adjacent
buttons meet on a straight shared edge instead of two rounded corners with a
notch between them. Pass `radius` to a single button when it needs a different
shape; an explicit value wins over the group's.

## Axis

`orientation` picks the axis, the same prop the other groups take.

| `orientation` | Layout | Children |
| ------------- | ------ | -------- |
| `horizontal` (default) | one row | their intrinsic width, centred on the cross axis |
| `vertical` | one column | stretched to the group's width |

The axis is layout only: `mode`, `gap`, the radius and the clip behave the same
in both directions, and an attached vertical group still squares its children
and rounds the group box. The group is not a segmented control — a pressed set
of options is `ToggleGroup`.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `mode` | `"attached" \| "separated"` | `"attached"` | zero gap + clipped group, or a spaced group |
| `orientation` | `"horizontal" \| "vertical"` | `"horizontal"` | a row of intrinsic-width buttons, or a column of stretched ones |
| `gap` | spacing step | `"sm"` | the gap in separated mode |
| `label` | `string` | none | the group's accessible name, written as `aria-label` |
| `style` | `StyleDesc` | — | merged last, e.g. `justifyContent: "flex-end"` |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the buttons |

## Keyboard

The group adds no key handling. Tab moves through each button in order; Enter and
Space follow each `Button`'s contract. A segmented control that should be one tab
stop with arrow navigation is a radio group, not a button group.

## Accessibility

- Role: `group`. The runtime has no `aria-labelledby`, so a visible heading
  cannot name the group by reference; pass its words as `label` and the group
  carries `aria-label`. Without `label` the group is anonymous, exactly as the
  runtime reports it.
- Each button keeps its own name and role.

## Theming

The gap uses `spacing[gap]`; the group radius is `radius.md`. No literal. The
axis changes layout only, so neither the tokens nor the clip follow it.

## Limitations

- The shape rule reaches `Button` children only (through `GroupShapeContext`); a
  `Toggle` or another control in the group keeps its own radius. A pressed set
  belongs in `ToggleGroup`, which owns that paint.
- The name must be passed as `label`; there is no automatic association with a
  heading.
- No overflow behaviour: a group wider than its parent does not collapse into a
  menu.

- `src/components/presentational.test.tsx` — attached and separated geometry
  plus `role="group"`, the `label` → `aria-label` contract, the default row axis
  and the vertical column axis, and the caller's `style` still winning last.

  paint `borderRadius: 0` while the group paints `radius.md` with `overflow:
  hidden`; separated children keep `radius.md`; an explicit per-button `radius`
  wins; a labelled group is an accessibility `Group` with that name (plan
  `078`). A vertical attached group stacks with 0px between neighbours, paints
  every button at the group's width, and keeps the same square children and
  clipped group box (plan `096`).
