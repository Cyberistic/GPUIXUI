---
title: Spinner
description: An activity indicator built from three dots, because the runtime cannot rotate.
---

`Spinner` is the activity indicator for work with no known proportion. The pinned
runtime's `motion` cannot rotate, so there is no spinning arc: three dots advance
a lit position every 120 ms and the trail fades through opacity. A `Progress`
with no `value` is the other honest option.

It is also the indicator a busy `Button` draws, and there its dots must paint the
**fill's on-colour** rather than the brand: a brand spinner on a brand button is
1.00:1, so the busy state would disappear exactly where it matters.

## Usage

```tsx
import { Spinner, Stack, Text } from "@gpuixui/primitives";

<Stack direction="row" align="center" gap="sm">
  <Spinner label="Refreshing revenue" />
  <Text role="caption" tone="muted">Refreshing…</Text>
</Stack>;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `size` | `number` | `theme.iconSize.md` | the dot side in pixels |
| `accent` | `primary \| destructive \| muted \| on-primary \| on-secondary \| on-destructive \| on-accent \| on-disabled` | `"primary"` | the role every dot paints; the `on-*` accents are the fill's on-colour |
| `label` | `string` | `"Loading"` | accessible name announced as a status |
| `reducedMotion` | `boolean` | `false` | holds the lit dot and schedules no interval |
| `className` | `string` | — | a Tailwind class string, joined after the recipe so it wins conflicts |
| `style` | `StyleDesc` | — | merged last |
| `testId` | `string` | — | stable locator |

`size` accepts a number because a spinner inside a `Button` often needs to match
the button's own icon size rather than a named icon step.

The `on-*` accents exist for that case: `variantSpinnerAccent(variant,
disabled)` maps a filled button to the on-colour its own label uses, and a
variant with no fill (outline, ghost, link) keeps the brand accent, which the
mark contract measures on the page. A **disabled** filled button paints the
neutral `disabled`/`disabledForeground` pair instead of its fill, so its spinner
takes `on-disabled` — `disabledForeground` — rather than white dots on the light
theme's neutral fill (1.0x:1). A disabled action with no fill keeps `primary`,
because it is not painted on the pair. `toggleSpinnerAccent(pressed, disabled)`
applies the same rule to a `Toggle`'s two faces: a pressed toggle is the accent
role and takes `on-accent` (`accentForeground`), a pressed-and-disabled one wears
the neutral pair and takes `on-disabled`, and an unpressed toggle keeps the brand
accent because it has no fill of its own.

## Keyboard

Not focusable. Activity is status, not an action.

## Accessibility

- Role: `Status`, with the `label` as its name.
- Announce **what** is happening: the default "Loading" is a poor name when three
  spinners share a screen.
- The dots themselves are decorative and carry no text.

## Theming

`spinnerDots` decides the lit index and each dot's opacity; `spinnerDotStyle`
resolves size and colour from the accent role on **every** dot. The step is the
opacity (1 for the lit dot, fading to 0.2), not a second colour, so an indicator
inside a filled control keeps its on-colour along the whole row. The gap is
`spacing["2xs"]`.

`reducedMotion` is the caller's: the runtime exposes no reduced-motion
preference, so the host application reads the platform setting and passes it
down. The dots keep the accent and the status role — they hold the first frame
and no interval is scheduled, so the indicator is still there to be seen.

```tsx
<Spinner label="Loading projects" reducedMotion={prefersReducedMotion} />
```

A busy `Button` forwards its own `reducedMotion` to this spinner, so one
preference covers the action and the indicator inside it.

## Limitations

- **Cannot rotate** (above).
- No smooth animation: the lit dot jumps by design, and the runtime paints no
  intermediate position for this component.
- No size scale: pass pixels or an icon size's number.
- The trail is the accent at reduced opacity rather than a separate quiet role;
  a caller who wants a grey trail is asking for a different mark, not a fade.
- No inline placement inside a text run; put it in a `Stack`.
- The reduced-motion preference is the caller's to supply (above).

## Verification

- `src/core/loading.test.ts` — the lit index and fade across steps, the accent on
  every dot, and each `on-*` accent resolving to its fill's on-colour (including
  `on-accent` on the selected surface and `on-disabled` on the neutral pair).
- `src/components/Button.test.tsx` — a busy filled button hands the spinner
  `on-primary`/`on-secondary`/`on-destructive`, a variant with no fill keeps
  `primary`, and a disabled filled button's spinner moves to `on-disabled` while
  a disabled unfilled one keeps `primary`.
- `runtime/loading.runtime.test.tsx` — the lit dot's index changes over real
  time (the opaque dot is the lit one), every dot paints the accent, a loading
  primary button's dots paint `primaryForeground` and a secondary one's paint
  `secondaryForeground`, a disabled busy primary button's dots paint
  `disabledForeground`, and AccessKit reports `Status` with the label. A
  `reducedMotion` spinner paints one frame across six samples.
- `runtime/examples.runtime.test.tsx` — the feedback example mounts it.

```sh
nub run --filter @gpuixui/primitives test
nub run --filter @gpuixui/primitives test:runtime
```
