---
title: Toggle
description: A button whose action has a persistent on/off state.
---

`Toggle` is a button that stays on: bold, grid view, snap-to-grid, mute. It is
**not** a `Switch` — a switch changes a setting immediately ("dark mode"), while a
toggle sets a mode for what happens next and usually sits in a toolbar beside
other actions.

## Usage

```tsx
import { Toggle } from "@gpuixui/primitives";
import { useState } from "react";

const [grid, setGrid] = useState(true);

<Toggle pressed={grid} onPressedChange={setGrid} label="Grid" variant="outline">
  Grid
</Toggle>;
```

Omit `pressed` to let the toggle own its state (`defaultPressed` sets the start).

## Variants, sizes and states

Pressing paints `colors.accent` with `colors.accentForeground` — the role the
theme reserves for a selected surface — so pressed, hover and focus are three
different states.

### Read-only

`readOnly` is the review state for a stored mode — a saved-settings page or a
document summary that shows "snap to grid: on" without letting the reader change
it. It keeps the tab stop, the focus ring, the accessible name and the announced
pressed state, and refuses every press (click, `Enter`, `Space`). The control
paints the normal accent fill at full contrast with a `default` cursor; only
`disabled` fades it and leaves the tab order, and `disabled` wins when both are
passed. 0.10.0 has no `aria-readonly`, so the state is behavioural and visual.

```tsx
<Toggle pressed readOnly label="Snap to grid">
  Snap to grid
</Toggle>
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `pressed` | `boolean` | — | controlled state |
| `defaultPressed` | `boolean` | `false` | uncontrolled start |
| `onPressedChange` | `(pressed: boolean) => void` | — | called with the new state |
| `variant` | `"default" \| "outline"` | `"default"` | no chrome at rest, or a border |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | from the density scale |
| `square` | `boolean` | `false` | equal width and height, for an icon-only toggle |
| `disabled` | `boolean` | `false` | out of the tab order, half opacity, no activation |
| `readOnly` | `boolean` | `false` | shows the pressed mode for review: keeps the tab stop and ring, refuses every press, full contrast with a `default` cursor (plan `804`) |
| `leading` / `trailing` | `ReactNode` | — | an icon or a count beside the label; the dedicated slots for an end icon, while a child element beside text shares the line (plan `803`) |
| `label` | `string` | none | accessible name. A non-blank value overrides the name derived from text children and is trimmed; a blank one is ignored. Required when the content is not text |
| `aria-description` | `string` | none | description announced after the name; trimmed, and a blank value is absent (a `Tooltip` writes its text here) |
| `style` | `StateStyle<ToggleState>` | — | merged last; an object or a state callback |
| `children` | `ReactNode` | — | the visible label |
| `testId` | `string` | — | stable locator |

## Keyboard

| Key | Effect |
| --- | ------ |
| `Enter` | activates on key **down** |
| `Space` | activates on key **up** |
| a held key | ignored, so it does not repeat |

A click activates as well. The toggle is one tab stop and paints the focus ring
while it holds focus. A read-only toggle keeps that stop and ring and answers
every activation key with nothing (above).

## As an overlay trigger

`Toggle` accepts the same slot contract as `Button` (plan `341`): a `Tooltip`
can wrap it, and the injected hover, focus and key handlers cross the component
boundary. The tip's string becomes the toggle's `aria-description`.

```tsx
<Tooltip content="Bold text">
  <Toggle label="Bold">B</Toggle>
</Tooltip>;
```

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). Role, name, tab order, keyboard operation and activation
  are unaffected.
- Role: `button` (AccessKit `Button`).
- **GPUix 0.10.0 has no `aria-pressed`**, so the state is announced through
  `aria-valuetext` — `"pressed"` or `"not pressed"` — exactly like `Checkbox`
  uses that channel for its state. A screen reader therefore hears a button with
  a value, not a pressed button. That is the limitation of the runtime, and the
  component does not pretend otherwise.
- The name is `label` when it says something (trimmed), otherwise the **text it
  paints** — string children, and text inside an element child such as an
  icon-plus-word label or a `Text` run — joined and trimmed. GPUix does not
  derive a button's name from painted text, so `Toggle` writes `aria-label`
  itself (measured: plan `058`). A computed `label=""` — or whitespace — is not
  a name and does not erase the content's (plan `396`). An element child with no
  text (a bare icon) yields no name — give it a `label`; the icon is decorative
  (plan `746`).
- A **read-only** toggle announces the same name and `"pressed"`/`"not pressed"`
  value: the state refuses changing the mode, not reading it. 0.10.0 has no
  `aria-readonly`, so assistive technology cannot be told the difference between
  a writable and a read-only toggle (plan `804`).
- The label is **chrome, not content**: `userSelect: "none"` on the control, so
  a drag across a toggle cannot select its text (measured before plan `386`:
  the drag selected `"Grid view"`). A caller's `style` still merges last and can
  opt back in.

## Theming

Rest and pressed are two rows of `core/variants.ts`' `toggleVariants`, so the
docs and the component read one table. Rest paints no fill (or a border for
`outline`); pressed paints `colors.accent`/`colors.accentForeground`; hover and
press lift the accent's alpha like a filled button. Nothing names a literal. A
read-only toggle declares no hover or press rule — it paints the resting row with
a `default` cursor, so the pointer promises nothing it refuses (plan `804`).


## Style by state

`style` takes an object or a callback over the toggle's public state — the
runtime's own `StateStyle` type:

```tsx
<Toggle style={(state) => ({ opacity: state.checked ? 1 : 0.8 })}>Bold</Toggle>
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `checked` | `boolean` | the pressed state (the contract's word for it) |
| `disabled` | `boolean` | refuses pointer and keys |
| `readOnly` | `boolean` | the review state: visible and focusable, refuses every press (plan `804`) |
| `focused` | `boolean` | holds native focus |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. `ToggleState` is exported.

## Limitations

- No `aria-pressed` (above).
- No `aria-readonly`: a read-only toggle keeps its tab stop and announced state,
  but assistive technology is not told that it refuses a press (plan `804`).
- No `loading` state: a toggle sets a mode instantly; a toggle that waits for a
  request should disable itself and show the result elsewhere.
- `square` sizes the button; it does not size the icon — pass an icon whose size
  matches the control (`theme.iconSize`).
- A label longer than a bounded toggle is clipped to **one line with an
  ellipsis**, so it cannot paint outside the control (plan `368`).

## Verification

- `src/components/state-style.test.tsx` — the state payload and the callback
  winning over the component's own rules (plan 079).
- `runtime/state-style.runtime.test.tsx` — the live state (focus, checked,
  invalid) reaching the painted style.

- `src/components/Toggle.test.tsx` — role and value text, no `aria-pressed`,
  the pressed paint from the accent role, the outline border, click/Enter/Space
  activation, held keys, disabled, the focus ring.
- `runtime/toggle.runtime.test.tsx` — a real click flips the announced state and
  repaints the accent fill; Enter down and Space up each activate once; a
  disabled toggle leaves the tab order; the ring follows focus. Measured
  2026-10-17 (plan 054 §9).
- `src/components/label-row.test.tsx` and `runtime/label-row.runtime.test.tsx`
  — an icon child beside the words is one row, a text-only label is unchanged,
  and a long mixed label stays inside a narrow toggle (plan `803`).
- `src/components/Toggle.test.tsx`, `src/core/style.test.ts` and
  `runtime/toggle-read-only.runtime.test.tsx` — the read-only state: the tab
  stop and ring stay, the press is refused, and the paint is full contrast with a
  `default` cursor (plan `804`).
- The disabled **handler** guard is proven at the element-tree level: a
  tabIndex-less toggle cannot be focused natively, so the runtime test can only
  prove the tab order.
