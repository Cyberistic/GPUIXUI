---
title: ToggleGroup
description: A set of pressed buttons — a segmented control or a formatting group.
---

`ToggleGroup` is a row (or column) of buttons with a pressed set. It is the
control for **modes** — text alignment, density, view — and for **formatting** —
bold, italic, underline. It is not a `RadioGroup` (a radio cannot be unselected
and its paint is a circle) and not a `ButtonGroup` (layout only, no selection).

Two selection rules, one component:

| `type` | Rule | Example |
| ------ | ---- | ------- |
| `single` | at most one pressed value; re-pressing the active item changes nothing | text alignment |
| `multiple` | each press adds or removes that value independently | bold / italic / underline |

## Usage

```tsx
import { ToggleGroup } from "@gpuixui/primitives";
import { useState } from "react";

const [align, setAlign] = useState("left");
const [format, setFormat] = useState<ReadonlyArray<string>>(["bold"]);

<ToggleGroup
  type="single"
  label="Alignment"
  options={[
    { value: "left", label: "Align left" },
    { value: "centre", label: "Align centre" },
    { value: "right", label: "Align right" },
  ]}
  value={align}
  onValueChange={setAlign}
/>;

<ToggleGroup
  type="multiple"
  label="Formatting"
  options={[
    { value: "bold", label: "Bold" },
    { value: "italic", label: "Italic" },
    { value: "underline", label: "Underline", disabled: true },
  ]}
  value={format}
  onValueChange={setFormat}
/>;
```

Omit `value` to let the group own its selection; `defaultValue` sets the start
(`"left"` for `single`, `["bold"]` for `multiple`). `onValueChange` fires only when
the selection actually changed.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `type` | `"single" \| "multiple"` | required | which selection rule applies |
| `options` | `ReadonlyArray<{ value, label, disabled? }>` | required | the items, in visual order; a blank `label` paints and announces the `value` |
| `value` / `defaultValue` | `string` for `single`, `readonly string[]` for `multiple` | — | controlled selection, or the uncontrolled start |
| `onValueChange` | `(value) => void` | — | the new selection, only on a real change |
| `orientation` | `"horizontal" \| "vertical"` | `"horizontal"` | flex direction and arrow axis |
| `variant` | `"default" \| "outline"` | `"default"` | `Toggle`'s two rest paints |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | control height and padding from the density scale |
| `disabled` | `boolean` | `false` | every item inert and out of the tab order |
| `label` | `string` | none | the group's accessible name |
| `style` | `StateStyle<ToggleGroupState>` | — | merged over the group container; an object or a state callback |
| `itemStyle` | `StateStyle<ToggleItemState>` | — | merged last on each item, after its focus ring; an object or a state callback |
| `testId` | `string` | — | the group's locator; items become `${testId}-${value}` |

Each item paints exactly like a standalone `Toggle`: rest from
`toggleVariants[variant].rest`, pressed from `toggleVariants[variant].pressed`
(the accent role), and the shared focus ring while it holds focus.

## Keyboard

The group is **one tab stop** — the selected item (`single`) or the item that
last held focus (`multiple`); with nothing selected (`single`), the first enabled
item holds it. An option valued `""` is an ordinary choice and does not become
the stop merely because the group has no value (plan `502`). Tab moves into the
group once and out again. The stop follows the item's **value**, so reordering
or filtering `options` does not move it to whatever now sits at the old index.

| Key | `single` | `multiple` |
| --- | -------- | ---------- |
| `←` / `→` (horizontal) | move focus **and** select the previous / next item, wrapping | move focus only |
| `↑` / `↓` (vertical) | the same on the vertical axis | the same on the vertical axis |
| `Home` / `End` | focus and select the first / last enabled item | focus the first / last enabled item |
| `Enter` | select on key **down** | toggle on key **down** |
| `Space` | select on key **up** | toggle on key **up** |
| any printable character | select **and** focus the next enabled item whose text starts with the typed prefix, wrapping; a repeated letter advances | focus that item without pressing it |
| a held key | ignored | ignored |

The group answers **only its orientation's axis**: `orientation="horizontal"`
(default) moves with `←`/`→`, `orientation="vertical"` with `↑`/`↓`, and the
cross-axis arrow is inert — the same contract as `RadioGroup`, and what keeps a
horizontal segmented control still while a user scrolls a form.

A disabled option is skipped by every movement and never receives focus from Tab
or the arrows; a disabled group has no tab stop at all. A pointer press on a
disabled item is refused, although the runtime still moves native focus to it
(measured, plan `601`) — the group records neither the press nor the stop.
Clicking an enabled item selects or toggles it, except the active item in
`single` mode, which is a no-op. A click also records
the item as the keyboard's return point: it moves native focus, but the pinned
release runtime dispatches no focus event, so `multiple` writes the tab stop
itself (plan `600`). A disabled item is never recorded, because its press is
refused.

An arrow **continues from the focused item**, not from the value-derived tab stop,
in both modes. A controlled parent can defer or reject the value an arrow reports;
the ring is the keyboard's cursor, so the next arrow moves on from the ring
instead of repeating the first move (plan `359`).

Type-ahead uses the item's resolved text (`label`, falling back to `value`) and
the same case-insensitive, 500 ms prefix rule as `RadioGroup` and `Select`
(plans `731`, `741`, `751`). The search starts after the keyboard's cursor — the
focused item, else the tab stop — and then after the last match, so a repeated
letter advances and a controlled parent that defers a report cannot pin the
prefix on one item. A disabled item or a blank label is skipped; a prefix that
matches nothing changes nothing and clears the buffer. `single` treats a match
like an arrow: it selects and focuses it. `multiple` only moves focus, because a
typed name must not toggle a formatting button — press `Enter` or `Space` to
activate the item it reached. A `cmd`/`ctrl`/`alt` chord, a held repeat and a
disabled group type nothing.

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). The same sample clears the group's event-tracked cursor
  when it names none of this group's items, so the ring and the arrow walk do
  not outlive focus (plan `601`). Role, name, tab order and activation are
  unaffected.
- The group is a named `group` (AccessKit `Group`); each item is a named
  `button` (`Button`) whose accessible name is the option's `label`, falling
  back to its `value` when the label is blank (plan `589`).
- **GPUix 0.10.0 has no `aria-pressed`** and no `aria-selected` for buttons, so
  the pressed state is announced through `aria-valuetext` — `"pressed"` /
  `"not pressed"` — exactly like `Toggle`, `Checkbox` and `Switch`. A screen
  reader therefore hears a button with a value, not a pressed button. There is
  also no single-select semantic in AccessKit for buttons; the group name says
  what the set is for.
- There is no `aria-labelledby`, so a visible heading cannot name the group by
  reference: put its words in `label`.
- Each item's label is **chrome, not content**: `userSelect: "none"`, so a drag
  across an item cannot select its text (measured before plan `386`: the drag
  selected `"Align left"`). A caller's `itemStyle` still merges last.

## Theming

Items read `core/variants.ts`' `toggleVariants` and the shared control resolver,
so pressed, hover and focus are three distinct states and no literal colour
appears here. The pressed fill is `colors.accent` / `colors.accentForeground`
(the theme's "selected surface"); the outline variant adds `colors.border`.
Sizes and the group gap come from `density` and `spacing["2xs"]`. Both themes
and the high-contrast palettes switch the whole group because it paints only
theme roles.

## Style by state

`style` takes an object or a callback over `ToggleGroupState` — the runtime's own
`StateStyle` type — merged last on the group container:

```tsx
<ToggleGroup style={(state) => ({ opacity: state.disabled ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | every item is disabled; an empty group is not |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

### Per-item style

`itemStyle` takes the same `StateStyle` over `ToggleItemState`, merged last on
the item — after its own paint and focus ring:

```tsx
<ToggleGroup
  type="multiple"
  itemStyle={(item) => (item.pressed ? { fontWeight: 600 } : {})}
/>
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `value` | `string` | the item's value |
| `index` | `number` | position in `options` |
| `pressed` | `boolean` | this item is pressed |
| `disabled` | `boolean` | the item is disabled |
| `focused` | `boolean` | the item holds native focus |

`ToggleItemState` is exported. One callback receives every item; branch on
`value` or `index`.

## Limitations


- No `aria-pressed` (above); the value text is the honest channel.
- The group has no container chrome: it is a flex row of buttons. Wrap it in a
  `Box` when you want a rounded segmented container, as `ButtonGroup` does for
  attached buttons.
- No arbitrary children: options are data (the `RadioGroup` decision, D16/D25).
  A per-item look is available through `itemStyle`; use `Toggle` when an item
  needs an icon or a count inside it.
- No `loading` state — a mode switch is instant; disable the group while a
  request is in flight.
- Pressing Space cannot be `preventDefault`ed in 0.10.0 (no
  `defaultPrevented`, no prevent API), so a group inside a scroll container may
  also scroll on Space.
- An item shares the group's width and clips its label to one line with an
  ellipsis, so a long option in a constrained group never paints outside it
  (plan `368`). A group with room still hugs its options. The **group root**
  carries the same floor removal: a bounded row shrinks the whole group to the
  row instead of letting it paint past it — measured, a group in a 220 px row
  painted 254 px before the rule and 220 px after, with its items shrinking to
  match (plan `747`). A caller's `style` still wins, so `minWidth` can pin a
  wider group.

## Verification

- `src/components/state-style.test.tsx` — the container state payload, each
  per-item payload, and the callback winning over the component's own rules
  (plans 080, 081).
- `runtime/state-style.runtime.test.tsx` — a labelled scroll region's focus, a
  select's open state, and the per-item states reaching the paint (plans 080,
  081).

- `src/core/toggle-group.test.ts` — single replaces and returns the same array
  on a re-press (no spurious `onValueChange`); multiple appends, removes and
  preserves a value the options do not contain.
- `src/components/ToggleGroup.test.tsx` — named group and buttons, value text
  and no `aria-pressed`, one tab stop in both modes, disabled item out of the
  tab order with its press refused, axis, accent paint, Enter/Space/click
  activation and the per-item `testId`.
- `runtime/toggle-group.runtime.test.tsx` — measured 2026-10-17 (plan 056 §9):
  a real click selects and unpresses the previous item; multiple toggles
  independently; Enter down and Space up activate once; an arrow moves focus
  **and** selection in `single` but only focus in `multiple`; a disabled item is
  skipped (wrapping past the ends); `focusNext` enters on the selected item and
  leaves the group on the next Tab; a disabled group is skipped and inert.
- `runtime/roving-arrows.runtime.test.tsx` — with a controlled parent that never
  applies the reported value, three arrows in `single` move the ring on to
  Centre, Right and back, and `multiple` keeps moving focus without reporting a
  press (plan `359`).
- `runtime/group-containment.runtime.test.tsx` — the group root shrinks to a
  220 px row it shares (measured 254 → 220), its items shrink inside it, a group
  in a 600 px row still hugs its options, the stretched-column paint is unchanged
  and a caller's `minWidth` wins (plan `747`).
- `runtime/toggle-group-typeahead.runtime.test.tsx` — a typed prefix selects and
  focuses the match in `single`, advances on a repeated letter, only focuses in
  `multiple` (a following Space presses it), skips disabled and blank items,
  leaves an unmatched letter inert, and types nothing for a held repeat or a
  disabled group (plan `751`).
- `src/docs-keyboard.test.ts` — the arrow rows on this page name their
  orientation and match `core/keyboard.ts`: every documented key is delivered for
  that axis, and the cross-axis pair is `None` (plan `394`).
