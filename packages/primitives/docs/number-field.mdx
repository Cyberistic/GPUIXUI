---
title: NumberField
description: A number in a text field, with steps and optional bounds.
---

`NumberField` is a numeric text field. GPUix's `<input>` has **no numeric
mode** — no `type`, no `min`, no spinner — so parsing, clamping, stepping and
the draft text are this package's (`core/number.ts`). It is not a slider: the
user types an exact number, and the arrows are a convenience.

## Usage

```tsx
import { NumberField, Label, Stack } from "@gpuixui/primitives";
import { useState } from "react";

const [copies, setCopies] = useState(1);

<Stack direction="column" gap="xs">
  <Label description="1–99">Copies</Label>
  <NumberField label="Copies" value={copies} onChange={setCopies} min={1} max={99} />
</Stack>;
```

An untouched field with neither `value` nor `defaultValue` renders empty, the
way a native number field does — it does not start with a zero to delete.

## Parts

| Part | Responsibility |
| ---- | -------------- |
| `NumberField` | the chrome, focus ring, state and the accessible name |
| `NumberFieldInput` | the native `<input>`: draft text, keys, focus and blur |
| `NumberFieldIncrement` | the step-up hit target (pointer only, never a tab stop) |
| `NumberFieldDecrement` | the step-down hit target |

The default composition is the input and a column of both steppers, painted by
the same functions the parts call. A caller who supplies `children` composes
the field themselves; each stepper accepts a custom glyph as its children, and
every part accepts `style`, `className` and `testId`, merged last.

```tsx
import { Icon } from "@gpuixui/icons";
import {
  NumberField,
  NumberFieldDecrement,
  NumberFieldIncrement,
  NumberFieldInput,
  Stack,
} from "@gpuixui/primitives";

<NumberField label="Copies" value={copies} onChange={setCopies} min={1} max={99}>
  <NumberFieldInput />
  <Stack direction="column" justify="between" style={{ height: "100%" }}>
    <NumberFieldIncrement>
      <Icon name="plus" size="xs" />
    </NumberFieldIncrement>
    <NumberFieldDecrement>
      <Icon name="minus" size="xs" />
    </NumberFieldDecrement>
  </Stack>
</NumberField>;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `number` | — | controlled value |
| `defaultValue` | `number` | none | start value; the field shows empty without one |
| `onChange` | `(value: number) => void` | — | the clamped number, after a valid edit or step |
| `min` / `max` | `number` | none | bound the value; absent means unbounded |
| `step` | `number` | `1` | arrow step |
| `precision` | `number` | `0` | decimals shown on commit |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | field height and padding |
| `disabled` | `boolean` | `false` | read-only, out of the tab order, inert |
| `invalid` | `boolean` | `false` | destructive border |
| `label` | `string` | none | accessible name |
| `placeholder` | `string` | none | empty-field hint |
| `autoFocus` | `boolean` | `false` | focus on mount |
| `formatValue` | `(value: number) => string` | fixed decimals | display text; parsing stays decimal |
| `style` | `StateStyle<FieldState>` | — | `StyleDesc` or `(state: { disabled, focused, invalid }) => StyleDesc`; resolved against the live state and merged last |
| `children` | `ReactNode` | input + steppers | the parts to draw |
| `testId` | `string` | — | stable locator on the field's chrome |

`NumberFieldInput` and both steppers accept `style`, `className` and `testId`;
the steppers also take `children` as a custom glyph. `NumberFieldInput` has no
`value`/`onChange` of its own: the parts read the field's state, so there is one
source of truth.

While the user types, the **draft text** is kept verbatim (`1.` stays `1.`), so
the caret never jumps. Every edit that parses reports the clamped number
through `onChange`; on blur or `Enter` the draft is reformatted to `precision`.

## Keyboard

| Key | Effect |
| --- | ------ |
| `ArrowUp` / `ArrowRight` | + one step |
| `ArrowDown` / `ArrowLeft` | − one step |
| `PageUp` / `PageDown` | ± ten steps |
| `Home` / `End` | `min` / `max` — only when the field has that bound |
| `Enter` | commit and reformat |

The spin buttons are pointer affordances, **not tab stops**: the field is one
tab stop and the arrows are the keyboard path, as in a native spinner. A click
on a stepper returns focus to the input so the next arrow works.

## Accessibility

- The input is a `TextInput` with the name from `label`; the steppers are
  `presentation`, so a screen reader sees one named number field rather than
  three controls.
- The value is the native input's text, which the runtime exposes to AccessKit.
  There is no `aria-valuenow`/`min`/`max` in GPUix 0.10.0.
- A disabled field is `readOnly`, out of the tab order and paints the disabled
  chrome; assistive technology hears read-only, which is the honest state (the
  host has no `disabled` prop).

## Theming

The field uses the shared field chrome (`colors.input`, `colors.border`,
`colors.inputForeground`), the `keyboardRing` outline on the **wrapper**, and
`colors.mutedForeground` icons in the spin column. Height and padding come from
`density`; nothing names a literal.

## Limitations

- **Decimal text only.** `1,5`, `0x10` and `Infinity` are rejected rather than
  guessed at; a locale decimal needs `formatValue` for display and parsing
  before the value reaches the field.
- **No `type="number"`, `inputMode` or `maxLength`.** The host input takes
  `value`, `placeholder`, `readOnly`, `theme` and its events — nothing else.
- **No drag-to-scrub.** The runtime has the coordinates and bounds for it, but a
  scrub that keeps tracking outside the field would need pointer capture, which
  does not exist; the steppers are the honest gesture.
- **`autoFocus` paints no ring on mount.** A focus that arrives without keyboard
  input (mount, programmatic) does not paint `focusVisible`, so the wrapper's ring
  appears at the first Tab. The same is true of `Input`.

## Verification

- `src/core/number.test.ts` — decimal-only parsing, clamping, precision,
  stepping, Home/End only with a bound.
- `src/components/NumberField.test.tsx` — the draft value, the key contract, the
  raw edit report, steppers as presentation, one tab stop, disabled/invalid,
  the four part names in a caller's composition, and the input part carrying
  the draft, name and keys.
- `runtime/number-field.runtime.test.tsx` — real typing through the native input
  reports `12`; `1.5` with `precision={2}`; `999` against `max=100` reports
  `100`; arrow/PageDown step; a hit-tested stepper press steps and refocuses;
  the chrome declares the keyboard ring and a press paints none; a disabled
  field refuses text, keys and clicks; a caller's composition of the input and
  both steppers reads the field's live value (a real press on each steps it).
  Measured 2026-10-17 (plan 054 §9).
