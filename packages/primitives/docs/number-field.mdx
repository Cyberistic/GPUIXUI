`NumberField` is a numeric text field: parsing, clamping and stepping are this
package's.

A field paints the number it holds: with no `precision` the box shows the value's
own decimals, so `step={0.5}` reads `1.5` rather than a rounded `2` and no key can
paint a number past the bound. `precision` fixes the painted width when a column
needs one (`precision={2}` paints `1.50`); it rounds and pads the **text**, and
the value channel keeps the number it was given.

## Usage

```tsx
import { NumberField, Label, Stack } from "@gpuixui/primitives";
import { useState } from "react";

const [copies, setCopies] = useState(1);

<Stack direction="column" gap="xs">
  <Label description="1–99">Copies</Label>
  <NumberField label="Copies" value={copies} onValueChange={setCopies} min={1} max={99} />
</Stack>;
```

## Composition

| Part | Responsibility |
| ---- | -------------- |
| `NumberField` | the chrome, state and the accessible name |
| `NumberFieldInput` | the native `<input>`: draft text, keys, focus, ring |
| `NumberFieldIncrement` / `NumberFieldDecrement` | the step hit targets (pointer only) |

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `number` | — | controlled value |
| `defaultValue` | `number` | none | start value; the field shows empty without one |
| `onValueChange` | `(value: number) => void` | — | the clamped number, after a valid edit or step |
| `onValueCommit` | `(value: number) => void` | — | the value a gesture ended on: once per stepper press, once per scrub release, once per arrow or page key that moved it, and once when a typed edit ends on a readable value |
| `onChange` | `(value: number) => void` | — | deprecated alias for `onValueChange` |
| `min` / `max` | `number` | none | bound the value; absent means unbounded, and an inverted pair is the range it means |
| `step` | `number` | `1` | arrow step |
| `precision` | `number` | the value's own decimals | decimals painted on commit; it rounds and pads the text, and the value keeps its own |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | field height and padding |
| `disabled` | `boolean` | `false` | read-only, out of the tab order, inert |
| `invalid` | `boolean` | `false` | destructive border |
| `label` | `string` | none | accessible name |
| `onSubmit` | `(event: EventPayload) => void` | — | Enter: the draft commits first, then this reports |
| `description` | `string` | none | announced help on the input (`aria-description`); a caller's permanent help wins over the hint |
| `placeholder` | `string` | none | empty-field hint, painted in the `placeholder` role and announced as the field's description while the box is empty (the host's own hint is a fixed grey no theme reaches) |
| `autoFocus` | `boolean` | `false` | focus on mount |
| `formatValue` | `(value: number) => string` | fixed decimals | the display text, display-only; pair it with `parseValue` |
| `parseValue` | `(text: string) => Option<number>` | none | reads the text `formatValue` painted; tried first, then decimal |
| `className` | `string` | — | a Tailwind class string, joined after the recipe so it wins conflicts |
| `style` | `StateStyle<FieldState>` | — | resolved against the live state, merged last |
| `children` | `ReactNode` | input + steppers | the parts to draw |
| `onClick` / `onKeyDown` / `onKeyUp` / `onFocus` / `onBlur` | host handlers | none | composed with the field's own; a disabled field keeps them observable |
| `ref` / `aria-id` / `onLayout` | host props | none | the native `<input>` is the addressed element |
| `testId` | `string` | — | stable locator on the field's chrome |

`formatValue` paints; it does not teach the field to read. `parseValue` is the
counterpart and is consulted before the decimal grammar, so a grouped field stays
editable, and a controlled owner's echo is read through the same path rather than
reformatting under the caret.

`onValueChange` is every frame the value moved; `onValueCommit` is the end of the
gesture. A scrub across the spin column reports a value per four pixels and one
commit on release, with the value the whole drag finished on; a stepper press, an
arrow and a PageUp/PageDown each commit as they land, because there is no release
after them to wait for. A typed edit commits when it ends — blur or Enter — if it
holds a readable number, including text that parses to the value the field already
held, because the edit happened. Text that is not a number produces no value, and
an arrow that cannot move the value at its bound is not a gesture that ended on a
new one, so neither commits. Persist or fetch here instead of debouncing
`onValueChange`.

## Absence

A field's value channel is a number, so **an empty box is a cancelled edit, not a
new value**. An edit that ends — blur or Enter — with no readable number leaves
the field showing the number it already had; a field that never had one stays
empty instead of painting the zero its internal range starts from. Text that is
not a number (`abc`) is the same case as no text, and neither reports
`onValueChange`. A field with `defaultValue={0}` or `value={0}` does hold zero,
and paints it, because that zero is a value the caller chose.

Starting empty and stepping works: the field's value channel starts at the
range's floor (`min`, else 0, clamped by `max`), while the box paints empty until
a gesture produces a number — so the first step moves one `step` from that floor
(with `min={72}` and `step={12}`, the first increment reports `84`) and is
reported like any other step.

## Keyboard

| Key | What it does |
| --- | ------------ |
| `↑` / `↓` | one `step` up or down, clamped |
| `PageUp` / `PageDown` | ten steps |
| `Home` / `End` | the core's bounds jump — **not delivered to a field in a window** |
| `Enter` | the draft commits — a readable edit reports `onValueCommit`, then `onSubmit` |
| any other key | left to the form |

A native `<input>` consumes `Home` and `End` for its own caret before React sees
them: measured on 0.11.0, neither the input's `onKeyDown` nor a wrapper's receives
them, while `PageDown` arrives. So the bounds jump is the pure contract's
(`core/number.ts`'s `decideNumberKey`) and the offscreen renderer's, and the keys
a window delivers are the arrows and the page pair. Bind `Home`/`End` at the
window level (`@gpuixui/keyboard`) when a form needs them;
`runtime/number-field.runtime.test.tsx` holds the measurement.

## Limitations

- Decimal text by default: a grouped or locale display is read through the
  `formatValue`/`parseValue` pair, never guessed.
- An inverted pair is the range it means: `min` above `max` is swapped, and the
  core's `Home`/`End` jump reads the ends of that swapped range — though a
  window never delivers those two keys to a text field (see Keyboard above).
- No `type="number"`, `inputMode` or `maxLength`: the runtime applies a value only when it changes, so a refused character stays in the box.
- `autoFocus` paints no ring; Enter is the runtime's Submit action, not a keydown.
