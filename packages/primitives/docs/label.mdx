---
title: Label
description: A control's visible name, with a required marker and a description.
---

`Label` renders the **visible** name of a field. It is not associated with the
control by reference — GPUix 0.10.0 has no `aria-labelledby` — so the control
carries its own `aria-label` through its `label` prop. `labelledBy(name)` builds
that prop from the same string.

It can still do the one thing a native label does: give it the control's ref as
`control` and a press on the visible name focuses that control. That is a
pointer convenience, **not** an association — the control's own `label` remains
its accessible name.

## Usage

```tsx
import { Input, Label, labelledBy } from "@gpuixui/primitives";

const name = "Workspace name";

<Label description="Shown on invitations and in the app switcher.">
  {name}
</Label>
<Input {...labelledBy(name)} fullWidth />;
```

With click-to-focus, pass the field's ref to both the label and the field:

```tsx
import { useRef } from "react";
import type { PublicInstance } from "@gpuix/react";
import { Input, Label } from "@gpuixui/primitives";

const field = useRef<PublicInstance | null>(null);

<Label control={field}>Workspace name</Label>
<Input ref={field} label="Workspace name" fullWidth />;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `required` | `boolean` | `false` | appends a destructive `*`, announced as an image named by `requiredLabel` |
| `requiredLabel` | `string` | `"required"` | the marker's accessible name; a blank value falls back to the default |
| `invalid` | `boolean` | `false` | paints the name in the destructive role |
| `description` | `string` | none | a caption line under the name; a blank one paints nothing |
| `control` | `RefObject<PublicInstance \| null>` | none | a press on the visible label moves native focus to that control; pointer-only, and no `aria-labelledby` association |
| `style` | `StateStyle<LabelState>` | — | merged last; an object or a state callback |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the name |

`labelledBy(name): { label: string }` returns the prop every control reads, so a
caller spreads it into an `Input`, `TextArea`, `Select`, `Checkbox`, `Switch` or
`RadioGroup` instead of spelling the name twice.

## Keyboard

Not focusable. A label is pointer-only: `control` moves focus on a press, and
keyboard users Tab to the control directly. The press runs no activation — it
never changes a value.

## Accessibility

- The visible name is an accessibility `Label` node.
- The control's own `label` prop is its accessible name; there is **no
  `aria-labelledby`**, so the two are separate nodes. A test asserts both exist
  (`fields.runtime.test.tsx`).
- `control` moves native focus on a press. It adds no relation, no `for` and no
  name — assistive technology still hears only the control's own `label`.
- `required` is a mark, not `aria-required`; 0.10.0 has no `aria-required`, and
  the runtime has no `aria-labelledby` to bind the mark to the control. The
  marker itself **is** announced — as an image named `required`, read after the
  name — but the field's own node carries no required flag. Validation must also
  be expressed in words and in the control's `invalid` state.
- `requiredLabel` localises that spoken name (e.g. `"obligatoire"`); a blank
  value falls back to `"required"` rather than publishing an unnamed image.
- The marker is a separate node: in reading order it follows the name, but
  tabbing straight to the control announces only the control's own `label`.
- `invalid` is colour plus the field's border; it is not announced by itself.

## Theming

The name uses the `label` role and the `foreground` (or `destructive`) role; the
description uses `caption` + `mutedForeground`. The required star is
`destructive`, and its **meaning** comes from `requiredLabel`: the star paints as
text but reaches assistive technology as an image with that name (plan `581`). No
literal size or colour.

A clickable label's only extra paint is `cursor: "pointer"`, and a caller's
`style` can still override it. It takes **no** hover or press wash: a label is
text, not a clickable row (plan `749`).

## Style by state

`style` takes an object or a callback over `LabelState` — the runtime's own
`StateStyle` type — merged last on the label stack:

```tsx
<Label style={(state) => ({ opacity: state.invalid ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `invalid` | `boolean` | the name takes the destructive role |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

## Limitations

- **Focus, not association.** `control` moves focus on a press; the name is
  still written twice (the visible label and the control's `label`), because
  GPUix 0.10.0 has no `aria-labelledby` and no `for`/`htmlFor`.
- `control` targets a **single-root** control: `Input`, `TextArea`,
  `NumberField`, `Select`, `Checkbox`, `Switch`, `Button` and `Toggle`. A roving
  group's ref is its non-focusable root, so a press on a label pointing at
  `RadioGroup`, `CheckboxGroup`, `ToggleGroup`, `Rating`, `Slider`,
  `RangeSlider` or `OTPField` focuses nothing.
- Only the **painted text** is a target: the empty part of a full-width label is
  not hit-tested (measured, plan `749`), so a press there does nothing.
- A **disabled** target receives focus if the ref points at one. The renderer
  exposes no focusable query and the ref carries no state; the control's
  handlers are guarded (plan `025`) and it paints no ring (plan `332`). Point
  `control` at a control that can take focus.
- `required` does not validate anything. Validate with `Schema` at the boundary.
- The required marker is not associated with the control (no `aria-labelledby`);
  it is announced in reading order as an image named by `requiredLabel`, but a
  screen-reader user who tabs directly to the control does not hear it.
- A long name wraps inside the label's own row (the label is full width), so a
  form column does not grow sideways (plan `368`).
- The required marker keeps its own width while the name wraps. A narrow column
  used to squeeze the star — measured, 2.5 px in a 60 px column and 0.5 px in a
  12 px one, from 6 px at full width — because the name's shrink floor also
  applied to the marker. The star now opts out of shrinking (plan `647`).
- A blank `description` is not a description: it paints no caption line, so a
  computed missing hint cannot leave a blank row under the name (plan `577`).

## Verification

- `src/components/state-style.test.tsx` — the state payload and the callback
  winning over the component's own rules (plan 080).
- `runtime/state-style.runtime.test.tsx` — a labelled scroll region's focus and
  a select's open state reaching the paint (plan 080).

- `src/components/fields.test.tsx` — name, description, required and invalid
  resolve as specified, and a blank description paints no caption (plan `577`).
- `src/components/presentational.test.tsx` — a named `Text` is an image, a blank
  name is absent, and the marker's name defaults/trims/falls back (plan `581`).
- `runtime/fields.runtime.test.tsx` — the visible `Label` and the control's
  `TextInput` name are both present in the accessibility dump.
- `runtime/label-required.runtime.test.tsx` — a required marker is an `Image`
  named `required` (or `requiredLabel`) and no bare `*` node exists; a label
  without `required` publishes no image (plan `581`); the marker keeps its
  painted width in a narrow column while the name wraps (plan `647`).
- `src/components/Label.test.tsx` — the activation rule (no control → no
  handler, a ref focuses its instance, a null ref and a missing renderer are
  no-ops), the pointer cursor with no wash, no tab stop or invented role, the
  caller's cursor winning, and the unchanged name/marker/description tree
  (plan `749`).
- `runtime/label-control.runtime.test.tsx` — a real press on the painted name
  and on the description focuses the field; a label without `control`, and a ref
  that names nothing, leave focus where it was; Tab still skips the label
  (plan `749`).
