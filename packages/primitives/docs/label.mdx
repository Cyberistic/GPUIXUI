---
title: Label
description: A control's visible name, with a required marker and a description.
---

`Label` renders the **visible** name of a field. It is not associated with the
control by reference, so the control carries its own `aria-label` through its
`label` prop; `labelledBy(name)` builds that prop.

## Usage

```tsx
import { Input, Label, labelledBy } from "@gpuixui/primitives";

const name = "Workspace name";
const help = "Shown on invitations and in the app switcher.";

<Label description={help}>{name}</Label>
<Input {...labelledBy(name)} description={help} fullWidth />;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `required` | `boolean` | `false` | appends a destructive `*`; visual only |
| `invalid` | `boolean` | `false` | paints the name in the destructive role |
| `description` | `string` | none | a caption line under the name |
| `className` | `string` | — | a Tailwind class string, joined after the recipe so it wins conflicts |
| `style` | `StyleDesc` | — | merged last |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the name |

## Limitations

- No click-to-focus: the runtime has no `for`/`htmlFor`.
- No association by reference — the name is written in two places when both the
  visible label and the control's name are needed; `labelledBy(name)` writes the
  control's copy.
- The visible description is a second copy: the control announces only its own
  `description`.
- `required` does not validate; validate with `Schema` at the boundary.
