`Label` renders the **visible** name of a field. It is not associated with the
control by reference — the runtime has no `aria-labelledby` — so the control
carries its own `aria-label` through its `label` prop, and `labelledBy(name)`
builds that prop. Given the control's `target` ref, a press on the label moves
native focus to it: the `htmlFor` behaviour, through the renderer's
`focusElement`.

## Usage

```tsx
import { useRef } from "react";
import type { PublicInstance } from "@gpuix/react";
import { Input, Label, labelledBy } from "@gpuixui/primitives";

const name = "Workspace name";
const help = "Shown on invitations and in the app switcher.";

export const NameField = () => {
  const ref = useRef<PublicInstance>(null);
  return (
    <>
      <Label target={ref} description={help}>
        {name}
      </Label>
      <Input ref={ref} {...labelledBy(name)} description={help} fullWidth />
    </>
  );
};
```

A label with no `target` is text only: that is the right form when there is no
single control to focus, or when the words sit in a legend above a group.

Help that comes from data is often blank rather than absent. A `description`
with no visible character paints **no line at all** — the same rule the name
keeps — because an empty `<text>` still pays its column's gap and a run of
spaces lays out a whole line. The control announces nothing for it either, so
the visible help and the spoken help cannot disagree.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `target` | `RefObject<PublicInstance \| null>` | none | a press on the label focuses this control |
| `disabled` | `boolean` | `false` | drops that press, for a control that is disabled |
| `required` | `boolean` | `false` | appends a destructive `*`; visual only |
| `invalid` | `boolean` | `false` | paints the name in the destructive role |
| `description` | `string` | none | a caption line under the name; a blank one paints nothing, the rule a blank name keeps |
| `className` | `string` | — | a Tailwind class string, joined after the recipe so it wins conflicts |
| `style` | `StyleDesc` | — | merged last |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the name |

## Limitations

- No association by reference: the runtime has no `aria-labelledby` and no
  `for`/`htmlFor`, so the name is written in two places when both the visible
  label and the control's name are needed. `target` moves the focus; it does not
  name the control — keep spreading `labelledBy(name)`.
- A press moves the focus; it does not activate the control. The runtime
  publishes no press verb for another element, so a checkbox or switch whose
  words must toggle is a `CheckboxGroup` row, where the row itself is the
  control.
- A label holds the control's element, not its state. Pass `disabled` with the
  control's own boolean, or a press focuses a control that refuses every key
  (measured: without it the disabled field took the focus).
- The visible description is a second copy: the control announces only its own
  `description`.
- `required` does not validate; validate with `Schema` at the boundary.
