---
title: OTPField
description: A one-time code in length cells, held as one contiguous string.
---

`OTPField` is a one-time-code entry control: `length` single-character
`<input>` cells over one value. GPUix's `<input>` holds text natively, so the
cells keep the caret and the selection; what is ours is the distribution of the
code over them (`core/otp.ts`) and the movement of native focus between cells.
It is **not** six independent fields: a caller passes and receives one string.

## Usage

```tsx
import { OTPField, Label, Stack } from "@gpuixui/primitives";
import { useState } from "react";

const [code, setCode] = useState("");

<Stack direction="column" gap="xs">
  <Label description="Six digits from your authenticator">
    Verification code
  </Label>
  <OTPField
    label="Verification code"
    value={code}
    onValueChange={setCode}
    onComplete={(complete) => verify(complete)}
  />
</Stack>;
```

`length` defaults to six. The value is **contiguous from the first cell**, so
typing into a cell beyond the current code appends at the end rather than
leaving a hole.

## Code handling

Only letters and digits are kept. A pasted `123-456` becomes `123456`, and a
code longer than `length` is truncated rather than partially applied. An edit
that carries no letter or digit — a typed separator, a space — **leaves the cell
as it was**, so a code a provider prints with hyphens can be typed without
losing a digit (plan `358`).

A real clipboard paste takes that same path. There is no `onPaste` in 0.10.0,
and none is needed: the native `<input>` reports the pasted run as one
multi-character edit, so `applyOtpInput` fills it forward from the receiving
cell. Measured in the runtime (plan `752`): copying `123456` and pasting into
cell 1 fills all six cells with **one** `onValueChange` and **one** `onComplete`
and leaves focus on the last cell; `123-456` drops the separator; an eight-digit
run truncates to six; a paste into a full code replaces from the receiving cell
onward (`999999` with `123456` pasted at cell 3 → `991234`); and a disabled field
refuses it. The headless `TestRenderer` and a real window both use the **system**
pasteboard, so the package's paste test replaces the clipboard.

`onComplete` is not a one-shot event: every edit that leaves the code full
reports the new code, including a correction made inside a code that was already
full. That is what lets the usual `onComplete={(code) => verify(code)}` verify a
mistyped digit again without the user clearing a cell first (plan `360`).

## Submit

Unlike `TextArea` — where Enter is the newline — a one-time code has no newline
to lose, so Enter is the platform's submit gesture on any cell (the `Input` and
`NumberField` rule, plans `046`/`339`). `onSubmit` reports **the code the field
holds**, not the cell's raw event: every other callback here speaks one string,
and which cell reported it is an implementation detail.

```tsx
<OTPField
  label="Verification code"
  onValueChange={setCode}
  onSubmit={(code) => verify(code)}
/>
```

A partial code is submitted as it stands — the field does not validate, exactly
as `onValueChange` reports partial codes — so the caller decides whether `12` is
worth sending. A `readOnly` field still submits the code it is showing, while a
`disabled` field reports nothing: it is inert on every path. Enter does not move
the caret or the cell.

## Read-only

`readOnly` shows a code without allowing an edit: every cell is visible, the
field keeps **one** tab stop — the first cell, because there is no editing
cursor — and the normal chrome. Typing, paste, Backspace and the arrow keys
change nothing, and neither `onValueChange` nor `onComplete` fires. Use it for a
verified code or a receipt; use `disabled` when the field should leave the tab
order entirely (plan `786`).

```tsx
<OTPField label="Verified code" value={code} readOnly />
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `length` | `number` | `6` | number of cells; a nonsense value resolves to at least one |
| `value` | `string` | — | controlled code, normalised to letters/digits |
| `defaultValue` | `string` | — | initial code when uncontrolled |
| `onValueChange` | `(value: string) => void` | — | the code after every edit that changed it |
| `onComplete` | `(value: string) => void` | — | fires after an edit that leaves the code full, with the new code |
| `onSubmit` | `(value: string) => void` | — | Enter in any cell, with the code the field holds; a partial code is submitted as it stands, a `readOnly` field still submits, and a `disabled` one reports nothing (plan `805`). The payload is the code, not the cell's event |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | no effect since plan `372`: every cell is the field's square (`h-9`, 36 × 36) |
| `disabled` | `boolean` | `false` | read-only, out of the tab order, inert |
| `readOnly` | `boolean` | `false` | visible and focusable, but no cell accepts typing, paste, Backspace or an arrow; one tab stop remains on the first cell (plan `786`) |
| `invalid` | `boolean` | `false` | destructive border on every cell |
| `label` | `string` | none | group name; each cell is named `<label> digit N` (`"Code digit N"` when blank) |
| `autoFocus` | `boolean` | `false` | focuses the first cell on every mount, including a field added after a loading state (plan `584`); its ring paints from mount |
| `style` | `StateStyle<OTPFieldState>` | — | merged last on the group; an object or a state callback |
| `cellStyle` | `StateStyle<OTPCellState>` | — | merged last on each cell; an object or a state callback |
| `testId` | `string` | — | the group's locator; cells are `<testId>-cell-N` |

## Keyboard

| Key | Effect |
| --- | ------ |
| `Tab` | enters the field at the first empty cell (the last when the code is full; the first cell when read-only) and leaves it from the focused cell |
| any letter or digit | replaces the cell, then focus advances |
| a separator (`-`, space, …) | kept out of the code; the cell and the caret stay put |
| `ArrowLeft` / `ArrowRight` | previous / next cell |
| `Home` / `End` | first / last cell |
| `Backspace` | deletes the current character; in an empty cell, clears the one before and moves there |
| `Delete` | deletes the current character (native) |
| `Enter` | reports the code to `onSubmit`; the caret and the cell stay put |

The field is **one tab stop**, not `length` stops (plan `076`): Tab enters where
typing continues and the next Tab leaves the code, so a form does not appear to
stall for five presses. While a cell holds focus it is the stop; once the field
is left, the resting stop is derived from the value. Arrows, Home/End and typing
are how a keyboard user moves inside the code.

The key contract runs on **key up**. GPUix's text editor consumes
Left/Right/Home/End/Backspace/Delete on key down, so those keys never reach the
element's key-down handler (measured 2026-10-17, plan 054 §9). A held arrow
therefore moves one cell rather than repeating. Backspace on a filled cell is
the native edit and arrives through `onValueChange`; the key-up handler knows this
and does not delete a second character.

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). Role, name, tab order, keyboard operation and activation
  are unaffected.
- The field is a named `Group` and each cell is a named `TextInput`
  ("Verification code digit 1" …). A screen reader can read every cell and the
  group's name.
- There is no `aria-labelledby` in 0.10.0, so each cell carries its own
  `aria-label` written from the group's `label`; a `Label` beside the field is
  the visible name.
- A disabled field is `readOnly` and every cell is out of the tab order; its
  `group` node announces `unavailable` in the description, and a read-only one
  announces `read only` (plan `810`). A **read-only** field keeps one tab stop
  (cell 1) and the normal chrome, and refuses every edit at the component as
  well as the host (plan `786`).
- `invalid` puts `invalid` in that same group description — the channel the
  missing `aria-invalid` is filled with (plan `812`) — and paints the cells'
  borders; a visible error message is still the caller's.
- The code is one tab stop, so assistive technology and the Tab order see one
  control with `length` named inputs inside it.
- The code itself is the native input text; there is no `aria-valuetext` on a
  cell, so the value is not announced twice.

## Theming

Cells use the shared field recipe via `otpCellStyle` (plan `372`): the recipe's
**36 high, 6 radius, 14/20 type**, made square with no horizontal padding so the
digit centres, plus the recipe's focus/invalid/disabled buckets — the ring lands
on the focused cell only. The theme supplies the paint (`colors.input`,
`colors.border`, `colors.inputForeground`) and the destructive role when
`invalid`; the row gap is the `sm` spacing step. A cell does not follow
`density`, and `size` no longer moves it. Every cell carries the recipe's
`shadow-xs` elevation at rest; the focused cell's ring replaces it (plan `585`).

## Style by state

`style` takes an object or a callback over `OTPFieldState` — the runtime's own
`StateStyle` type — merged last on the group box:

```tsx
<OTPField style={(state) => ({ opacity: state.disabled ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | the field refuses input and leaves the tab order |
| `readOnly` | `boolean` | the field refuses edits but stays focusable (plan `786`) |
| `invalid` | `boolean` | every cell paints the destructive border |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

### Per-item style

`cellStyle` takes the same `StateStyle` over `OTPCellState`, merged last on each
native `<input>` cell:

```tsx
<OTPField cellStyle={(cell) => (cell.filled ? { opacity: 1 } : { opacity: 0.7 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `index` | `number` | 0-based cell position |
| `filled` | `boolean` | the cell holds a character |
| `focused` | `boolean` | the cell holds native focus |
| `disabled` | `boolean` | the field is disabled |
| `readOnly` | `boolean` | the field is read-only (plan `786`) |
| `invalid` | `boolean` | every cell paints the destructive border |

`OTPCellState` is exported. One callback receives every cell; branch on `index`
or `filled`.

## Limitations

- **Arrows do not repeat.** They are handled on key up, because the editor
  consumes their key down.
- **The code is contiguous.** Clearing a middle character shifts the following
  characters left; there is no sparse representation, which is why the public
  value is a single string.
- **No letter casing rule.** Letters are kept as typed; a caller that needs
  uppercase normalises in `onValueChange`.
