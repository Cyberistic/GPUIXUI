---
title: OTPField
description: A one-time code in length cells, held as one contiguous string.
---

`OTPField` is a one-time-code entry control: `length` single-character
`<input>` cells over one value. GPUix's `<input>` holds text natively, so the
cells keep the caret and the selection; what is ours is the distribution of the
code over them (`core/otp.ts`) and the movement of native focus between cells.
It is **not** six independent fields: a caller passes and receives one string.

## Usage

```tsx
import { OTPField, Label, Stack } from "@gpuixui/primitives";
import { useState } from "react";

const [code, setCode] = useState("");

<Stack direction="column" gap="xs">
  <Label description="Six digits from your authenticator">
    Verification code
  </Label>
  <OTPField
    label="Verification code"
    value={code}
    onValueChange={setCode}
    onComplete={(complete) => verify(complete)}
  />
</Stack>;
```

`length` defaults to six. The value is **contiguous from the first cell**, so
typing into a cell beyond the current code appends at the end rather than
leaving a hole.

## Variants, sizes and states

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `length` | `number` | `6` | number of cells; a nonsense value resolves to at least one |
| `value` | `string` | — | controlled code, normalised to letters/digits |
| `defaultValue` | `string` | — | initial code when uncontrolled |
| `onValueChange` | `(value: string) => void` | — | the code after every edit that changed it |
| `onComplete` | `(value: string) => void` | — | fires when an edit makes the code full |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | cell height and width, from the density scale |
| `disabled` | `boolean` | `false` | read-only, out of the tab order, inert |
| `invalid` | `boolean` | `false` | destructive border on every cell |
| `label` | `string` | none | group name; each cell is named `<label> digit N` |
| `autoFocus` | `boolean` | `false` | focuses the first cell on mount; its ring paints from mount |
| `style` | `StateStyle<OTPFieldState>` | — | merged last on the group; an object or a state callback |
| `cellStyle` | `StateStyle<OTPCellState>` | — | merged last on each cell; an object or a state callback |
| `testId` | `string` | — | the group's locator; cells are `<testId>-cell-N` |

Only letters and digits are kept. A pasted `123-456` becomes `123456`, and a
code longer than `length` is truncated rather than partially applied.

## Keyboard

| Key | Effect |
| --- | ------ |
| `Tab` | enters the field at the first empty cell (the last when the code is full) and leaves it from the focused cell |
| any character | replaces the cell, then focus advances |
| `ArrowLeft` / `ArrowRight` | previous / next cell |
| `Home` / `End` | first / last cell |
| `Backspace` | deletes the current character; in an empty cell, clears the one before and moves there |
| `Delete` | deletes the current character (native) |

The field is **one tab stop**, not `length` stops (plan `076`): Tab enters where
typing continues and the next Tab leaves the code, so a form does not appear to
stall for five presses. While a cell holds focus it is the stop; once the field
is left, the resting stop is derived from the value. Arrows, Home/End and typing
are how a keyboard user moves inside the code.

The key contract runs on **key up**. GPUix's text editor consumes
Left/Right/Home/End/Backspace/Delete on key down, so those keys never reach the
element's key-down handler (measured 2026-10-17, plan 054 §9). A held arrow
therefore moves one cell rather than repeating. Backspace on a filled cell is
the native edit and arrives through `onValueChange`; the key-up handler knows this
and does not delete a second character.

## Accessibility

- The field is a named `Group` and each cell is a named `TextInput`
  ("Verification code digit 1" …). A screen reader can read every cell and the
  group's name.
- There is no `aria-labelledby` in 0.10.0, so each cell carries its own
  `aria-label` written from the group's `label`; a `Label` beside the field is
  the visible name.
- A disabled field is `readOnly` and every cell is out of the tab order.
- The code is one tab stop, so assistive technology and the Tab order see one
  control with `length` named inputs inside it.
- The code itself is the native input text; there is no `aria-valuetext` on a
  cell, so the value is not announced twice.

## Theming

Cells use the shared field chrome (`colors.input`, `colors.border`,
`colors.inputForeground`) via `otpCellStyle`, the destructive role when
`invalid`, and `controlFocusStyle`'s ring on the focused cell only. Cell size
comes from `density.controlHeight[size]`; the row gap is the `sm` spacing step.
No literal colour, size or radius is named.

## Style by state

`style` takes an object or a callback over `OTPFieldState` — the runtime's own
`StateStyle` type — merged last on the group box:

```tsx
<OTPField style={(state) => ({ opacity: state.disabled ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | the field refuses input and leaves the tab order |
| `invalid` | `boolean` | every cell paints the destructive border |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

### Per-item style

`cellStyle` takes the same `StateStyle` over `OTPCellState`, merged last on each
native `<input>` cell:

```tsx
<OTPField cellStyle={(cell) => (cell.filled ? { opacity: 1 } : { opacity: 0.7 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `index` | `number` | 0-based cell position |
| `filled` | `boolean` | the cell holds a character |
| `focused` | `boolean` | the cell holds native focus |
| `disabled` | `boolean` | the field is disabled |
| `invalid` | `boolean` | every cell paints the destructive border |

`OTPCellState` is exported. One callback receives every cell; branch on `index`
or `filled`.

## Limitations


- **Paste is unverified.** `@gpuix/native` 0.10.0 has no `onPaste` and the
  `TestRenderer` has no clipboard simulation. A multi-character edit fills
  forward from the receiving cell — proven as a pure rule — but the real
  clipboard path has not been observed; it is documented as unverified rather
  than claimed.
- **Arrows do not repeat.** They are handled on key up, because the editor
  consumes their key down.
- **The code is contiguous.** Clearing a middle character shifts the following
  characters left; there is no sparse representation, which is why the public
  value is a single string.
- **No letter casing rule.** Letters are kept as typed; a caller that needs
  uppercase normalises in `onValueChange`.

- `src/components/state-style.test.tsx` — the container state payload, each
  per-item payload, and the callback winning over the component's own rules
  (plans 080, 081).
- `runtime/state-style.runtime.test.tsx` — a labelled scroll region's focus, a

  replacement and advance, accumulated-text stripping, multi-character fill,
  range clamping, Backspace and navigation rules, and the resting tab stop
  (first empty cell, last cell when full, nonsense lengths).
- `src/components/OTPField.test.tsx` — `length` named inputs, per-cell handlers,
  click-to-pick, autoFocus on the first cell, one ring, destructive borders,
  square geometry, disabled guards, and **exactly one `tabIndex={0}`** on the
  first empty / focused cell.
- `runtime/otp.runtime.test.tsx` — six digits **typed one at a time** fill six
  cells and complete once; focus advances and moves back with the arrow keys;
  Backspace clears backwards on an empty cell and only one character on a
  filled one; the a11y tree has a `Group` and six `TextInput`s; invalid paints
  every cell; one ring, painted from mount with `autoFocus`; disabled refuses
  input and leaves the tab order; **Tab enters the code once and leaves it**
  (plan `076`). Measured 2026-10-17 (plans 054 §9, 064 §6 and 076 §7).
