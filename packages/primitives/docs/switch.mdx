---
title: Switch
description: An immediate on/off, distinct from a checkbox in intent.
---

`Switch` is the "takes effect now" control: a track and a thumb, announced with
the switch role. It shares `core/selection.ts`'s metrics with `Checkbox`, so the
two line up on the same row, but they mean different things — a checkbox is a
choice submitted with a form, a switch is applied immediately.

## Usage

```tsx
import { Switch } from "@gpuixui/primitives";

<Switch checked={paused} onValueChange={setPaused}>
  Pause all notifications
</Switch>;

<Switch
  checked={wifi}
  onValueChange={setWifi}
  label="Wi-Fi"
/>;
```

A text child is the switch's **visible label**: the row becomes the hit area,
the tab stop and the accessible name, so a press anywhere toggles it and a
screen reader hears the text. Without children the track renders on its own and
takes its name from `label`. The text may be wrapped (`<Switch><Text>Pause
</Text></Switch>`) or sit beside a decorative icon: the name is the text the row
paints (plan `746`). An icon **alone** paints no text and names nothing — pass
`label`.
The icon and the words share **one line**: GPUix stacks a box's children on the
cross axis by default, so before plan `803` the star painted above the word in a
33 px label column instead of the row's one 17 px line. A text-only label is
unchanged.

**A blank text child is not a label.** A computed label that trims to nothing
paints no row: the track renders on its own and `label` (when supplied) still
names it. A blank run beside real text is ignored, and the row is named by the
text that says something (plan `743`). The same holds when the label is wrapped
for typography — `<Switch><Text>{label}</Text></Switch>` is looked through,
because a `Text` run paints exactly its children (plan `782`). This is the same
blank-text rule as an empty `label` or caption, and it prevents an empty row and
an unnamed focus stop.

A labelled row can carry a second line. `description` is a visible hint under
the label, and the same string is the row's announced description:

```tsx
<Switch description="Pauses every background sync.">Pause syncing</Switch>;
```

A blank `description` paints no line and announces nothing. Without `children`
there is no row to paint into, so the hint is announced but not painted.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `checked` | `boolean` | — | controlled; omit to let the switch keep its own state |
| `defaultChecked` | `boolean` | `false` | initial state when uncontrolled |
| `onValueChange` | `(next: boolean) => void` | none | the next boolean |
| `disabled` | `boolean` | `false` | refuses pointer and keys, leaves the tab order |
| `readOnly` | `boolean` | `false` | keeps the tab stop, ring and announced value; refuses every change and paints full contrast (plan `799`) |
| `autoFocus` | `boolean` | `false` | takes native focus on mount, including a later mount, and rings while it holds it; a disabled switch never does, a read-only one still does (plan `807`) |
| `invalid` | `boolean` | `false` | the track takes the destructive role |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | track height from `iconSize` |
| `accent` | `"primary" \| "destructive"` | `"primary"` | the on-track fill |
| `label` | `string` | none | accessible name; wins over `children`, and a blank value falls back to them |
| `children` | `ReactNode` | none | a visible label **inside** the control: the row becomes the hit area, the tab stop and the name. Text may be nested in an element (a `Text` run, or a word beside an icon); an icon alone names nothing (plan `746`). A blank text child — raw or inside a `Text` run — paints no row (plans `743`, `782`) |
| `description` | `string` | none | a visible hint **under** the label in a labelled row; it is also the row's announced description, trimmed, and a blank value paints and announces nothing. Without `children` it is announced but not painted, and a slot tip is composed after it (`"hint. tip"`) — plan `748` |
| `aria-description` | `string` | none | description announced after the name; trimmed, and a blank value is absent (a `Tooltip` writes its text here) |
| `style` | `StateStyle<SwitchState>` | — | merged last on the control surface — the track without text, the row with it; an object or a state callback |
| `testId` | `string` | — | stable locator |

`readOnly` is the review state: the switch keeps its tab stop, name, announced
value and focus ring, paints full contrast with a `default` cursor, and refuses
click, Enter and Space. `disabled` is the stronger state — it also leaves the
tab order and fades the track. 0.10.0 has no `aria-readonly`, so the difference
is behavioural and visual; the control announces `read only` / `unavailable` in
its description (plan `810`).

## Keyboard

| Key | Contract |
| --- | -------- |
| Space | toggles on key **up** |
| Enter | toggles on key **down** |
| held key | repeat events do nothing |
| Tab | reaches the switch when it is not disabled |

## Accessibility

**A switch as the first control of a surface** can start with the keyboard:
`autoFocus` puts native focus on the row and its ring follows — the same
contract the fields have (plan `584`), because the control owns exactly one
focusable root. A control mounted after a loading state focuses too; a disabled
one never does, and a read-only one still does (plan `807`).

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). Role, name, tab order, keyboard operation and activation
  are unaffected.
- Role: `Switch`.
- State is announced through **`aria-valuetext`** (`checked` / `unchecked`);
  there is no `aria-checked` in 0.10.0.
- `disabled` removes the tab stop and announces `unavailable`; no `aria-disabled`
  (plan `810`).
- `readOnly` keeps the tab stop, the name, `aria-valuetext` and the ring, and
  refuses every change; it announces `read only`. There is no `aria-readonly` in
  0.10.0, so the description is the channel (plans `799`, `810`).
- `invalid` announces `invalid` in the same description, the channel the missing
  `aria-invalid` is filled with (plan `812`), and paints the track's border; a
  visible error message is still the caller's.
- The name comes from the text child, else `label`; there is no
  `aria-labelledby`.
- With children, the row is **one** node: role `switch`, the text as its name,
  one tab stop and one hit area; the track inside is decoration. A **sibling**
  `Label` beside a standalone switch is still inert — association only works by
  putting the text inside the control.
- **Slot trigger:** forwards a `Tooltip`'s handlers and `aria-description`, so a
  tip opens on hover and on keyboard focus.
- **A visible description** (`description`) is the row's `aria-description`, so
  the printed hint and the heard one are the same string. A slot tip is joined
  after it, so a switch can carry both its own hint and a tooltip.

## Theming

`switchTrackStyle` and `switchThumbStyle` resolve both parts from the same
selection spec. The thumb is absolutely positioned from
`switchThumbOffset`, which derives both ends from the theme's icon size, `2xs`
inset and border width — there is no `transform`, so the slide is a `left`
inset, and it cannot drift out of the pill. A toggle animates that inset over
200 ms with the runtime's `motion`; a switch that mounts already checked rests
at the far end rather than sliding there. Disabled adds half opacity and
removes feedback. `invalid` gives an off-switch the destructive border, the
same role a checkbox uses, and that border survives hover and press — the
healthy interaction rule never repaints the error cue (plan 356). Focus paints
the shared selection ring.

With children, the track keeps this paint and the **row** takes
`selectionRowStyle`'s hover/press wash, so the label column responds to the
pointer; the ring still paints on the track. The caller's `style` merges on the
row in that shape.


## Style by state

`style` takes an object or a callback over the switch's public state:

```tsx
<Switch
  label="Dark mode"
  style={(state) => ({ opacity: state.checked ? 1 : 0.85 })}
/>
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `checked` | `boolean` | the pill's on/off state |
| `disabled` | `boolean` | refuses pointer and keys, leaves the tab order |
| `readOnly` | `boolean` | refuses pointer and keys, keeps the tab stop (plan `799`) |
| `focused` | `boolean` | holds native focus |
| `invalid` | `boolean` | paints the destructive border |

The callback's result merges after the component's own rules; `SwitchState` is
exported.

## Limitations

- No `aria-checked` and no on/off text inside the control; the switch names
  itself through its text child, else `label`. A **sibling** label is still not
  associated.
- `description` is a **string** and paints only inside a labelled row. A node
  description and a description above a bare track are not offered; there is no
  per-part `descriptionStyle` (the caption uses the `caption` role).
- The thumb's slide is a `left` inset because GPUix has no `transform`; there is
  no separate reduced-motion switch (0.10.0 exposes no OS preference), so an app
  that needs one should render a static indicator instead.
- The thumb's two resting offsets derive from the theme's `iconSize`, `2xs`
  spacing and border width. A caller who overrides the track's `width`/`height`
  through `style` changes the pill but not the thumb's travel — change the
  theme's `iconSize` instead when a different switch size is wanted.
- No loading or pending state; disable it while a request is in flight.

## Verification

- `src/components/state-style.test.tsx` — the state payload and the callback
  winning over the component's own rules (plan 079).
- `runtime/state-style.runtime.test.tsx` — the live state (focus, checked,
  invalid) reaching the painted style.
- `src/components/selection-read-only.test.tsx` — a read-only switch keeps its
  tab stop, reports `readOnly`, and refuses click/Enter/Space (plan `799`).
- `runtime/selection-read-only.runtime.test.tsx` — `Tab` reaches the read-only
  switch, its ring paints, and a real click and both keys report nothing while a
  writable twin reports them (plan `799`).

- `src/core/selection.test.ts` — track and thumb geometry across sizes and
  states; `switchThumbOffset` at both ends; the destructive border when
  `invalid`; the focus ring.
- `src/components/selection.test.tsx` — controlled/uncontrolled wiring, and the
  element tree's absolute thumb with the offset as its motion target; the
  labelled row's name, explicit-label precedence and the track/thumb staying
  inside it (plan `740`).
- `runtime/controls.runtime.test.tsx` — a click toggles; the role is `Switch`;
  the announced value flips; Space and Enter both toggle; the thumb slides
  through an intermediate position and rests at dx 3/13, dy 2 (plan 329).
- `runtime/labelled-selection.runtime.test.tsx` — a press on the visible text
  toggles the labelled switch and announces the new state (plan `740`), and a
  **blank** text child paints the bare track, named by `label`, rather than an
  empty row (plan `743`) — including a blank label wrapped in a `Text` run
  (plan `782`). A **description** paints its caption, is announced as the row's
  description, and a press on the caption still toggles (plan `748`).
- `src/components/label-row.test.tsx` and `runtime/label-row.runtime.test.tsx`
  — an icon beside the words is one row: the element tree carries the layout,
  the painted boxes overlap on the vertical axis, a text-only label is
  unchanged, and a long mixed label stays inside a narrow control (plan `803`).
