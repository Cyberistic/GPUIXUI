---
title: Switch
description: An immediate on/off, distinct from a checkbox in intent.
---

`Switch` is the "takes effect now" control: a track and a thumb, announced with
the switch role. It shares `core/selection.ts`'s metrics with `Checkbox`, so the
two line up on the same row, but they mean different things — a checkbox is a
choice submitted with a form, a switch is applied immediately.

Two parts: the track, and `SwitchThumb`. `Switch`'s children are the thumb's
content, drawn inside the recipe's `pointer-events-none` guard.

## Usage

```tsx
import { Switch } from "@gpuixui/primitives";

<Switch
  checked={paused}
  onCheckedChange={setPaused}
  label="Pause all notifications"
/>;
```

A glyph on the knob:

```tsx
import { Icon } from "@gpuixui/icons";
import { useTheme } from "@gpuixui/primitives";

const theme = useTheme();

<Switch checked={dark} onCheckedChange={setDark} label="Theme">
  <Icon name="moon" size={8} color={theme.colors.primaryForeground} />
</Switch>;
```

## API

### `Switch`

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `checked` | `boolean` | — | controlled; omit to let the switch keep its own state |
| `defaultChecked` | `boolean` | `false` | initial state when uncontrolled |
| `onCheckedChange` | `(next: boolean) => void` | none | the next boolean |
| `onChange` | `(next: boolean) => void` | none | deprecated alias for `onCheckedChange`, removed next release; the new name wins when both are passed |
| `children` | `ReactNode` | none | a glyph inside the knob |
| `disabled` | `boolean` | `false` | refuses pointer and keys, leaves the tab order |
| `invalid` | `boolean` | `false` | the track takes the destructive role |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | track height from `iconSize` |
| `accent` | `"primary" \| "destructive"` | `"primary"` | the on-track fill |
| `label` | `string` | none | accessible name |
| `onClick` / `onKeyDown` / `onKeyUp` / `onFocus` / `onBlur` | host handlers | none | composed with the switch's own; yours runs first |
| `style` | `StyleDesc` | — | merged last |
| `testId` | `string` | — | stable locator |

### `SwitchThumb`

The knob. `Switch` renders it; a caller's `children` are its content.

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `children` | `ReactNode` | none | a glyph on the knob |
| `className` | `string` | — | compiled through the recipe, joined after the thumb's rules |
| `style` | `StyleDesc` | — | merged last |

## Keyboard

| Key | Contract |
| --- | -------- |
| Space | toggles on key **up** |
| Enter | toggles on key **down** |
| held key | repeat events do nothing |
| Tab | reaches the switch when it is not disabled |

A Space **press** calls `preventDefault()`, so a scroll container does not
also scroll while the control waits for the release.

## Accessibility

- Role: `Switch`.
- State is announced through **`aria-valuetext`** (`checked` / `unchecked`);
  there is no `aria-checked` in `@gpuix/native` 0.11.0.
- `disabled` removes the tab stop; no `aria-disabled`.
- The name comes from `label`; there is no `aria-labelledby`.

The five host handlers are `InteractionProps`: your handler runs first with the
runtime's own event and the switch still toggles. A disabled switch installs no
`onClick` at all; its keys and focus stay observable.

## Theming

`switchTrackClass` and `switchThumbClass` compile both parts from the same
selection spec. The thumb is positioned by the track's `justifyContent`, not a
pixel offset, because the runtime has no `transform` — so it cannot drift out of
the pill. Disabled adds half opacity and removes feedback. `invalid` gives an
off-switch the destructive border, the same role a checkbox uses, and focus
declares the shared keyboard outline at rest (`controlRing`), which the runtime
paints after keyboard focus only; a disabled switch declares none.

## Limitations

- No `aria-checked` and no on/off text inside the control. A `Label` beside it
  is visible text only — it does not name the switch — so pass the same string
  as the switch's own `label` prop, or spread `labelledBy(name)`. A glyph on the
  knob is decoration, not a state label.
- No slide animation: the thumb jumps between the two `justifyContent` values.
- No loading or pending state; disable it while a request is in flight.

## Verification

- `src/core/selection.test.ts` — track and thumb geometry across sizes and
  states; the destructive border when `invalid`; the keyboard ring.
- `src/components/Switch.test.tsx` — the knob's geometry from the theme scale, a
  custom glyph inside it, and the pointer guard that keeps the glyph from taking
  the press.
- `src/components/handlers.test.tsx` — a caller's click, keys and focus are
  composed with the switch's own, and a disabled switch installs none.
- `runtime/controls.runtime.test.tsx` — a click toggles; the role is `Switch`;
  a custom glyph still toggles on a real hit test; the announced value flips;
  Space and Enter both toggle.
- `runtime/labelling.runtime.test.tsx` — a `Label` beside the switch paints its
  text but does not name it; the same string through `labelledBy` does.
