title: TextArea
description: A multi-line text field sized in rows.
---

`TextArea` is `Input`'s multi-line sibling: the same field contract on the
runtime's native `<textarea>`. It deliberately **does not accept `onSubmit`** —
with that handler set, GPUix turns Enter into a submit and the newline never
arrives (plan 046).

## Usage

```tsx
import { Label, TextArea, labelledBy } from "@gpuixui/primitives";

const notes = "Description";

<Label>{notes}</Label>
<TextArea
  {...labelledBy(notes)}
  value={value}
  onValueChange={setValue}
  minRows={3}
  maxRows={8}
  fullWidth
/>;
```

## API

`TextArea` takes every `FieldProps` except `onSubmit`, plus:

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `minRows` | `number` | runtime default | minimum visible rows |
| `maxRows` | `number` | runtime default | rows after which the field scrolls |

Shared props: `value`, `defaultValue`, `onValueChange`, `placeholder`, `readOnly`,
`disabled`, `autoFocus`, `invalid`, `size`, `fullWidth`, `label`,
`aria-description`, `onClick`, `style`, `testId`. `size` has no effect in the
shadcn slice (one recipe size) and `fullWidth` is implied by the recipe's
`w-full`. `onClick` is the host click — the pointer edge a `Tooltip` trigger
dismisses through, because the native `<textarea>` receives no mouse-down (plan
`605`).
`aria-description` is trimmed and a blank value is absent (plan `586`).
`autoFocus` takes focus on every mount, including a field added after a loading
state (plan `584`).

Its padding, radius, type and paint come from the same new-york-v4 recipe as
`Input` (`px-3 py-1 rounded-md text-sm`, plan `370`). Its **height** comes from
`minRows`/`maxRows` instead of the recipe's single-line `h-9`, so a textarea can
show more than one line — the one deliberate deviation from the class string.

## Keyboard

| Key | Contract |
| --- | -------- |
| typing | native editing; changes reach `onValueChange` |
| Enter | inserts a newline — never submits |

Submit-on-Enter is a single-line interaction: use `Input` when that is what you
mean.

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). Role, name, tab order, keyboard operation and activation
  are unaffected.
- The native element is announced as `MultilineTextInput` (measured: the
  accessibility dump prints `MultilineTextInput:"Notes"`), not the single-line
  `TextInput` that `Input` reports.
- The name comes from `label`; there is no `aria-labelledby`.
- `invalid` is visual; put the message beside the field in words.
- As with `Input`, there is no `aria-describedby`.
- **Slot trigger:** forwards a `Tooltip`'s handlers and `aria-description`, so
  the tip opens on keyboard focus. A `<textarea>` host receives no
  `onMouseEnter`, so hover cannot open it (measured, plan `345`).

## Theming

The same `fieldChrome` and native text theme as `Input`; only the height model
changes. It also carries the field recipe's `shadow-xs` elevation at rest, which
a focus ring replaces (plan `585`).

## Style by state

`style` is the same `StateStyle<FieldState>` as `Input` — `disabled`, `readOnly`,
`focused`,
`invalid` — resolved after the chrome:

```tsx
<TextArea
  label="Notes"
  invalid={tooLong}
  style={(state) => ({ opacity: state.disabled ? 0.5 : 1 })}
/>
```

The textarea re-bases its own height and vertical padding **before** the resolved
style, so the caller wins: `style={{ height: 120 }}` paints a 120 px composer and
a callback's `paddingTop`/`paddingBottom` survive too. With no caller height the
field still derives its height from `rows`. `FieldState` is exported from
`Input`, and `src/components/style-order.test.tsx` guards the merge order.

## Limitations

- **No `onSubmit`** — by design; see plan 046.
- No rich text, no markdown preview, no character counter.
- No auto-grow beyond `maxRows`: past it the field scrolls.
- `disabled` is read-only at the host plus tab-order and handler guards, because
  GPUix has no `disabled` prop (plan 025); assistive technology hears a
  read-only field.

## Verification

- `src/components/state-style.test.tsx` — the state payload and the callback
  winning over the component's own rules (plan 079).
- `runtime/state-style.runtime.test.tsx` — the live state (focus, checked,
  invalid) reaching the painted style.

- `src/components/fields.test.tsx` — rows, chrome and the absence of `onSubmit`
  in the public props.
- `src/components/style-order.test.tsx` — a caller's `height` and padding win
  over the row re-base; with no caller height the rows own it (plan 097).
- `runtime/fields.runtime.test.tsx` — height follows `rows`; a newline is
  accepted; the probe in plan 046 measured that adding `onSubmit` costs the
  newline, which is why it is not in the type.

```sh
nub run --filter @gpuixui/primitives test:runtime
```
