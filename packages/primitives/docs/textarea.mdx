---
title: TextArea
description: A multi-line text field sized in rows.
---

`TextArea` is `Input`'s multi-line sibling: the same field contract on the
runtime's native `<textarea>`. It deliberately **does not accept `onSubmit`** —
with that handler set, GPUix turns Enter into a submit and the newline never
arrives (measured by `runtime/fields.runtime.test.tsx`).

## Usage

```tsx
import { Label, TextArea, labelledBy } from "@gpuixui/primitives";

const notes = "Description";
const help = "Markdown is not interpreted.";

<Label description={help}>{notes}</Label>
<TextArea
  {...labelledBy(notes)}
  description={help}
  value={value}
  onValueChange={setValue}
  minRows={3}
  maxRows={8}
  fullWidth
/>;
```

## API

`TextArea` takes every `FieldProps` except `onSubmit`, plus:

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `minRows` | `number` | runtime default | minimum visible rows |
| `maxRows` | `number` | runtime default | rows after which the field scrolls |

Shared props: `value`, `defaultValue`, `onValueChange`, `placeholder`, `readOnly`,
`disabled`, `autoFocus`, `invalid`, `size`, `fullWidth`, `label`, `description`,
`tabIndex`, `style`, `testId`, the runtime's `ref` / `aria-id` / `onLayout` host
props, and the five composed host handlers from `InteractionProps`
(`onClick`, `onKeyDown`, `onKeyUp`, `onFocus`, `onBlur`): yours runs first and
the field still tracks focus and edits.

Its height is rows, not a control height, so the component re-bases vertical
padding to the density's horizontal padding step to keep the text inset square.

## Keyboard

| Key | Contract |
| --- | -------- |
| typing | native editing; changes reach `onValueChange` |
| Enter | inserts a newline — never submits |

Submit-on-Enter is a single-line interaction: use `Input` when that is what you
mean.

## Accessibility

- The native element is announced as a multi-line text input.
- The name comes from `label`; there is no `aria-labelledby`.
- `description` is announced after the name through the runtime's
  `aria-description`, so the help a visible `Label description` paints has to be
  handed to the field as well.
- `invalid` is visual; put the message in `description` so it is announced, and
  paint the same words beside the field.
- As with `Input`, there is no `aria-describedby`: the description is a string,
  not a reference.

## Theming

The same `fieldChrome` and native text theme as `Input`; only the height model
changes — and the same `StateStyle<FieldState>` (`{ disabled, focused, invalid }`)
`style` contract, merged last. The field keeps its text out of the runtime's
keyboard dim (`keyboardFocusDim: false`), because the text being read is content
rather than chrome; see `Input` §Theming for the measurement.

## Limitations

- **No `onSubmit`** — by design; see `runtime/fields.runtime.test.tsx`.
- No rich text, no markdown preview, no character counter.
- No auto-grow beyond `maxRows`: past it the field scrolls.
- `disabled` is read-only at the host plus tab-order and handler guards, because
  GPUix has no `disabled` prop; assistive technology hears a
  read-only field.

## Verification

- `src/components/fields.test.tsx` — rows, chrome, the absence of `onSubmit` in
  the public props, and the address and announced help it shares with `Input`.
- `src/components/change.test.ts` — the textarea routes its props through the
  shared `valueChange` precedence rule, so `onValueChange` runs and the
  deprecated `onChange` alias only runs alone.
- `src/components/handlers.test.tsx` — a caller's click, keys and focus run
  before the textarea's own tracking.
- `runtime/fields.runtime.test.tsx` — height follows `rows`; a newline is
  accepted; a probe measured that adding `onSubmit` costs the
  newline, which is why it is not in the type; typing reports `onValueChange`
  and not the deprecated alias when both are passed.

```sh
nub run --filter @gpuixui/primitives test
nub run --filter @gpuixui/primitives test:runtime
```
