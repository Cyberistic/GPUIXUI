title: Tooltip
description: A short label on hover or keyboard focus — a themed wrapper over GPUix's Tooltip.
---

`Tooltip` reuses `@gpuix/react/tooltip` for the anchored layer, the open delay
and dismissal, and themes the tip to the popover surface and caption type. It is
a wrapper, not a reimplementation.

## Usage

```tsx
import { Icon } from "@gpuixui/icons";
import { IconButton, Tooltip, useTheme } from "@gpuixui/primitives";

const theme = useTheme();

<Tooltip content="Booked revenue, net of refunds." side="bottom">
  <IconButton
    label="Revenue definition"
    icon={
      <Icon
        name="info"
        size={theme.iconSize.sm}
        color={theme.colors.mutedForeground}
      />
    }
  />
</Tooltip>;
```

A host element works too, and it needs a **role** to exist in the accessibility
tree (a `div` carrying only a description is not a node a screen reader visits):

```tsx
<Tooltip content="Booked revenue, net of refunds." side="bottom">
  <div role="button" aria-label="Revenue definition" tabIndex={0}>
    Definition
  </div>
</Tooltip>;
```

The child must be a single **focusable element**. `Tooltip`'s trigger clones it
with the hover and focus handlers, so a control has to forward them. `Button`, `IconButton`
and `Toggle` forward the whole `TooltipTriggerProps` pair (`onMouseEnter`,
`onMouseLeave`) and the tip's `aria-description`; a component that forwards
neither — this package's `Box`, for instance — paints the trigger but does not
open the tip or announce the description.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `content` | `ReactNode` | — (required) | the tip; keep it short and unwrapped |
| `description` | `string` | `content` when it is a string | the trigger's accessible description |
| `children` | `ReactNode` | — (required) | the trigger: a focusable host element, or a control that forwards the trigger pair |
| `side` | `FloatingSide` | `"top"` | preferred placement |
| `align` | `FloatingAlign` | GPUix's default | alignment against the trigger |
| `delay` | `number` | provider default | hover delay in milliseconds |
| `style` | `StyleDesc` | — | extra style on the tip's surface, merged last |
| `className` | `string` | — | a Tailwind string joined after the recipe, so it wins conflicts |
| `testId` | `string` | — | locator on the **tip** |

## Keyboard

Owned by GPUix: the tip opens when its trigger receives a focus event, and
Escape dismisses it. A click dismisses it.

**A `Tab` traversal opens the tip** — measured in a real window: the traversal
focuses the trigger and React's `onFocus` runs, so the keyboard path works. The
trigger has to be focusable, because a host with no `tabIndex` never receives
the focus to open from. Escape then closes the tip and leaves the focus on the
trigger, so a keyboard reader can dismiss it and keep going.
Evidence: `apps/playground/README.md` §`tooltip-lifecycle`.

## Accessibility

- The tip is the trigger's **`aria-description`** when `content` is a string (or
  `description` is set): GPUix 0.11.0 has `aria-description` but no
  `aria-describedby`, so the wrapper passes it to the trigger.
  `Button`/`IconButton`/`Toggle` hand it to their host; a component that does not
  forward it cannot carry it. The text is trimmed and a blank one is not published — an
  empty description is still an attribute a reader dismisses.
- **Measured in the accessibility tree**: the `description` field is one of the
  four attribute fields `getA11yTree()` reports, so the tip reaches a screen
  reader through the trigger. Two limits come with it: a node needs a `role` to
  exist at all (a `div` with only a description paints no node), and the tree is
  a `TestRenderer` fact — a window's automation protocol has no a11y verb.
  Evidence: the playground's `a11y-tree` probe and the tooltip case in
  `runtime/fields.runtime.test.tsx`.
- The description is supplementary, not a name. A button whose only name is
  inside a tooltip is unnamed to assistive technology, so give the control its
  own `label`.
- A tooltip is **supplementary**: the same information must be reachable without
  hovering (visible text, or the control's name).
- A mouse-opened and a keyboard-opened tip look identical: the runtime reports
  focus, not *how* the trigger was focused.

## Theming

`tooltipStyle` resolves the tip's surface: the `popover` fill with
`popoverForeground` text — the pair `contrastPairs` measures at the body floor —
`radius.sm`, a `border` rule, the `caption` type and one spacing step of inset.
Content is `whiteSpace: nowrap`.

The tip paints **no shadow**: the recipe asks the resolver for the `overlay`
elevation level, which is deliberately reserved and resolves to no shadow (a
level that lifts something would be `md`/`lg`). A tip is separated from the page
by its border and its own fill.

A caller can restyle it in the package's merge order — the recipe, then
`className`, then `style`:

```tsx
<Tooltip content="Booked revenue, net of refunds." className="bg-card" style={{ maxWidth: 240 }}>
  <IconButton label="Revenue definition" icon={<Icon name="info" color={theme.colors.foreground} />} />
</Tooltip>;
```

Without a caller the text is `popoverForeground` rather than whatever colour the
anchored layer happened to inherit: an inherited colour is one the wrapper
cannot see and no contrast pair measures.

## Dependencies

| Package | Why |
| ------- | --- |
| `@gpuix/react/tooltip` | the anchored layer, the hover/focus wiring and dismissal, which this wrapper themes rather than reimplements |
| `@gpuixui/icons` | the `info` glyph in the usage snippet; any `24×24` SVG works, and the icon is optional |

## Limitations

- The trigger must be a focusable element: a host with no `tabIndex` never
  receives the focus that opens the tip, and a component only works if it
  forwards `TooltipTriggerProps` (`Button`, `IconButton` and `Toggle` do).
- No `aria-describedby`: a non-string tip has no description unless `description`
  is passed, and an element with no `role` is absent from the accessibility tree,
  so its description is never announced.
- No wrapping or rich content: a paragraph is a popover, not a tooltip.
- No arrow/caret and no touch-long-press behaviour.
- Open/close timing is GPUix's; this wrapper only sets the delay.

## Verification

- `src/components/Select.test.tsx` / `fields.test.tsx` — the wrapper's theme
  spec at the render seam.
- `src/components/Tooltip.test.tsx` — a string tip and an explicit `description`
  reach the host trigger and a control trigger that forwards them, a non-text
  tip without one invents nothing, and a component that forwards nothing is not
  pretended to carry the description; the tip paints `popoverForeground` on its
  own `popover` fill and that pair clears the body floor in both shipped
  palettes; a caller's `className` beats the recipe and their `style` beats
  both. `src/components/Button.test.tsx` / `IconButton.test.tsx` hold the
  forwarded pair.
- `src/docs.test.ts` — every snippet's `@gpuixui/primitives` import resolves to a
  real export of the package, which is how this page's `Icon` (an
  `@gpuixui/icons` glyph) stopped being taught as a primitive.
- `runtime/fields.runtime.test.tsx` — opens on hover and on keyboard focus in
  the `TestRenderer` from a host trigger **and from the `IconButton` it wraps**,
  dismisses on click, keeps its content inside the anchoring frame, paints the
  popover role, and the a11y tree reports the tip as the trigger's
  `description`.
- The `tooltip-lifecycle` live probe (`apps/playground/README.md`) — the same
  wrapper in a **real window** (14 checks on 0.11.0): a `Tab` traversal opens the
  tip and Escape closes it with the focus on the trigger; hover opens it above
  the trigger, leaving closes it, and a second hover opens it for Escape.
- `runtime/examples.runtime.test.tsx` — the feedback example's tooltip opens on
  hover.
