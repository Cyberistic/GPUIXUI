---
title: Tooltip
description: A short label on hover or keyboard focus — a themed wrapper over GPUix's Tooltip.
---

`Tooltip` reuses `@gpuix/react/tooltip` for the anchored layer, the open delay
and dismissal, and themes the tip to the popover surface and caption type. It is
a wrapper, not a reimplementation. It also makes the tip anchor to **its
trigger**: GPUix's tooltip root otherwise stretches to its parent, which put the
tip at the edge or centre of the surrounding layout (plan 060).

## Usage

```tsx
import { Button, Tooltip } from "@gpuixui/primitives";

<Tooltip content="Delete this file" side="bottom">
  <Button label="Delete">Delete</Button>
</Tooltip>;
```

The child must be a single **focusable host element with a role and a name**.
`Tooltip`'s trigger clones its child with the hover and focus handlers, so a
component that does not forward those props (including this package's `Box`)
will not open the tip — and a bare focus stop with no role produces no
accessibility node at all.

For the common "info icon that explains a term" case, use **InfoTip** instead of
writing that trigger by hand: it owns the role, the name, the tab stop and the
focus ring.

## Placement

The root sets `alignSelf: "flex-start"` (`tooltipRootStyle`), so it hugs the
trigger instead of filling the parent. The anchored layer then measures the
trigger, in a column **and** a row parent.

`align` decides which edge of the trigger the tip lines up with:

| `align` | Result |
| ------- | ------ |
| `start` (default) | the panel's start edge meets the trigger's start edge — exact |
| `end` | the panel's end edge meets the trigger's end edge — exact |
| `center` | the panel's centre meets the trigger's centre within 1 px |

The runtime's own `center` is not usable: it puts the panel's **end** on the
trigger's centre line, half a panel off (plans `060` §0, `156` §8). The wrapper
never passes it through — it maps `center` to `start` plus half the difference
between the trigger and the open tip. The difference is taken on the **layer's
own axis**: above/below aligns horizontally, so widths; `side="left"`/`"right"`
aligns vertically, so heights (measured, plan `098`: a width difference handed to
the vertical axis painted the tip 90 px below its trigger). The correction is
applied in a layout effect, before the frame is painted, so a centre tip does not
visibly jump (plans `095`, `098`).

`side` decides which side of the trigger the tip opens on. It prefers **above**,
and flips **below** when the tip does not fit above — the runtime's layer is
`fit="snap"`, which clamps a layer inside the window **without flipping it**
(plan `156` §8), so at the top edge the tip used to open at `y 8..34` over a
trigger at `y 12..30` (plan `067` §1). The wrapper measures its root and
estimates the tip's height from `tooltipStyle` (padding, one caption line,
border). Automatic side choice is vertical only.

A **`left`/`right` side is a preference.** The wrapper measures the tip's width
and the trigger's edges: when the tip cannot fit on the requested side it opens
on the other one, or on the roomier side when it fits on neither. The runtime
alone would clamp it — measured on a trigger at `x 12..72`, a `side="left"` tip
painted `x 8..55`, over the trigger (plan `335`). An explicit `top`/`bottom`
still skips the vertical decision and is exact where the window allows it.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `content` | `ReactNode` | — (required) | the tip; keep it short and unwrapped |
| `children` | `ReactNode` | — (required) | the trigger, a focusable host element |
| `side` | `FloatingSide` | auto — above, flipped below when it does not fit; a `left`/`right` side flips when it cannot fit | preferred placement |
| `align` | `FloatingAlign` | `"start"` | alignment against the trigger; `center` is measured exact — see Placement |
| `delay` | `number` | provider default | hover delay in milliseconds |
| `testId` | `string` | — | locator on the **tip** |

## Keyboard

Owned by GPUix: the tip opens when its trigger takes keyboard focus, and Escape
dismisses it. A click dismisses it.

## Accessibility

- **A string tip is the trigger's description.** GPUix 0.10.0 has no
  `aria-describedby`, but it exposes `aria-description`; the wrapper writes the
  string content there, so a screen reader announces the explanation when the
  trigger takes focus, even while the tip is closed.
- **The open tip is its own node.** The content carries `role="tooltip"` and,
  for a string, an `aria-label` with the same text — measured in the runtime
  (plan `071`). Non-string content is painted and becomes a `tooltip` node, but
  the wrapper does not invent a name for it; pass a string to have it announced.
- The trigger must be focusable **and** named. A bare `div tabIndex={0}` gets
  focus but produces no accessibility node, so it cannot carry the description;
  give it a role (`role="img"` for an info icon) and an `aria-label`.
- A tooltip is **supplementary**: the same information must be reachable without
  hovering (visible text, or the control's name).
- There is no `focusVisible` state, so a mouse-opened and a keyboard-opened tip
  look identical.

## Theming

`tooltipStyle` uses the `popover` surface, `radius.sm`, `elevation.overlay`, the
`caption` type and one spacing step of inset; content is `whiteSpace: nowrap`.

## Limitations

- The trigger must be a focusable host element (above).
- **A `center` tip measures once.** The runtime has no layout callback, so the
  tip's box is known only after its first layout; the offset is applied in a
  layout effect before paint, so there is no visible jump. A tip whose size
  changes while open (it cannot, with `whiteSpace: nowrap`) would not re-centre.
- **The flip sees one line.** The side is chosen from an estimated height
  (padding + one caption line + border), which is exact for the tip this wrapper
  paints and for `whiteSpace: nowrap`; a multi-line tip is a popover.
- **A tip wider than the room on both sides is clamped.** The horizontal side is
  chosen from the tip's measured width, but a tip wider than both sides can
  still be clamped by the runtime and painted over its trigger.
- No `aria-describedby` association: the content is the trigger's
  `aria-description` instead, which is a description but not a reference.
- A non-string tip has no description on the trigger and no name of its own.
- No wrapping or rich content: a paragraph is a popover, not a tooltip.
- No arrow/caret and no touch-long-press behaviour.
- Open/close timing is GPUix's; this wrapper only sets the delay.

## Verification

- `src/components/Select.test.tsx` — the wrapper's theme spec, the root hug, the
  default `align` at the render seam, the tip-height estimate checked against
  `tooltipStyle`, and the description/name mapping for string and non-string
  content (plan `071`).
- `src/core/floating.test.ts` — the shared side rule, including a preferred
  `top` and its fallback below, the horizontal fit rule (fits, flips, exact fit,
  roomier) and the alignment rule on both axes (widths above/below, heights
  beside — plans `098`, `335`).
- `runtime/fields.runtime.test.tsx` — opens on hover and on keyboard focus,
  dismisses on click, keeps its content inside the anchoring frame, paints the
  popover role, paints the tip against the trigger in a column (`start`, `end`)
  and in a row (`bottom`), and **centres it within 1 px** of a 400 px trigger
  (plan `095`; the failing direction was 176.5 px left). Removing the root hug fails the `end` and row
  tests; making `center` the default fails the first (plan 060 §6).
  **Placement (067):** at the top edge the tip opens below its trigger
  (`8 >= 30` fails without the decision), a tip with room above stays above, and
  the painted height equals the estimate.
  **Horizontal sides (098):** `side="right"` and `side="left"` with
  `align="center"` centre the tip on the trigger's vertical centre within 1 px
  (the failing direction was 90 px low), and the left case has real room instead
  of the runtime's clamp.
  **Horizontal fit (335):** a `side="left"` tip at the window's left edge opens
  on the right of its trigger (the failing direction painted the tip `x 8..55`
  over the trigger), and a `side="right"` tip at the right edge opens on the
  left. Without the side decision the runtime clamps both onto the trigger.
  **Description (071):** the trigger's accessibility node carries the content as
  its description while the tip is closed, and the open tip is a named `Tooltip`
  node — the failing direction had neither.
- `runtime/examples.runtime.test.tsx` — the feedback example's tooltip opens on
  hover and on keyboard focus, and its trigger announces the description.

```sh
nub run --filter @gpuixui/primitives test
nub run --filter @gpuixui/primitives test:runtime
```
