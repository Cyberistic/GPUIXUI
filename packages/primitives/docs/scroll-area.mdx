---
title: ScrollArea
description: A bounded container that scrolls on the chosen axes.
---

`ScrollArea` is a frame around the one scroll container the runtime has. The
frame owns the padding, radius, border and bounded size; `ScrollAreaViewport` is
the scroller, with the overflow axes and `onScroll`.

GPUix 0.11.0 paints the scrollbar itself and exposes `scrollbarColor` and
`scrollbarWidth`, so the viewport tints the native thumb from the theme's
`scrollbar` role. There is still no `Scrollbar`/`Thumb`/`Corner` part: the
platform paints one thumb that takes no pointer input.

## Usage

```tsx
import { ScrollArea, Stack, Text } from "@gpuixui/primitives";

<ScrollArea axis="vertical" style={{ height: 240 }} padding="md">
  <Stack direction="column" gap="sm">
    {rows.map((row) => (
      <Text role="body" key={row}>{row}</Text>
    ))}
  </Stack>
</ScrollArea>;
```

**Give it a bounded size.** A scroll container with no height constraint grows
with its content and never scrolls.

The parts put a heading outside the scroller:

```tsx
import {
  ScrollArea,
  ScrollAreaViewport,
  Stack,
  Text,
} from "@gpuixui/primitives";

<ScrollArea axis="vertical" style={{ height: 240 }} padding="md">
  <Text role="label">Properties</Text>
  <ScrollAreaViewport>
    <Stack direction="column" gap="sm">
      {rows.map((row) => (
        <Text role="body" key={row}>{row}</Text>
      ))}
    </Stack>
  </ScrollAreaViewport>
</ScrollArea>;
```

Plain children are the content of one implicit viewport, so
`<ScrollArea>rows</ScrollArea>` keeps scrolling. A `ScrollAreaViewport` among
the children is the caller's own scroller; it inherits the area's axis,
`onScroll` and thumb unless it overrides them.

## Parts

| Part | Responsibility |
| ---- | -------------- |
| `ScrollArea` | the frame: padding, radius, border, bounded size, scroll context |
| `ScrollAreaViewport` | the overflow axes, `onScroll`, and the native thumb's colour and width |

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `axis` | `"vertical" \| "horizontal" \| "both"` | `"vertical"` | which overflow axes are `scroll` (the others are `hidden`) |
| `onScroll` | `(event: EventPayload) => void` | none | wheel/trackpad **deltas** (`deltaX`, `deltaY`, `precise`, `touchPhase`) |
| `padding` | spacing step | none | frame padding; it does not scroll |
| `radius` | radius step | none | frame radius; the scroller is clipped by it |
| `border` | `boolean` | `false` | the frame's `border` role |
| `scrollbarColor` | `string` | `colors.scrollbar` | the viewport thumb's colour |
| `scrollbarWidth` | `number` | platform's | the viewport thumb's thickness in px |
| `style` | `StyleDesc` | — | merged last on the frame; put the bounded size here |
| `className` | `string` | — | Tailwind classes, joined last on the frame |
| `children` | `ReactNode` | — | viewport content, or a composed `ScrollAreaViewport` |
| `testId` | `string` | — | the frame's locator |
| `viewportTestId` | `string` | — | the implicit viewport's locator, for scroll automation |

`ScrollAreaViewport` accepts `axis`, `onScroll`, `scrollbarColor`,
`scrollbarWidth`, `style`, `className`, `children` and `testId`; each prop
defaults to the area's value.

`onScroll` reports a delta, not a position: there is no `onScrollChange` and no
absolute offset in `EventPayload`. A consumer that needs a position accumulates
deltas itself and clamps at the content's ends.

## Keyboard

Not focusable by itself. The runtime scrolls with the wheel; keyboard scrolling
belongs to the focused content inside the area. The wrapper does not intercept
keys, so Space/PageDown reach whatever holds focus.

## Accessibility

No role. The content inside is what assistive technology traverses; a scroll
region with no label is not announced as a region. Keep lists short enough to
navigate, or pair the area with a heading.

## Theming

The frame resolves `padding`, `rounded-*` and `border` from the theme's spacing,
radius and colour roles. The viewport resolves only the axes plus
`scrollbarColor = colors.scrollbar` and the optional `scrollbarWidth`; the
scrollbar's paint is otherwise the platform's.

## Limitations

- **No `Scrollbar`/`Thumb`/`Corner` parts.** The platform paints one native
  thumb from `scrollbarColor`/`scrollbarWidth`; it takes no pointer input, so
  there is nothing to compose or make draggable.
- **No fade mask** at the edges.
- **No absolute scroll position.** `onScroll` carries deltas only; the runtime
  has no `onScrollChange` and no offset field.
- No virtualisation: a long list mounts every row. `packages/data-grid` owns the
  virtual-list work when it lands.

## Verification

- `src/core/style.test.ts` — the four axis combinations, and that the pure
  resolver stays theme-free (the thumb paint lives on the viewport).
- `src/components/presentational.test.tsx` — the frame's padding/radius stay off
  the viewport, the implicit viewport keeps `onScroll`, the thumb colour defaults
  to `colors.scrollbar`, a `scrollbarWidth` reaches it, and a caller's
  `ScrollAreaViewport` composes.
- `runtime/layout.runtime.test.tsx` — a wheel with `deltaY -100` leaves the
  viewport's offset at `y -100` and the caller's `onScroll` receives `-100`; the
  renderer retains `scrollbarColor` (`colors.scrollbar`) and `scrollbarWidth`.
