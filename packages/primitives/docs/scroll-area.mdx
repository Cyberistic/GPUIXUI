title: ScrollArea
description: A bounded container that scrolls on the chosen axes.
---

`ScrollArea` is a frame around the one scroll container the runtime has. The
frame owns the padding, radius, border and bounded size; `ScrollAreaViewport` is
the scroller, with the overflow axes, `onScroll` and `onScrollChange`.

GPUix 0.11.0 paints the scrollbar itself and exposes `scrollbarColor` and
`scrollbarWidth`, so the viewport tints the native thumb from the theme's
`scrollbar` role. There is still no `Scrollbar`/`Thumb`/`Corner` part: the
platform paints one thumb that takes no pointer input.

The viewport is also a **keyboard scroll region**: it is a tab stop, and arrows,
PageUp/PageDown, Home and End move it (see [Keyboard](#keyboard)).

## Usage

```tsx
import { ScrollArea, Stack, Text } from "@gpuixui/primitives";

<ScrollArea axis="vertical" style={{ height: 240 }} padding="md" label="Rows">
  <Stack direction="column" gap="sm">
    {rows.map((row) => (
      <Text role="body" key={row}>{row}</Text>
    ))}
  </Stack>
</ScrollArea>;
```

**Give it a bounded size.** A scroll container with no height constraint grows
with its content and never scrolls.

The parts put a heading outside the scroller:

```tsx
import {
  ScrollArea,
  ScrollAreaViewport,
  Stack,
  Text,
} from "@gpuixui/primitives";

<ScrollArea
  axis="vertical"
  style={{ height: 240 }}
  padding="md"
  label="Properties"
>
  <Text role="label">Properties</Text>
  <ScrollAreaViewport>
    <Stack direction="column" gap="sm">
      {rows.map((row) => (
        <Text role="body" key={row}>{row}</Text>
      ))}
    </Stack>
  </ScrollAreaViewport>
</ScrollArea>;
```

Plain children are the content of one implicit viewport, so
`<ScrollArea>rows</ScrollArea>` keeps scrolling. A `ScrollAreaViewport` among
the children is the caller's own scroller; it inherits the area's axis,
callbacks, thumb and keyboard behaviour unless it overrides them.

## Parts

| Part | Responsibility |
| ---- | -------------- |
| `ScrollArea` | the frame: padding, radius, border, bounded size, scroll context |
| `ScrollAreaViewport` | the overflow axes, `onScroll`/`onScrollChange`, keyboard scrolling, and the native thumb's colour and width |

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `axis` | `"vertical" \| "horizontal" \| "both"` | `"vertical"` | which overflow axes are `scroll` (the others are `hidden`) |
| `onScroll` | `(event: EventPayload) => void` | none | wheel/trackpad **deltas** (`deltaX`, `deltaY`, `precise`, `touchPhase`) |
| `onScrollChange` | `(event: EventPayload) => void` | none | the **absolute offset** after any move — wheel, scrollbar, `scrollTo`, keyboard — as `scrollX`/`scrollY` (0 at the start, negative after) |
| `padding` | spacing step | none | frame padding; it does not scroll |
| `radius` | radius step | none | frame radius; the scroller is clipped by it |
| `border` | `boolean` | `false` | the frame's `border` role |
| `scrollbarColor` | `string` | `colors.scrollbar` | the viewport thumb's colour |
| `scrollbarWidth` | `number` | platform's | the viewport thumb's thickness in px |
| `focusable` | `boolean` | `true` | whether the viewport is a tab stop and answers the scroll keys |
| `label` | `string` | `"Scroll region"` while the viewport is a tab stop | names the region (`role="group"` + `aria-label`); a non-focusable viewport has no region at all unless named |
| `style` | `StyleDesc` | — | merged last on the frame; put the bounded size here |
| `className` | `string` | — | Tailwind classes, joined last on the frame |
| `children` | `ReactNode` | — | viewport content, or a composed `ScrollAreaViewport` |
| `testId` | `string` | — | the frame's locator |
| `viewportTestId` | `string` | — | the implicit viewport's locator, for scroll automation |

`ScrollAreaViewport` accepts `axis`, `onScroll`, `onScrollChange`,
`scrollbarColor`, `scrollbarWidth`, `focusable`, `label`, `style`, `className`,
`children` and `testId`; each prop defaults to the area's value.

`onScroll` reports wheel input; `onScrollChange` reports where the content ended
up, whatever moved it. Use the second for a position (a pinned header, a
restored offset) and the first for a gesture.

## Keyboard

The viewport is a tab stop by default. It moves one row per arrow
(`theme.density.rowHeight`), one measured viewport per PageUp/PageDown, to the
start with Home and to the end with End; horizontal regions take Left/Right and
the ends of their own axis.

```tsx
<ScrollArea axis="vertical" style={{ height: 240 }} label="Rows">
  <Stack direction="column" gap="sm">{rows}</Stack>
</ScrollArea>;
```

A key is only consumed when the scroller itself holds the focus: GPUI bubbles a
key from the focused element, so a field inside the area keeps its own arrow
keys (and Home/End keep their caret meaning). `focusable={false}` removes the
tab stop for content that carries its own scroll contract.

The viewport is a tab stop, so it **declares the keyboard ring** (`controlRing` →
`focusVisible`) at rest, like every other focusable primitive: the runtime paints
the outline after a `Tab` and never after a mouse press, so a keyboard reader can
see where the focus landed. The declaration sits on the viewport — the element
that holds the focus — never on the frame around it, and `focusable={false}`
removes the ring with the stop.

## Accessibility

The viewport is a `group`, and it carries a name even when the caller gives
none: `"Scroll region"`. That is not decoration — GPUix builds an accessibility
node only for an element with a role, so an unnamed viewport was a **tab stop
the accessibility tree could not hold** (measured on 0.11.0: the window had 12
tab stops and 11 nodes). Pass `label` to replace the default with the region's
own name, e.g. `"Rows"` for a table's scroller. `focusable={false}` with no
label adds neither the stop nor the node, which is what a purely visual
scroller wants.

The keyboard contract above is what makes the scroller usable without a pointer,
and the `focusVisible` outline is what makes the stop visible: a tab stop with no
cue is a place a keyboard reader arrives without knowing.

## Theming

The frame resolves `padding`, `rounded-*` and `border` from the theme's spacing,
radius and colour roles. The viewport resolves only the axes plus
`scrollbarColor = colors.scrollbar` and the optional `scrollbarWidth`; the
scrollbar's paint is otherwise the platform's. The keyboard step is the theme's
`density.rowHeight`, so a compact theme moves in smaller steps.

## Limitations

- **No `Scrollbar`/`Thumb`/`Corner` parts.** The platform paints one native
  thumb from `scrollbarColor`/`scrollbarWidth`; it takes no pointer input, so
  there is nothing to compose or make draggable.
- **No fade mask** at the edges.
- **No smooth scrolling.** A key jumps the offset; the runtime has no
  transform/animation path for a scroll position.
- **No virtualisation.** A long list mounts every row. `packages/data-grid` owns
  the virtual-list work when it lands.
- **The default region name is fixed English.** `"Scroll region"` names a
  viewport the caller did not label; a caller that needs its own words passes
  `label`.

## Verification

- `src/core/scroll.test.ts` — the key → offset arithmetic: arrows, pages,
  Home/End, the start clamp, the axes a region does not scroll, and a key the
  region does not own.
- `src/components/presentational.test.tsx` — the viewport is a tab stop with the
  area's absolute-offset callback; an unnamed one is the named `group`
  `"Scroll region"`; a named one keeps its group without a stop; `focusable={false}`
  with no label drops the stop, the role and the name; the viewport declares the
  keyboard ring and a non-focusable one declares none; the frame's
  padding/radius stay off the viewport.
- `runtime/layout.runtime.test.tsx` — a wheel with `deltaY -100` leaves the
  viewport's offset at `y -100` and the caller's `onScroll` receives `-100`;
  keyboard Down/PageDown/Home/End move the painted offset; `onScrollChange`
  reports it; a focused field inside keeps its Down key (the scroller stays at
  `0`); the renderer retains `scrollbarColor` (`colors.scrollbar`) and
  `scrollbarWidth`; an unnamed viewport reaches the accessibility tree as a
  focusable group; the focusable viewport declares `focusVisible` and `Tab`
  lands on it, while a non-focusable one declares none.
