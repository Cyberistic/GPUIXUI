---
title: Text
description: One run of type, named by a theme role and a semantic tone.
---

`Text` names a role from the theme's type scale and a tone that decides its
colour. It adds no behaviour: the runtime has one `text` host element, so every
typographic role is the same element with a different resolved `StyleDesc`. The
role also decides the **accessibility semantics**: `h1`-`h3` are headings with a
level, and `code`/`codeBlock` are code. Other roles stay static text.

## Usage

```tsx
import { Text, Stack } from "@gpuixui/primitives";

<Stack direction="column" gap="2xs">
  <Text role="h2">Version 0.10.0</Text>
  <Text role="body" tone="muted">
    Released 17 October 2026.
  </Text>
  <Text role="code">nub add @gpuixui/primitives</Text>
</Stack>;
```

Inline decoration is one prop — a former price, or an inline emphasis that is
still plain text (`Text` is not a link; a real one is Tier 2):

```tsx
<Stack direction="row" gap="2xs" align="baseline">
  <Text role="caption" tone="muted" decoration="line-through">$49</Text>
  <Text role="bodyStrong">$39</Text>
</Stack>;

<Text tone="primary" decoration="underline">View changelog</Text>;
```

## Roles

| `role` | Family | Typical use |
| ------ | ------ | ----------- |
| `display` | sans | a landing or empty-state headline |
| `h1`, `h2`, `h3` | sans | page, section and subsection titles |
| `body` | sans | running text |
| `bodyStrong` | sans | the lead sentence of a section |
| `label` | sans | a control's visible name |
| `caption` | sans | metadata and helper text |
| `code` | mono | an inline identifier or command |
| `codeBlock` | mono | a block of code |

Sizes, line heights and weights come from `theme.typography`. No component picks
a font size.

## Tones

| `tone` | Colour role | Use for |
| ------ | ----------- | ------- |
| `default` | `foreground` | body and headings |
| `muted` | `mutedForeground` | metadata, help, disabled-adjacent copy |
| `primary` | `primary` | a link-like non-interactive emphasis |
| `destructive` | `destructive` | an error or a breaking change |
| `inherit` | none | text on a coloured surface, taking its parent's colour |

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `role` | `TextRole` | `"body"` | size, leading, weight and family |
| `tone` | `TextTone` | `"default"` | colour role |
| `align` | `"start" \| "center" \| "end"` | runtime default | horizontal alignment; `"end"` is sent to the runtime as its `right` (plan `365`) |
| `decoration` | `"underline" \| "line-through"` | none | the runtime's `textDecoration`; paint only, never a semantic emphasis (plan `377`) |
| `label` | `string` | none | names a **mark** (e.g. a required `*`) as an image; omit it for prose, and a blank name is absent |
| `truncate` | `boolean \| "start" \| "end"` | `false` | one line; `true`/`"end"` clips the tail, `"start"` keeps the tail and clips the beginning (plan `783`) |
| `clamp` | `number` | none | hard-clip after N lines (a value below 1 is ignored) |
| `selectable` | `boolean` | `false` | a pointer drag takes the text (measured, plan `385`); off keeps chrome inert |
| `shrink` | `boolean` | `true` | may shrink below its widest word (`minWidth: 0`); `false` restores the automatic floor a `Grid` `max-content` track measures (plan `587`) |
| `style` | `StyleDesc` | — | merged last |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the string (or inline nodes) |

`align="end"` means the end of a **left-to-right** box: GPUix 0.10.0 has no text
direction, and its `textAlign` implements `center`, `right` and `left`/`start`
only. The resolver therefore sends `"right"` for the public `"end"`; passed
through verbatim it painted as `start` (measured, plan `365`). There is no RTL
claim to make.

A text run **shrinks to the width it is given** instead of keeping its
max-content width: `minWidth` is `0`, so a long sentence in a bounded row wraps
rather than painting past the row and pushing its sibling out (measured, plan
`383`: a 439 px run in a 220 px row). A column already stretches its children, so
nothing changes there; `truncate` gets the bounded width its ellipsis needs. A
caller can raise the floor again with `style={{ minWidth: 120 }}`.

That floor is also what the published runtime reads when it sizes a
`Grid columnMin="max-content"` track: a `Text` cell therefore measures **0**
wide unless the run opts out with `shrink={false}`, which restores the runtime's
automatic content floor (`minWidth: "auto"`). Measured (plan `587`): the same
two runs paint `33 / 235` px with `shrink={false}` and `0 / 0` without it. The
default stays `true` because the bounded-row overflow is the common case; a
content-sized grid cell is the exception and says so.

## Truncation

`truncate` clips a run to **one line** and keeps the end that carries the
meaning. Prose is identified by its first words, so the default (`true`, and the
explicit `"end"`) clips the tail. A path, package specifier or identifier is
identified by its **last** segment, so `truncate="start"` keeps that end and
clips the beginning:

```tsx
// Good: the filename survives the narrow column.
<Text role="caption" truncate="start">
  workspaces/primitives/packages/primitives/src/components/Button.tsx
</Text>

// Wrong: the reader sees the shared prefix and never the file.
<Text role="caption" truncate>
  workspaces/primitives/packages/primitives/src/components/Button.tsx
</Text>
```

The two forms send the runtime's own `textOverflow` values — `"ellipsis"` and
`"ellipsis-start"` — and a capture comparison proves the leading form paints the
tail and differs from the tail form (plan `783`). Truncation needs a bounded
width; a run that fits is untouched. A valid `clamp` wins over either truncation
(a clamp is a multi-line height cap with no ellipsis, plan `082`), and a
fixed-height **control** label always clips its tail — only the standalone
`Text` chooses its end.

## Keyboard

Not focusable. A `selectable` run takes a **pointer drag**, and the dragged text
becomes the window's selection — measured in the runtime (plan `385`): a drag
across `"Alpha bravo charlie"` selected the whole run, and the same drag over a
non-selectable copy selected nothing. There is no keyboard selection and no copy
command binding in the component; the highlight uses the platform's own colour.

## Accessibility

The runtime exposes every `<text>` as a `Label` carrying its string. `Text`
adds the outline semantics the role implies, from one table (`textSemantics`,
plan `059`):

| `role` | Host attributes | AccessKit |
| ------ | --------------- | --------- |
| `h1`, `h2`, `h3` | `role="heading"`, `aria-level={1,2,3}` | `Heading` with that level and the text as its value |
| `code`, `codeBlock` | `role="code"` | `Code` |
| any role, with `label` | `role="img"`, `aria-label={label}` | `Image` with that name (a mark, not prose — plan `581`) |
| `display`, `body`, `bodyStrong`, `label`, `caption` | none | `Label` (the runtime default) |

`display` is deliberately not a heading: it is a visual scale, and the page's
outline level is the app's decision — use `h1` for the page title. A screen
reader therefore hears a real document outline when the roles are used honestly,
and a flat list of labels otherwise. A `decoration` is paint only: it is not
announced, so a struck-out value still needs words ("was", "no longer
available") when the removal is information the reader needs.

A **mark** is the exception to "text is prose": a run whose visible glyph
carries meaning — `Label`'s required `*`, a status dot — takes `label`, and the
runtime exposes it as an `Image` named by that string. Measured (plan `581`):
`<text role="img" aria-label="required">*</text>` reports `Image: "required"`,
while the same run without a name reports `Label: "*"`. The name wins over the
role's own semantics, so use it for marks only; a blank name is absent.

## Theming

`textStyle` reads `typography[role]`, the mono/sans family and the tone's colour
role. `userSelect` defaults to `"none"` so chrome does not accept a text
selection by accident; turn it on for content. `minWidth: 0` is the containment
rule above; `shrink={false}` sends the runtime's `"auto"` instead, and neither is
a colour or size token.

`clamp` is a **height cap, not the runtime's `lineClamp`**: `maxHeight` is
`clamp × typography[role].lineHeight` and `overflow` is `"hidden"`. The runtime
caches one shaped text layout per string/font/width for the whole window and its
`lineClamp` is not part of that key, so a clamp written that way leaks to every
identical string at the same width (plan `082`). The cap is per element, so it
cannot leak, and the line count follows the role's own leading rather than a
hard-coded pixel value.

`selectionColor` is the runtime's **inherited** selection wash — the platform
default is the accent at 35 %. Set it through `style` on the run or on any
container above it; a child's own value wins. There is no dedicated prop,
because `style` is the one escape hatch (the same rule as `Box`):

```tsx
<Text selectable style={{ selectionColor: alpha(theme.colors.primary, 0.35) }}>
  Selectable release notes
</Text>
```

Measured in the runtime (plan `784`): the default wash repaints under a drag, a
caller's colour changes the paint, a container's colour inherits into the run,
and the run's own value overrides its container. `alpha` is exported by
`@gpuixui/primitives/core` (re-exported from `@gpuixui/tokens`).

## Limitations

- `clamp` is a **hard cut with no ellipsis**. It stops at the line boundary; the
  runtime's ellipsizing `lineClamp` cannot be used, because the shared text
  layout would apply one component's clamp to another component's identical
  string (measured in plan `082`: clamped-then-plain painted `36 / 36` px, and
  plain-then-clamped painted `108 / 108` px). Use `truncate` when one line with
  an ellipsis is what you want.
- `display` carries no heading level (above); use `h1` when the large text is
  the page title.
- No paragraph grouping: each `Text` is its own node; there is no semantic
  container the runtime maps to a paragraph.
- No rich text: one run, one role. Composition is several `Text` nodes in a
  `Stack`.
- `label` is for marks, not prose: a named run is an `Image`, so a heading or
  paragraph with a name loses its heading/paragraph semantics. Leave prose
  unnamed; its text is already the node's value.
- A run inside a `Grid columnMin="max-content"` cell must set
  `shrink={false}`; the default floor (`minWidth: 0`) is what the track reads,
  so the column collapses to zero (measured, plan `587`). This is the one place
  the shrink rule is the wrong shape.
- **No italic.** `StyleDesc` has no `fontStyle`; the runtime offers family and
  weight only, so emphasis is a different face or a heavier role, not a slant.
- `decoration` is one value per run: no decoration colour, thickness, style or
  offset, and no way to decorate part of a string. Split the run into adjacent
  `Text` nodes when only a word is struck (they merge onto one line).
- No responsive type scale or fluid sizing.
- Selection is **pointer-only**: no keyboard extension and no copy binding. The
  wash colour is caller-controlled through the inherited `selectionColor` style
  (above); the runtime owns the highlight geometry.
- `truncate` needs a bounded width to truncate against, and it is one line: the
  leading form cannot be combined with a multi-line `clamp`, because the clamp
  wins and clips the bottom edge without an ellipsis.
- `clamp` needs a bounded width to know how many lines the text would take;
  the cap is a maximum, so shorter text keeps its natural height.

## Verification

- `src/core/variants.test.ts` — every role resolves from the theme.
- `src/core/style.test.ts` — the clamp payload (`maxHeight`, `overflow`, no
  `lineClamp`), the values it refuses, and the shrink floor's two values
  (`0` / `"auto"`, plan `587`).
- `src/components/presentational.test.tsx` — tone, alignment, truncate, clamp and
  selectable; every role removes the content floor and a caller's `minWidth`
  wins (plan `383`); `shrink={false}` restores `"auto"` (plan `587`);
  decoration resolves, and a caller's `style` wins (plan `377`); a named run is
  an image and a blank name is absent (plan `581`).
- `runtime/layout.runtime.test.tsx` — a `max-content` grid cell measures 0 with
  the default shrink and its content with `shrink={false}` (plan `587`).
- `runtime/text-selection.runtime.test.tsx` — a real drag selects a
  `selectable` run and selects nothing from a non-selectable one (plan `385`);
  four captured windows also prove the default wash, a caller's
  `selectionColor`, its inheritance from a container and a child's override
  (plan `784`).
- `runtime/text.runtime.test.tsx` — the clamp's measured height at 1/2/3 lines,
  both directions of the shared-layout regression, and the full string in the
  accessibility tree (plan `082`).
- `runtime/text-decoration.runtime.test.tsx` — a capture proves underline is
  byte-identical to a manual `textDecoration` frame and different from plain,
  and that line-through differs from both (plan `377`).
- `runtime/text-align.runtime.test.tsx` — `align="end"` is byte-identical to a
  manual `textAlign: "right"` frame and different from `align="start"` (plan
  `365`).
- `runtime/text-overflow.runtime.test.tsx` — a 220 px row wraps a long sentence,
  keeps its 40 px sibling inside, leaves a column's width alone, and truncates a
  one-line run to the row's width (plan `383`); a capture also proves
  `truncate="start"` is byte-identical to a manual
  `textOverflow: "ellipsis-start"` frame, different from `truncate`, on one line
  inside its row, and inert on a run that fits (plan `783`).
- `runtime/layout.runtime.test.tsx` — the string is painted, its box height
  equals the role's line height, and each role's measured semantics match the
  table above: `h1`/`h2` are `Heading` nodes with level 1/2 and their text as
  the value, `code` is a `Code` node, `body` stays a `Label` (plan `059`).
