---
title: Text
description: One run of type, named by a theme role and a semantic tone.
---

`Text` names a role from the theme's type scale and a tone that decides its
colour. It adds no behaviour: the runtime has one `text` host element, so every
typographic role is the same element with a different resolved `StyleDesc`. The
role also decides the **accessibility semantics**: `h1`-`h3` are headings with a
level, and `code`/`codeBlock` are code. Other roles stay static text.

## Usage

```tsx
import { Text, Stack } from "@gpuixui/primitives";

<Stack direction="column" gap="2xs">
  <Text role="h2">Version 0.10.0</Text>
  <Text role="body" tone="muted">
    Released 17 October 2026.
  </Text>
  <Text role="code">nub add @gpuixui/primitives</Text>
</Stack>;
```

Inline decoration is one prop — a former price, or an inline emphasis that is
still plain text (`Text` is not a link; a real one is Tier 2):

```tsx
<Stack direction="row" gap="2xs" align="baseline">
  <Text role="caption" tone="muted" decoration="line-through">$49</Text>
  <Text role="bodyStrong">$39</Text>
</Stack>;

<Text tone="primary" decoration="underline">View changelog</Text>;
```

## Roles

| `role` | Family | Typical use |
| ------ | ------ | ----------- |
| `display` | sans | a landing or empty-state headline |
| `h1`, `h2`, `h3` | sans | page, section and subsection titles |
| `body` | sans | running text |
| `bodyStrong` | sans | the lead sentence of a section |
| `label` | sans | a control's visible name |
| `caption` | sans | metadata and helper text |
| `code` | mono | an inline identifier or command |
| `codeBlock` | mono | a block of code |

Sizes, line heights and weights come from `theme.typography`. No component picks
a font size.

## Tones

| `tone` | Colour role | Use for |
| ------ | ----------- | ------- |
| `default` | `foreground` | body and headings |
| `muted` | `mutedForeground` | metadata, help, disabled-adjacent copy |
| `primary` | `primary` | a link-like non-interactive emphasis |
| `destructive` | `destructive` | an error or a breaking change |
| `inherit` | none | text on a coloured surface, taking its parent's colour |

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `role` | `TextRole` | `"body"` | size, leading, weight and family |
| `tone` | `TextTone` | `"default"` | colour role |
| `align` | `"start" \| "center" \| "end"` | runtime default | horizontal alignment; `"end"` is sent to the runtime as its `right` (plan `365`) |
| `decoration` | `"underline" \| "line-through"` | none | the runtime's `textDecoration`; paint only, never a semantic emphasis (plan `377`) |
| `truncate` | `boolean` | `false` | one line, clipped with an ellipsis |
| `clamp` | `number` | none | hard-clip after N lines (a value below 1 is ignored) |
| `selectable` | `boolean` | `false` | `userSelect: "text"`; off for chrome, on for content |
| `style` | `StyleDesc` | — | merged last |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the string (or inline nodes) |

`align="end"` means the end of a **left-to-right** box: GPUix 0.10.0 has no text
direction, and its `textAlign` implements `center`, `right` and `left`/`start`
only. The resolver therefore sends `"right"` for the public `"end"`; passed
through verbatim it painted as `start` (measured, plan `365`). There is no RTL
claim to make.

## Keyboard

Not focusable. Selectable text is pointer-selectable when `selectable` is on;
there is no copy command binding in the component.

## Accessibility

The runtime exposes every `<text>` as a `Label` carrying its string. `Text`
adds the outline semantics the role implies, from one table (`textSemantics`,
plan `059`):

| `role` | Host attributes | AccessKit |
| ------ | --------------- | --------- |
| `h1`, `h2`, `h3` | `role="heading"`, `aria-level={1,2,3}` | `Heading` with that level and the text as its value |
| `code`, `codeBlock` | `role="code"` | `Code` |
| `display`, `body`, `bodyStrong`, `label`, `caption` | none | `Label` (the runtime default) |

`display` is deliberately not a heading: it is a visual scale, and the page's
outline level is the app's decision — use `h1` for the page title. A screen
reader therefore hears a real document outline when the roles are used honestly,
and a flat list of labels otherwise. A `decoration` is paint only: it is not
announced, so a struck-out value still needs words ("was", "no longer
available") when the removal is information the reader needs.

## Theming

`textStyle` reads `typography[role]`, the mono/sans family and the tone's colour
role. `userSelect` defaults to `"none"` so chrome does not accept a text
selection by accident; turn it on for content.

`clamp` is a **height cap, not the runtime's `lineClamp`**: `maxHeight` is
`clamp × typography[role].lineHeight` and `overflow` is `"hidden"`. The runtime
caches one shaped text layout per string/font/width for the whole window and its
`lineClamp` is not part of that key, so a clamp written that way leaks to every
identical string at the same width (plan `082`). The cap is per element, so it
cannot leak, and the line count follows the role's own leading rather than a
hard-coded pixel value.

## Limitations

- `clamp` is a **hard cut with no ellipsis**. It stops at the line boundary; the
  runtime's ellipsizing `lineClamp` cannot be used, because the shared text
  layout would apply one component's clamp to another component's identical
  string (measured in plan `082`: clamped-then-plain painted `36 / 36` px, and
  plain-then-clamped painted `108 / 108` px). Use `truncate` when one line with
  an ellipsis is what you want.
- `display` carries no heading level (above); use `h1` when the large text is
  the page title.
- No paragraph grouping: each `Text` is its own node; there is no semantic
  container the runtime maps to a paragraph.
- No rich text: one run, one role. Composition is several `Text` nodes in a
  `Stack`.
- **No italic.** `StyleDesc` has no `fontStyle`; the runtime offers family and
  weight only, so emphasis is a different face or a heavier role, not a slant.
- `decoration` is one value per run: no decoration colour, thickness, style or
  offset, and no way to decorate part of a string. Split the run into adjacent
  `Text` nodes when only a word is struck (they merge onto one line).
- No responsive type scale or fluid sizing.
- `truncate` needs a bounded width to truncate against.
- `clamp` needs a bounded width to know how many lines the text would take;
  the cap is a maximum, so shorter text keeps its natural height.

## Verification

- `src/core/variants.test.ts` — every role resolves from the theme.
- `src/core/style.test.ts` — the clamp payload (`maxHeight`, `overflow`, no
  `lineClamp`) and the values it refuses.
- `src/components/presentational.test.tsx` — tone, alignment, truncate, clamp and
  selectable; decoration resolves, and a caller's `style` wins (plan `377`).
- `runtime/text.runtime.test.tsx` — the clamp's measured height at 1/2/3 lines,
  both directions of the shared-layout regression, and the full string in the
  accessibility tree (plan `082`).
- `runtime/text-decoration.runtime.test.tsx` — a capture proves underline is
  byte-identical to a manual `textDecoration` frame and different from plain,
  and that line-through differs from both (plan `377`).
- `runtime/text-align.runtime.test.tsx` — `align="end"` is byte-identical to a
  manual `textAlign: "right"` frame and different from `align="start"` (plan
  `365`).
- `runtime/layout.runtime.test.tsx` — the string is painted, its box height
  equals the role's line height, and each role's measured semantics match the
  table above: `h1`/`h2` are `Heading` nodes with level 1/2 and their text as
  the value, `code` is a `Code` node, `body` stays a `Label` (plan `059`).
