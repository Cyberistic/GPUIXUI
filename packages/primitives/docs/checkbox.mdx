---
title: Checkbox
description: An independent yes/no, optionally indeterminate.
---

`Checkbox` is a square selection control for an independent choice. It shares one
three-state paint (`unchecked`, `checked`, `indeterminate`) with `Switch` and
`RadioGroup` through `core/selection.ts`, so they cannot drift apart.

## Usage

```tsx
import { Checkbox } from "@gpuixui/primitives";

<Checkbox
  checked={email}
  onValueChange={setEmail}
  label="Email notifications"
/>;
```

An indeterminate **parent** over a set of options is `CheckboxGroup`'s job — it
derives the tri-state and never clears a disabled option:

```tsx
import { CheckboxGroup } from "@gpuixui/primitives";

<CheckboxGroup label="Channels" selectAll="All channels" options={channels} />;
```

`Checkbox` itself paints `indeterminate` when a caller owns that state.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `checked` | `boolean` | — | controlled state; omit to let the box keep its own |
| `defaultChecked` | `boolean` | `false` | initial state when uncontrolled |
| `onValueChange` | `(next: boolean) => void` | none | the next boolean, only when it changed |
| `indeterminate` | `boolean` | `false` | paints a dash and announces `mixed`; overrides `checked` |
| `disabled` | `boolean` | `false` | refuses pointer and keys, leaves the tab order |
| `invalid` | `boolean` | `false` | the empty box takes the destructive border |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | box side from `iconSize` |
| `accent` | `"primary" \| "destructive"` | `"primary"` | the fill and mark colour |
| `label` | `string` | none | accessible name |
| `aria-description` | `string` | none | description announced after the name; trimmed, and a blank value is absent (a `Tooltip` writes its text here) |
| `style` | `StateStyle<CheckboxState>` | — | merged last; an object or a state callback |
| `testId` | `string` | — | stable locator |

`indeterminate` is a **paint override**: activation still toggles the underlying
boolean, so an indeterminate parent becomes checked on the next click rather than
clearing.

## Keyboard

| Key | Contract |
| --- | -------- |
| Space | toggles on key **up** |
| Enter | toggles on key **down** |
| held key | repeat events do nothing |
| Tab | reaches the box when it is not disabled |

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). Role, name, tab order, keyboard operation and activation
  are unaffected.
- Role: `CheckBox` in the runtime's accessibility tree.
- State is announced through **`aria-valuetext`** (`checked`, `unchecked`,
  `mixed`), because GPUix 0.10.0 has no `aria-checked` (plan 020 §1.4).
- `disabled` removes the tab stop; there is no `aria-disabled`.
- The visible name is a separate `Label`: the text is painted and the box
  carries its own `label`, but the `Label` is **not clickable and not
  associated** — GPUix has no `aria-labelledby` and a sibling `<text>` is not
  part of the interactive element. Use `CheckboxGroup` when a clickable labelled
  row is needed.
- **Slot trigger:** forwards a `Tooltip`'s handlers and `aria-description`, so a
  tip opens on hover and on keyboard focus.

## Theming

`selectionBoxStyle` resolves box side from `iconSize`, radius from `radius.sm`,
border from `input`/`destructive`, fill from the accent role and the mark from
`selectionMarkColor`. Hover and press are declared in `style.hover`/`style.active`,
not scripted. An invalid **empty** box keeps the destructive border through both
— the border is the error cue, so the healthy interaction rule never paints over
it — while a chosen box keeps its accent feedback (plan 356). Disabled adds half
opacity and removes pointer feedback. Focus paints the selection ring
(`colors.ring`, spread by `borderWidth.strong`).

## Style by state

`style` takes an object or a callback over the checkbox's public state — the
runtime's own `StateStyle` type:

```tsx
<Checkbox
  label="Email notifications"
  style={(state) => ({ opacity: state.indeterminate ? 0.8 : 1 })}
/>
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `checked` | `boolean` | the resolved value (controlled or its own) |
| `indeterminate` | `boolean` | the dash state; never true together with `checked` |
| `disabled` | `boolean` | refuses pointer and keys |
| `focused` | `boolean` | holds native focus |
| `invalid` | `boolean` | the empty box paints the destructive border |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. `CheckboxState` is exported.

## Limitations

- No `aria-checked` (above).
- No label-inside-the-control composition for a standalone box: a `Label` beside
  it is cosmetic (not clickable, not associated). `Checkbox` still names itself
  through `label`; for one clickable labelled row use `CheckboxGroup` (or a
  Tier 2 field row for other controls).
- No partial-state animation and no custom mark.

- `src/components/state-style.test.tsx` — the state payload and the callback
  winning over the component's own rules (plan 079).

- `src/core/selection.test.ts` — the three-state paint and mark colour.
- `src/components/selection.test.tsx` — toggle, indeterminate and disabled
  wiring at the render seam.
- `runtime/controls.runtime.test.tsx` — click and Space-up toggle; the announced
  value flips `unchecked → checked`; indeterminate reads `mixed`; the AccessKit
  role is `CheckBox`; focus paints the ring and moves it with focus.
- `runtime/examples.runtime.test.tsx` — the **checkbox example** (plan `374`)
  mounts the standalone box in its real role: a tri-state header over a column
  of row boxes. The header announces `mixed`, a row click repaints the caller's
  count, and selecting all announces `checked`.
