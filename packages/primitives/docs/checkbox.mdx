---
title: Checkbox
description: An independent yes/no, optionally indeterminate.
---

`Checkbox` is a square selection control for an independent choice. It shares one
three-state paint (`unchecked`, `checked`, `indeterminate`) with `Switch` and
`RadioGroup` through `core/selection.ts`, so they cannot drift apart.

Two parts: the box, and `CheckboxIndicator` — the mark. `Checkbox`'s children
are the indicator's content, so a custom glyph needs no rebuild of the control.

## Usage

```tsx
import { Checkbox } from "@gpuixui/primitives";

<Checkbox
  checked={email}
  onCheckedChange={setEmail}
  label="Email notifications"
/>;
```

An indeterminate parent:

```tsx
<Checkbox
  checked={email && push}
  indeterminate={!email !== !push}
  onCheckedChange={(next) => {
    setEmail(next);
    setPush(next);
  }}
  label="All channels"
/>;
```

A custom mark:

```tsx
import { Icon } from "@gpuixui/icons";
import { useTheme } from "@gpuixui/primitives";

const theme = useTheme();

<Checkbox
  checked={favourite}
  onCheckedChange={setFavourite}
  label="Favourite"
>
  <Icon
    name="star-filled"
    size={theme.iconSize.sm}
    color={theme.colors.primaryForeground}
  />
</Checkbox>;
```

Passing children replaces the default check/dash glyph. They are drawn inside
the mark's `pointerEvents: "none"` region, so a custom mark cannot swallow the
press that toggles the box.

## API

### `Checkbox`

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `checked` | `boolean` | — | controlled state; omit to let the box keep its own |
| `defaultChecked` | `boolean` | `false` | initial state when uncontrolled |
| `onCheckedChange` | `(next: boolean) => void` | none | the next boolean, only when it changed |
| `onChange` | `(next: boolean) => void` | none | deprecated alias for `onCheckedChange`, removed next release; the new name wins when both are passed |
| `children` | `ReactNode` | the default glyph | the mark's content |
| `indeterminate` | `boolean` | `false` | paints a dash and announces `mixed`; overrides `checked` |
| `disabled` | `boolean` | `false` | refuses pointer and keys, leaves the tab order |
| `invalid` | `boolean` | `false` | the empty box takes the destructive border |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | box side from `iconSize` |
| `accent` | `"primary" \| "destructive"` | `"primary"` | the fill and mark colour |
| `label` | `string` | none | accessible name |
| `style` | `StyleDesc` | — | merged last |
| `testId` | `string` | — | stable locator |

### `CheckboxIndicator`

The mark region. `Checkbox` renders it; compose it directly only when you need
its props (a `style`, a `className`) in addition to `Checkbox`'s children.

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `children` | `ReactNode` | the default check/dash | the glyph |
| `className` | `string` | — | compiled through the recipe registry, after the part's rules |
| `style` | `StyleDesc` | — | merged last |

`indeterminate` is a **paint override**: activation still toggles the underlying
boolean, so an indeterminate parent becomes checked on the next click rather than
clearing.

## Keyboard

| Key | Contract |
| --- | -------- |
| Space | toggles on key **up** |
| Enter | toggles on key **down** |
| held key | repeat events do nothing |
| Tab | reaches the box when it is not disabled |

A Space **press** calls `preventDefault()`, so a scroll container does not
also scroll while the control waits for the release.

## Accessibility

- Role: `CheckBox` in the runtime's accessibility tree.
- State is announced through **`aria-valuetext`** (`checked`, `unchecked`,
  `mixed`), because `@gpuix/native` 0.11.0 has no `aria-checked` (plan 020 §1.4).
- `disabled` removes the tab stop; there is no `aria-disabled`.
- The visible name is a separate `Label`, but it does not name the box: there is
  no `aria-labelledby`, so the box's own `label` prop is its accessible name —
  pass the same string, or spread `labelledBy(name)`.

## Theming

`selectionBoxClass` compiles the box through the recipe registry: side from
`iconSize`, radius from `radius.sm`, border from `input`/`destructive`, fill from
the accent role, and the mark colour from `selectionMarkColor`. Hover and press
are declared in `style.hover`/`style.active`, not scripted. Disabled adds half
opacity and removes pointer feedback. Focus is the keyboard outline declared at
rest (`keyboardRing`, `colors.ring` at `borderWidth.strong`), painted by the
runtime after Tab and never after a mouse press.

## Limitations

- No `aria-checked` (above).
- No label-inside-the-control composition: a `Label` beside the box is visible
  text only — it does not name the control. The box is named by its own `label`
  prop, which `labelledBy(name)` builds from the same string.
- No partial-state animation.

## Verification

- `src/core/selection.test.ts` — the three-state paint and mark colour.
- `src/components/Checkbox.test.tsx` — toggle, indeterminate and disabled
  wiring; the mark's state flows into its colour; a custom glyph replaces the
  default; the mark keeps the pointer guard; the callback name and its alias.
- `runtime/controls.runtime.test.tsx` — click and Space-up toggle; the announced
  value flips `unchecked → checked`; a custom mark still toggles on a real hit
  test; indeterminate reads `mixed`; the AccessKit role is `CheckBox`; focus
  declares the keyboard ring and moves native focus with the selection.
- `runtime/labelling.runtime.test.tsx` — a `Label` beside the box paints its
  text but does not name the box; the same string through `labelledBy` does.
