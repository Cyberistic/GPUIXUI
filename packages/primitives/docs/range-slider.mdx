---
title: RangeSlider
description: Two values — the ends of one interval — on a single track.
---

`RangeSlider` is a minimum and a maximum on one track: a price band, a time
window, a size range. It is a **second component**, not a mode of `Slider`,
because its accessibility contract is different: the group contains two
sliders, each with its own value and tab stop.

## Usage

```tsx
import { RangeSlider, Stack, Text } from "@gpuixui/primitives";
import { useState } from "react";

const [price, setPrice] = useState<readonly [number, number]>([20, 80]);

<Stack direction="column" gap="sm">
  <Text role="caption" tone="muted">${price[0]} – ${price[1]}</Text>
  <RangeSlider
    label="Budget"
    value={price}
    onValueChange={setPrice}
    step={5}
    formatValue={(value) => `$${value}`}
  />
</Stack>;
```

The value is always `[start, end]` in that order. A press picks the nearer end;
a press beyond both thumbs picks the end it passed. The ends can touch but never
cross.

The ends of the **range** are stops as well: a step that does not divide the
span (`min: 0`, `max: 10`, `step: 3`) leaves 10 reachable, so the last band
cannot be selected away.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `readonly [number, number]` | — | controlled span |
| `defaultValue` | `readonly [number, number]` | `[min, max]` | uncontrolled start |
| `onValueChange` | `(value: readonly [number, number]) => void` | — | called with the ordered pair |
| `onChange` | `(value: readonly [number, number]) => void` | — | deprecated alias for `onValueChange` |
| `min` / `max` | `number` | `0` / `100` | the closed range |
| `step` | `number` | `1` | quantisation; `0` is continuous |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | thumb and track metrics |
| `disabled` | `boolean` | `false` | both thumbs leave the tab order |
| `invalid` | `boolean` | `false` | destructive fill and thumb borders |
| `label` | `string` | none | group name; thumbs become `"<label> minimum"` / `"<label> maximum"` |
| `formatValue` | `(value: number) => string` | `String` | the announced text of each thumb |
| `style` | `StateStyle<SliderState>` | — | resolved against the live state, merged last on the track |
| `className` | `string` | — | joined after the recipe, so it wins conflicts |
| `children` | `ReactNode` | — | the parts to draw; omit for the default two-thumb composition |
| `onClick` / `onKeyDown` / `onKeyUp` / `onFocus` / `onBlur` | host handlers | none | composed with the range's own; keys and focus land on a thumb, the press on the track or the thumb it hit |
| `testId` | `string` | — | stable locator for the track |

The parts are the same three `Slider` exports: `SliderTrack` holds
`SliderIndicator index={0}` / `SliderThumb index={0}` /
`SliderIndicator index={1}` / `SliderThumb index={1}`. Each thumb keeps its own
`role="slider"`, name and tab stop; `index` is what tells the parts which end
they paint. A custom composition may reorder or restyle them, but each thumb is
still a tab stop and the root still owns the pointer handling.

Your host handlers are composed with the range's, never substituted. A key and a
focus event arrive from the thumb they landed on; a press arrives from the track
— or from the thumb the runtime hit, since `<div>`s do not bubble. A disabled
range installs no `onClick` and keeps every key and focus observable.

## Keyboard

Each thumb is its own tab stop and answers:

| Key | Effect on the focused thumb |
| --- | --------------------------- |
| `ArrowRight` / `ArrowUp` | + one step |
| `ArrowLeft` / `ArrowDown` | − one step |
| `PageUp` / `PageDown` | ± ten steps |
| `Home` / `End` | `min` / `max`, clamped at the other thumb |

A press moves native focus to the thumb it grabbed, so the arrows that follow
act on the end the user is holding. The focused thumb paints the ring.

## Accessibility

- The group is `role="group"` with `aria-label`; each thumb is `role="slider"`
  (AccessKit `Slider` and `Group`, verified in the real renderer).
- Each thumb announces its own value through `aria-valuetext`. There is no
  `aria-valuenow`/`min`/`max` in `@gpuix/native` 0.11.0, so the two values reach a screen
  reader but the range does not.
- The default names — `"Budget minimum"`, `"Budget maximum"` — are derived from
  `label`, so a group with one name is never two unnamed sliders.

## Theming

Same resolver as `Slider`: `colors.muted` rail, `colors.primary` fill, thumb
`colors.input` with a `colors.primary` border, the keyboard outline
(`keyboardRing` → the runtime's `focusVisible`) on each thumb because each thumb
is its own tab stop. The end
values are painted as two fills; the second fill is the length between the ends.

`style` takes the same `StateStyle<SliderState>` as `Slider` — a `StyleDesc`, or
a callback that receives `{ disabled, focused, invalid }`. A range reports
`focused` while **either** thumb holds focus, because the callback styles the
track both components share, not an individual thumb.

## Limitations

- **No pointer capture** — a drag stops updating when the pointer leaves the
  track; press-to-position and the keyboard are the precise paths.
- **No `aria-valuenow`/`min`/`max`** (above).
- Both thumbs are the same pill as `Slider`'s; a custom glyph goes inside a
  `SliderThumb` in the caller's composition, one `index` per end.
- A custom composition may not add a marker that answers a press: the root owns
  the pointer handling, and the runtime does not bubble a press to it from a
  child that takes the hit.

## Verification

- `src/core/value.test.ts` — span ordering, the crossing guard, the nearest-end
  rule (including both thumbs at one value), and the maximum staying reachable
  when the step does not divide the span.
- `src/components/Slider.test.tsx` — two named sliders, per-thumb keys, the
  crossing result, per-thumb rings, disabled tab stops; the second segment's
  width from the parts; a `style` callback reporting focus anywhere in the group
  and winning over the recipe.
- `runtime/value.runtime.test.tsx` — a real press at 10% moves the start, at 90%
  the end; focus follows the grabbed thumb; an arrow moves only that end; a
  start driven past the end stops on it. Measured 2026-10-17 (plan 053 §11).
