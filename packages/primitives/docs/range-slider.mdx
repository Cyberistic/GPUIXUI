---
title: RangeSlider
description: Two values — the ends of one interval — on a single track.
---

`RangeSlider` is a minimum and a maximum on one track: a price band, a time
window, a size range. It is a **second component**, not a mode of `Slider`,
because its accessibility contract is different: the group contains two
sliders, each with its own value and tab stop.

## Usage

```tsx
import { RangeSlider, Stack, Text } from "@gpuixui/primitives";
import { useState } from "react";

const [price, setPrice] = useState<readonly [number, number]>([20, 80]);
const [savedPrice, setSavedPrice] = useState<readonly [number, number]>([20, 80]);

<Stack direction="column" gap="sm">
  <Text role="caption" tone="muted">${price[0]} – ${price[1]}</Text>
  <RangeSlider
    label="Budget"
    value={price}
    onValueChange={setPrice}
    onValueCommit={setSavedPrice}
    step={5}
    formatValue={(value) => `$${value}`}
  />
</Stack>;
```

The value is always `[start, end]` in that order. A press picks the nearer end;
a press beyond both thumbs picks the end it passed. The runtime captures the
press, so a dragged thumb keeps tracking after the pointer leaves the track. The
ends can touch but never cross. The stops include `max` even when `step` does not
divide the span, so the default `[min, max]` band paints end to end: `min 0`,
`max 10`, `step 3` has the stops `0, 3, 6, 9, 10`. A gesture that leaves both
ends where they were — a second press on the same spot, an `End` already at the
maximum — reports nothing, the same no-op rule `Slider` follows. Each end is
clamped before the pair is ordered: `NaN` reads as `min`, `+Infinity` as `max`
and `-Infinity` as `min`, so `[0, Infinity]` is the full band.

`onValueChange` is the continuous stream; `onValueCommit` is the settled half —
one call when a drag is released with the ordered pair it ended on, and one call
per keyboard step. A form can save a finished gesture without debouncing. A
gesture that ends on its starting pair reports no commit (the stream still
reported the pairs it passed through), and a press that changed nothing reports
neither callback.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `readonly [number, number]` | — | controlled span |
| `defaultValue` | `readonly [number, number]` | `[min, max]` | uncontrolled start |
| `onValueChange` | `(value: readonly [number, number]) => void` | — | called with the ordered pair, only when it changed |
| `onValueCommit` | `(value: readonly [number, number]) => void` | — | one call when a changed drag is released, or per key step |
| `min` / `max` | `number` | `0` / `100` | the closed range |
| `step` | `number` | `1` | quantisation; `0` is continuous, and **`max` is always a stop** |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | thumb and track metrics |
| `disabled` | `boolean` | `false` | both thumbs leave the tab order |
| `invalid` | `boolean` | `false` | destructive fill and thumb borders |
| `label` | `string` | none | group name, trimmed; thumbs become `"<label> minimum"` / `"<label> maximum"`, and a blank label leaves the group and both thumbs unnamed |
| `formatValue` | `(value: number) => string` | `String` | the announced text of each thumb; a blank result falls back to the value |
| `style` | `StateStyle<RangeSliderState>` | — | merged last, on the track; an object or a state callback |
| `thumbStyle` | `StateStyle<RangeSliderThumbState>` | — | merged last on each thumb; an object or a state callback |
| `testId` | `string` | — | names the track; thumbs become `${testId}-thumb-start` / `-thumb-end` |

## Keyboard

Each thumb is its own tab stop and answers:

| Key | Effect on the focused thumb |
| --- | --------------------------- |
| `ArrowRight` / `ArrowUp` | + one step |
| `ArrowLeft` / `ArrowDown` | − one step |
| `PageUp` / `PageDown` | ± ten steps |
| `Home` / `End` | `min` / `max`, clamped at the other thumb |

A press moves native focus to the thumb it grabbed, so the arrows that follow
act on the end the user is holding. The focused thumb paints the ring, and the
ring clears when focus leaves the group. Only the **primary button** starts a
press: a right or middle click moves neither end and takes no focus. Each
accepted key step reports `onValueCommit` once with the settled pair; a step
that cannot move — an arrow at a bound, or one blocked by the other thumb —
reports nothing.

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). The same sample clears the ring and the thumb cursor when
  focus moves to a host outside the group (plans `601`, `602`). Role, name, tab
  order, keyboard operation and activation are unaffected.
- The group is `role="group"` with `aria-label`; each thumb is `role="slider"`
  (AccessKit `Slider` and `Group`, verified in the real renderer).
- Each thumb announces its own value through `aria-valuetext`. There is no
  `aria-valuenow`/`min`/`max` in GPUix 0.10.0, so the two values reach a screen
  reader but the range does not.
- The default names — `"Budget minimum"`, `"Budget maximum"` — are derived from
  `label`, so a group with one name is never two unnamed sliders.

## Theming

Same resolver as `Slider`: `colors.muted` **rail** (the track paints no surface
at rest), `colors.primary` fill, thumb `colors.input` with a `colors.primary`
border, `focusRing` for focus. The end values are painted as two fills; the
second fill is the length between the ends. The track carries the
`colors.hover` / `colors.active` wash while the pointer is over it or a thumb is
being dragged, and a disabled group paints neither (plan `361`).

## Pointer behaviour

A press picks the nearer end and moves it; a press beyond both thumbs picks the
end it passed. The **track is the hit area**, so it — not the thumb — carries the
pointer feedback and the `cursor: "pointer"`. Both thumbs are
`pointerEvents: "none"` in the rail so a press on either reaches the track; the
focus ring stays on the focused thumb, which is the one the arrows act on.

## Style by state

`style` takes an object or a callback over `RangeSliderState` — the runtime's own
`StateStyle` type — merged last on the track:

```tsx
<RangeSlider style={(state) => ({ opacity: state.disabled ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | refuses pointer and keys |
| `invalid` | `boolean` | paints the destructive role |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

### Per-item style

`thumbStyle` takes the same `StateStyle` over `RangeSliderThumbState`, merged
last on each thumb:

```tsx
<RangeSlider
  thumbStyle={(thumb) =>
    thumb.end === "start" && thumb.focused ? { opacity: 1 } : {}
  }
/>
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `end` | `"start" \| "end"` | which end of the range this thumb paints |
| `focused` | `boolean` | this thumb holds native focus |
| `disabled` | `boolean` | refuses pointer and keys |
| `invalid` | `boolean` | paints the destructive role |

`RangeSliderThumbState` extends `SliderThumbState`, so a callback written for
one slider reads the same focus/disabled/invalid fields on the other.

## Limitations


- **No `aria-valuenow`/`min`/`max`** (above).
- The thumbs cannot be given custom glyphs in this version; they are the same
  pill as `Slider`'s.
