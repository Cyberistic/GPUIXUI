---
title: Checkbox Group
description: Several checkboxes that make up one selection, with an optional select-all parent.
---

`CheckboxGroup` is a data-driven set of checkboxes for one value — the multi-select
counterpart of `RadioGroup`. It owns two things a consumer would otherwise write
by hand: the **select-all tri-state** and a row whose **visible label is part of
the control**.

It is not a `Checkbox` with extra props: a lone yes/no is `Checkbox`. It is not a
form wrapper either — there is no validation orchestration and no submit; that is
the Tier 2 `Field`/`Form` work.

## Usage

```tsx
import { CheckboxGroup } from "@gpuixui/primitives";

<CheckboxGroup
  label="Notification channels"
  selectAll="All channels"
  value={channels}
  onValueChange={setChannels}
  options={[
    {
      value: "email",
      label: "Email",
      description: "A digest to your account address.",
    },
    { value: "push", label: "Push" },
  ]}
/>;
```

Uncontrolled, with no parent row:

```tsx
<CheckboxGroup
  label="Formatting"
  defaultValue={["bold"]}
  options={[
    { value: "bold", label: "Bold" },
    { value: "italic", label: "Italic" },
  ]}
/>
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `options` | `CheckboxGroupOption[]` | required | `value`, `label`, optional `description` and `disabled` |
| `value` | `readonly string[]` | — | controlled selection; omit to let the group keep its own |
| `defaultValue` | `readonly string[]` | `[]` | initial selection when uncontrolled |
| `onValueChange` | `(value: readonly string[]) => void` | none | the next set, only when it changed |
| `selectAll` | `string` | none | renders one parent row with this visible name and a derived state |
| `orientation` | `"vertical" \| "horizontal"` | `"vertical"` | row flow |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | box side from `iconSize` |
| `accent` | `"primary" \| "destructive"` | `"primary"` | the fill and mark colour |
| `disabled` | `boolean` | `false` | disables every row, the parent included |
| `invalid` | `boolean` | `false` | every **empty** box takes the destructive border |
| `label` | `string` | none | the group's accessible name |
| `style` | `StateStyle<CheckboxGroupState>` | — | merged last on the group; an object or a state callback |
| `rowStyle` | `StateStyle<CheckboxRowState>` | — | merged last on each row; an object or a state callback |
| `testId` | `string` | — | names the group; rows become `${testId}-${value}` and the parent `${testId}-all` |

### The select-all parent

Its state is derived from the **enabled** options:

| Selected among enabled options | Parent announces | Press does |
| ------------------------------ | ---------------- | ---------- |
| all | `checked` | clears every enabled value |
| none | `unchecked` | selects every enabled value |
| some | `mixed` | selects the rest |

A **disabled** option's value is never changed by the parent in either
direction: the user has no way to toggle it here, so the group must not decide
it for them. A group with no enabled option renders the parent disabled.

### Values

The selection is an array in **selection order**: a toggle appends the newly
selected value, and select-all appends the missing enabled values in option
order. A press that changes nothing does not call `onValueChange`.

## Keyboard

| Key | Contract |
| ---- | -------- |
| Tab | moves to the **next row**; every enabled row is its own tab stop, as a checkbox group is on the platform |
| Shift+Tab | moves to the previous row |
| Space | toggles the focused row on key **up** |
| Enter | toggles the focused row on key **down** |
| held key | repeat events do nothing |
| disabled row | Enter and Space do nothing, even when the row was focused before it became disabled (plan 332) |
| arrows | **not handled** — arrows do not move between checkboxes on the platform |

## Accessibility

- The group is a named `group`; each row is a `checkbox` named by its `label`.
- State is announced through **`aria-valuetext`** (`checked`, `unchecked`,
  `mixed`), because GPUix 0.10.0 has no `aria-checked` (plan 020 §1.4).
- The **whole row** — box, label and description — is one interactive element and
  one tab stop. This is deliberate: the runtime has no `aria-labelledby`/`htmlFor`,
  so a separate `Text` beside a control is inert to the pointer and to assistive
  technology. Nesting a focusable box inside a clickable row would be two
  interactive elements in one.
- `disabled` removes the row's tab stop; there is no `aria-disabled`. Native focus
  can outlive the prop change — a form that disables while saving leaves the
  keyboard where it was — so a disabled row is inert to both the pointer and the
  keys and paints no focus ring (plan 332).
- `option.description` is painted as visible supporting text, not wired as
  `aria-describedby` (unsupported).

## Theming

Each row paints through `core/selection.ts`, the same resolver `Checkbox`,
`RadioGroup` and `Switch` use: box side from `iconSize`, radius from `radius.sm`,
empty border from `input` (or `destructive` when `invalid`), fill from the accent
role, mark from `selectionMarkColor`. The **row** — the element that owns the
role, the name, the tab stop and both handlers — takes its layout and pointer
feedback from `selectionRowStyle`: a `colors.hover` wash on hover and
`colors.active` on press, and **neither** while disabled, so the label column
responds exactly like the box does (plan 355). The box keeps its own border
feedback, so hovering the circle shows both signals. An invalid **empty** box
keeps the destructive border on hover and press, so the row's wash is the only
thing the gesture adds — the error cue is never repainted healthy (plan 356).
A disabled row adds half
opacity and no wash. Focus paints `colors.ring` on the box, not on the row, so
the ring sits on the control the way it does in `Checkbox`. A disabled row
paints **no** ring, even when it kept native focus: the rule lives in
`controlFocusStyle` and the selection painters, so an inert control never
advertises the caret (plan 332).

## Style by state

`style` takes an object or a callback over `CheckboxGroupState` — the runtime's own
`StateStyle` type — merged last on the group box:

```tsx
<CheckboxGroup style={(state) => ({ opacity: state.disabled ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | every row is disabled |
| `invalid` | `boolean` | paints the empty rows' borders destructive |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

### Per-item style

`rowStyle` takes the same `StateStyle` over `CheckboxRowState`, merged last on
the row that owns the hit area, the tab stop and the accessible name:

```tsx
<CheckboxGroup
  selectAll="All"
  rowStyle={(row) =>
    row.parent && row.selection === "indeterminate"
      ? { backgroundColor: theme.colors.selected }
      : {}
  }
/>
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `value` | `Option.Option<string>` | the option's value; `None` on the select-all row |
| `index` | `number` | paint order, select-all included (the parent is 0 when present) |
| `parent` | `boolean` | true on the select-all row only |
| `selection` | `"checked" \| "unchecked" \| "indeterminate"` | the row's own tri-state |
| `disabled` | `boolean` | the row is disabled |
| `focused` | `boolean` | the row holds native focus |
| `invalid` | `boolean` | the group's failed validation |

`CheckboxRowState` is exported. One callback receives every row; branch on
`value`/`index`/`parent`. The select-all row never reports a value — absence is
`Option`, not an empty string.

## Limitations


- No `aria-checked`; state rides on `aria-valuetext` (above).
- No arrow-key movement between rows (deliberate; the platform contract is Tab).
- No mixed/indeterminate **option** state: only the select-all parent is
  tri-state. An option is checked or unchecked.
- No per-option `testId` override; ids are derived from the group's `testId`.
- No `aria-labelledby`, so `label` is written once on the group and each row
  carries its own option label.

- `src/components/state-style.test.tsx` — the container state payload, each
  per-item payload, and the callback winning over the component's own rules
  (plans 080, 081).
- `runtime/state-style.runtime.test.tsx` — a labelled scroll region's focus, a
  select's open state, and the per-item states reaching the paint (plans 080,
  081).

- `src/core/checkbox-group.test.ts` — toggling, the parent tri-state over enabled
  options only, select-all that leaves a disabled value alone, and the identity
  no-op.
- `src/components/selection.test.tsx` — the group/row roles, `aria-valuetext`,
  tab stops, the error border and the focus ring at the render seam; the row's
  hover/active wash, absent on a disabled row, and the caller's `rowStyle`
  winning last (plan 355).
- `runtime/checkbox-group.runtime.test.tsx` — a hit-tested press anywhere on the
  row toggles it, the parent's `mixed → checked → unchecked` cycle, a disabled
  value surviving both directions, Space-up/Enter-down/held keys, Tab skipping a
  disabled row, and the painted error border and ring.
- `runtime/row-feedback.runtime.test.tsx` — every enabled `CheckboxGroup` and
  `RadioGroup` row declares the theme's hover/active wash in the real renderer,
  a disabled row declares neither, and a vertical row's painted width equals the
  group's, so the wash covers the hit area (plan 355).
- `runtime/disabled.runtime.test.tsx` — the cross-control "disabled after focus"
  matrix: every control acts while enabled, focus survives the disable, nothing
  acts afterwards, and no disabled control paints a ring (plan 332).
