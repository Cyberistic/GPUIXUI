`Button` is the action primitive.

<ComponentPreview name="button-variants" />

## Usage

```tsx
import { Button, Stack } from "@gpuixui/primitives";

<Stack direction="row" gap="sm">
  <Button variant="outline">Cancel</Button>
  <Button variant="primary" onActivate={save} loading={saving}>
    Save changes
  </Button>
</Stack>;
```

## Variants

| `variant` | Rest |
| --------- | ---- |
| `primary` (default) | `primary` fill, `primaryForeground` text |
| `secondary` | `secondary` fill with the `borderStrong` edge |
| `outline` | border only |
| `ghost` | no chrome at rest |
| `destructive` | `destructive` fill |
| `link` | text in `brandText(theme)` |

`secondary`'s edge is functional, not decoration: its fill measures under the
1.05:1 perceptibility floor against a row's `hover`, `active`, `accent` and
`selected` washes in most shipped styles, so a tonal action in a row's
`trailing` slot would be a label with no button around it. The edge is
`borderStrong`, the role the boundary contract holds to 3:1 on every strip a
control sits on. `Button.test.tsx` measures it against those washes in all 16
shipped, platform and authored styles and names the fill it replaced.

### Layering over an action

A layer painted on top of an action — a busy loader, a chevron, an effect's
wash — is the control's label drawn another way, so it takes the action's own
label role. `actionOnColor(theme, variant)` answers with the role the variant
table paints from; it is published by `@gpuixui/primitives/button` beside the
component, so a layered caller does not carry a second map:

```tsx
import { Button, actionOnColor } from "@gpuixui/primitives/button";
import { useTheme } from "@gpuixui/primitives";
import { Icon } from "@gpuixui/icons";

const theme = useTheme();

<Button
  variant="primary"
  leading={<Icon name="loader" color={actionOnColor(theme, "primary")} />}
>
  Saving
</Button>;
```

Any other role names a colour picked for a different fill: `secondaryForeground`
on a `primary` fill measures 1.42:1 in Windows dark, so the chevron would be
invisible. `button-entry.test.ts` holds the export and its role map, and
`Button.test.tsx` holds the published role to the label the painter draws for
every variant in both shipped themes.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `variant` | `ButtonVariant` | `"primary"` | the paint from `core/variants.ts` |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | height and padding from density |
| `square` | `boolean` | `false` | icon-only geometry |
| `fullWidth` | `boolean` | `false` | `width: 100%` |
| `disabled` | `boolean` | `false` | blocks activation; out of the Tab order (`tabIndex: -1`) |
| `loading` | `boolean` | `false` | spinner, busy description, blocks activation |
| `loadingLabel` | `string` | `loading.busy` (`"Loading"`) | the busy word, announced as the description and the spinner's name; a blank one silences both |
| `reducedMotion` | `boolean` | the motion provider | holds the busy spinner's lit dot; the prop overrides the provider |
| `leading` / `trailing` | `ReactNode` | none | an icon or element on either side |
| `label` | `string` | none | accessible name; required for an icon-only button |
| `onActivate` | `(event: EventPayload) => void` | none | click or activating key; not called while busy |
| `onClick` / `onKeyDown` / `onKeyUp` / `onFocus` / `onBlur` | host handlers | none | composed with the button's own. `onClick` is the **pointer** route: a keyboard activation never runs it (a click is observed first, an activating key acts first) |
| `onMouseEnter` / `onMouseLeave` | host handlers | none | forwarded to the host; the pair a `Tooltip` trigger needs |
| `aria-description` | `string` | none | supplementary description; `Tooltip` passes the tip here |
| `ref` | `Ref<PublicInstance>` | — | the element itself |
| `aria-expanded` / `aria-selected` | `boolean` | — | announced state, forwarded through `ActionHostProps` |
| `className` | `string` | — | a Tailwind class string, joined after the recipe so it wins conflicts |
| `style` | `StateStyle<ButtonState>` | — | resolved against `{ disabled, focused }`, merged last |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the visible label |

A key is the one interaction the button acts on before handing it over: a
trigger opens in its own `onKeyDown` and records the row its surface must focus,
so the activation leads and the caller's handler observes it afterwards. A
click keeps the caller-first order.

## Limitations

- No `aria-disabled` and no `aria-pressed`.
- No native button element: a `div` with a role and handlers.
- The runtime's headless `@gpuix/react/button` is **not adopted**: `buttonProps` would drop the busy description, hand a `style` callback only `disabled`, keep a disabled action in the tab order and lose the held-key guard on the Space release (evaluated and declined).
- An icon-only button must pass `label`; use `IconButton`.
- `onClick` is the pointer route: a keyboard activation reaches `onActivate`
  alone (measured in a window — six key events, no press), so anything a
  keyboard must reach is wired through `onActivate`.
- The ring paint is the runtime's.
