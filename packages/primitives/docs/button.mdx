title: Button
description: The primary action — clickable and keyboard-activatable, with busy and disabled states.
---

`Button` is the action primitive. `@gpuix/react` 0.11.0 publishes a headless
`Button`/`buttonProps`; this component keeps its own activation contract
(`core/keyboard.ts`: Enter on key down, Space on key up, a held key ignored) and
adds the recipe, `loading`, and the parts contract on top, so the keyboard rules
it ships are the ones its tests and runtime probes measure. **The headless
primitive is not adopted, and that is a decision with a reason**: `buttonProps`
keeps a disabled button in the tab order (`tabIndex: -1`) where this component
removes the stop, exposes only `{ disabled }` to its `style` callback where this
one reports focus too, and has no `loading`/`Spinner` state or
`aria-description="Loading"`. Its Space release also fires without the held-key
guard this component applies. The measured comparison is in `TODO.md` §Salvage.

## Usage

```tsx
import { Button, Stack } from "@gpuixui/primitives";

<Stack direction="row" gap="sm">
  <Button variant="outline">Cancel</Button>
  <Button variant="primary" onActivate={save} loading={saving}>
    Save changes
  </Button>
</Stack>;
```

## Variants

| `variant` | Rest | Hover / press |
| --------- | ---- | ------------- |
| `primary` (default) | `primary` fill, `primaryForeground` text | fill at 90% / 80% alpha |
| `secondary` | `secondary` fill | alpha wash |
| `outline` | border only — `borderStrong`, the measured control boundary | hover wash |
| `ghost` | no chrome | hover wash |
| `destructive` | `destructive` fill | alpha wash |
| `link` | text in the primary role | underline + hover wash |

## Sizes and states

| `size` | Height | Horizontal padding |
| ------ | ------ | ------------------ |
| `sm` | `density.controlHeight.sm` | `density.controlPaddingX.sm` |
| `md` (default) | `density.controlHeight.md` | `density.controlPaddingX.md` |
| `lg` | `density.controlHeight.lg` | `density.controlPaddingX.lg` |

- `square` — equal width and height, no horizontal padding: an icon-only button.
- `fullWidth` — stretches to its parent.
- `disabled` — refuses click and keys, and leaves the tab order.
- `loading` — shows a spinner in the variant's own on-colour (a busy primary
  button paints `primaryForeground`, not a brand dot on a brand fill), announces
  `Loading`, refuses activation, and **stays focusable**.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `variant` | `ButtonVariant` | `"primary"` | the paint from `core/variants.ts` |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | height and padding from density |
| `square` | `boolean` | `false` | icon-only geometry |
| `fullWidth` | `boolean` | `false` | `width: 100%` |
| `disabled` | `boolean` | `false` | blocks activation, leaves the tab order |
| `loading` | `boolean` | `false` | spinner, `Loading` description, blocks activation |
| `leading` / `trailing` | `ReactNode` | none | an icon or element on either side |
| `label` | `string` | none | accessible name; required for an icon-only button |
| `onActivate` | `() => void` | none | click or activating key; not called while busy |
| `onClick` / `onKeyDown` / `onKeyUp` / `onFocus` / `onBlur` | host handlers | none | composed with the button's own; yours runs first |
| `style` | `StateStyle<ButtonState>` | — | resolved against the live state and merged last |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the visible label |

The five host handlers are `InteractionProps`. They are **composed**, never
substituted: your handler runs first with the runtime's own event and the button
still activates. A busy or disabled button installs no `onClick` at all, so
neither your handler nor `onActivate` runs; keys and focus stay observable.

## Keyboard

| Key | Contract |
| --- | -------- |
| Enter | activates on key **down** |
| Space | activates on key **up** |
| held key | repeat events never activate |

`disabled` and `loading` refuse both. A `disabled` button is not tabbable; a
`loading` one is, so a keyboard user is not dropped from the page mid-action.
A Space **press** calls `preventDefault()`, so the platform default (scrolling a
container) does not run while activation waits for the release.

## Accessibility

- Role: `button`; the name comes from `label`, or from a plain text child when
  `label` is absent or blank — a blank label is omitted rather than published as
  an empty name.
- `loading` sets `aria-description="Loading"` — this runtime has no `aria-busy`.
- There is no `aria-disabled`: a disabled button is removed from the tab order
  instead, which is the strongest truthful alternative.
- Focus is a **keyboard-only outline**: the button declares `focusVisible`
  (`controlRing` from `core/focus.ts`, `colors.ring` at `borderWidth.strong`)
  at rest, and the runtime paints it after keyboard input only. A mouse click
  shows no ring, which is the native contract (measured in plan 053). A disabled
  button declares no ring: disabling the focused button does not move the
  runtime's focus, so a declared ring would stay painted on a control that
  refuses every key.

## Theming

`controlStyle` resolves fill, text, border, hover, active and disabled from the
theme, and the keyboard ring is `controlFocusStyle` (`keyboardRing`); `buttonVariants` maps each variant to colour **roles**, never
colours. Size and padding come from `density`.

`style` takes a `StateStyle<ButtonState>` — a `StyleDesc`, or a callback that
receives `{ disabled, focused }` and returns one. The result merges after every
role decision, so a callback is the last word on a property the recipe also sets:

```tsx
<Button style={(state) => ({ opacity: state.focused ? 1 : 0.9 })}>Save</Button>
```

`loading` is not in the state: a busy button reports `disabled`, because it
refuses activation.

## Limitations

- The ring's paint is the runtime's: the unit and runtime suites assert the
  declaration, and the playground's `focus-visible` probe holds the paint
  (plan 053).
- No `aria-disabled` and no `aria-pressed`/toggle-button state.
- An icon-only button must pass `label`; use `IconButton`, whose required prop is
  the name.
- No native button element: the runtime exposes a `div` with role and handlers.
- Overlaps the runtime's headless `Button`: `@gpuix/react` 0.11.0 ships
  `Button`/`buttonProps`, and this component predates it. Adoption was evaluated
  and declined — `buttonProps` lacks `loading`, the focused `style` state and the
  held-key guard, and keeps a disabled button in the tab order; the comparison is
  in `TODO.md` §Salvage, so nobody re-litigates it from memory.

## Verification

- `src/core/keyboard.test.ts` — the Enter/Space/held rules as pure decisions.
- `src/components/Button.test.tsx` — tree-level props, busy blocking, the
  loading description, a busy filled button handing its spinner the fill's
  on-colour, and a `style` callback receiving the live state and winning over
  the recipe.
- `src/components/handlers.test.tsx` — a caller's click, keys and focus run
  before the button's own action, and a busy button installs no press handler.
- `runtime/controls.runtime.test.tsx` — a hit-tested click activates once; Enter
  on down, Space on up, a held key ignored; disabled and loading refuse both and
  a busy button still announces its role and name.
- `runtime/loading.runtime.test.tsx` — a busy primary button's spinner dots paint
  `primaryForeground` and a secondary one's paint `secondaryForeground` in a real
  window.
- `runtime/examples.runtime.test.tsx` — the form example's busy action creates a
  progress state.
