---
title: Button
description: The primary action — clickable and keyboard-activatable, with busy and disabled states.
---

`Button` is the action primitive. `@gpuix/react` 0.10.0 publishes **no**
`./button` subpath, so this component owns the keyboard contract itself
(`core/keyboard.ts`) instead of wrapping a headless one.

## Usage

```tsx
import { Button, Stack } from "@gpuixui/primitives";

<Stack direction="row" gap="sm">
  <Button variant="outline">Cancel</Button>
  <Button variant="primary" onActivate={save} loading={saving}>
    Save changes
  </Button>
</Stack>;
```

## Variants

| `variant` | Rest | Hover / press |
| --------- | ---- | ------------- |
| `primary` (default) | `primary` fill, `primaryForeground` text | fill at 90% / 80% alpha |
| `secondary` | `secondary` fill | alpha wash |
| `outline` | border only | hover wash |
| `ghost` | no chrome | hover wash |
| `destructive` | `destructive` fill | alpha wash |
| `link` | text in the primary role | underline + hover wash |

## Sizes and states

| `size` | Height | Horizontal padding |
| ------ | ------ | ------------------ |
| `sm` | `density.controlHeight.sm` | `density.controlPaddingX.sm` |
| `md` (default) | `density.controlHeight.md` | `density.controlPaddingX.md` |
| `lg` | `density.controlHeight.lg` | `density.controlPaddingX.lg` |

- `square` — equal width and height, no horizontal padding: an icon-only button.
- `radius` — the corner radius on the theme's scale (`none`, `sm`, `md`, `lg`,
  `xl`, `full`). Defaults to `md`; an attached `ButtonGroup` supplies `none` so
  its buttons share one clipped surface.
- `fullWidth` — stretches to its parent.
- `disabled` — refuses click and keys, and leaves the tab order.
- `loading` — shows a spinner, announces `Loading`, refuses activation, and
  **stays focusable** — unless `disabled` is also set, which always removes the
  tab stop.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `variant` | `ButtonVariant` | `"primary"` | the paint from `core/variants.ts` |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | height and padding from density |
| `square` | `boolean` | `false` | icon-only geometry |
| `radius` | `RadiusStep` | `"md"` | corner radius; an attached `ButtonGroup` supplies `"none"` |
| `fullWidth` | `boolean` | `false` | `width: 100%` |
| `disabled` | `boolean` | `false` | blocks activation, leaves the tab order |
| `loading` | `boolean` | `false` | spinner, `Loading` description, blocks activation |
| `leading` / `trailing` | `ReactNode` | none | an icon or element on either side |
| `label` | `string` | none | accessible name. Overrides the name derived from text children; required when the content is not text (e.g. an icon) |
| `onActivate` | `() => void` | none | called after `onClick` for a click or an activating key; not called while busy |
| `onClick` | `(event) => void` | none | the event that activated the button: the pointer click, or the Enter/Space key event. Runs before `onActivate` |
| `onMouseEnter`, `onMouseLeave`, `onMouseMove`, `onMouseDown`, `onMouseUp`, `onMouseDownOutside`, `onAuxClick`, `onScroll` | host handlers | none | forwarded to the button element — the slot contract a `Tooltip` trigger uses |
| `onFocus`, `onBlur`, `onKeyDown`, `onKeyUp` | host handlers | none | composed with the button's own focus ring and activation rule, never replacing them |
| `aria-description` | `string` | none | announced after the name; a `Tooltip` trigger's text arrives here, joined after `"Loading"` while busy |
| `style` | `StateStyle<ButtonState>` | — | merged last; an object or a state callback |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the visible label |

## Keyboard

| Key | Contract |
| --- | -------- |
| Enter | activates on key **down** |
| Space | activates on key **up** |
| held key | repeat events never activate |

`disabled` and `loading` refuse both. A `disabled` button is not tabbable; a
`loading` one is, so a keyboard user is not dropped from the page mid-action.
When both are set, `disabled` wins: a busy control that is also disabled is not
a tab stop.

`onClick` receives the event that activated the button — the pointer click, or
the key event itself — so a button wired with the familiar prop still works from
the keyboard. `onActivate` is the no-argument convenience, called after it on
the same path.

Escape is not a button key. A slot's `onKeyDown` still runs **after** the
activation rule, so a `Tooltip` trigger closes on Escape without activating.

## As an overlay trigger

GPUix composes an overlay's trigger with `asChild`, which clones the child with
its mouse, focus and key handlers and `aria-description`. A React component
boundary drops any prop it does not declare, so `Button` accepts that slot
contract explicitly (plan `341`) — which makes the documented tooltip shape work:

```tsx
import { Button, Tooltip } from "@gpuixui/primitives";

<Tooltip content="Delete this file">
  <Button label="Delete">Delete</Button>
</Tooltip>;
```

Hover opens the tip, Tab (focus) opens it, Escape and click close it, and the
string tip becomes the button's `aria-description`. `IconButton` inherits the
same contract; `Toggle` implements it too. Activation is still the button's:
the injected `onClick` runs through the activation path, so a disabled or busy
button reports nothing, while hover still opens its tip.

## Accessibility

- Role: `button`; the name is `label` when given, otherwise the **text-only**
  children joined and trimmed (`"Save changes"`). GPUix does not derive a
  button's name from painted text, so the component writes `aria-label` itself
  (measured: plan `058`). Content that is not all text — an icon, an element, a
  mixed list — yields no name; pass `label` then.
- `loading` sets `aria-description="Loading"` — this runtime has no `aria-busy`.
- There is no `aria-disabled`: a disabled button is removed from the tab order
  instead, which is the strongest truthful alternative.
- Focus is drawn as a zero-offset shadow ring (`controlFocusStyle`), because the
  runtime has no `focusVisible`. A mouse click therefore shows the same ring as
  Tab.

## Theming

`controlStyle` resolves fill, text, border, radius, hover, active, disabled and
focus from the theme; `buttonVariants` maps each variant to colour **roles**,
never colours. Size and padding come from `density`.

## Style by state

`style` takes an object or a callback over the button's public state — the
runtime's own `StateStyle` type:

```tsx
<Button style={(state) => ({ opacity: state.disabled ? 0.6 : 1 })}>Save</Button>;
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | the `disabled` prop |
| `focused` | `boolean` | holds native focus (the ring is painted) |
| `loading` | `boolean` | busy: spinner painted, activation refused |

The callback runs on every render, and its result merges after the component's
own rules — it wins per property. Nested `hover`/`active` rules in the base still
apply unless the callback supplies its own; returning `{}` keeps the default
look. `ButtonState` is exported.

## Limitations

- No `focusVisible`: the ring cannot distinguish pointer from keyboard focus.
- No `aria-disabled` and no `aria-pressed`/toggle-button state.
- An icon-only button (or one whose children are elements) must pass `label`;
  the component cannot infer a name and will not invent one.
- No native button element: the runtime exposes a `div` with role and handlers.

  slot handlers reach the host, focus/blur/keys compose, and a busy description

  on down, Space on up, a held key ignored; disabled and loading refuse both and
  a busy button still announces its role and name; a button wired with `onClick`
  alone reports Enter and Space, while a held key, a disabled one and a busy one
  report nothing (plan 085).

  `IconButton` and `Toggle` opens on hover; the `Button` also opens on focus,
  closes on click, and carries the tip as its `aria-description` (plan 341).
- `runtime/examples.runtime.test.tsx` — the form example's busy action creates a
  progress state.
