---
title: Button
description: The primary action — clickable and keyboard-activatable, with busy and disabled states.
---

`Button` is the action primitive. `@gpuix/react` 0.10.0 publishes **no**
`./button` subpath, so this component owns the keyboard contract itself
(`core/keyboard.ts`) instead of wrapping a headless one.

## Usage

```tsx
import { Button, Stack } from "@gpuixui/primitives";

<Stack direction="row" gap="sm">
  <Button variant="outline">Cancel</Button>
  <Button variant="primary" onActivate={save} loading={saving}>
    Save changes
  </Button>
</Stack>;
```

## Variants

| `variant` | Rest | Hover / press |
| --------- | ---- | ------------- |
| `primary` (default) | `primary` fill, `primaryForeground` text | fill at 90% / 80% alpha |
| `secondary` | `secondary` fill | alpha wash |
| `outline` | border only | hover wash |
| `ghost` | no chrome | hover wash |
| `destructive` | `destructive` fill | alpha wash |
| `link` | text in the primary role | underline + hover wash |

## Sizes and states

| `size` | Height | Horizontal padding |
| ------ | ------ | ------------------ |
| `sm` | `density.controlHeight.sm` | `density.controlPaddingX.sm` |
| `md` (default) | `density.controlHeight.md` | `density.controlPaddingX.md` |
| `lg` | `density.controlHeight.lg` | `density.controlPaddingX.lg` |

- `square` — equal width and height, no horizontal padding: an icon-only button.
- `fullWidth` — stretches to its parent.
- `disabled` — refuses click and keys, and leaves the tab order.
- `loading` — shows a spinner, announces `Loading`, refuses activation, and
  **stays focusable**.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `variant` | `ButtonVariant` | `"primary"` | the paint from `core/variants.ts` |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | height and padding from density |
| `square` | `boolean` | `false` | icon-only geometry |
| `fullWidth` | `boolean` | `false` | `width: 100%` |
| `disabled` | `boolean` | `false` | blocks activation, leaves the tab order |
| `loading` | `boolean` | `false` | spinner, `Loading` description, blocks activation |
| `leading` / `trailing` | `ReactNode` | none | an icon or element on either side |
| `label` | `string` | none | accessible name; required for an icon-only button |
| `onActivate` | `() => void` | none | click or activating key; not called while busy |
| `onClick` | `(event) => void` | none | the raw click, called before `onActivate` |
| `style` | `StateStyle<ButtonState>` | — | resolved against the live state and merged last |
| `testId` | `string` | — | stable locator |
| `children` | `ReactNode` | — | the visible label |

## Keyboard

| Key | Contract |
| --- | -------- |
| Enter | activates on key **down** |
| Space | activates on key **up** |
| held key | repeat events never activate |

`disabled` and `loading` refuse both. A `disabled` button is not tabbable; a
`loading` one is, so a keyboard user is not dropped from the page mid-action.

## Accessibility

- Role: `button`; the name comes from `label` or its text content.
- `loading` sets `aria-description="Loading"` — this runtime has no `aria-busy`.
- There is no `aria-disabled`: a disabled button is removed from the tab order
  instead, which is the strongest truthful alternative.
- Focus is drawn as a zero-offset shadow ring (`controlFocusStyle`), because the
  runtime has no `focusVisible`. A mouse click therefore shows the same ring as
  Tab.

## Theming

`controlStyle` resolves fill, text, border, hover, active, disabled and focus
from the theme; `buttonVariants` maps each variant to colour **roles**, never
colours. Size and padding come from `density`.

`style` takes a `StateStyle<ButtonState>` — a `StyleDesc`, or a callback that
receives `{ disabled, focused }` and returns one. The result merges after every
role decision, so a callback is the last word on a property the recipe also sets:

```tsx
<Button style={(state) => ({ opacity: state.focused ? 1 : 0.9 })}>Save</Button>
```

`loading` is not in the state: a busy button reports `disabled`, because it
refuses activation.

## Limitations

- No `focusVisible`: the ring cannot distinguish pointer from keyboard focus.
- No `aria-disabled` and no `aria-pressed`/toggle-button state.
- An icon-only button must pass `label`; the component cannot infer one.
- No native button element: the runtime exposes a `div` with role and handlers.

## Verification

- `src/core/keyboard.test.ts` — the Enter/Space/held rules as pure decisions.
- `src/components/Button.test.tsx` — tree-level props, busy blocking, the
  loading description, and a `style` callback receiving the live state and
  winning over the recipe.
- `runtime/controls.runtime.test.tsx` — a hit-tested click activates once; Enter
  on down, Space on up, a held key ignored; disabled and loading refuse both and
  a busy button still announces its role and name.
- `runtime/examples.runtime.test.tsx` — the form example's busy action creates a
  progress state.
