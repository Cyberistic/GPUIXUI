---
title: Select
description: One choice from a list, in a popover — a themed wrapper over GPUix's own Select.
---

`Select` reuses `@gpuix/react/select` for dismissal and arrow navigation, and
themes it to match the field chrome. The **open state is the wrapper's** — it
follows the package's one controlled rule — so a select can be opened from code
and a disabled select cannot be left with a dead menu (plan `346`). It is **not**
a reimplementation: what this package owns is the trigger's paint, the list
surface, the item states, the open state and the **accessibility contract**
GPUix's headless Select does not set (plan `057`).

## Usage

```tsx
import { Label, Select } from "@gpuixui/primitives";

<Label>Region</Label>
<Select
  value={region}
  onValueChange={setRegion}
  label="Region"
  fullWidth
  options={[
    { value: "eu-west", label: "Europe — West" },
    { value: "us-east", label: "United States — East" },
    { value: "legacy", label: "Legacy region", disabled: true },
  ]}
/>;
```

Group a long list by giving `options` a `{ label, options }` entry:

```tsx
<Select
  label="Region"
  value={region}
  onValueChange={setRegion}
  options={[
    {
      label: "Europe",
      options: [
        { value: "eu-west", label: "Europe — West" },
        { value: "eu-north", label: "Europe — North" },
      ],
    },
    {
      label: "Americas",
      options: [{ value: "us-east", label: "United States — East" }],
    },
  ]}
/>;
```

## Trigger indicator

The trigger paints a **decorative chevron** after the value: it points down at
rest and up while the list is open, so the field reads as "this opens a list"
before it is pressed (plan `343`). The runtime has no `transform`, so the two
directions are two icons rather than a rotation.

It is `theme.iconSize.sm` on the `mutedForeground` role — `placeholder` while the
select is disabled — carries no accessible name (it is decoration, not content),
and sets `pointerEvents: "none"`, so a click aimed at it reaches the trigger. The
indicator does not change the combobox's name or add an `Image` node.

## Open state

`open` / `defaultOpen` / `onOpenChange` follow the same rule as every value in
this package: a supplied `open` makes the parent the owner, and the list changes
only when the parent supplies a new one. That is what lets a command palette, an
"edit" button or a tour open a select from code:

```tsx
const [open, setOpen] = useState(false);

<Button onClick={() => setOpen(true)}>Change region</Button>
<Select
  open={open}
  onOpenChange={setOpen}
  value={region}
  onValueChange={setRegion}
  label="Region"
  options={regions}
/>;
```

`defaultOpen` opens an uncontrolled select on mount; a click on the trigger,
Escape, an outside press and committing an option all report through
`onOpenChange`. The chevron, the trigger ring, `SelectState.open` and the list
read one derived value, so they cannot disagree.

**A disabled select is closed.** Disabling a select while its list is open
removes the list: GPUix refuses every choice and the outside-press path on a
disabled select, so a painted list would be a menu that cannot act (measured,
plan `346`). An uncontrolled select closes itself; a controlled parent receives
`onOpenChange(false)` and the wrapper paints closed regardless, so a stale
`open` cannot resurrect the dead menu.

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `options` | `ReadonlyArray<SelectOption \| SelectOptionGroup>` | — (required) | choices in paint order (`{ value, label, disabled? }`), optionally under a heading |
| `value` | `string` | — | controlled selection; `""` is a real value (see below) |
| `defaultValue` | `string` | — | initial selection when uncontrolled; omit it (with `value`) for no selection |
| `onValueChange` | `(value: string) => void` | none | committed value |
| `open` | `boolean` | — | controlled open state; the list changes only when the parent changes it |
| `defaultOpen` | `boolean` | `false` | initial open state when uncontrolled |
| `onOpenChange` | `(open: boolean) => void` | none | the select asks to open or close; a disabled select asks to close |
| `placeholder` | `string` | none | shown before a choice |
| `disabled` | `boolean` | `false` | refuses opening, closes an open list, and leaves the tab order |
| `invalid` | `boolean` | `false` | destructive border on the trigger |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | no effect since plan `372`: a field is one height (`h-9`, 36 px) |
| `fullWidth` | `boolean` | `false` | the trigger takes the field recipe's `w-full`; the list matches its measured width |
| `side` | `FloatingSide` | auto — below, flipped above when it does not fit; any requested side flips when it cannot fit | preferred side the list opens on |
| `label` | `string` | none | accessible name for the select |
| `aria-description` | `string` | none | description announced after the name; a `Tooltip` writes its text here |
| `style` | `StateStyle<SelectState>` | — | merged last on the select root; an object or a state callback |
| `triggerStyle` | `StateStyle<SelectTriggerState>` | — | merged last on the visible trigger; an object or a state callback |
| `testId` | `string` | — | names the select; the visible trigger becomes `${testId}-trigger`, the indicator `${testId}-chevron`, and each option `${testId}-option-${value}` |

```ts
interface SelectOption {
  value: string;
  label: string;
  disabled?: boolean;
}

interface SelectOptionGroup {
  label: string;
  options: ReadonlyArray<SelectOption>;
}
```

## Values and absence

A selection is a **string**, and `""` is an ordinary one. A "show all" filter is
`{ value: "", label: "Any" }`:

```tsx
<Select
  label="Status"
  defaultValue=""
  options={[
    { value: "", label: "Any" },
    { value: "active", label: "Active" },
    { value: "archived", label: "Archived" },
  ]}
  onValueChange={setStatus}
/>
```

Absence is the **missing prop**, not the empty string (plan `501`). Supplying
neither `value` nor `defaultValue` leaves the select unselected and paints the
placeholder; `value=""`/`defaultValue=""` selects the option valued `""` and
announces its label. Choosing the current value again reports nothing, the same
no-op rule the other controls follow.

A caller that needs a placeholder **and** an "any" choice has one option: use a
non-empty sentinel (`value="any"`) for the choice, or start with no selection and
let the placeholder carry the "not chosen yet" state. The wrapper does not
invent a second absence value.

## Option groups

A group is a **heading before a run of options**, not a second control. The
heading paints the caption role on `mutedForeground`, inset like an option row,
and is **not selectable**: GPUix's SelectItem order stays one flat run, so the
arrow keys move from the last option of one group to the first of the next
without stopping on a title (plan `075`).

- An **empty** group paints nothing — no orphan heading, no group node, no row —
  and contributes nothing to the height estimate (plan `363`: the branch used to
  paint the heading anyway, leaving a title over blank space and a list one
  caption row taller than the estimate that chose its side).
- A group whose `label` **says nothing** is not a heading: its options paint
  flat, with no empty caption row and no unnamed `group` node, and the estimate
  counts only its options. A real heading is trimmed, so the painted caption and
  the group's `aria-label` agree (plan `579`).
- Option values stay unique across groups; the wrapper passes the flat list to
  GPUix, which keys items by value.
- The group is a named `group` node in the accessibility tree. GPUix has no
  `aria-labelledby`, so the wrapper writes the heading to `aria-label` and keeps
  the visible heading beside it.

The heading is counted in the placement estimate (one caption line plus its
padding), so a grouped list near the window edge flips sides using the height it
will really paint.

## Keyboard

Owned by GPUix's Select: the trigger opens with Enter/Space, the arrows move the
highlight, Enter commits, Escape dismisses. This wrapper does not intercept any
key. It **does** follow the highlight: the option the arrows (or the pointer)
newly highlight is scrolled into view through the renderer, so a capped list
moves with the keyboard instead of leaving the active option beyond the fold
(plan `069`). Opening on a selected option scrolls that row into view too.

The trigger is one tab stop. It paints the focus ring whenever it holds focus
**or** its list is open: the open list owns native focus, so without the second
half a keyboard user would see no active state at all between opening and
committing (plan `083`). Escape and a committed option both return focus to the
trigger.

## Accessibility

GPUix's published `Select` sets **no ARIA role at all** — measured on 0.10.0, the
trigger, list and items produced no accessibility node (plan `057` §0). The
wrapper supplies the whole contract, and the roles are the runtime's own
mappings (`role_from_aria`):

- The trigger is a **`combobox`** named by `label`, with `aria-expanded`
  following the real open state and `aria-valuetext` carrying the chosen label
  (or the placeholder). AccessKit reports it as `ComboBox`, `expanded`,
  `value`. An option valued `""` announces its label like any other; the empty
  string is never mistaken for "no choice" (plan `501`).
- The list is a **`listbox`** named by the same `label`.
- Each item is an **`option`** with its own label and `aria-selected` on the
  chosen one. AccessKit reports `ListBox`, `ListBoxOption`, `selected`.
- A group is a **`group`** named by its heading, because the runtime has no
  `aria-labelledby`. AccessKit reports `Group` with that label; the visible
  heading is painted beside it as text.

There is no `aria-haspopup` in `HostProps`, so the combobox role is the strongest
honest claim. The value is announced through `aria-valuetext` — the runtime
exposes no other value channel — and the visible text inside the trigger is not
itself the accessible value.

Focus is **visible**: the trigger paints the field recipe's 3 px ring while
focused or open, the same ring `Input` paints. The runtime has no `focusVisible`,
so a mouse-opened trigger shows it too.

The trigger is **chrome, not content**: it declares `userSelect: "none"` and a
pointer cursor, because the field recipe's text cursor and selectable text
belong to a native `<input>` (measured before plan `386`: the trigger painted
`cursor: "text"` and a drag selected its value). The open list opts out the same
way — options and group headings are chrome — so dragging across a list cannot
start a text selection. A caller's `triggerStyle` still merges last.

**Slot trigger:** the trigger forwards a `Tooltip`'s handlers and
`aria-description`, so a tip opens on hover and on keyboard focus. GPUix's
`SelectTrigger` composes the injected key handler with its own open/move rule,
so the list still opens on Enter, Space and the arrows (measured, plan `345`).

## Theming

`selectTriggerStyle`, `selectContentStyle` and `selectItemStyle` resolve the
trigger (the field recipe: **36 high, 12 horizontal, 4 vertical, 6 radius,
14/20**, plan `372`), the list (`surfaceStyle` with `popover` + `radius.md` +
`elevation.overlay`) and the item states (`selected`, `hover`,
`disabledForeground`). The list is one spacing step inset and **at least the
trigger's measured width**.

The trigger is a field, so it hugs its value unless `fullWidth` asks for the
recipe's `w-full`; `size` no longer moves it. The option rows are not inputs and
keep their own metric (`density.controlHeight.sm`, 28) until `select.tsx`'s item
string joins `@gpuixui/tw` — a recorded follow-up, not a second field recipe.

The width is a number, not a percentage: `minWidth: "100%"` resolves against the
anchored layer, so it painted a 57 px list under a 900 px field (measured, plan
`062` §0). The wrapper measures the trigger through the renderer after mount and
again when the list opens or `fullWidth` changes. Rendered as an element tree
(no renderer), the list hugs its labels.

## Placement

The list opens **below** the trigger, and **above** it when it does not fit
below. That is the wrapper's job, not the runtime's: GPUix's layer is
`side="bottom"` with `fit="snap"`, and snap clamps a layer into the window
**without flipping it** (measured, plan `156` §8). A select at the window's
bottom edge therefore opened a 68 px list at `y 724` over a trigger at `y 740` —
covering the field the user had just pressed (plan `066` §1).

The choice costs one estimate, because the side is decided before the list
exists: the surface's padding and borders, one `controlHeight.sm` row per
option, one caption row per non-empty group, and the row gap — the same numbers
`selectContentStyle`, `selectItemStyle` and `selectHeadingStyle` paint. Only a
group that has a heading is counted; a blank heading paints flat (plan `579`).
When neither side has room, the side with more room wins (the runtime still clamps).
An explicit `top`/`bottom` is the same rule's **preference**, so it flips when
it cannot fit (plan `336`).

A list **taller than the space it chose** is capped to exactly that space and
scrolls. Without the cap a 30-option list painted a 908 px layer from `y 8`, with
its last option at `y 888` in an 800 px window and no way to reach it (plan
`068` §1). Rows keep their height inside the cap (`flexShrink: 0`), so the list
scrolls instead of squashing the options.

A list opened **beside** the trigger (`side="left"`/`"right"`) is capped on the
other axis: the runtime's `align="start"` puts its top edge on the trigger's, so
the free space runs from there to the window's bottom margin. Only the vertical
sides computed a cap before plan `098`, so a left/right list painted 908 px from
`y 12` in an 800 px window with the last option unreachable; the same cap now
applies to all four sides (measured: 780 px, scrollable, last option inside).

A **`left`/`right` side is a preference.** The wrapper measures the open list's
width (the trigger's width is its minimum) and the trigger's edges; when the
list cannot fit on the requested side it opens on the other one, or on the
roomier side when it fits on neither. The runtime alone would clamp it —
measured on a trigger at `x 524..572`, a `side="right"` list painted
`x 535..592`, over the trigger (plan `335`). Its **width cap follows the side it
opens on** (plan `379`): a `side="left"` list on a right-aligned trigger used to
paint the 228 px that happened to remain on the *right*, truncating a label with
1036 px of left room. The cap is now the room between the window margin and the
trigger on that side.

A **`top`/`bottom` side is the same preference on the vertical axis** (plan
`336`). At the bottom edge a `side="bottom"` list used to be squashed to the
20 px the cap believed it had (`selectListHeight` is 84 px for two options); it
now opens above at its full height. A `side="top"` list at the top edge used to
paint `y 2..12`, inside the margin; it now opens below.

## Style by state

`style` takes an object or a callback over `SelectState` — the runtime's own
`StateStyle` type — merged last on the select root:

```tsx
<Select style={(state) => ({ opacity: state.open ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `open` | `boolean` | the list is open |
| `disabled` | `boolean` | the trigger is disabled |
| `invalid` | `boolean` | the trigger paints the destructive border |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

### Per-item style

`triggerStyle` takes the runtime's own `StateStyle<SelectTriggerState>` — the
state `SelectTrigger` reports, plus the focus the wrapper tracks — merged last
on the visible trigger:

```tsx
<Select triggerStyle={(state) => ({ opacity: state.open ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `open` | `boolean` | the list is open |
| `disabled` | `boolean` | the trigger is disabled |
| `placeholder` | `boolean` | the trigger is showing the placeholder |
| `focused` | `boolean` | the trigger itself holds native focus |

`SelectTriggerState` is exported by this package: GPUix's own three fields plus
`focused`. The component always resolves all four, so a callback never sees a
partial state. The caller's style merges **after** the focus ring, so an explicit
`boxShadow` wins.

## Limitations


- **Options are data.** No rich option content and no compound escape hatch in
  the public API; use `RadioGroup` for those. A group is a heading and a run of
  options, not a custom row.
- **The width is measured, not live.** A resize while the list is closed is
  picked up the next time it opens; there is no resize observer in 0.10.0.
- **The side uses an estimated list height.** It is exact for the styles this
  package paints, and a test pins the estimate to them; when neither side has
  room, the list is capped to the roomier one and scrolls. An explicit
  `top`/`bottom` follows the same fit rule rather than pinning the side.
- **The side uses a measured list width.** A move to the other horizontal side
  is decided from the width the list painted on open; a list wider than both
  sides is still clamped by the runtime and may cover its trigger.
- **A long label is clipped, not painted outside.** The selected value takes one
  line with an ellipsis, so the chevron stays inside the trigger; the list is
  capped to the window's usable width, and an option that does not fit shows its
  start with an ellipsis (plan `368`).
- The list's dismissal and positioning are GPUix's; this package owns the open
  **state** (above) but cannot change the open animation or the outside-click
  rules.
- A controlled parent that ignores `onOpenChange(false)` while the select is
  disabled keeps `open` true; the wrapper still paints closed and shows the list
  again if both `open` and `disabled` stop disagreeing. The request is sent once,
  not on every render.
- No search or type-ahead. A long list wants a combobox, which is Tier 2.
- No multi-select.
- No `aria-haspopup` (absent from the runtime's host props); the `combobox`
  role, `expanded` and `selected` carry the semantics instead.
