---
title: Select
description: One choice from a list, in a popover — a themed wrapper over GPUix's own Select.
---

`Select` reuses `@gpuix/react/select` for the open state, dismissal and arrow
navigation, and themes it to match the field chrome. It is **not** a
reimplementation: what this package owns is the trigger's paint, the list surface
and the item states.

## Usage

```tsx
import { Label, Select } from "@gpuixui/primitives";

<Label>Region</Label>
<Select
  value={region}
  onValueChange={setRegion}
  label="Region"
  fullWidth
  options={[
    { value: "eu-west", label: "Europe — West" },
    { value: "us-east", label: "United States — East" },
    { value: "legacy", label: "Legacy region", disabled: true },
  ]}
/>;
```

Options can be grouped under a caption. Groups are **presentational**:
`SelectGroup`/`SelectLabel` are plain elements in 0.11.0 with no role, so the
caption is visible text and each row keeps its own accessible name. The runtime
still receives one flat list in render order, so keyboard navigation crosses a
group boundary exactly as it crosses any other row.

```tsx
import { Select } from "@gpuixui/primitives";

<Select
  label="Density"
  options={[
    {
      label: "Comfortable",
      options: [
        { value: "compact", label: "Compact" },
        { value: "cozy", label: "Cosy" },
      ],
    },
    {
      label: "Spacious",
      options: [{ value: "roomy", label: "Roomy" }],
    },
  ]}
/>;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `options` | `ReadonlyArray<SelectOption \| SelectOptionGroup>` | — (required) | `{ value, label, disabled? }` items, or `{ label, options }` groups painted under a caption and a rule |
| `value` | `string` | — | controlled selection |
| `defaultValue` | `string` | — | initial selection when uncontrolled |
| `onChange` | `(value: string) => void` | none | deprecated alias for `onValueChange`; the new name runs when both are passed |
| `onValueChange` | `(value: string) => void` | none | the committed value |
| `placeholder` | `string` | none | shown before a choice |
| `disabled` | `boolean` | `false` | refuses opening |
| `invalid` | `boolean` | `false` | destructive border on the trigger |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | trigger height and padding |
| `fullWidth` | `boolean` | `false` | trigger and list fill the parent |
| `side` | `FloatingSide` | GPUix's choice | which side the list opens on |
| `label` | `string` | none | accessible name for the select |
| `style` | `StyleDesc` | — | merged last on the select root, which only carries its width |
| `triggerStyle` | `StateStyle<SelectTriggerState>` | — | resolved against the trigger's live state, merged last |
| `itemStyle` | `StateStyle<SelectItemState>` | — | resolved per option against that option's state, merged last |
| `testId` | `string` | — | stable locator |

## Keyboard

Owned by GPUix's Select: the trigger opens with Enter/Space, the arrows move the
highlight, Enter commits, Escape dismisses. This wrapper does not intercept any
key.

## Accessibility

- The select and its trigger are GPUix's; the wrapper adds the accessible name
  through the `label` prop.
- The trigger wears the field chrome, so it is announced as a control with the
  current value.
- Disabled items are painted from the `disabled` state GPUix reports and cannot
  be committed.

## Theming

`selectTriggerStyle`, `selectContentStyle` and `selectItemStyle` resolve the
trigger (`controlStyle`), the list (`surfaceStyle` with `popover` +
`radius.md` + `elevation.overlay`) and the item states (`selected`, `hover`,
`disabledForeground`). A selected row also paints a **check mark** in the
`popoverForeground` role at its end: the row's children are a function of the
state GPUix reports, so an uncontrolled select needs no mirror of its value and
the mark cannot disagree with the selection. It is decorative — the row is
already `aria-selected`, and the mark is `role="presentation"`. The trigger
declares the shared keyboard outline at rest (`keyboardRing`, destructive while
`invalid`), so the runtime paints it after Tab and not after a mouse press; a
disabled trigger declares none. The list is one spacing step inset, full trigger
width.

`triggerStyle` and `itemStyle` are the state-aware hooks. The trigger callback
receives GPUix's own `{ open, disabled, placeholder }`, so a caller can paint the
open state; the item callback receives `{ selected, highlighted, disabled }` and
runs once per option, so a data-driven list can style its rows. Both merge after
the recipe and its role decisions, so a callback is the last word. The root
`style` stays a plain `StyleDesc`: the root is a positioning wrapper with no live
state of its own.

## Limitations

- **Options are data.** No rich option content and no compound escape hatch in
  the public API; use `RadioGroup` for rich options. Group captions are painted,
  not announced: 0.11.0's `SelectGroup`/`SelectLabel` carry no role, so a reader
  who hears a row does not hear which group it belongs to.
- A group's name has no semantic effect on the keyboard; the arrows walk the
  flat list in render order.
- The list's dismissal and positioning are GPUix's; this package cannot change
  the open animation or the outside-click rules. **Measured on 0.11.0:** the
  layer snaps into the window (`fit: "snap"` with an 8px margin), so a trigger at
  the bottom edge opens a list that sits inside it instead of painting off it.
- **A list taller than the window does not scroll.** The content sets no
  maximum height and no overflow, and GPUix's `SelectScrollUpButton`/
  `SelectScrollDownButton` are empty elements in 0.11.0; the runtime measured a
  40-option list with its tail outside the window and **no scroller anywhere in
  its ancestry**, so arrowing to a row past the edge cannot reveal it. Keep a
  select's list short, or reach for a `Combobox`/`SearchInput` composition for a
  long one.
- No search or type-ahead. A long list wants a combobox, which is Tier 2.
- No multi-select.

## Verification

- `src/components/Select.test.tsx` — trigger chrome, the keyboard ring (ring
  role, destructive while invalid, absent while disabled), list surface and item
  states, both state-aware callbacks receiving their live state and winning, and
  the selected row's mark coming from the state the runtime reports. Four group
  cases: the flat list in render order, the caption's muted role and one-pixel
  rule, the group/rule/group tree, and a grouped row still being a real item with
  its own state function.
- `runtime/fields.runtime.test.tsx` — opens, paints its options and commits a
  clicked option in the real renderer; exactly one row paints the mark, and the
  mark moves to the row that becomes selected (negative control measured:
  rendering the label alone fails `expected [] to have a length of 1`). Open
  state and dismissal are GPUix's. Two placement cases measure the limits above:
  a bottom-edge trigger's list is painted inside the window in order, and a
  40-option list's last row sits past the window edge with no scroll offset in
  any ancestor. A grouped list paints both captions and commits a row clicked
  inside a group.

```sh
nub run --filter @gpuixui/primitives test
nub run --filter @gpuixui/primitives test:runtime
```
