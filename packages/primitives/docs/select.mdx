---
title: Select
description: One choice from a list, in a popover — a themed wrapper over GPUix's own Select.
---

`Select` reuses `@gpuix/react/select` for the open state, dismissal and arrow
navigation, and themes it to match the field chrome. It is **not** a
reimplementation: what this package owns is the trigger's paint, the list
surface, the item states, and the **accessibility contract** GPUix's headless
Select does not set (plan `057`).

## Usage

```tsx
import { Label, Select } from "@gpuixui/primitives";

<Label>Region</Label>
<Select
  value={region}
  onChange={setRegion}
  label="Region"
  fullWidth
  options={[
    { value: "eu-west", label: "Europe — West" },
    { value: "us-east", label: "United States — East" },
    { value: "legacy", label: "Legacy region", disabled: true },
  ]}
/>;
```

Group a long list by giving `options` a `{ label, options }` entry:

```tsx
<Select
  label="Region"
  value={region}
  onChange={setRegion}
  options={[
    {
      label: "Europe",
      options: [
        { value: "eu-west", label: "Europe — West" },
        { value: "eu-north", label: "Europe — North" },
      ],
    },
    {
      label: "Americas",
      options: [{ value: "us-east", label: "United States — East" }],
    },
  ]}
/>;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `options` | `ReadonlyArray<SelectOption \| SelectOptionGroup>` | — (required) | choices in paint order (`{ value, label, disabled? }`), optionally under a heading |
| `value` | `string` | — | controlled selection |
| `defaultValue` | `string` | — | initial selection when uncontrolled |
| `onChange` | `(value: string) => void` | none | committed value |
| `placeholder` | `string` | none | shown before a choice |
| `disabled` | `boolean` | `false` | refuses opening |
| `invalid` | `boolean` | `false` | destructive border on the trigger |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | trigger height and padding |
| `fullWidth` | `boolean` | `false` | the trigger fills the parent; the list matches its measured width |
| `side` | `FloatingSide` | auto — below, flipped above when it does not fit | which side the list opens on |
| `label` | `string` | none | accessible name for the select |
| `style` | `StyleDesc` | — | merged last on the select root |
| `testId` | `string` | — | stable locator |

```ts
interface SelectOption {
  value: string;
  label: string;
  disabled?: boolean;
}

interface SelectOptionGroup {
  label: string;
  options: ReadonlyArray<SelectOption>;
}
```

## Option groups

A group is a **heading before a run of options**, not a second control. The
heading paints the caption role on `mutedForeground`, inset like an option row,
and is **not selectable**: GPUix's SelectItem order stays one flat run, so the
arrow keys move from the last option of one group to the first of the next
without stopping on a title (plan `075`).

- An **empty** group paints nothing — no orphan heading — and contributes
  nothing to the height estimate.
- Option values stay unique across groups; the wrapper passes the flat list to
  GPUix, which keys items by value.
- The group is a named `group` node in the accessibility tree. GPUix has no
  `aria-labelledby`, so the wrapper writes the heading to `aria-label` and keeps
  the visible heading beside it.

The heading is counted in the placement estimate (one caption line plus its
padding), so a grouped list near the window edge flips sides using the height it
will really paint.

## Keyboard

Owned by GPUix's Select: the trigger opens with Enter/Space, the arrows move the
highlight, Enter commits, Escape dismisses. This wrapper does not intercept any
key. It **does** follow the highlight: the option the arrows (or the pointer)
newly highlight is scrolled into view through the renderer, so a capped list
moves with the keyboard instead of leaving the active option beyond the fold
(plan `069`). Opening on a selected option scrolls that row into view too.

## Accessibility

GPUix's published `Select` sets **no ARIA role at all** — measured on 0.10.0, the
trigger, list and items produced no accessibility node (plan `057` §0). The
wrapper supplies the whole contract, and the roles are the runtime's own
mappings (`role_from_aria`):

- The trigger is a **`combobox`** named by `label`, with `aria-expanded`
  following the real open state and `aria-valuetext` carrying the chosen label
  (or the placeholder). AccessKit reports it as `ComboBox`, `expanded`,
  `value`.
- The list is a **`listbox`** named by the same `label`.
- Each item is an **`option`** with its own label and `aria-selected` on the
  chosen one. AccessKit reports `ListBox`, `ListBoxOption`, `selected`.
- A group is a **`group`** named by its heading, because the runtime has no
  `aria-labelledby`. AccessKit reports `Group` with that label; the visible
  heading is painted beside it as text.

There is no `aria-haspopup` in `HostProps`, so the combobox role is the strongest
honest claim. The value is announced through `aria-valuetext` — the runtime
exposes no other value channel — and the visible text inside the trigger is not
itself the accessible value.

## Theming

`selectTriggerStyle`, `selectContentStyle` and `selectItemStyle` resolve the
trigger (`controlStyle`), the list (`surfaceStyle` with `popover` +
`radius.md` + `elevation.overlay`) and the item states (`selected`, `hover`,
`disabledForeground`). The list is one spacing step inset and **at least the
trigger's measured width**.

The width is a number, not a percentage: `minWidth: "100%"` resolves against the
anchored layer, so it painted a 57 px list under a 900 px field (measured, plan
`062` §0). The wrapper measures the trigger through the renderer after mount and
again when the list opens or `size`/`fullWidth` change. Rendered as an element
tree (no renderer), the list hugs its labels.

## Placement

The list opens **below** the trigger, and **above** it when it does not fit
below. That is the wrapper's job, not the runtime's: GPUix's layer is
`side="bottom"` with `fit="snap"`, and snap clamps a layer into the window
**without flipping it** (measured, plan `156` §8). A select at the window's
bottom edge therefore opened a 68 px list at `y 724` over a trigger at `y 740` —
covering the field the user had just pressed (plan `066` §1).

The choice costs one estimate, because the side is decided before the list
exists: the surface's padding and borders, one `controlHeight.sm` row per
option, one caption row per non-empty group, and the row gap — the same numbers
`selectContentStyle`, `selectItemStyle` and `selectHeadingStyle` paint. When
neither side has room, the side with more room wins (the runtime still clamps).
An explicit `side` skips the decision.

A list **taller than the space it chose** is capped to exactly that space and
scrolls. Without the cap a 30-option list painted a 908 px layer from `y 8`, with
its last option at `y 888` in an 800 px window and no way to reach it (plan
`068` §1). Rows keep their height inside the cap (`flexShrink: 0`), so the list
scrolls instead of squashing the options.

## Limitations

- **Options are data.** No rich option content and no compound escape hatch in
  the public API; use `RadioGroup` for those. A group is a heading and a run of
  options, not a custom row.
- **The width is measured, not live.** A resize while the list is closed is
  picked up the next time it opens; there is no resize observer in 0.10.0.
- **The side uses an estimated list height.** It is exact for the styles this
  package paints, and a test pins the estimate to them; when neither side has
  room, the list is capped to the roomier one and scrolls.
- The list's dismissal and positioning are GPUix's; this package cannot change
  the open animation or the outside-click rules.
- No search or type-ahead. A long list wants a combobox, which is Tier 2.
- No multi-select.
- No `aria-haspopup` (absent from the runtime's host props); the `combobox`
  role, `expanded` and `selected` carry the semantics instead.

## Verification

- `src/components/Select.test.tsx` — trigger chrome, list surface, item states,
  the measured `minWidth` (present with a width, absent without), the decoded
  role/name/expanded/selected props the wrapper passes down, the list-height
  estimate checked against the styles it mirrors, the capped content style, the
  non-shrinking row, and a grouped tree: one named `group`, its caption heading,
  the flat `items` order, and the selected label across a group (plan `075`).
- `src/core/select.test.ts` — the entry model: a flat list reads as itself, a
  group flattens in paint order without its heading, an empty group contributes
  nothing, and disabled flags survive the flatten.
- `src/core/floating.test.ts` — the side decision: fits below, does not fit
  below but fits above, the collision margin, an exact fit, the more-room
  fallback, a preferred side, and the space on each side.
- `runtime/fields.runtime.test.tsx` — measured 2026-10-17: a closed Select is a
  named `ComboBox` with `expanded: false` and the placeholder as its value;
  opening flips `expanded` to `true` and paints a named `ListBox` of named
  `ListBoxOption`s; committing "Pear" closes the list, reports the value as
  `Pear`, and marks only that option `selected` when reopened (plan `057`). The
  same suite proves the list is at least as wide as a hugging trigger and
  matches a `fullWidth` one (plan `062`; without the measurement the list was 57
  px under both a 108 px and a 900 px trigger). **Placement (066):** a select at
  the bottom of a 760 px column opens its list entirely above the trigger
  (`792 <= 740` fails without the decision), a select with room opens below, and
  the painted list height equals the estimate the decision used. **Long lists
  (068):** a 30-option list is capped to the window margin, is a scroller, the
  wheel moves its offset, and the last option is reachable after scrolling
  (without the cap the layer is 916 px tall); dropping `overflowY` leaves it
  unscrollable, and dropping `flexShrink` squashes the rows instead. **Keyboard
  (069):** 40 Down presses in a 60-option list scroll it to offset `-455` and
  leave the highlighted "Option 39" inside the list (without the wrapper's
  `scrollIntoView` the offset stays `0`); opening on "Option 49" scrolls to
  offset `-755` with the selected row inside the list; a three-option list is
  not a scroller and does not move. **Groups (075):** a two-group list paints
  both headings and all three options, exposes a named `Group`, measures its
  heading row at the estimate's caption height, and paints the exact estimated
  height; Enter/Down/Enter commits the first grouped option (the heading is
  skipped), and a click on an option in the second group commits it.
