---
title: Input
description: A single-line text field, controlled or uncontrolled.
---

`Input` is the runtime's native `<input>` with the shared field chrome. The
native element holds the text; `onValueChange` reports every edit and `value` pushes an
external value back in. The controlled/uncontrolled decision is
`core/state.ts`'s, so an input and a checkbox cannot disagree about which value
wins. It is decided on **every render**: a `value` supplied now wins, and an
absent one leaves the field on its own draft — so a form that loads its record
after mount does not need to remount the field.

## Usage

```tsx
import { Input, Label, labelledBy } from "@gpuixui/primitives";

const email = "Contact email";

<Label description="Where notifications are delivered.">{email}</Label>
<Input
  {...labelledBy(email)}
  value={value}
  onValueChange={setValue}
  placeholder="you@example.com"
  fullWidth
/>;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `string` | — | controlled text; omit to let the field keep its own draft. A value supplied after mount takes over, so `value={loaded?.name}` works when the data arrives |
| `defaultValue` | `string` | `""` | initial text when uncontrolled; it is also the draft a controlled field falls back to if `value` is removed |
| `onValueChange` | `(value: string) => void` | none | called after each edit that changed the value |
| `onSubmit` | `(event) => void` | none | Enter; the raw runtime event |
| `onClick` | `(event) => void` | none | the host click; a `Tooltip` trigger's dismissal writes here (the native input receives no mouse-down) |
| `placeholder` | `string` | none | empty-state text |
| `readOnly` | `boolean` | `false` | accepts focus and selection, refuses edits |
| `disabled` | `boolean` | `false` | read-only, out of the tab order, de-emphasised; no edit, submit or ring |
| `autoFocus` | `boolean` | `false` | takes focus on every mount — including a field added after a loading state — and the ring paints from mount (the runtime focuses without dispatching a focus event; plan `584`) |
| `invalid` | `boolean` | `false` | the border takes the destructive role and it wins over focus, hover and press, so the error survives the caret and the whole gesture (the field family shares the rule, plan `781`) |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | no effect since plan `370`: the recipe has one field size (`h-9`, 36 px) |
| `fullWidth` | `boolean` | `false` | implied by the recipe's `w-full`; kept for API stability |
| `label` | `string` | none | accessible name; pair with a visible `Label` |
| `aria-description` | `string` | none | description announced after the name; trimmed, and a blank value is absent (a `Tooltip` writes its text here) |
| `style` | `StateStyle<FieldState>` | — | merged last; an object or a state callback |
| `testId` | `string` | — | stable locator |

## Keyboard

| Key | Contract |
| --- | -------- |
| typing | native editing; every change reaches `onValueChange` |
| Enter | reaches `onSubmit` with the runtime event |
| Tab | moves focus with the runtime's own order |

`onKeyDown`/`onKeyUp` are forwarded to the native host (a slot uses Escape to
dismiss a tooltip). An application shortcut still belongs to the window key
handler, not to a field.

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). Role, name, tab order, keyboard operation and activation
  are unaffected.
- The native element is announced as `TextInput`.
- The name comes from `label`; there is no `aria-labelledby`, so a visible
  `Label` is not associated by reference.
- **Slot trigger:** forwards a `Tooltip`'s handlers and `aria-description`.
  GPUix's `<input>` host receives no `onMouseEnter`, so the tip opens on
  keyboard focus only (measured, plan `345`).
- `invalid` is a border colour (and an inner error cue), not an announced
  error. Put the message in a `Text role="caption" tone="destructive"` beside
  the field.
- `readOnly` remains focusable and selectable, which is the platform contract.
- A `disabled` field is read-only at the host (GPUix has no `disabled` prop), so
  assistive technology hears a read-only field, not a disabled one. It is out of
  the tab order and its handlers are guarded, so keyboard and pointer users
  cannot edit or submit it.

## Theming

The new-york-v4 recipe (`INPUT_BASE` + `INPUT_FOCUS` + `INPUT_INVALID` from
`@gpuixui/tw`, plan `370`) supplies the geometry, radius and type — `h-9 px-3
py-1 rounded-md text-sm`, i.e. **36 high, 12 horizontal, 4 vertical, 6 radius,
14/20** — and the focus/invalid/disabled buckets. The theme supplies the paint:
the `input` fill and `inputForeground`, the hover/press boundary, and
`nativeTextTheme` for the caret and selection. A field therefore **does not
follow density**, and neither does the rest of the field family (`TextArea`,
`Select`'s trigger, `NumberField`, `OTPField` — plan `372`); the presets still
move the other controls, and `size` no longer moves a field.

The recipe's `shadow-xs` also paints a resting elevation (`elevation.sm`, plan
`585`). GPUix paints one shadow per element, so the focus ring replaces it while
the field is focused; an invalid or disabled field keeps the elevation.


## Style by state

`style` takes an object or a callback over the field's public state:

```tsx
<Input
  label="Email"
  invalid={hasError}
  style={(state) => ({ opacity: state.invalid ? 0.9 : 1 })}
/>
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | read-only, out of the tab order, guarded |
| `readOnly` | `boolean` | refuses edits but stays focusable (plan `786`) |
| `focused` | `boolean` | the native input holds focus |
| `invalid` | `boolean` | paints the destructive border |

The callback's result merges after the field chrome, so it wins per property;
`FieldState` is exported and shared by `Input`, `TextArea` and `NumberField`.
A read-only field paints the normal surface (the recipe has no read-only
bucket); a disabled field uses the disabled bucket.

## Limitations

- No `type`, `maxLength`, `inputMode` or `pattern`: the component exposes a
  string field, not every native attribute. Validate with `Schema` at the
  boundary.
- `disabled` is emulated: the runtime exposes no `disabled` host prop (plan
  025). The component forwards `readOnly`, drops the field from the tab order
  and guards its handlers; the accessibility difference is the limitation above.
- No masks, formatting or prefix/suffix slots.
- **Not a password field.** GPUix 0.10.0's `<input>` has no `type`, no
  `secureTextEntry` and no masking surface (`InputProps` carries only `value`,
  `placeholder`, `readOnly` and `theme`), so every character a user types is
  painted and announced in clear. Do not collect a password, API key or token in
  `Input`. Resolve a secret through the operating system's credential prompt
  (keychain / password manager) or load it from configuration and pass it
  programmatically; no `PasswordInput` will ship until the runtime provides a
  masking surface (plan `389`).
- No `aria-describedby`; help text is adjacent content, not associated.
