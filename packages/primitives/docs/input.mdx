---
title: Input
description: A single-line text field, controlled or uncontrolled.
---

`Input` is the runtime's native `<input>` with the shared field chrome. The
native element holds the text; `onValueChange` reports every edit and `value` pushes an
external value back in. The controlled/uncontrolled decision is
`core/state.ts`'s, so an input and a checkbox cannot disagree about which value
wins.

## Usage

```tsx
import { Input, Label, labelledBy } from "@gpuixui/primitives";

const email = "Contact email";
const help = "Where notifications are delivered.";

<Label description={help}>{email}</Label>
<Input
  {...labelledBy(email)}
  description={help}
  value={value}
  onValueChange={setValue}
  placeholder="you@example.com"
  fullWidth
/>;
```

The visible `Label` paints `help`; the field's own `description` is what
assistive technology hears, because there is no `aria-describedby` to connect the
two (see §Accessibility).

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `string` | — | controlled text; omit to let the field keep its own draft |
| `defaultValue` | `string` | `""` | initial text when uncontrolled |
| `onChange` | `(value: string) => void` | none | deprecated alias for `onValueChange`; the new name runs when both are passed |
| `onValueChange` | `(value: string) => void` | none | called after each edit that changed the value |
| `onSubmit` | `(event) => void` | none | Enter; the raw runtime event |
| `placeholder` | `string` | none | empty-state text |
| `readOnly` | `boolean` | `false` | accepts focus and selection, refuses edits |
| `disabled` | `boolean` | `false` | read-only, out of the tab order, de-emphasised; no edit, submit or ring |
| `autoFocus` | `boolean` | `false` | takes focus on mount; required for keys to arrive |
| `invalid` | `boolean` | `false` | border and focus ring take the destructive role |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | height and padding from density |
| `fullWidth` | `boolean` | `false` | `width: 100%` |
| `label` | `string` | none | accessible name; a visible `Label` does not name the field on its own |
| `description` | `string` | none | announced help after the name, through the runtime's `aria-description`; a blank string publishes nothing |
| `tabIndex` | `number` | none | the field's place in the runtime's tab order; a `disabled` field is always `-1` |
| `ref` | `Ref<PublicInstance>` | none | the native `<input>` itself, for a form that focuses the field it failed on |
| `aria-id` | `string` | none | author id exposed as `AXIdentifier` / UIA AutomationId |
| `onLayout` | `(event) => void` | none | the element's painted box, after the first paint and each resize |
| `onClick` / `onKeyDown` / `onKeyUp` / `onFocus` / `onBlur` | host handlers | none | composed with the field's own; yours runs first |
| `style` | `StateStyle<FieldState>` | — | resolved against the live state and merged last |
| `testId` | `string` | — | stable locator |

The five host handlers are `InteractionProps`: your handler runs first with the
runtime's own event and the field still tracks focus and edits. A disabled field
is read-only rather than inert, so it keeps them — the value still cannot change.

`ref`, `aria-id` and `onLayout` are the runtime's own host props; a field
forwards them because the element is addressed from outside it. A text host owns
no disclosure state, so there is no `aria-expanded` or `aria-selected` here, and
the tab stop stays the field's own rule.

## Keyboard

| Key | Contract |
| --- | -------- |
| typing | native editing; every change reaches `onValueChange` |
| Enter | reaches `onSubmit` with the runtime event |
| Tab | moves focus with the runtime's own order |

`onKeyDown`/`onKeyUp` are the `InteractionProps` handlers: yours runs first
with the runtime's own event and the field still edits. A *global* shortcut — a
window chord, a command that means the same thing in every field — belongs to the
application's window key handler; a key the field sees is the one the runtime
delivered to the focused element.

## Accessibility

- The native element is announced as `TextInput`.
- The name comes from `label`; there is no `aria-labelledby`, so a visible
  `Label` is not associated by reference.
- `description` is announced as the field's description, after its name and
  role. It is a string the field carries (`aria-description`), not a reference
  to painted text, so the visible `Label description` is a second copy written by
  the caller.
- `invalid` is a border colour, not an announced error. Put the message in
  `description` so it is announced, and paint the same words in a
  `Text role="caption" tone="destructive"` beside the field.
- `readOnly` remains focusable and selectable, which is the platform contract.
- A `disabled` field is read-only at the host (GPUix has no `disabled` prop), so
  assistive technology hears a read-only field, not a disabled one. It is out of
  the tab order and its handlers are guarded, so keyboard and pointer users
  cannot edit or submit it.

## Theming

`fieldChrome` uses `fieldVariant` (the `input` role) and the density metrics;
`fieldTextStyle` sets the field's own text metrics and selection wash, and
`nativeTextTheme` — re-exported from `@gpuixui/tokens` so the field and the
token contract share one mapping — hands the host the theme's mode and families,
the `inputForeground` value role, the `placeholder` hint role and the `primary`
caret. It takes the fill the value sits on (`input` for these fields), because
the token contract measures both field fills. The `select-text` recipe utility
declares `selectionColor: theme.colors.selection`, the wash the token contract
measures, rather than the runtime's accent-at-35% default. Focus is the shared
keyboard outline (`keyboardRing`), declared at rest and painted after Tab, not
after a click.

**The hint is painted, not handed to the host.** At the pinned
`@gpuix/native@0.11.0` an empty `<input>`/`<textarea>` shapes its own placeholder
with a fixed `#8F8F8F` (`custom_elements/input.rs`), so `nativeTextTheme`'s
`textFaint` never reaches it and no theme value can move it — that grey measures
**2.84:1** on a white field. `Input` therefore gives the host **no**
`placeholder` prop and paints the caller's words over the empty host in the
`placeholder` role, inset to the field's own text origin and taking no pointer
input, so a press through the hint still focuses the field. The hint fades with
the field's disabled paint (`disabledOpacity`). A theme's `placeholder` role is
now the colour the reader sees, and it is the role `contrastPairs` holds to the
secondary floor on the field's fill.

An `invalid` field keeps its `input` fill and paints only the **edge** — the
border and the focus line — in `destructive`. The solid role is designed to
carry `destructiveForeground`; behind the value it leaves `inputForeground` at
2.45:1 in the dark theme, while `inputForeground` on `input` is a pair the
token contract measures.

`style` takes a `StateStyle<FieldState>` — a `StyleDesc`, or a callback that
receives `{ disabled, focused, invalid }`. `TextArea` and `Input` share the type,
so a form styles both the same way, and the result merges after the ring (the
last word on a property the recipe also sets).

A field's own text is content, not chrome: while another control holds keyboard
focus the runtime dims every other focusable element to 40%
(`keyboardFocusDimOpacity`), and on a field that composites the value and the
placeholder into the field's own fill (`keyboardDimFailures` measures the pair).
The field therefore declares `keyboardFocusDim: false`, so its content stays
readable while Tab is elsewhere; the ring still says where the keyboard focus
is. `style` merges last, so an application that wants the cue on a field can put
it back.

**A correction reaches the box only when it moves the value.** The host is given
the owner's text as `value`, and the runtime re-applies that text only when it
changed. An owner that normalises every edit therefore works while the
normalised text differs from what the box holds — trimming, reformatting,
clamping into a range — but the edit that leaves the value where it was is never
sent back: the box keeps the character just typed. That is why this field offers
no `maxLength` and no filter: a cap whose sixth character is refused is exactly
that edit. The honest composition is a counting hint beside the field (a
`Text role="caption"` with the length and the limit) plus boundary validation,
or a controlled field whose owner moves the value on every accepted edit.
`examples/form.example.tsx` is that composition — the project name counts past
sixty, marks the field invalid and the action refuses to save.

## Limitations

- **No `maxLength`, filter or mask** — the runtime applies a field's `value`
  only when it **changes**, so a correction that leaves the value where it was
  cannot be taken back from the box: an owner clamping five characters reports
  `abcde` while the native box keeps the sixth character and hands it back on the
  next edit (the reports run `abcde`, `abcdef`, `abcdefg`). A change that moves
  the value is applied, so formatting or clamping a value still shows. A hard cap
  is a counting hint beside the field plus validation at the boundary;
  `runtime/fields.runtime.test.tsx` measures both directions, so this note dies
  with a runtime that re-applies an unchanged value. See §Theming for the rule.
- No `type`, `inputMode` or `pattern`: the host takes `value`, `readOnly`,
  `theme` and its events — nothing else. Validate with `Schema` at the boundary.
- `disabled` is emulated: the runtime exposes no `disabled` host prop (plan
  025). The component forwards `readOnly`, drops the field from the tab order
  and guards its handlers; the accessibility difference is the limitation above.
- No masks, formatting or prefix/suffix slots.
- The hint is the field's own `<text>`, not the host's placeholder property:
  `0.11.0` exposes no `aria-placeholder` channel this library can set, so the
  hint reads as a label beside the field rather than as the field's placeholder.
  It is one line, clipped at the field's edge; a multi-line hint is not available.
- No `aria-describedby`: help is a string the field carries as
  `aria-description`, so a visible help line and the announced one are written
  twice. `invalid` still paints an edge rather than announcing the error.

## Verification

- `src/core/state.test.ts` — controlled/uncontrolled transitions.
- `src/components/fields.test.tsx` — chrome, invalid state, the element's
  address (`ref`, `aria-id`, `onLayout`), the announced `description` and the
  tab order a disabled field refuses.
- `src/components/handlers.test.tsx` — a caller's click, keys and focus run
  before the field's own tracking, on both fields.
- `src/components/keyboard-dim.test.tsx` — the fields (`Input`, `TextArea`,
  `NumberField`'s input, every OTP cell, `Select`'s trigger) declare
  `keyboardFocusDim: false`, a caller's `style` can put the cue back, and a
  `Toggle` and a `Slider` keep it (both directions measured: dropping a field's
  declaration fails its case by name, and opting every control out fails the two
  negative cases).
- `runtime/fields.runtime.test.tsx` — runtime keystrokes reach `onValueChange` with
  the accumulated text; Enter reaches `onSubmit`; a controlled field reports each
  edit; the field hands the host the whole text theme (`text`, `textFaint`,
  `bg`) but **no** `placeholder`, because the hint is painted in the
  `placeholder` role (negative control measured: dropping the `theme` prop fails
  with `hint handed the runtime no text theme`), and the `selection` wash
  reaches both a selectable `Text` and the field. The field's `description` and
  `aria-id` are read back off its `TextInput` node in the accessibility tree, the
  caller's `ref` receives the runtime's own instance, and a disabled field with a
  tab order is skipped by the traversal.
- `src/components/field-hint.test.tsx` — the hint's contract in the element tree:
  no placeholder reaches any host, the words paint in the `placeholder` role at
  the body metrics, a value or a blank placeholder shows none, the hint fades by
  the same share as the field chrome, and the frame is paint-only at the field's
  own text origin.
- `runtime/field-hint.runtime.test.tsx` — the same hint measured in a window:
  its painted colour is the theme's `placeholder`, its box starts at the field's
  text origin and sits inside the field, a press through it focuses the host, a
  typed value removes it and a cleared controlled value brings it back, and the
  `TextArea`/`NumberField` hint sits on the first row and inside its input.
