---
title: RadioGroup
description: One choice from a small set, with a roving tab stop and arrow navigation.
---

`RadioGroup` is a data-driven radio group. The group owns the roving index and
the arrow contract, so options arrive as `RadioOption[]` rather than compound
children — a deviation from shadcn's shape recorded as decision D13 in
`PLAN.md`. It follows the platform contract: the arrows **select and move focus
together**, and the focused option paints the ring.

## Usage

```tsx
import { RadioGroup } from "@gpuixui/primitives";

<RadioGroup
  label="Digest cadence"
  value={cadence}
  onValueChange={setCadence}
  options={[
    { value: "daily", label: "Daily" },
    { value: "weekly", label: "Weekly", description: "Every Monday." },
    { value: "never", label: "Never" },
  ]}
/>;
```

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `options` | `ReadonlyArray<RadioOption>` | — (required) | the choices, in order; a blank `label` paints and announces the `value` |
| `value` | `string` | — | controlled selection; `""` is a real value (see below) |
| `defaultValue` | `string` | — | initial selection when uncontrolled; omit it (with `value`) for no selection |
| `onValueChange` | `(value: string) => void` | none | the selected option's value |
| `orientation` | `"vertical" \| "horizontal"` | `"vertical"` | layout and the arrow axis |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | radio circle size |
| `accent` | `"primary" \| "destructive"` | `"primary"` | the dot's fill |
| `disabled` | `boolean` | `false` | disables every option |
| `invalid` | `boolean` | `false` | a failed validation: the empty circles take the destructive border |
| `label` | `string` | none | accessible name for the group |
| `style` | `StateStyle<RadioGroupState>` | — | merged last; an object or a state callback |
| `optionStyle` | `StateStyle<RadioOptionState>` | — | merged last on each option row; an object or a state callback |
| `testId` | `string` | — | names the group; options become `${testId}-${value}` |

`RadioOption` is `{ value, label, description?, disabled? }`. `description` is a
caption beside the name **and** the option's `aria-description`, so the visible
hint is also announced. A blank description is absent — neither announced nor
painted (plans 500, `577`).

A selection is a **string**, and `""` is an ordinary value: a "None"/"No
preference" choice is `{ value: "", label: "None" }` and behaves like any other
(checked paint, announcement and `onValueChange("")`). Absence is the **missing
prop** — supplying neither `value` nor `defaultValue` leaves every option
unchecked (plan `502`).

`invalid` is the same failed-validation paint as `Checkbox`, `Switch` and the
fields: an **empty** circle's border takes `colors.destructive`; a chosen one
keeps its accent, so the error cannot be mistaken for the selection.

## Keyboard

| Key | Contract |
| --- | -------- |
| ↑ / ↓ (vertical) | move the selection and native focus, **wrapping**, skipping disabled options |
| ← / → (horizontal) | the same on the horizontal axis |
| Home / End | jump to the first / last **enabled** option and select it |
| Enter / Space | select the focused option |
| Any printable character | select the next **enabled** option whose text starts with the typed prefix, wrapping; a repeated letter advances |
| Tab | moves to the group as **one** stop; the selected option holds it, or the first enabled one when nothing is selected |

Arrows and Home/End **select as they move** and take focus with them, matching
the platform radio contract. The tab stop is the selection, or the first enabled
option while nothing is selected; a controlled `value` change from the parent
moves the tab stop with it. The focus ring follows the focused option's
**identity**, so reordering or filtering `options` does not move it.

`Enter` and `Space` act on the option that **holds focus**, which is not always
the selected one: a controlled parent can defer or reject an arrow's move (a
validation step, a permission check), leaving focus ahead of the value. The key
then reports the focused option, so the keyboard and the focus ring always name
the same radio (plan `353`). Space acts on key **up**, Enter on key **down**, and
a held key does nothing — the shared contract in `core/keyboard.ts`.

An arrow also **continues from the focused option**, not from the value: the ring
is the keyboard's cursor, so a deferring parent cannot trap the keyboard by
moving focus once and repeating the same move on every later key (plan `359`).
The tab stop stays value-derived (or the first enabled option when nothing is
selected), so Tab still enters on what is selected.

### Type-ahead

A long group is arrow-only without it, so the group answers a typed prefix the
way a desktop radio group does (plan `741`). The rule is the same
`core/typeahead.ts` module `Select` uses:

- the next **enabled** option whose text (`label`, else `value`) starts with the
  prefix is selected **and** focused, exactly like an arrow;
- matching is case-insensitive, the search starts after the keyboard's cursor —
  the focused option, else the tab stop — and wraps; a repeated letter
  therefore advances (`E`, `E` on Europe/Estonia chooses Europe, then Estonia);
- a disabled option and an option with no text at all are never matched;
- a prefix that matches nothing changes nothing, and clears the buffer, so a dead
  letter cannot poison the next one;
- a `cmd`/`ctrl`/`alt` chord, a held repeat, `space`, `enter`, the arrows and
  Home/End are not typed characters — the move, jump and activation branches
  consume their keys first;
- a `disabled` group types nothing.

The buffer lives 500 ms after its last keystroke, matching `Select`. A controlled
parent that defers or rejects the report still advances: the search starts from
the group's cursor, not from the value the parent still holds (the plan-`732`
rule, measured in the runtime).

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). The same sample clears the group's event-tracked cursor
  when it names none of this group's options, so the ring and the arrow walk do
  not outlive focus (plan `601`). Role, name, tab order and activation are
  unaffected.
- Roles: `RadioGroup` and `RadioButton` in AccessKit.
- The group's name comes from `label`.
- Each option announces its selected state through **`aria-valuetext`**
  (`checked` / `unchecked`); there is no `aria-checked`.
- An option's own `label` is its accessible name and its visible text; a blank
  label falls back to the option's `value`, so the row is never an unnamed stop
  (plan `589`). The text beside the circle is a separate `Text`.
- Disabled options are skipped by the arrows and are not tab stops.
- The focused option paints a ring (the `ring` role, spread by
  `borderWidth.strong`), tracked per item because GPUix dispatches focus to the
  element that owns the handler — a wrapper never sees it.

## Theming

The circle is `selectionBoxStyle` with `shape: "circle"` and the dot is
`radioDotStyle`, both from `core/selection.ts`, so a radio and a checkbox of the
same size are the same square/circle family. Gaps use `spacing.sm`.

The **option row** — the element that owns the name, the tab stop and the click
and key handlers — takes its layout and pointer feedback from
`selectionRowStyle`: a `colors.hover` wash on hover and `colors.active` on press,
and neither while disabled (plan 355). The row also carries `minWidth: 0`, so a
**horizontal** group shares its width between the options and a long label wraps
inside its row instead of painting past the group (plan 380). The circle keeps
its own border feedback, so the row and the control both answer the pointer. An
invalid **empty** circle keeps the destructive border on hover and press; the
healthy interaction colours never paint over the error cue, while a chosen
circle keeps its accent (plan 356).

## Style by state

`style` takes an object or a callback over `RadioGroupState` — the runtime's own
`StateStyle` type — merged last on the group box:

```tsx
<RadioGroup style={(state) => ({ opacity: state.disabled ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | every option is disabled; an empty group is not |
| `invalid` | `boolean` | paints the empty circles destructive |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

### Per-item style

`optionStyle` takes the same `StateStyle` over `RadioOptionState`, merged last on
the option row:

```tsx
<RadioGroup
  optionStyle={(option) =>
    option.disabled ? { opacity: 0.6 } : {}
  }
/>
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `value` | `string` | the option's value |
| `index` | `number` | position in `options` |
| `checked` | `boolean` | this option is the selection |
| `disabled` | `boolean` | the option is disabled |
| `focused` | `boolean` | the option holds native focus (and paints the ring) |
| `invalid` | `boolean` | the group's failed validation |

`RadioOptionState` is exported. One callback receives every option; branch on
`value` or `index`.

## Limitations


- Options are data: no compound `RadioGroupItem`, no rich child content.
- A long option label **wraps** inside the row rather than widening it, so the
  text stays inside the group in **both** orientations (plans `368`, `380`).
