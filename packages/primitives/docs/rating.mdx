---
title: Rating
description: A whole number of stars, or none.
---

`Rating` is a radio group shaped input: one tab stop, arrows move a cursor (the
ring) and commit the star it lands on. It differs from `RadioGroup` in two ways a
rating needs — the arrows **clamp** at the ends instead of wrapping, and `Delete`
clears it back to zero. It is not a slider: the value is a small whole number,
not a position.

## Usage

```tsx
import { Rating, Stack, Text } from "@gpuixui/primitives";
import { useState } from "react";

const [score, setScore] = useState(0);

<Stack direction="column" gap="xs">
  <Rating label="Quality" value={score} onValueChange={setScore} />
  <Text role="caption" tone="muted">
    {score === 0 ? "Not rated" : `${score} of 5`}
  </Text>
</Stack>;
```

Omit `value` to let the rating own its state; `defaultValue` sets the start
(`0` is unrated). Clicking the selected star keeps it — clearing is a deliberate
key (`Delete`/`Backspace`) or the app calling `onValueChange(0)`.

## Values

Values are truncated to whole stars and clamped to `0..max`. `NaN` reads as
unrated; an infinity is out of range and clamps to its own end (`+Infinity` is
`max`, `-Infinity` is `0`).

## API

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `number` | — | controlled rating, `0..max` |
| `defaultValue` | `number` | `0` | uncontrolled start |
| `onValueChange` | `(value: number) => void` | — | the new rating; `0` means cleared |
| `max` | `number` | `5` | how many stars to paint; a non-finite count (`NaN`, `Infinity`) reads as one star (plan `366`) |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` | star size from `iconSize` |
| `disabled` | `boolean` | `false` | out of the tab order, half opacity, inert |
| `readOnly` | `boolean` | `false` | shows the value and keeps the group's one tab stop, but takes no input; full contrast, default pointer, rings while focused (plans `796`, `800`) |
| `invalid` | `boolean` | `false` | a failed validation paints the empty stars destructive |
| `label` | `string` | none | the group's name; stars are announced "N of max" |
| `autoFocus` | `boolean` | `false` | puts the keyboard on the value's star on mount (star 1 when unrated). A disabled rating never focuses; a read-only one still does (plan `808`) |
| `style` | `StateStyle<RatingState>` | — | merged last; an object or a state callback |
| `starStyle` | `StateStyle<RatingStarState>` | — | merged last on each star; an object or a state callback |
| `testId` | `string` | — | names the group; stars become `${testId}-star-N` (1-based) |

## Keyboard

| Key | Effect |
| --- | ------ |
| `ArrowRight` / `ArrowUp` | + one star from the focused star, clamped at `max` |
| `ArrowLeft` / `ArrowDown` | − one star from the focused star, clamped at `0` |
| `Home` / `End` | one star / `max` |
| `Enter` / `Space` | select the star the ring is on (key down / key up) |

`autoFocus` puts native focus on the star that holds the group's tab stop when
the rating mounts — the value's star, or star 1 when unrated — including a later
mount behind a loading state. A disabled rating never focuses; a read-only one
still does (plan `808`).
| `Delete` / `Backspace` | clear to `0` |

The group holds **one tab stop** — on the current rating, or on the first star
when unrated — and an arrow moves the ring and commits the star it lands on, so
the ring is always on the star the value came from.

The **ring is the keyboard's cursor**: a controlled parent that defers or rejects
a reported value leaves the ring ahead of the paint, so an arrow continues from
the ring rather than repeating the first move (plan `359`). Because the unrated
tab stop (star 1) is not itself selected, `Enter`/`Space` is how a keyboard user
chooses one star; the arrows then move on to 2.

Clearing moves native focus to the first star — the group's tab stop when it is
unrated — so the ring and the keyboard are always on the same star (plan `334`).

## Hover preview

While the pointer is over an interactive rating, the stars paint the value a
click would set. The preview follows the star under the pointer — hovering star
4 fills stars 1–4 — and leaving the group restores the committed value. It is
**paint only**: the committed value, `onValueChange` and the star's announced
state do not change, because a preview is not a selection.

`disabled` and `readOnly` ratings take no hover handlers and never preview: a
preview is an input affordance, and an inert control has none. A rating that
*becomes* inert also drops the preview it was holding, so a read-only lock while
the pointer is over star 4 does not revive star 4's preview when the field is
editable again — the committed value paints until the pointer enters a star
(plan `801`). An `invalid` preview fills with the brand role like any other; the
destructive role stays on the stars that are still missing.

`starStyle`'s `filled` follows the paint, not the committed value, so a custom
star style cannot disagree with the icon beside it.

A star declares **no `hover` style rule**: the preview *is* its pointer feedback,
and it is stronger than a wash — the paint answers which value the click would
set, not merely that the pointer arrived. This is the one recorded exception to
the library's "an element that owns a pointer gesture declares its feedback"
rule (`runtime/pointer-feedback.runtime.test.tsx`, plan `361`); an interactive
star still declares `cursor: "pointer"` and keeps the press contract, while a
read-only one is `default` and a disabled one `not-allowed` (plan `796`).

## Accessibility

- **Release-runtime focus:** the pinned 0.10.0 runtime moves native focus but
  delivers no `onFocus`/`onBlur` to a component
  ([measured](../../../docs/gpuix-capabilities.md#focus-events)). The ring still
  paints: `ThemeProvider`'s native-focus tracker samples
  `getFocusedElementId()` every 50 ms, so focus reaches the paint up to one tick
  late (plan `590`). The same sample clears the rating's event-tracked cursor
  when it names none of these stars, so the ring and the arrow walk do not
  outlive focus (plan `601`). Role, name, tab order and activation are
  unaffected.
- Roles: `radiogroup` with the group's `label`, and one `radio` per star
  (AccessKit `RadioGroup` / `RadioButton`).
- Each star's name is `"N of max"` and its state is announced through
  **`aria-valuetext`** (`"checked"` / `"unchecked"`), because GPUix 0.10.0 has no
  `aria-checked`. A hover preview never changes that announcement — only the
  committed value does.
- `readOnly` is a **display state that stays reachable** (plan `800`, the rule
  plan `786` gave every field): the group keeps its one tab stop — on the
  value's star, or star 1 when unrated — so a keyboard user can hear the value,
  and the focused star paints the ring. It takes no input: no click, no
  `Enter`/`Space`, no arrows, no preview. GPUix 0.10.0 has no `aria-readonly`,
  so that reachable star's `"N of max"` and `checked`/`unchecked` are the only
  announcement. `disabled` is the blocked state: it leaves the tab order, paints
  muted, `not-allowed` and no ring. Only `disabled` drops out of the tab order
  (plan `800`).

## Theming

A selected star paints `colors.primary`, an empty one
`colors.mutedForeground`, using two icons of the same geometry: `star-filled`
and `star`. With `invalid`, the **empty** stars paint `colors.destructive` while
a chosen one keeps the brand role — the error marks what is missing, not what is
chosen (the `RadioGroup` rule, plan `061`). The filled icon is still monochrome —
its `#000` fill is what GPUix retints — so a theme change repaints both states.
The star size is `theme.iconSize[size]` and the focus ring is the shared
`focusRing`.

## Style by state

`style` takes an object or a callback over `RatingState` — the runtime's own
`StateStyle` type — merged last on the star row:

```tsx
<Rating style={(state) => ({ opacity: state.disabled ? 0.9 : 1 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `disabled` | `boolean` | refuses pointer and keys, and leaves the tab order |
| `readOnly` | `boolean` | shows the value and keeps the tab stop, refuses pointer, keys and preview (plans `786`, `800`) |
| `invalid` | `boolean` | paints the empty stars destructive |

The callback's result merges after the component's own rules, so it wins per
property; returning `{}` keeps the default look. The state type is exported.

### Per-item style

`starStyle` takes the same `StateStyle` over `RatingStarState`, merged last on
each star:

```tsx
<Rating starStyle={(star) => (star.filled ? { opacity: 1 } : { opacity: 0.7 })} />
```

| Field | Type | Meaning |
| ----- | ---- | ------- |
| `index` | `number` | 1-based, matching the star's announced "N of max" |
| `filled` | `boolean` | this star is painted filled — at or below the value, or inside the hover preview |
| `disabled` | `boolean` | the rating is disabled |
| `readOnly` | `boolean` | the rating is read-only |
| `invalid` | `boolean` | paints the empty stars destructive |
| `focused` | `boolean` | this star holds native focus |

`RatingStarState` is exported. One callback receives every star; branch on
`index` or `filled`.

## Limitations


- **Validation is paint only.** GPUix 0.10.0 has no `aria-invalid`, so `invalid`
  marks the empty stars and is not announced; pair the rating with an error
  `Text`, as with every other control.
- **Whole stars only.** Half stars would need clipping or a transform, neither of
  which exists in GPUix 0.10.0; a caller that needs a finer score can keep it in
  state and paint the label beside the stars.
- **Clearing is explicit** (Delete/Backspace or the app), not "click the selected
  star again" — a rating is not a toggle.
