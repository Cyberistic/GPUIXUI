## Usage

```tsx
import { MarkdownEditor } from "@gpuixui/editor";

<MarkdownEditor
  value={value}
  onValueChange={setValue}
  label="Release notes"
  width={640}
  height={300}
/>;
```

## Names

`label` names the editor and every part of it: the source field is `"<label> source"`, the preview `"<label> preview"` and the split's divider `"<label> split"`. A label that arrives blank — from an i18n table or a saved record — is an absence, so each part falls back to `Markdown editor` rather than publishing `" source"`; a label that is not text at all (a number a record kept) is no name either, so the parts keep the same default instead of the render throwing out of the name seam.

## Views

The three view buttons are a choice, not three separate actions: the painted
view is the one with `secondary` paint, and it also carries **`aria-selected`** —
0.11.0 has no `aria-current`, and `aria-selected` is the substitution the
Pagination, Stepper and Timeline controls publish for the same job. Every button
states its own value, so the colour of the paint is not the only channel that
says which view is showing; a reader on a screen reader gets the same fact from
the control it is on.

## Limitations

- **A stored draft that is not text reads as an empty document**: a saved
  record writes `null` where it carried no draft, and the status line and the
  preview read the text directly — so the value is read once through
  `draftOf`, which keeps a string as written (whitespace included) and answers
  `""` for anything else, rather than throwing out of the render.
- **An unclosed fence is closed in the preview only**: the source keeps every
  character the reader typed and the preview appends the missing marker on the
  next line, so a document written mid-block does not swallow the page. A draft
  that already ends on a newline gains no blank line in the block, and a blank
  line the reader did type stays.
- **No formatting toolbar.** It needs a selection API the runtime does not have.
- **No caret or selection read-back.** `MarkdownEditor` cannot insert at the reader's cursor.
- **Two panes, horizontal only.** A split divides the editor left/right and the preview takes the rest; there is no stacked split.
