## Usage

```tsx
import { DiffViewer } from "@gpuixui/editor";

<DiffViewer before={before} after={after} mode="unified" />;
```

## API

| Prop | Type | Default | Notes |
| ---- | ---- | ------- | ----- |
| `before` | `string` | — | The before source. |
| `after` | `string` | — | The after source. |
| `mode` | `"unified" \| "split"` | `"unified"` | One merged column, or two. A stored name that is neither reads as the default. |
| `contextLines` | `number` | `3` | Unchanged rows kept either side of a change before the diff skips to a hunk heading. A negative or non-numeric value reads as the default. |
| `lineNumbers` | `boolean` | `true` | Number the rows on both sides. |
| `label` | `string` | `"Diff"` | The accessible name; a blank or non-text name reads as the default (the rows are presentational, so this is the whole surface's name). |
| `className` | `string` | — | A Tailwind class string, merged last. |
| `style` | `StateStyle<DiffViewerState>` | — | The surface, or a function of `{ changed }`. |
| `testId` | `string` | `"diff-viewer"` | The address an automation host locates the diff by. A unified line appends `-row-<index>`; a split line appends `-row-<index>-before` and `-row-<index>-after`; a hunk heading appends `-hunk-<index>`. |

## The row model

The viewer paints data, not decisions. `diff/logic` exports the whole script:

- `hunks(numbered, context)` groups the numbered script into hunks, keeps `context`
  unchanged rows either side of a change, and names the lines a skip dropped
  (`@@ -beforeStart,count +afterStart,count @@`). Two changes within `2·context`
  rows share a hunk, so their context windows abut and no change is shown twice.
- `rows(numbered, context)` is the unified sequence: a hunk heading, then each
  changed pair with the removal and the addition it became **adjacent**, then
  every context row once.
- `pairs(numbered, context)` is the split sequence: the same hunks zipped across the
  divider, with a blank cell on the side that ran out. A heading pairs with
  nothing on the right, so a split viewer paints it once across both columns.

## Split mode

`mode="split"` puts a changed line and its replacement on **one** row: the two
equal columns share a row height, so a pair sits level across the divider. Each
column carries its own line-number gutter and its own horizontal scroller; a
long line scrolls inside the column it belongs to instead of pushing or clipping
its neighbour. A one-line edit is therefore one row with the old line on the
left and the new one on the right, not a removal and an addition stacked apart.
