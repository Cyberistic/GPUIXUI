---
title: Registry
description: Install a component's source with the shadcn CLI.
---

Every component is published as a [shadcn registry](https://ui.shadcn.com/docs/registry)
item, so `shadcn add` copies the source you own into your project. The files are
GPUix native: they render through GPUix's reconciler against `@gpuix/react`, not
the DOM.

## Install

```sh
npx shadcn@latest add @sudokw/primitives-button
```

`@sudokw` is the namespace shadcn's directory publishes; the item also has a
direct address:

```sh
npx shadcn@latest add https://gpuixui.sudokw.com/primitives-button.json
```

Either form installs three things:

- the component's source and the part files it imports;
- the `@gpuixui/*` runtime it imports, as separate `gpuix-tokens`, `gpuix-tw`,
  `gpuix-motion` and `gpuix-primitives` items — written once per project, not
  copied into each component;
- the npm packages those files import (`@gpuix/react`, `@gpuix/native`,
  `effect`, `react`), at the versions the library pins rather than `latest`.

Names are `<package>-<component>` because the registry is flat and eight page
names belong to two components (`primitives-progress` and `components-progress`).
`npx shadcn@latest search @sudokw` lists every item.

## Where the files land

Under the project's `ui` alias, in one `gpuixui` folder that keeps the library's
package layout:

```
src/components/ui/gpuixui/primitives/components/Button.tsx
src/components/ui/gpuixui/tokens/index.ts
src/components/ui/gpuixui/tw/index.ts
```

Imports between installed files are relative, so the tree moves with the alias
and needs no path mapping of its own.

## The setting the files need

The CLI removes the comment block at the top of each copied file, and that is
where the source's `@jsxImportSource` pragma lives. Set the runtime once in the
project instead:

```json
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "@gpuix/react"
  }
}
```

`tsconfig.json` is what TypeScript and Vite both read; with it, the installed
files compile against GPUix's element types instead of React DOM's. A project
that skips it still installs, and every render fails to type-check.

## Render it

```tsx
import { render } from "@gpuix/react";
import { Button } from "@/components/ui/gpuixui/primitives/components/Button";
import { ThemeProvider } from "@/components/ui/gpuixui/primitives/components/ThemeProvider";
import { darkTheme } from "@/components/ui/gpuixui/tokens";

render(
  <ThemeProvider theme={darkTheme}>
    <Button variant="primary" onActivate={save}>
      Save changes
    </Button>
  </ThemeProvider>,
);
```

`render` takes one element: a fragment at the root paints only its last child
and reports nothing. `ThemeProvider` is required — a primitive with no theme
above it throws rather than inventing a palette.

`@gpuix/native` ships prebuilt binaries for Apple Silicon, Linux x64 and
Windows. On any other host, build the binding first; the
[playground README](https://github.com/Cyberistic/GPUIXUI/blob/master/apps/playground/README.md#the-binding-on-this-host)
names the script.

## Updating, previewing, replacing

```sh
npx shadcn@latest add @sudokw/primitives-button --dry-run   # what would be written
npx shadcn@latest add @sudokw/primitives-button --view      # the file contents
npx shadcn@latest add @sudokw/primitives-button --overwrite # replace edited files
```

The copied source is yours: edit it in place. `--overwrite` is the only command
that replaces it, and it replaces every file the item ships.

## The documents

The registry is flat: an index at [`/registry.json`](/registry.json) and one
document per item beside it, `/<package>-<component>.json` and
`/gpuix-<package>.json`. The index lists each item's file paths; each item's own
document carries their content. A client that speaks the shadcn schema reads
both with no special case.
