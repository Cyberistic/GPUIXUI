## What coverage means here

This table is the **status coverage** of the inventory: one row per Tier 3–5
target, generated from `COMPONENTS.md`, so a target cannot be missing without
the inventory changing. "Coming soon" is the reader's word for a row whose
status is `todo`: it has no implementation and no page yet.

It is not a code-coverage figure. No line, branch or function coverage is
measured or published, and a `done` status is not a claim about one. The
evidence that does exist lives on three pages: the [GPUix
capabilities](/docs/capabilities) matrix (what the runtime can do, with the
scenario that proves it), the [Native smoke suite](/docs/native-testing) (what
the suite proves and what it does not), and [Previews](/docs/previews) (how each
page's evidence is labelled).

## What a status means

- **`todo`** — tracked, not built. No package, no page.
- **`wip`** — code exists and is documented, but at least one bar below is unmet.
- **`done`** — code, a test appropriate to its behaviour, a working example, a docs page, and a
  verified interaction in the real GPUix runtime.
- **`blocked`** / **`unsupported`** — the reason and the evidence are recorded. Where the limit is
  the runtime rather than the package, [GPUix capabilities](/docs/capabilities) names the measured
  behaviour and the scenario that proves it.

The **GPUix support** column is the runtime's own answer, not our status: `yes` means GPUix publishes
the primitive, `?` means it is unverified, and `ours` means the library must implement it. The
component index uses the same vocabulary.
