Two minutes from a clone to a native window.

## Install

```sh
git clone https://github.com/Cyberistic/GPUIXUI.git
cd GPUIXUI
nub install
nub add @gpuixui/components@workspace:*
```

Node 24.18.0 and [`nub`](https://nub.dev). A host with no prebuilt GPUix binding builds one first; [`apps/playground/README.md`](https://github.com/Cyberistic/GPUIXUI/blob/master/apps/playground/README.md#the-binding-on-this-host) names the targets and the script.

## The first component

```tsx
import { render } from "@gpuix/react";
import { Button } from "@gpuixui/primitives";
import { darkTheme } from "@gpuixui/tokens";
import { ThemeProvider } from "@gpuixui/tokens/react";

render(
  <ThemeProvider theme={darkTheme}>
    <Button variant="primary" onActivate={save}>
      Save changes
    </Button>
  </ThemeProvider>,
);
```

`render` takes **one** element: a fragment at the root paints only its last child and reports nothing. Run it with `nub run dev:playground`, and run `nub run check` before you call a change done.

## Four rules

- **Effect first.** An expected failure is a value in `Effect.Effect<A, E, R>`; domain code does not throw.
- **Semantic roles only.** A component reads `colors.primary` or `spacing.md`, never a literal.
- **The runtime is the limit.** No DOM, CSS, `transform`, grid span or canvas. See [the capability record](https://github.com/Cyberistic/GPUIXUI/blob/master/docs/gpuix-capabilities.md) and [the reference](/reference).
- **Every fix lands with a test** that fails without it.

## The theme in seven lines

```tsx
import { getTheme, platformTheme } from "@gpuixui/tokens";

const theme = getTheme("dark"); // light or dark; add "high" for contrast
const windows = platformTheme(theme, "win32"); // darwin, win32, linux, default

<ThemeProvider theme={windows}>{app}</ThemeProvider>;
```

A theme decides the colour roles, type, spacing, radius and density. The mode picks light or dark; the platform switch resolves the same roles for another host.
