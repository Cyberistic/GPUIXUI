The workspace layer is what makes GPUIXUI a desktop library: resizable split
panes, panel groups, collapsible sidebars, tabbed panels, docking layouts and a
command palette. These are the components that benefit most from a native
runtime and the least from a browser imitation.

They will live in `@gpuixui/docking`, which is not published yet, and depend on
`@gpuixui/components`. Each one is proven in the native playground before its
inventory row may say `done`; where GPUix cannot support an interaction (for
example, detachable windows), the page records the limitation with evidence
rather than shipping a placeholder. The [Roadmap](/docs/roadmap) lists every
target and its status.

## Proven today

The frame that holds these regions is already composable from the layout
primitives: the [app-shell pattern](/docs/patterns/app-shell) builds a title bar,
a collapsible navigation rail, a scrolling content region and a status bar on the
live surface. Resizing, panel groups and docking stay in `@gpuixui/docking`, and
nothing here claims otherwise.

The package is not published, but the runtime primitives it will compose are
measured. The scenarios below drive a real split pane, a real tab drag and a
real divider resize in GPUix; run them yourself:

```sh
nub run --filter playground build
nub apps/playground/dist/smoke/run.js --only workspace-tab-drag
```
