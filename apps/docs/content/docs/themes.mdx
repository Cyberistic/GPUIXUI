Edit the semantic tokens the library ships and watch them apply to a preview in
real time. The editor reads its defaults from `@gpuixui/tokens` and emits the
same `createTheme` shape the library consumes; it invents no palette of its own.

## How it works

The editor edits the shadcn-core roles — `background`, `foreground`, `card`,
`popover`, `primary`, `secondary`, `muted`, `accent`, `destructive`, `border`,
`input` and `ring` — plus `radius.md` and the `sans` family. Light and dark are
independent; pick the mode, edit, and the preview follows. Edits persist to the
URL (shareable) and to `localStorage`; **Reset** restores the built-in themes.

## The token bridge

`@gpuixui/tokens` ships TypeScript objects, not CSS variables, and the library
paints through GPUix. This preview is CSS, so the editor exposes each role as
the shadcn variable name (`--primary`, `--background`, …) on the preview
element, maps `radius.md` to `--radius`, and maps `.SystemUIFont` to a CSS
system stack because GPUI resolves that sentinel natively and the browser
cannot. The bridge exists only for this preview.

## The theme audit

The readout under the preview runs `auditTheme` on the theme the edits resolve to
— the same gate `@gpuixui/tokens` tells a theme author to run before shipping, so
an edit is measured against exactly the contract the library holds itself to. One
call reports four independent failures:

- **Roles** the renderer cannot paint. GPUix ignores a colour string it cannot
  parse and keeps the previous value or paints black, so the editor names the role
  and the value instead of failing in silence.
- **Contrast**: `contrastFailures` checks {contrastPairs.length} role pairs — body
  text at 7:1, secondary text at 4.5:1, boundaries and focus rings at 3:1 — and
  the readout names every pair an edit breaks, with its measured ratio. A
  translucent value is reported as **unmeasurable** rather than counted as a pass,
  because its contrast depends on the surface behind it.
- **Decorative surfaces**: dividers, skeleton fills, the modal veil and status
  edges carry no text, so WCAG gives them no floor at all. `decorativeFailures`
  holds them to 1.05:1 against the surface they sit on — editing `border` towards
  `background` is how a card loses its edge, and no contrast pair would see it.
- **Data series**: `seriesFailures` measures the five categorical colours a chart
  paints against the three surfaces a plot is drawn on (`background`, `card`,
  `popover`) at the boundary floor, and each pair against `seriesDistinctnessFloor`
  in OKLab — a blue and a violet of one lightness pass contrast and still read as
  one series. The editor does not edit the scale, so an edit cannot break it; the
  readout reports it because `auditTheme` does, and a line that only appears for
  some themes would make a passing readout mean less than it says.

The same role check guards the URL and `localStorage`: a persisted state that
carries a value the renderer cannot paint is rejected, and the editor falls back to
the built-in themes instead of restoring an edit that would paint black in
silence. A theme that merely misses a contrast, decorative or series floor is a
design choice the readout reports, not a malformed state.

## Copy theme

**Copy theme** emits a `createTheme` module — one theme per mode — in the exact
format `@gpuixui/tokens` consumes, plus a one-line usage note. Running the same
audit on the result is up to the consumer; `auditTheme`, `contrastFailures`,
`decorativeFailures` and `seriesFailures` are public for exactly that.
