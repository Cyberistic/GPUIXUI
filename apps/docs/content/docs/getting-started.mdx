A GPUix application is a React tree rendered into a native window. The entry
file ends with `render()`, which creates the window, mounts React and starts the
frame loop.

```tsx title="app.tsx"
import { render } from "@gpuix/react";

function App() {
  return (
    <div style={{ padding: 24 }}>
      <text>Hello from GPUix</text>
    </div>
  );
}

render(<App />, { title: "My app" });
```

```sh
nub app.tsx
```

## Try the library in an example

[`examples/basic-app`](https://github.com/Cyberistic/GPUIXUI/tree/master/examples/basic-app)
composes the Tier 1 components into a settings workflow and is the one example
in the repository today:

```sh
nub install
nub run --filter @gpuixui/basic-app dev
```

It needs the GPUix native binding and a desktop session; on a host without one
the app is type-checked but never launched. See [Examples](/docs/examples) for
what that does and does not prove.

## The native playground

A companion playground (`apps/playground`) will host a screen per component and
the screenshot capture used by these pages. It is a Phase B deliverable: the
repository holds its design and README, but no app and no `package.json` yet, so
`nub run dev:playground` does not resolve.

Each component page names the playground screen that will demonstrate it. Until
that screen exists, the page shows the honest "not verified in the GPUix
runtime" notice instead of a browser imitation.

## Native previews

This site does not render GPUix in the browser. A page either shows a real
capture from the runtime, links to the playground, labels a browser
approximation explicitly, or states that the component is unverified. The rules
are summarised in [Architecture](/docs/architecture) and recorded in full in
`docs/preview-strategy.md`.
