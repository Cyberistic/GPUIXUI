Every documented component's table is generated from its real TypeScript types
with `fumadocs-typescript` — not written by hand, so it cannot drift. A prop's
tsdoc becomes its description, and `@internal` hides it from the published
table. Pick a component to jump to the table on its page.

## How the tables are generated

The site and its tests share one generator, so a table cannot pass a test
against a configuration the site does not run:

</include>

The MDX pipeline turns each prop-table tag into a table at build time. Includes
are read in the same pass, so a renamed file fails the build instead of leaving
a stale copy:
