`@gpuixui/keyboard` turns a press into a command.

| Module | Responsibility |
| ------ | -------------- |
| decode | `decodeGpuixEvent` — a GPUix event to a parsed chord |
| match | `match` — exact modifier matching |
| keymap | `Keymap`, `resolve` — a scope stack as data, first match wins |
| sequence | `makeSequenceMatcher` — multi-step matches with an injected clock |
| registry | `Command`, the `CommandRegistry` Effect service and its layer |
| display | `formatSymbols` — a binding as keycap parts, in platform order (an alias over `formatForDisplay`) |
| helpers | `parseHotkey`, `validateHotkey`, `normalizeHotkey`, `areHotkeysEqual`, `hasNonModifierKey`, `formatForDisplay` — the grammar's own, re-exported |
| platform | `Platform`, `toTanstackPlatform` |
| React | `@gpuixui/keyboard/react` — `CommandRegistryProvider`, `useCommandRegistry` |

The grammar is `@tanstack/hotkeys`: parsing, normalization, comparison, display and `Mod` resolution.

## Decode, then match

GPUix delivers `key`, `keyChar` and modifier flags. There is no `code`, so bindings never read `keyChar`.

```ts
import { decodeGpuixEvent, match, type Platform } from "@gpuixui/keyboard";
import type { EventPayload } from "@gpuix/react";

const platform: Platform = "darwin";

export const isSave = (event: EventPayload): boolean =>
  match("mod+s", event, platform);

export const chordOf = (event: EventPayload) => decodeGpuixEvent(event, platform);
```

`match` is exact: `Mod+K` does not match `Mod+Shift+K`, and `cmd` stays distinct from `ctrl`.

## Chords as text

Six grammar helpers are re-exported, so a caller that validates, normalises or
paints a binding does not install `@tanstack/hotkeys` itself.

| Helper | Answers |
| ------ | ------- |
| `parseHotkey` | the parsed chord a binding string stands for — the shape `decodeGpuixEvent` returns |
| `validateHotkey` | `{ valid, warnings, errors }` for a binding from storage or a form |
| `normalizeHotkey` | the canonical string: `Meta+S` reads `Mod+S` where the platform allows it, with the modifiers in order |
| `areHotkeysEqual` | whether two bindings press the same keys with the same modifiers |
| `hasNonModifierKey` | whether a press is more than a modifier — the test a recorder waits for |
| `formatForDisplay` | the words a reader sees, or with `parts: true` the keycaps |

**The platform argument is not the same type twice.** `decodeGpuixEvent` and
`formatSymbols` take this package's `Platform` (`darwin`, `linux`, `win32`,
`default`); the bare helpers take the grammar's (`mac`, `windows`, `linux`),
which `toTanstackPlatform` produces — `default` folds into `linux`, where `Mod`
is Control.

The shipped `HotkeyRecorder` is the worked path: decode the press, drop a
modifier-only chord, store the normalised string, paint the parts.

```ts
import {
  decodeGpuixEvent,
  hasNonModifierKey,
  normalizeHotkey,
  toTanstackPlatform,
  type Platform,
} from "@gpuixui/keyboard";
import type { EventPayload } from "@gpuix/react";

export const record = (
  event: EventPayload,
  platform: Platform,
): string | undefined => {
  const grammar = toTanstackPlatform(platform);
  const chord = decodeGpuixEvent(event, platform);
  return hasNonModifierKey(chord, grammar)
    ? normalizeHotkey(chord, grammar)
    : undefined;
};
```

`formatSymbols` returns one entry per keycap — `["⇧", "⌘", "S"]` on macOS,
`["Ctrl", "Shift", "S"]` elsewhere — so `KeyboardShortcuts` and the app menu
render parts rather than a string.

## One command list

```tsx
import type { Command } from "@gpuixui/keyboard";
import { Effect } from "effect";

export const commands: ReadonlyArray<Command> = [
  {
    id: "palette",
    title: "Open the command palette",
    scope: "global",
    hotkey: "mod+k",
    handler: Effect.void,
  },
];
```

`render`'s `onKeyDown` is the only app-level route; the focused element handles the key first.

## The React provider

The provider and the hook are published at `@gpuixui/keyboard/react`; the root entry point does not re-export them.

```tsx
import {
  CommandRegistryProvider,
  useCommandRegistry,
} from "@gpuixui/keyboard/react";

<CommandRegistryProvider commands={commands}>
  <App />
</CommandRegistryProvider>;

const registry = useCommandRegistry(); // the nearest list, or an empty one
```

A subtree with no provider reads an empty registry, so a command palette inside an app that never mounted one resolves nothing rather than throwing.

## Limitations

- **No global or system shortcut**: a binding fires only while the window is focused.
- **A focused field sees the key first**; the root handler is a fallback.
- **Physical bindings cannot match**: `Mod+[KeyS]` parses but never resolves.
