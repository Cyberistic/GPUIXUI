---
title: Platform
description: The behaviours only the operating system owns.
---

**The rule:** if the OS owns the behaviour, take it from the OS; if it is a picture,
paint it. A button, row, popover or tooltip is a picture and repaints with the
theme, while a file panel, zoom button and title bar lights come from the system.

## What ships

| Surface | Entry | What the OS owns |
| --- | --- | --- |
| Window | `Window`, `SourceList`, `nativeWindowOptions` | the traffic lights over the app's own sidebar and toolbar, and the blur behind them |
| Appearance | `watchAppearance`, `appearanceOverrides` | the accent colour, Light/Dark and Reduce Transparency, read from `defaults` |
| Window verbs | `useWindowActions` | minimise, zoom, fullscreen, rename, activate |
| Path picker | `window.pickPaths` | the system's open panel, and its cancel |

The window is opened with `nativeWindowOptions`, which sets
`titlebarTransparent`, `trafficLightX` / `trafficLightY` and the theme's
`windowBackground` on macOS, and nothing elsewhere:

```tsx
render(<App />, { title: "Files", ...nativeWindowOptions(theme, currentPlatform) });
```

## What stays painted

The OS menu bar has no API in this release, so `AppMenu` draws it in-window
(`/shell/app-menu`); alerts, sheets and popovers are the library's floating layers,
not `NSAlert` or `NSPopover`, and a native colour panel and tooltip remain in
`TODO.md`.
