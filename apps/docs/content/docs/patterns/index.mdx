---
title: Patterns
description: Realistic compositions, not isolated controls.
---

Patterns are where components meet real tasks: a settings page with validation,
a confirmation flow, a searchable command menu, a searchable list with filters.
Each page shows the composition, explains the state it owns, and says which
parts are verified in the native runtime.

## Settings form

The first pattern is the workspace settings screen from
[`examples/basic-app`](/docs/patterns/settings-form): labelled fields with live
validation, a select, three kinds of selection control, save progress, a loading
skeleton, a tooltip and a light/dark switch, all composed from the public
primitives. It is type-checked and its source is the real application file; it
has not been launched natively.

## Confirmation flow

The second pattern is the check before an irreversible action
([`/docs/patterns/confirmation-flow`](/docs/patterns/confirmation-flow)): a
`ConfirmDialog` that requires the workspace's name before its destructive
button commits, an inline error when the name does not match, and a success
toast when it does. It runs as a live scene on GPUix's published WebAssembly
renderer, and the release smoke types the name and confirms so the success
state is proved rather than illustrated.

## Command palette

The third pattern runs a project command without a menu tree
([`/docs/patterns/command-palette`](/docs/patterns/command-palette)): the real
`CommandMenu` opens from a `Commands` control, the highlighted command runs on
Enter or a click, and `Duplicate project` adds a named copy through a pure
rule. It runs as a live scene on GPUix's published WebAssembly renderer, and the
release smoke opens the palette and runs the command so the result is proved
rather than illustrated.

## Project browser

The fourth pattern is the ordinary find-and-open task
([`/docs/patterns/project-browser`](/docs/patterns/project-browser)): a real
`SearchInput` filters a real `List` by name or description, a no-match query
paints the `EmptyState` with a way back, and opening a row shows its detail. It
runs as a live scene on GPUix's published WebAssembly renderer, and the release
smoke types the name, proves the count changed and opens the match. It is a
list, not a table: `@gpuixui/data-grid` is still a roadmap target.

## App shell

The fifth pattern is the frame around everything else
([`/docs/patterns/app-shell`](/docs/patterns/app-shell)): a title bar, a
navigation rail that starts collapsed and opens from one control, one scrolling
content region and a status bar, composed from the real layout primitives. It
runs as a live scene on GPUix's published WebAssembly renderer, and the release
smoke opens the rail and proves its destinations were not painted before the
click. It is a frame, not a docking layout: resizable splits and panel groups
remain `packages/docking` targets.

## Still to come

The inspector workspace waits on `packages/docking`, which does not exist yet.
The command palette's **package** example is still owed by the component
workstream; the page above is a docs-owned composition, not a substitute for a
package example.

A pattern is never assembled from browser imitations and presented as working
native behaviour.
