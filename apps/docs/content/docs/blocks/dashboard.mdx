A dashboard recipe that composes the most parts of a window: a `Card` grid of
stats, `Progress` rows for projects and apps, `Badge` deltas, a `SearchInput`,
`Icon` glyphs, and the `Stack`/`Text` layout for the sidebar and top bar.

## Composition

The block composes:

- `Badge` from `@gpuixui/components/badge`, `Card` and its parts from
  `@gpuixui/components/card`, `SearchInput` from `@gpuixui/components/search-input`
- `Button`, `Progress`, `Stack` and `Text` from `@gpuixui/primitives`
- `Icon` from `@gpuixui/icons`

## Charts are a gap

The library has no chart component yet, so the recipe ships a minimal
`<svg source>` primitive — bars, a donut and stacked bars — as the strongest
honest stand-in until a chart component lands, labelled as a gap in the source.

The runtime paints an `<svg source>` as **one tint** (measured by the
playground's `content-surfaces`: the whole markup is masked in `style.color`, so
a shape's own `fill` never reaches the frame). A multi-series chart is therefore
one stacked `<svg>` per colour, and the recipe's `Chart` takes that colour
rather than pretending one element can hold a palette.

The preview above is a browser reproduction of the recipe's geometry and
palette; the code tab is the `@gpuixui/*` source. Its five colours are not the
recipe's: they are the theme's categorical
[data series](/docs/theming#data-series), read through `seriesColors(theme)` — or
as `--series-1` to `--series-5` in the browser preview, which is why the platform
and look switch repaints the bars, the donut, the stacked bars and every legend
swatch together. The app and database glyphs are not in the icon set either; the
recipe uses monograms and a hand-drawn database mark.
