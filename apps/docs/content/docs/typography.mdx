A component names a role and `Text` resolves it from the theme.

<TypeScale />

## Override the scale

```tsx
import { extendTheme, lightTheme } from "@gpuixui/tokens";

const brand = extendTheme(lightTheme, {
  typography: { body: { fontSize: 15, lineHeight: 22 } },
});
```

Roles merge field by field.

## Families

`sans` covers every role except `code` and `codeBlock`, which paint `mono`.
Every platform's UI face is GPUix's `.SystemUIFont` sentinel — the runtime
resolves the host's own — while each preset names the mono face it expects:

| Platform | Mono face |
| -------- | --------- |
| macOS | `Menlo` |
| Linux | `DejaVu Sans Mono` |
| Windows | `Consolas` |
| Default | `Menlo` |

Density never changes type sizes: a preset moves a control's height, padding and
row height, not its type.

## Semantics

A role is also what the runtime tells assistive technology. `h1`, `h2` and `h3`
publish `heading` with their own level, `code` and `codeBlock` publish the code
role, and every other role is a plain text run. There is no paragraph, list or
landmark role — compose those from the component that owns them.

## Tones

`Text` takes `default`, `muted`, `primary`, `destructive` or `inherit`.

## Limitations

- **One run, one role**: no rich text; a bold word is a second `Text`.
- **No paragraph or list semantics**: only the heading and code roles are published.
- **No responsive sizes**: one size per theme, not per window width.
