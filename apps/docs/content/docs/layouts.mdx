The layout primitives are the foundation every other component is built from.
They map onto GPUix's flexbox and fixed-track grid, not a browser's CSS layout:
there are no media queries, no auto-flow and no percentage tracks beyond the
runtime's own.

They ship in `@gpuixui/primitives`. The layout pages carry the real source, a
generated props table and their runtime observations — `Stack` documents both
flex stacks and the runtime's grid:

- [`Box`](/docs/components/box) — the surface and padding container; the place an
  application overrides a background or a border.
- [`Stack`](/docs/components/stack) — one axis, a theme-owned `gap`, and explicit
  alignment. `direction` is required so a row cannot silently become a column.
  The same page documents `Grid`: equal numeric tracks, `columns` + `rows`, with
  no auto-placement and no named areas.
- [`Separator`](/docs/components/separator) — one border step across the surface.
- [`Spacer`](/docs/components/spacer) — a flexible filler that pushes siblings to
  the far edge.
- [`ScrollArea`](/docs/components/scroll-area) — a scroll container that reports
  its deltas; the scrollbar itself is platform-themed and cannot be tinted on
  the pinned runtime.

Spacing is always a theme step (`2xs` … `5xl`), never a pixel value at the call
site, so a layout cannot drift from the design system. What the runtime cannot
do — responsive breakpoints, ragged grids, a tinted scrollbar — is recorded on
the component page rather than worked around in a wrapper.

The primitives composed into a real application frame — title bar, collapsible
navigation rail, scrolling content and status bar — are the
[app-shell pattern](/docs/patterns/app-shell), which runs on the live surface.

## Localization and direction

The library ships no i18n layer, and the pinned runtime has no direction
option. Each limit is proved on the page that owns it:

- **Labels are fixed English.** [Date pickers](/docs/components/date-picker)
  build their month and weekday names from a literal table, with no `Intl` and
  no locale lookup; [Time pickers](/docs/components/time-picker) show a fixed
  24-hour form with no AM/PM, locale, seconds or timezone;
  [Countdown](/docs/components/countdown) renders a locale-free clock; the
  [confirmation flow](/docs/patterns/confirmation-flow) says its copy is
  English-only. Pagination's previous and next controls own their English
  `aria-label`.
- **There is no `locale` prop and no formatter.** A label a component shows is
  either a prop the caller sets or a string the component owns; nothing
  formats numbers or dates for a locale. A prop that accepted a locale and
  silently did nothing would be worse than none.
- **Right-to-left layout is not implemented.** The pinned runtime's style
  surface has no `direction`, and the layout primitives place children with
  `row`/`column` only, so nothing mirrors for an RTL locale. [Styling](/docs/styling)
  records the rest of the absent CSS surface.

The honest alternative is app-owned: pass your own strings where a component
takes them, and compose mirrored order at the application level. A consumer
who needs a full locale layer should not expect one from the component
packages.
