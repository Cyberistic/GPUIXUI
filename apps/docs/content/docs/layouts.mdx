A layout is a tree of native boxes with flex facts. You own the page frames: there are six layout primitives — `Box`, `Stack`, `Grid`, `Separator`, `Spacer` and `ScrollArea` — and no layout components; five inventory rows, because `Stack` and `Grid` share one.

Rows and statuses come from `COMPONENTS.md`.

The frame repeats: a `Box` for the surface, a `Stack` per axis, `Separator` between regions and `ScrollArea` for the region that grows. The sidebar is `flexShrink: 0` with a fixed width; the content column grows with `minWidth: 0`.

## The runtime's rules

| The runtime has | So |
| --------------- | -- |
| Flexbox and a fixed numeric grid | use `Stack` and `Grid`; no areas or `minmax()` |
| No media queries | a layout change is application state |
| `onLayout` reports a size, not a position | keep positions in app state |
| No `transform`; absolute only inside an overlay | no sliding panels or animated widths |
| A shadow, or a shadow list | the levels each paint one shadow; hierarchy comes from tone and separators |
| No `zIndex` | paint order is source order |
| A scroll container with no height grows | give `ScrollArea` a bounded parent |
| No direction input | RTL is the app's helper; every edge is physical |

Split panes, docking and collapsible sidebars live in `@gpuixui/dock` ([Workspace](/workspace)); the runtime's full matrix is on [Runtime](/runtime).
