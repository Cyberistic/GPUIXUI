## Theme shape

| Field | What it decides |
| ----- | --------------- |
| `colors` | semantic roles: surfaces, text, actions, status, borders, focus |
| `typography` | display, headings, body, label, caption, code and families |
| `spacing` | the spacing scale for gaps and padding |
| `radius` | `sm` through `xl` and `full` |
| `density` | control heights and horizontal padding for `sm`, `md`, `lg` |
| `elevation` | the shadow steps (`sm`, `md`, `lg`) |
| `borderWidth` | thin and strong boundaries |
| `iconSize` | icon sizes paired with each type role |

## Colour roles

| Role | Use |
| ---- | --- |
| `background` | window and application canvas |
| `foreground` | default text |
| `card` | raised content surface |
| `popover` | menus, popovers and dialogs |
| `primary` / `primaryForeground` | primary action and its text |
| `secondary` | secondary action |
| `mutedForeground` | secondary text |
| `accent` | tinted emphasis surface |
| `hover` / `active` / `selected` | pointer, press and chosen-row washes |
| `destructive` | destructive action |
| `border` / `borderStrong` | decorative and essential boundaries |
| `ring` | focus ring |

The full catalogue is [`docs/tokens.md`](https://github.com/Cyberistic/GPUIXUI/blob/master/docs/tokens.md).

## Code colours

A code host paints from the theme's `syntax` table — {syntaxRoles.length} token types from `comment` to `invalid`. `syntaxColors(theme)` answers one colour per role, and `syntaxFailures(theme)` holds each to its floor on the two fills a host paints (<TokenList names={syntaxSurfaces} />): a comment answers {contrastFloors.secondary}:1, a code role {contrastFloors.body}:1.

This site's blocks use the same palette: `apps/docs/src/lib/code-theme.ts` builds both schemes from `syntaxColors(themes[mode])`.

## Override a theme

`createTheme` starts from a built-in mode; `extendTheme` merges into a base without mutating it.

```tsx
import { createTheme } from "@gpuixui/tokens";

export const acmeDark = createTheme({
  mode: "dark",
  name: "Acme",
  colors: {
    primary: "#B49CFF",
    primaryForeground: "#1C1547",
    ring: "#9B8CFF",
  },
  radius: { md: 8 },
  density: "compact",
});
```

Only what changes is written; every other role is inherited.

## Density

`compact` for toolbars and data-dense surfaces; `comfortable` is the default. Density changes control geometry, never type.

## Platform styles

```tsx
import { platformTheme, themes } from "@gpuixui/tokens";

const windows = platformTheme(themes.dark, "win32");
```

A high-contrast base keeps its own colours and takes only geometry and families.

A browser that refuses site storage keeps the URL's choice and the identity, and does not remember the choice.

### Take a platform style

<PlatformStyleSource />

Each tab is the library's own `platformStyles` entry, not a second copy
written for this page. Copy one into your repository, edit any value and apply
it over a base theme; the `label` is yours too. A colour role you delete from
`colors` keeps the base theme's value, and so does an optional table you leave
out (`switch`, `switchMetrics`, `series`, `syntax`); the required fields are what
make the object a style, so the type checker asks for them. The audit you run
before shipping is the same gate the library uses.

### The look picker

<LookPicker />

A **platform style** is one of the four variants of the identity; an **authored
look** is a style applied over one. The picker paints a look over whichever
platform the sidebar switch shows and writes it to the URL (`?look=luna`), so a
link carries the choice and the store remembers it. The sidebar itself offers
the four platform names only, because a look is not a fifth platform.

| Look | `mono` | `radius.md` | Density |
| ---- | ------ | ----------- | ------- |
| `luna` — Windows XP (Luna) | `Lucida Console` | 2 | `compact` |
| `aero` — Windows 7 (Aero) | `Consolas` | 4 | `comfortable` |
| `omarchy` — Omarchy | `JetBrains Mono` | 2 | `compact` |

The UI face stays the runtime's sentinel on all three: the package bundles no
font, so naming Tahoma, Segoe UI or JetBrains Mono as the UI face would silently
fall back on a machine that lacks it. The monospace family is the look's own.

#### What an authored look does not draw

A look is token values — colours, radii, density and the monospace family. It
copies no artwork: no gradient, bitmap, icon, cursor or logo, so there is no
redistributable asset and no trademark in the identity. The runtime could not
paint most of that chrome at all: there is no `backdropFilter` for Aero's glass,
no multi-stop, radial or conic gradient for a title bar, and no CSS `filter`,
`clip-path`, blend mode or per-element `transform` for a glow, reflection or
shaped clip. Two-stop linear gradients and `inset` shadows are available; see
[Runtime](/docs/runtime) for the measured verdicts.

Neither Windows era shipped a dark mode, so the two dark editions are authored
here — invented, not reconstructions. Omarchy's pair is not invented: its dark
set is Tokyo Night and its light set the Flexoki Light reference. All six themes
are held to the same contrast and decorative contracts as every other theme.
Provenance and the palette mapping are recorded in `docs/tokens.md` §Authored
looks and §Omarchy's `colors.toml`.

### Author a style

`platformStyles` and `retroStyles` are ordinary tables — `packages/tokens/src/platforms.ts` and `packages/tokens/src/retro.ts`. Copy one, edit a value, and apply it; a role the style omits keeps the base theme's value.

```tsx
import { applyStyle, themes, type PlatformStyle } from "@gpuixui/tokens";

const acme: PlatformStyle = {
  label: "Acme",
  sans: "sans",
  mono: "Menlo",
  radius: { none: 0, sm: 4, md: 6, lg: 8, xl: 12, full: 9999 },
  density: "compact",
  contrast: "default",
  colors: {
    light: { primary: "#0F5E8C", primaryForeground: "#FFFFFF" },
    dark: { primary: "#4FA9E0", primaryForeground: "#06222F" },
  },
};

const brand = applyStyle(themes.light, acme);
```

`contrast` names the variant the palette was designed for: a base of another variant ignores the style's colours and data series and takes only its geometry and families. Run `auditTheme(brand)` before shipping; `passed` is true only when every report is empty.
