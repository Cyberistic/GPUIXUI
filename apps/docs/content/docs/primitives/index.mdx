Primitives are the bottom layer of the library. Each one owns a single job, is
built directly on a GPUix host element, and reads the theme's semantic roles
instead of a colour. There is no composed behaviour here: a `Select` opens a
GPUix list, a `Checkbox` paints a box and reports a boolean, a `Stack` spaces
children along an axis.

The pages come from the package itself — `packages/primitives/docs` is mounted
at this URL, so the page you read and the file the component ships with are the
same file. They carry the real API tables, the keyboard contract, the roles each
component reads and the measured limitations; they do not carry browser
previews. Run the component natively from `apps/playground` instead.

## How to read a page

Each page follows the same order: what it is, usage, variants and sizes, API,
keyboard, accessibility, theming, limitations, verification and related. A
section that does not apply is omitted rather than faked. Where GPUix lacks a
capability, the page names the gap and the alternative in use — never a promise.

Composed components — dialogs, menus, tabs, pickers — sit in
[Components](/docs/components), one tier up. The status of every row, with its
runtime evidence, lives in the repository's `COMPONENTS.md`.
