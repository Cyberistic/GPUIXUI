Data presentation covers tables, sortable and selectable rows, column
configuration, resizable columns, filtering controls, tree views and key-value
displays. Virtualisation is the interesting case: it is only offered where GPUix
can actually render it, and the pages record the measured behaviour rather than
promising it. The [Performance](/docs/performance) page collects those
measurements into the painted window, its cost model and what has not been
measured.

These will live in `@gpuixui/data-grid`, which is not published yet. They depend
on `@gpuixui/components` and are verified in the native playground before their
inventory row moves to `done`. The [Roadmap](/docs/roadmap) lists every target
and its status.

## Proven today

The package is not published, but the runtime primitives it will compose are
measured. The scenarios below paint a real virtualised table, a real tree and a
real bottom-anchored log list, and hit-test a row and a column divider:

```sh
nub run --filter playground build
nub apps/playground/dist/smoke/run.js --only virtualized-table
```

A `<virtual-list>` retains every row but paints a window of about nine, so the
table's own contract is written against the painted rows. The
[GPUix capabilities](/docs/capabilities) page carries the full matrix, the
measured limits and the provenance of the run.
