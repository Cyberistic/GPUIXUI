title: Runtime capabilities
description: What the pinned GPUix runtime provides, what it does not, and the honest workaround for each gap.
---

The library pins `@gpuix/react` / `@gpuix/native` at **0.11.0**. This page records
what that runtime provides, what it does not, and the strongest honest alternative
for each gap. `@gpuixui/runtime` encodes the same matrix in code — `capabilities`
and `unsupportedFeature` — and its compile-time guards fail the build the moment
the runtime adds a key the matrix claims is absent, so the table below cannot go
stale silently.

## The matrix

| Capability | Status | Workaround |
| ---------- | ------ | ---------- |
| Terminal rendering | Supported | `render(<App />, { terminal: true })`, or set `GPUIX_TERMINAL=1` |
| Headless `Dialog` | Supported | `@gpuix/react/dialog` owns the Escape layer and the Tab trap |
| Tab / Shift+Tab focus | Supported | Default; `preventDefault()` keeps one Tab |
| `transform` | Not supported | Animate motion with `@gpuixui/motion`; static rotation/scale is unsupported |
| Grid span | Not supported | Size the track with `gridTemplateColumns`/`gridTemplateRows` or an explicit width |
| Canvas drawing | Not supported | Render `svg` or compose `div`/`svg` primitives; no retained draw API — a `<canvas>` also tracks no painted bounds (`content-surfaces`) |
| IME composition | Not supported | Compose at the application layer from `onInput`/`onKeyDown` |
| Global shortcut | Not supported | Window-level `onKeyDown`; background hotkeys need a runtime change |
| Tray / menu bar | Not supported | Ship an in-window menu; a system tray needs a runtime change |
| Native view / webview | Not supported | Use `markdown`/`code`/`diff` surfaces |

## Measured in a window

Some limits are not in the matrix above, because the matrix is built from the
runtime's own typings and these were measured by a probe that paints: the type
does not say them, so a reader must not infer them from the table's silence.

| Gap | What a window measured | Use instead |
| --- | ---------------------- | ----------- |
| Sticky positioning | `position: "sticky"` paints nothing — a sticky sample inside its scroller moves by exactly the scroll amount, so it behaves like `relative` (`data-grid-fixed-header`) | put the header **outside** the row scroller as a sibling, and wrap header and rows in one `overflowX` scroller so both move together |
| Floating layer placement | `side="right"` paints the panel one 6px gap off the anchor's right edge and `side="left"` mirrors it; `align="start"` holds the panel's top on the anchor's top; but **`align="center"` ends the panel at the anchor's centre line** rather than centring it, so the panel starts half its height low (`floating-sides`). The headless `floating-placement` scenario drives the `TestRenderer`, and the two can differ | use `side` with `align="start"` when the box matters; for a genuinely centred panel, offset it yourself by half its measured height, as the overlay components do |
| Select option reveal | a list paints in its own layer one 6px gap below the trigger's start edge, takes the focus, opens on the selected row, moves the highlight with the arrows (wrapping past a disabled row), selects on `Enter`, and dismisses on `Escape` (focus returns) or an outside press (`select-lifecycle`). What a keyboard cannot do is **reveal** a row past the list's edge: the runtime sets no max height or overflow and its two scroll-button parts are empty in 0.11.0, so a 40-option list is a 320px scroller the **wheel** moves (`-200`) while twenty `ArrowDown`s leave the offset alone (`fields.runtime.test.tsx`) | cap the surface and make it a scroller (the shipped `Select` caps at 320px); keep a keyboard-critical list short, or use a `Combobox`/`SearchInput` composition where the query narrows it |
| Frozen column | no sticky, so a frozen first column is **composed**: its own vertical scroller beside the grid's, mirrored in both directions through `onScrollChange` → `scrollTo` (a 120px label pane and a 240px grid stay on the same `y` at `-300` and `-600`; the row under the reader keeps its `y`; a press on a frozen cell selects the row for the whole grid; a `deltaX` wheel pans the grid and leaves the column still; a `-10000` wheel clamps both at `-1440`) (`data-grid-frozen-column`) | give each pane its own scroller, mirror offsets through `onScrollChange` and guard the echo with a **ref** (`scrollTo` paints synchronously); pan horizontally on the data pane alone — there is no single-scroller freeze |
| Caret position, selection ranges and code decoration | the arrow keys move the native caret and `getSelectedText()` returns the selected text, but nothing reports *where* the caret is or what range is selected, and `<code>` takes `language`/`showLineNumbers` with no decoration layer (`editor-surface`) | edit in a `<textarea>`, display in `<code>`; a highlighted *editable* surface is not buildable |
| Keyboard focus events | a `Tab` traversal moves the focus without running React's `onFocus`: a tooltip's trigger is focused while its tip stays closed (`tooltip-lifecycle`), and `Tabs` counts `focuses=0` for the same traversal (`tabs-lifecycle`) | read the key event's own `elementId` or `getFocusedElementId`; publish what only focus would reveal as `aria-description` |
| Scroll event payloads | `onScroll` reports the wheel **input**, not the travel — a `-100000` wheel reports `-100000` after the offset moved 200px and clamped — while `onScrollChange` reports the clamped absolute `scrollX`/`scrollY` pair `getScrollOffset` returns (`scroll-lifecycle`) | a scrollbar, a saved position or a follow-the-tail scroller reads `onScrollChange`; `onScroll` is the gesture's own delta |
| Pointer capture | the runtime arms capture on a left press **only** for an element that listens to both `onMouseDown` and `onMouseMove`: the paired sample kept all eight moves and its release 120px outside its box, while a move-only sample got the pre-press move and the sibling received the eight, and the shipped `Slider` followed a drag off its track (`pointer-capture`) | a drag handle, splitter or slider subscribes to **both** `onMouseDown` and `onMouseMove`; a move-only element captures nothing and the element under the pointer resolves the drag |
| Text selection | a **pointer** drag over a selectable `Text` paints the wash and `getSelectedText()` reports the run, `Cmd+C` pastes that run into a field and `clearSelection()` clears it, while a default `Text` paints none (`selection-lifecycle`) | give a selectable line a box that hugs its glyphs (`alignSelf: "start"`) — a press past the last glyph selects nothing; a component may offer "select and copy", but an **initiated** copy has no API (`clipboard-lifecycle`) |
| Inline SVG | `<svg source>` paints, but as **one tint** — the whole markup is masked in `style.color`, so a shape's own `fill` never reaches the frame; five stacked `<svg>` elements each paint their own tint while `<text>` inside the markup paints (`content-surfaces`) | stack one `<svg>` per colour, so a multi-series chart is one element per series; labels can live in the markup |
| Image bytes | `<img>` paints a path, an http(s) URL and a data-URL PNG; a pixel buffer set through `ref.setImagePixels` paints **only from a layout effect** — a passive `useEffect` leaves the element's `img: no src` fallback (`content-surfaces`) | upload pixels before the frame paints (the waveform example's `useLayoutEffect` pattern); a data URL needs no timing |
| Virtualized list | **Two modes.** The children form retains every row and skips only the off-screen build and paint. The **`itemCount`** form (`itemCount` + `estimatedItemHeight` + `windowStart`) mounts only the slice the app renders: 100 000 logical rows with a 60-row window retain just the window (`wrow-60` absent), the estimate positions mounted rows the paint never reached, `onVisibleRange` reports **absolute** indices (`20..27`) but lags the paint by one gesture (the paint had reached `40..46`), a press reports the row's absolute index, and `scrollToItem(90000)` paints `File 90000` at `-90000 × 28` after the app moved its window (`virtual-list-windowed`). In the children form `scrollToItem` reveals a row that was never mounted and fires **no** `onVisibleRange`; changing the row count reports ranges computed against the spliced child list (`1..2`, `0..1`), not the painted rows; and roving focus moves through `renderer.focusElement` (`virtual-tree-lifecycle`). Either way `onVisibleRange` describes the **previous** scroll — rows 13–21 paint while its report still reads `first=0 last=9` (`virtual-list-lifecycle`). Rows **may differ in height**: 400 rows cycling 24 / 48 / 72px each paint their own height and start where the previous ended, `scrollToItem(150)` lands the row at the viewport's top edge from estimates, and growing row 0 by 40px while the reader sits at row 150 leaves the painted rows and the offset untouched — a row outside the window is not remeasured until it paints again (`virtual-list-rows`) | reveal with `scrollToItem`; in `itemCount` mode move the app's `windowStart` **first** and scroll after that commit, since the window is app state native cannot infer. Size the window wider than the viewport plus overdraw (60 rows against 280px) so the one-gesture lag cannot expose empty estimate boxes. Measure an expandable or streamed row while it is **on screen** — one that grows outside the window keeps its old height until it paints again. Read the painted rows or the anchor, not the index; never paginate from `onVisibleRange` across a row-count change; a tree keeps one focus and moves it with `focusElement` |
| Portals (`createPortal`) | a portalled card paints inside its **target's** box and outside an ancestor's clip, keeps the provider context above the caller, receives a pointer press and keys typed in its field, and unpaints when detached (`portal-layer`); `getPaintedText` still lists a clipped sibling's glyphs, and a clip only holds when the clipping box is the child's containing block | prove a clip with a capture rather than the paint report, and give the clipping box `position: "relative"`; a portal moves content within the one window — the binding opens one window per process, so a tab cannot detach into its own |
| Clipboard | the binding has no clipboard read or write, and the keys do not cross the window seam: `cmd-a`/`cmd-c`/`cmd-v`/`cmd-x` reach a focused field's `onChange` — select-all, copy, paste and cut all work — but never reach the app's window handler, while `cmd-k` from the same control does (`clipboard-lifecycle`) | an app-level "copy" action is not buildable; offer the text in a read-only field the user can select and copy from |

The durable record — every host element, every limit, its verdict, its evidence
path and the alternative — is
[`docs/gpuix-capabilities.md`](https://github.com/Cyberistic/GPUIXUI/blob/master/docs/gpuix-capabilities.md).
This page publishes the subset a reader of the docs needs; that document is what
a component plan cites.

## Not in the typings

The matrix above is built from `@gpuixui/runtime`'s own keys. These five are
different: the pinned typings declare neither the host nor the prop, so there is
nothing to pass and no probe to run — a component composes the alternative
instead. `COMPONENTS.md`'s rows rely on each of them.

| Capability | What the pinned typings have instead | Use instead |
| --- | --- | --- |
| Links (`href`) | `ElementType` has no `a`, and `HostProps` declares no `href`; the Breadcrumb, Navigation Menu and Lists inventory rows record the same absence | render a pressable `<text>` (the link-styled button) and show the destination in the copy; there is no visited state, middle-click or pointer cursor |
| Form grouping (`fieldset` / `legend`) | `ElementType` has no `fieldset`; the shipped `Fieldset` is a `role="group"` div with a legend-styled text | compose it from a div and a text; a group-level disabled state is not announced either, because there is no `aria-disabled` |
| Context-menu event (`onContextMenu`) | `HostProps` declares no `onContextMenu`; a right press arrives as `onAuxClick`, which `isRightClick` distinguishes — the shipped `ContextMenu` uses that path, and `context-menu-lifecycle` measured a right press opening the surface at the press point | handle `onAuxClick` and place your own surface at the pointer |
| Paste event (`onPaste`) | `HostProps` declares no `onPaste`; a paste runs inside a focused field and reaches `onChange` with the new value (`clipboard-lifecycle`) | read the pasted text from the new value in `onChange`; there is no paste payload, caret or insert-at-selection API |
| Accessibility attributes | the closed set is `role`, `aria-label`, `aria-description`, `aria-id`, `aria-expanded`, `aria-selected`, `aria-valuetext` and `aria-level` — no checked or pressed state, no `aria-labelledby`, and no `aria-live` | name the control itself, put a numeric value in `aria-valuetext`, and do not present a toast or a countdown as announced |

## What to do instead

The unsupported rows are not decorative placeholders — each has a named gap and a
working alternative.

### `transform`

`StyleDesc` has no `transform`, nor `transformOrigin`, `rotate`, `scale`,
`translate` or `skew`. You cannot statically rotate or scale an element.

```tsx
import { motion } from "@gpuix/react";
import { layoutSpring } from "@gpuixui/motion";
import { useSpring } from "@gpuixui/motion/react";

function Grow({ open }: { open: boolean }) {
  const { value } = useSpring(open ? 100 : 0, layoutSpring);
  return <motion.div animate={{ width: value }} transition={{ duration: 0 }} />;
}
```

`@gpuixui/motion` drives the numeric `MotionStyle` fields the runtime *does* have
— `width`, `height`, `top`, `right`, `bottom`, `left`, `opacity`, `borderRadius`.
Static rotation/scale stays unsupported until the runtime grows a `transform` key.

### Grid span

The grid exposes only `gridColumnMin`/`gridRowMin` and integer
`gridTemplateColumns`/`gridTemplateRows`. `col-span-*` / `row-span-*` /
`grid-area-*` are unrepresentable — `@gpuixui/tw` refuses them by name rather than
dropping them.

Size the track to do the spanning instead of asking an item to cross tracks:

```tsx
<div style={{ display: "grid", gridTemplateColumns: 2, gridTemplateRows: 1 }} />
```

### Canvas drawing

`canvas` is a blank host element — it appears in `ElementType` but has no
2D-context or draw props. Compose the shape from `svg` / `div` primitives, which
are first-class.

### IME composition

No composition events reach the React surface. Compose at the application layer
from `onInput`/`onKeyDown`; live IME preview needs a runtime change.

### Global shortcut

Key events fire only while the window is focused; there is no system-wide hotkey
registration. Bind window-level `onKeyDown` via `render`'s key handlers.
Background hotkeys need a runtime change.

### Tray / menu bar

There is no tray, menu-bar or status-item host. Ship the menu inside the window;
a system tray needs a runtime change.

### Native view / webview

There is no webview or native child-view host. Use the `markdown`/`code`/`diff`
surfaces for rich content; embedded web content needs a runtime change.

## `isTerminal()`

`isTerminal()` is re-exported from `@gpuixui/runtime`. It is `false` until
`init()` runs, so read it while rendering, not at module scope:

```tsx
import { isTerminal } from "@gpuixui/runtime";

// A terminal has no titlebar: drop the macOS traffic-light space.
if (isTerminal()) {
  // …render without the window chrome…
}
```

## Read the matrix from code

```ts
import { capabilities, unsupportedFeature } from "@gpuixui/runtime";

capabilities.transform.supported; // false
capabilities.transform.workaround; // "Animate motion with @gpuixui/motion; …"

const refusal = unsupportedFeature("gridSpan");
// UnsupportedRuntimeFeature { feature: "gridSpan", reason, workaround }
```
