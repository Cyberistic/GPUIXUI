title: Motion
description: Springs, retained values, easing, keyframes, inertia and reduced motion, sampled from a clock you own.
---

GPUix tweens a numeric style field on its own clock. `@gpuixui/motion` adds closed-form springs, retargeting, keyframes, inertia and reduced-motion policy. It is pure: every function samples at an elapsed time you pass in.

| Module | Responsibility |
| ------ | -------------- |
| spring | `springPhysics`, three presets, `sampleSpring`, `atRest`, `retarget` |
| easing | `linear`, `ease`, `easeIn`, `easeOut`, `easeInOut`, `circIn`/`circOut`/`circInOut`, `backIn`/`backOut`/`backInOut`, `anticipate`, `bezier`, `motionCurve` |
| timeline | `keyframe`, `sampleKeyframes`, `stagger`, `Sequence` |
| inertia | `inertia`, `project`, `sampleInertia` |
| value | `MotionValue` with `DEFAULT_TWEEN_MS`, `instant`, `tween`, `springTransition`, `transitionEquals` |
| React | `useSpring`, `useTransition`, `useInertia`, `useMotion`, `useSurfaceTiming`, `useSurfacePresence`, `useMotionPreference`, `MotionProvider` |
| timing | `motionLevels`, `motionEasings`, `motionTiming`, `motionTimingOf`, `preferenceOf`, `reducedMotionOf` |
| presence | `fadeFrom`, `fadeFromSide`, `fadeFromAnchor`, `fadeOnly`, `presenceTiming`, `presenceTimingOf`, `presenceMotion`, `presenceStyle`, `transitionWindowMs`, `exitWindowMs`, `delayedTiming` |

The package publishes six entry points: the root (`spring`, `easing`, `timeline`, `inertia`, `MotionValue`), `@gpuixui/motion/react`, `@gpuixui/motion/react/presence` (the provider and the two presence hooks, published without the physics), `@gpuixui/motion/timing`, `@gpuixui/motion/timeline` and `@gpuixui/motion/presence`.

## House timing

```ts
import { motionTiming } from "@gpuixui/motion";

const enter = motionTiming("normal", { phase: "enter" });
// { duration: 0.2, ease: "easeOut" }
```

| Level | ms | For |
| ----- | -- | --- |
| `step` | 120 | a step indicator's tick |
| `fast` | 160 | a tooltip or indicator |
| `normal` | 200 | a popover, menu, panel or tab pill |
| `slow` | 320 | a dialog or drawer |
| `notice` | 500 | a toast |

`motionTiming` names a level; `motionTimingOf` is the seam for a timing read back from a store — a resumed tween, a saved panel's phase:

```ts
import { motionTimingOf } from "@gpuixui/motion/timing";

motionTimingOf(220, { phase: "enter" }); // { duration: 0.22, ease: "easeOut" }
motionTimingOf(220); // { duration: 0.22, ease: "easeInOut" }
motionTimingOf(Number.NaN); // the house 200 ms, `easeInOut`
```

A duration that is not positive and finite — or one past the clock the renderer schedules (`1e300` ms) — is the house surface arrival (`motionLevels.normal`) rather than a `NaN` on the runtime, and the options object is a config as often as a literal: `null` is the house timing, a phase it does not name is `standard`, and a preference is read by the policy in **Reduced motion**.

## Springs

A spring is sampled at an elapsed time you pass — the package owns no clock, so a resumed panel is read at the frame it was saved at. `sampleSpring(physics, from, target, velocity, elapsedMs)` answers `{ value, velocity, target, settled }`; a sample inside the physics' rest thresholds (`restDelta` `0.001`, `restSpeed` `0.01`) is the target, with zero velocity and `settled: true`.

```ts
import { layoutSpring, retarget, sampleSpring } from "@gpuixui/motion";

const mid = sampleSpring(layoutSpring, 0, 100, 0, 80); // 39.7 at 80 ms, still moving
const next = retarget(mid, 200); // the same value and velocity, toward 200
sampleSpring(layoutSpring, 0, 100, 0, 2000).settled; // true — at rest
```

`retarget` is how a running spring changes its mind: it carries the sampled value and velocity into a new run, so sample the new run at `0` to continue from that frame. The presets are `affordanceSpring`, `layoutSpring` (collapse, expand, insert, remove) and `continuitySpring` (a retargeted pane, divider or zoom); `atRest(physics, value, target, velocity)` is the threshold rule on its own, for a driver that keeps its own state.

A physics and a sample are caller data as often as literals, so the samplers repair what they are handed: a field that cannot be read takes the house default (`springPhysics({})` — stiffness `260`, damping `28`, mass `1`), a declaration carrying no physics at all is that same house spring, and `retarget(null, 2)` is a run from `0` toward `2` rather than a `TypeError` in the render that resumed it.

## Curves

The timing table hands the runtime a **name**; a movement this package samples needs a function. `motionCurve(name)` resolves the same name to the same curve, so the two halves of one transition trace one path:

```ts
import { motionCurve } from "@gpuixui/motion";

motionCurve("easeOut")(0.5); // 0.6846 — cubic-bezier(0, 0, 0.58, 1), the renderer's default
motionCurve("ease")(0.5); // 0.8024 — cubic-bezier(0.25, 0.1, 0.25, 1)
```

The five names are the binding's own curves, not cubic polynomials that share their labels — a lookalike paints `0.875` at the midpoint where the runtime paints `0.685`, so a number counted beside a tweened box would run at a different speed from the box. `linear` is the progress itself, the one curve a control-point pair cannot describe, and `bezier(x1, y1, x2, y2)` is the same cubic for your own control points. A name this release does not carry is the linear progress as well: the runtime rejects a description naming an easing it does not know, so there is no curve to imitate.

## Keyframes

```ts
import { keyframe, sampleKeyframes, Sequence, stagger } from "@gpuixui/motion";

const journey = [keyframe(1, 40), keyframe(0, 0), keyframe(0.5, 100)];
sampleKeyframes(journey, 0.25); // 50 — read by offset, not declaration order
sampleKeyframes(journey, 0.75); // 70

stagger(40, 2, 4); // 80 ms — the third of four, from the start
stagger(40, 0, 4, "end"); // 120 ms — the first of four from the end

const sequence = new Sequence<string>().at("title", 0, 120).append("body", 180);
sequence.duration(); // 300
```

`keyframe(at, value, easing?)` is a stop at normalized progress, and a segment takes the easing of the stop it ends at. The set is read as stops, not as the order it was declared — a caller building frames from a map hands them over in whatever order the source iterates — and two frames at one offset are an instant jump, the value declared last at it holding from that offset on. A stored timeline whose list never decoded, or an entry that is not a frame, is no stop: a set with none paints `0`.

`stagger(stepMs, index, count, from)` spaces a group from `start` (the house), `end` or `center`; an out-of-range index or an empty group answers `0`, as does a step that is not a wait.

`Sequence` places keyed steps at absolute elapsed time and samples them all from one clock: `at(key, startMs, durationMs, easing?)` and `append(key, durationMs, easing?)` place them, `stagger(keys, startMs, stepMs, durationMs)` places a group, and `sample`/`complete` read the clock the same way — a clock before the sequence is its start and a duration a step cannot run ends it at its start, so the two entry points cannot disagree about the end.

## Inertia

```ts
import { inertia, project, sampleInertia } from "@gpuixui/motion";

const coast = inertia(); // the house 350 ms time constant, no bounds
project(coast, 0, 600); // 210 — where the release comes to rest
sampleInertia(coast, 0, 600, 350).value; // 132.7 after one time constant

project(inertia(350, { max: 100 }), 0, 600); // 100 — a wall is the rest
```

The rest a release projects is `position + velocity × tau`, clamped to its bounds; `sampleInertia` decelerates toward it and reports `settled` once the speed reaches `0.001`. A bound is a wall the coast stops at only while it moves into it — a surface released *on* a wall with its velocity pointing back into the range is at the start of a journey, not the end of one, so it travels inward instead of being reported settled at the far rest.

An `Inertia` is structural too: a time constant that cannot run, or one past the seconds a clock can name (`1e300` is a 1e297-second coast whose decay never starts), takes the house 350 ms, an inverted bound pair is swapped, an unreadable position or velocity is a standstill, and a declaration carrying no object at all is the house coast. A rest the arithmetic cannot represent has no frame to paint: the coast lands on the nearest finite destination — a wall in the direction it was thrown, else the frame it was released from.

## Values

`MotionValue` retains one scalar and samples it at the elapsed time you pass, so a resumed panel is read at the frame it was saved at and no timer lives in the value:

```ts
import { linear, MotionValue, tween } from "@gpuixui/motion";

const value = new MotionValue(0);
value.animate(100, tween(200, linear));
value.sample(100); // 50 — still running
value.sample(200); // 100 — the completing frame
```

`animate(target, transition)` retargets from the frame on screen, and a repeated declaration is a no-op so a re-render cannot restart the run. `set(value)` assigns at once and retires the declaration, and `coast(inertia, velocity?)` releases the retained velocity — or the one you pass — through `sampleInertia`. `sample(elapsedMs, reducedMotion?)` advances the run and returns `{ value, velocity, active, complete }`; `complete` is a one-shot edge on the frame that finishes the run, and a reduced sample finishes at the target immediately.

`tween(durationMs?, easing?)` names the house `DEFAULT_TWEEN_MS` (`300`) and `easeOut` when you name neither. A duration that cannot run — `NaN`, an infinity, or a value past `Number.MAX_SAFE_INTEGER` (about 285 000 years) — is the house duration, because its frames would stay finite and the run would never complete; a zero or negative duration is an instant assignment, and a large duration the clock can still name is kept. `springTransition(physics)` builds the same declaration from a spring, and `transitionEquals(left, right)` compares two declarations by the run they sample — the duration a tween actually uses and the physics a spring actually reads — so a repaired field does not restart a value. A declaration a store handed over without a run at all is the house tween, the rule every other structural config in the package follows.

## Reduced motion

```tsx
import { MotionProvider } from "@gpuixui/motion/react";

<MotionProvider preference={reduceMotion ? "reduced" : "animated"}>
  <App />
</MotionProvider>;
```

The preference is a setting your application persists, so the provider decodes what it is handed through `preferenceOf` from `@gpuixui/motion/timing` instead of trusting the union:

- `"reduced"` and `"animated"` are the only two names read as themselves.
- An absent value — `null` or `undefined`, the shape a database column has when the setting was never written — is the house `"animated"`, which is what a tree that states no preference has always moved with.
- A value that is present and is not one of those names — a renamed setting, an old release's string — takes `"reduced"`. The two mistakes are not equal: animating a reader who asked for less motion is the failure the policy exists to prevent, while a lost journey the application can see is one a developer fixes.

The provider is the default for **every** hook below it, the physics hooks included: `useMotion`, `useSpring`, `useTransition` and `useInertia` read it, so a tree wrapped for a reader who asked for less motion does not count up, tween a width or release a coast unless a caller overrides it. `options.reducedMotion` is the per-run override and wins in both directions — a decorative animation can be silenced in an animated tree, and one that must move keeps moving in a reduced one — and `reducedMotionOf(override, preference)` is the rule, so a package composing the table does not re-decide what less motion means.

A reduced run is a zero-duration assignment.

## Presence

A surface that leaves keeps a frame mounted while it fades, and a box that is still painted must not take a press. `@gpuixui/motion/presence` owns the three frames, the enter and exit timing, and the window's conversion; the **mounted window** itself is a timer, so it belongs to the React entry — `useSurfacePresence` keeps a leaving box painted and `useSurfaceTiming` pairs the level with the provider's preference. Both hooks, and the provider, are published on `@gpuixui/motion/react/presence` — the presence half of the React entry — so a surface that only enters and leaves does not load the spring, inertia and timeline samplers a fade never samples; `@gpuixui/motion/react` re-exports that half for a consumer that also drives a spring. A dialog, a popover and a reveal therefore agree about the journey.

```ts
import {
  exitWindowMs,
  fadeFromSide,
  presenceStyle,
  presenceTiming,
} from "@gpuixui/motion/presence";
import {
  useSurfacePresence,
  useSurfaceTiming,
} from "@gpuixui/motion/react/presence";

const frames = fadeFromSide("top", 8); // initial, animate and exit
const timing = presenceTiming("normal"); // enter and exit transitions
const held = exitWindowMs(timing); // 200 — the exit window, in ms
const rule = presenceStyle(false, "target"); // { pointerEvents: "none" }

const surfaceTiming = useSurfaceTiming("normal"); // the provider's preference
const presence = useSurfacePresence(open, surfaceTiming);
if (!presence.mounted) return null; // render until the exit has run
```

`presenceMotion(frames, present, timing)` returns the `motion` prop the surface paints. `presenceStyle(present, rest)` takes the pointer rule: `"target"` for an overlay, which blocks the pointer behind it, and `"wrapper"` for a reveal, which paints no surface of its own and so paints nothing at rest.

A timing read back from storage goes through `presenceTimingOf`: a record that lost a phase reads as no transition for that phase, so a surface closes at once instead of throwing on a run that is not there.

| Frames | Shape |
| ------ | ----- |
| `fadeOnly` | opacity only, for a box that must not move |
| `fadeFrom(axis, offset)` | fades and travels `offset` pixels along `top` or `left` |
| `fadeFromSide(side, offset)` | arrives from a window edge |
| `fadeFromAnchor(side, offset)` | travels out from the trigger's own edge |

**A wait rides with a journey that actually runs.** `delayedTiming(timing, delayMs)` adds a stagger's wait to a transition, but the runtime sits the wait out *before* it starts the tween — so a wait kept beside a journey that cannot travel holds the box at its first frame for exactly the wait the reader removed. The wait is therefore dropped for every no-journey shape: a duration that is absent, one the arithmetic cannot read (`NaN`), one that is not positive — the zero a reduced run takes — and one whose seconds overflow the millisecond conversion. A wait that cannot be scheduled itself (negative, zero, `NaN`, infinite) adds nothing, and a run with no wait keeps the object it was handed.

## Limitations

- **No `transform`**: scale, rotate and translate have no style key.
- **A value, not a graph**: a colour or multi-property timeline is several values you compose.
- **No scheduler**: values advance only when sampled; the hooks sample every 16 ms.
