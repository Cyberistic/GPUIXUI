---
title: Styling and recipes
description: How a class string becomes a GPUix style, and how to extend the rules.
---

A GPUix element takes a flat `StyleDesc`, not CSS. Components hold their appearance as class-string recipes, and `@gpuixui/tw` compiles a string against the theme.

```tsx
import { BUTTON_BASE, BUTTON_SIZES, BUTTON_VARIANTS, cn, classesToStyle } from "@gpuixui/tw";
import { useTheme } from "@gpuixui/tokens/react";

const theme = useTheme();
const recipe = cn(BUTTON_BASE, BUTTON_VARIANTS[variant], BUTTON_SIZES[size], className);
const { style, focus, invalid, disabled } = classesToStyle(recipe, theme);
```

A later class wins; a component passes your `className` last and merges `style` after the compiled result.

## Two registries

| Registry | Compiles against | Who uses it |
| -------- | ---------------- | ----------- |
| the default registry | fixed metrics — `h-9` is 36, `px-3` is 12, `text-sm` is 14/20 | `@gpuixui/components` |
| `recipeTw` | the theme's named steps — `h-md` is the density height, `gap-sm` the spacing scale, `type-body` a type role | `@gpuixui/primitives` |

## The default registry

| Class | Resolves to |
| ----- | ----------- |
| `h-9` | `height: 36` |
| `px-3` | `paddingLeft`/`paddingRight: 12` |
| `gap-2` | `gap: 8` |
| `rounded-lg` | `borderRadius: 8` |
| `border` | `borderWidth: 1` |
| `border-input` | the `border` role |
| `border-strong` | the 3:1 boundary role |
| `bg-card` | the `card` role |
| `text-foreground` | the `foreground` role |
| `bg-primary/90` | the `primary` role at 90% alpha |
| `shadow-md` | the theme's `md` elevation |
| `grid-cols-3` | `gridTemplateColumns: 3` |

## States

A token lands in a resting property, a `hover`/`active` nesting, or one of the `focus`/`invalid`/`disabled`/`open`/`closed` state styles.
