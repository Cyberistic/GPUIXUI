title: Styling and recipes
description: How a class string becomes a GPUix style, and how to extend the rules.

A GPUix element takes a flat `StyleDesc`, not CSS. Components hold their appearance as class-string recipes, and `@gpuixui/tw` compiles a string against the theme.

```tsx
import { BUTTON_BASE, BUTTON_SIZES, BUTTON_VARIANTS, cn, classesToStyle } from "@gpuixui/tw";
import { useTheme } from "@gpuixui/tokens/react";

const theme = useTheme();
const recipe = cn(BUTTON_BASE, BUTTON_VARIANTS[variant], BUTTON_SIZES[size], className);
const { style, focus, invalid, disabled } = classesToStyle(recipe, theme);
```

A later class wins; a component passes your `className` last and merges `style` after the compiled result.

## Two registries

| Registry | Compiles against | Who uses it |
| -------- | ---------------- | ----------- |
| the default registry | the theme's density steps — `h-9` is the `md` control height, `px-3` is 12, `text-sm` is 14/20 | `@gpuixui/components` |
| `recipeTw` | the theme's named steps — `h-md` is the density height, `gap-sm` the spacing scale, `type-body` a type role | `@gpuixui/primitives` |

## The default registry

| Class | Resolves to |
| ----- | ----------- |
| `h-9` | `height: density.controlHeight.md` — 32 at the default, 28 compact, 36 spacious |
| `px-3` | `paddingLeft`/`paddingRight: 12` |
| `gap-2` | `gap: 8` |
| `rounded-lg` | `borderRadius: theme.radius.lg` — 8 at the default, 14 on macOS, 12 on Linux |
| `border` | `borderWidth: 1` |
| `border-input` | the `border` role |
| `border-strong` | the 3:1 boundary role |
| `bg-card` | the `card` role |
| `text-foreground` | the `foreground` role |
| `bg-primary/90` | the `primary` role at 90% alpha |
| `shadow-md` | the theme's `md` elevation |
| `grid-cols-3` | `gridTemplateColumns: 3` |

The three shadcn control heights map to the density scale's `sm`/`md`/`lg`, so `h-8`, `h-9` and `h-10` resolve to the active theme's control heights rather than Tailwind's fixed 32/36/40 — the platform switch resizes a control instead of pinning it.

## States

A token lands in a resting property, a `hover`/`active` nesting, or one of the `focus`/`invalid`/`disabled`/`open`/`closed` state styles.

## Your own utilities

`createTw` binds the compiler to a registry you extend; the built-in table stays underneath, so a class you do not override resolves exactly as before.

```ts
import { createTw } from "@gpuixui/tw";
import { brandText } from "@gpuixui/tokens";

const tw = createTw({
  utilities: {
    // `text-brand` paints the brand where it clears the contrast floor.
    "text-brand": (theme) => ({ color: brandText(theme) }),
  },
});

const { style } = tw.classesToStyle("text-brand", theme);
tw.unsupportedReason("rotate-45"); // GPUix `StyleDesc` has no `transform` …
```

`TwRegistryConfig` carries the four extension points: `utilities`, `variants`, `aliases` and `unsupported`. A class the renderer cannot paint is refused by name — `unsupportedReason` returns the gap and its workaround — rather than compiled to nothing.

## React wrappers and the JSX runtime

The root entry is renderer-free. `@gpuixui/tw/react` adds the class-aware hosts and the registry context:

```tsx
import { Tw, TwProvider } from "@gpuixui/tw/react";

<TwProvider registry={tw.registry}>
  <Tw.div className="bg-card rounded-lg p-md">
    <Tw.text className="text-foreground type-body">Settings</Tw.text>
  </Tw.div>
</TwProvider>;
```

Or point the compiler's JSX runtime at the package and keep shadcn host elements as written:

```json
{ "compilerOptions": { "jsxImportSource": "@gpuixui/tw" } }
```

```tsx
<div className="bg-card rounded-lg p-md" />;
```

Both paths resolve the class string against the nearest theme and registry, and merge your explicit `style` last. `Tw.div`, `Tw.text` and `Tw.input` are the three hosts; each takes `className`, the state props a class can target, and `style`.
