GPUIXUI is consumed inside a [GPUix](https://github.com/remorses/gpuix)
application. GPUix renders with GPUI; install and pin it exactly as its own
documentation describes before adding the component packages.

## Prerequisites

GPUIXUI runs inside a GPUix application, so install and pin GPUix first. A
clean checkout of this repository also needs the following. The versions are
the ones the workspace pins, and a test fails when this table and the manifests
disagree.

| Requirement | Pinned version | Why |
| ----------- | -------------- | --- |
| Node.js | `24.18.0` | `.node-version`; `engines.node` in the root `package.json` |
| nub | `^0.9.6` | `devEngines.packageManager`; every command in this repository runs through it |
| GPUix | `0.10.0` | `@gpuix/react` and `@gpuix/native` are pinned together in the workspace catalog |
| A desktop session | — | a native GPUix window needs one; `check-types` and the unit suites run headless |

## Native bindings

`@gpuix/native` ships a prebuilt binary for macOS on Apple silicon
(`aarch64-apple-darwin`, arm64), Linux x64 (`x86_64-unknown-linux-gnu`) and
Windows x64 (`x86_64-pc-windows-msvc`). A platform without one installs the
JavaScript package but cannot create a window.

<NativePlatforms />

GPUix **0.10.0 publishes no Intel Mac (`x86_64-apple-darwin`) binary**. This
repository builds the identical 0.10.0 source on that host with `gpui_macos`'s
`runtime_shaders` feature:

```sh
sh apps/playground/scripts/build-native-binding.sh
```

The script installs the pinned Rust toolchain, builds the cdylib and places
`gpuix-native.darwin-x64.node` under `node_modules/@gpuix/native/`. It is the
same repository remedy the playground's native suite documents; the shipped
package's provenance and the measured result are on [GPUix
capabilities](/docs/capabilities) and [Native smoke
suite](/docs/native-testing). A published-binary run on CI remains the gold
standard.

## Packages are not published yet

The workspace is under construction and the packages are **not on a registry
yet**. The install commands below are the intended shape; until the first
release they will not resolve. The packages are built from this repository:

```sh
nub install
nub run --filter @gpuixui/basic-app dev
```

`basic-app` is the example that composes the Tier 1 components. Its `dev`
script currently runs `bun src/main.tsx`, so the command needs Bun, the GPUix
native binding and a desktop session;
`nub run --filter @gpuixui/basic-app check-types` is the check that runs
without a window. [Examples](/docs/examples) records what it verifies.

## The intended install

```sh
# the native runtime and its React adapter, pinned together
nub add --exact @gpuix/react @gpuix/native react

# the library, plus the package that owns the theme provider
nub add @gpuixui/tokens @gpuixui/primitives @gpuixui/components
```

Pin `@gpuix/react` and `@gpuix/native` to the **same exact version**. GPUix is
pre-1.0, so a release can break either package and the adapter's version range
can install a newer native binary.

`@gpuixui/tokens` is declared directly because its React provider is part of the
public API: primitives mount `ThemeProvider` from `@gpuixui/primitives`, and
components read the context from `@gpuixui/tokens/react`. A mixed app mounts
both, tokens outside primitives; [Getting started](/docs/getting-started) shows
the nesting, and [Theming](/docs/theming) explains the roles it carries.

## TypeScript

GPUix requires its JSX types. Without `jsxImportSource`, TypeScript uses DOM
types and the native host elements fail to type-check:

```json title="tsconfig.json"
{
  "compilerOptions": {
    "jsx": "react-jsx",
    "jsxImportSource": "@gpuix/react",
    "strict": true
  }
}
```
