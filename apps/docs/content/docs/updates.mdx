`@gpuix/native` implements a **signed update client** in its Node entry. It is
not a component and not part of `@gpuix/react`: an application calls it beside
the window, decides what UI to show, and owns the quit that finishes the
install. This page is that contract, and the boundary of what exists.

The library supplies the surfaces around it — [Confirmation
dialogs](/docs/components/confirm-dialog) for the decision, [Progress](/docs/components/progress)
while it downloads, [Toasts](/docs/components/toast) for the outcome.

## What the runtime ships

`checkUpdate(currentVersion, options)` asks the feed; `downloadAndInstall()`
replaces the app. Every member below is checked against the installed
declarations, so a dependency upgrade fails the docs suite by name rather than
leaving this page guessing.

<UpdaterTables />

`checkUpdate` resolves `null` — not an error — when the feed answers `204` or
when the version it announces is not newer. A request that fails rejects; the
app decides whether that is worth telling the reader about, because the runtime
does not distinguish "offline" from "up to date". The signature is checked when
the bundle is downloaded and installed, not when the check runs.

## Check, confirm, install

A real workflow: check once at startup, ask before replacing anything, then
toast the outcome. The dialog is the library's own; the update call is the
runtime's.

```tsx
import { useEffect, useState } from "react";
import { checkUpdate, type AvailableUpdate } from "@gpuix/native";
import {
  ToastProvider,
  ToastViewport,
  useToast,
} from "@gpuixui/components/toast";
import { ConfirmDialog } from "@gpuixui/components/confirm-dialog";

const FEED = "https://updates.example.com/{{target}}/{{arch}}/{{current_version}}";

export function UpdatePrompt({
  currentVersion,
  pubkey,
}: {
  readonly currentVersion: string;
  readonly pubkey: string;
}) {
  const toast = useToast();
  const [update, setUpdate] = useState<AvailableUpdate | null>(null);
  const [installing, setInstalling] = useState(false);

  useEffect(() => {
    let live = true;
    checkUpdate(currentVersion, { endpoints: [FEED], pubkey }).then(
      (available) => {
        if (live) setUpdate(available);
      },
      () => {
        if (live) setUpdate(null);
      },
    );
    return () => {
      live = false;
    };
  }, [currentVersion, pubkey]);

  const install = () => {
    if (update === null) return;
    setInstalling(true);
    update.downloadAndInstall().then(
      () => {
        setInstalling(false);
        setUpdate(null);
        toast.push({
          title: "Update installed",
          description: "Quit and reopen to run the new version.",
          tone: "success",
        });
      },
      () => {
        // The download or its signature failed; nothing was replaced.
        setInstalling(false);
        toast.push({
          title: "Update failed",
          description: "The download was refused. The running app is unchanged.",
          tone: "danger",
        });
      },
    );
  };

  return (
    <ConfirmDialog
      open={update !== null}
      onOpenChange={(open) => {
        if (!open) setUpdate(null);
      }}
      title={`Install ${update?.version ?? "the update"}?`}
      description="The download is signature-checked before it replaces the app. It does not relaunch."
      confirmLabel="Download and install"
      loading={installing}
      onConfirm={install}
    />
  );
}

export const App = () => (
  <ToastProvider>
    <UpdatePrompt currentVersion="1.4.0" pubkey="<public key>" />
    <ToastViewport />
  </ToastProvider>
);
```

The endpoint is a **feed template**: `{{target}}`, `{{arch}}` and
`{{current_version}}` are filled in before the request. `pubkey` is the public
half of the signing key the bundles are signed with — the same key
`cargo packager signer generate` produces. A bundle whose signature does not
verify is not installed.

`downloadAndInstall()` writes the new files over the running app and returns. It
does **not** relaunch, and the example deliberately does not quit for the reader:
an application that wants the new version to run immediately quits after the
promise resolves. The two callbacks are the two real outcomes — a verified bundle
that replaced the files, or a rejected download that changed nothing.

## What the library does not provide

<UpdaterAbsences />

The runtime owns the protocol; everything above the protocol is ordinary
application code. A component that shipped its own updater would have to own a
feed URL, a signing key and a quit policy, which are decisions no library can
make for its consumer.

## What is not verified

**No packaged application is built, signed or run in this repository.** There is
no `.app` bundle, installer project or hosted feed, so:

- the four packager formats and `installMode` are **declared, never executed**;
- signature verification has **no measured evidence** on this site;
- the interaction between a replaced bundle and a running window is
  **untested**;
- the check has never run against a real feed.

The page is derived from `@gpuix/native@0.10.0`'s installed declarations, and
`src/updater.test.ts` re-reads them on every run. A reader who packages an
application with these APIs is the first to exercise them — if that produces a
contradiction, the page is wrong and should be corrected with the evidence.
