GPUIXUI is a TypeScript-first monorepo. Dependencies point one way:

```
tokens → primitives → components → data-grid · docking · editor
```

- `@gpuixui/tokens` — colour, spacing, typography, radii and density roles.
- `@gpuixui/primitives` — foundational parts (layout, text, buttons, inputs).
- `@gpuixui/components` — composition and feedback components.
- `@gpuixui/data-grid`, `@gpuixui/docking`, `@gpuixui/editor` — specialised
  packages built on the components.

No package is on a registry yet. The [component index](/docs/components) records
what exists and what is still planned, so this page never has to claim that a
package is further along than it is.

The native runtime never depends on this documentation site. The full document
will live at `docs/architecture.md` in the repository; it is registered as a
Phase A/B deliverable in `docs/README.md` and is not written yet.

## Preview strategy

The library renders through GPUix; this site is a browser app. Rather than fake
a native surface, every preview is one of:

1. a **real native run** in the playground, named per component when a screen
   exists;
2. a **real screenshot** captured from the GPUix runtime;
3. **native coverage** by an automated suite, naming the suite and its command;
4. a **browser approximation**, always labelled "not GPUix";
5. **source and a limitation notice** when the runtime cannot do something.

Today the delivered pages use native coverage, and four carry a labelled
approximation; no per-component playground screen exists yet. The decision, its
evidence and the exact label text are recorded in `docs/preview-strategy.md` in
the repository.
