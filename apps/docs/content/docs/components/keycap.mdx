`KeyboardShortcuts` displays shortcuts; it does not bind them. A row is
documentation, so it has no click handler and no key registration. The chord
grammar and platform glyphs are one pure module that the
[hotkey recorder](/docs/components/hotkey-input) also uses.

## Usage

```tsx
import {
  KeyboardShortcut,
  KeyboardShortcuts,
  KeyboardShortcutsGroup,
} from "@gpuixui/components";

<KeyboardShortcuts label="Editor shortcuts">
  <KeyboardShortcutsGroup label="File">
    <KeyboardShortcut label="New file" accelerator="mod+n" />
    <KeyboardShortcut label="Save" accelerator="mod+s" />
  </KeyboardShortcutsGroup>
</KeyboardShortcuts>;
```

## Variants

None. `platform` on a row renders another platform's glyphs
(`"darwin" | "linux" | "win32" | "default"`); the default is the host platform.

## Sizes

None. Keycaps use the `caption` type role, `radius.sm` and the theme's spacing.

## States

None. The display is static; a `style` callback receives
`{ keys }` for a chord and `{ label }` for a keycap.

## Keyboard and focus

None. Rows and keycaps are not focusable and no action fires. A shortcut row
documents a chord; binding it is the application's job.

The accelerator grammar is `+`-separated, case-insensitive and trimmed:
`mod` is Command on macOS and Control elsewhere; `shift+mod+k` preserves the
declared order as `⇧ ⌘ K`; unknown multi-character tokens display verbatim.

## Theming

Keycaps use `muted` / `mutedForeground`, the `border` edge, `radius.sm` and
`caption` type. Rows use `foreground` and the theme's spacing; separators are
`border`-coloured 1px elements.

## Accessibility and limitations

- The root is a named `list`; every shortcut is a `listitem`; each group is a
  named `group` with a level-3 heading.
- Keycaps are text, so a screen reader reads the chord's glyphs in order — "⌘ N"
  on macOS, "Ctrl N" on Windows.
- 0.10.0 has no `aria-keyshortcuts`, so a keycap cannot be attached to the
  control it activates.
- **Display-only:** no handler is registered and no action fires.
- Rows are separated by 1px elements rather than borders, because one element
  has one `borderColor` and per-side widths only.
