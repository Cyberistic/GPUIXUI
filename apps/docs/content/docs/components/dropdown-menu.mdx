## Usage

```tsx
import {
  DropdownMenu,
  DropdownMenuContent,
  DropdownMenuItem,
  DropdownMenuSeparator,
  DropdownMenuTrigger,
} from "@gpuixui/components/dropdown-menu";

<DropdownMenu>
  <DropdownMenuTrigger variant="secondary" size="sm">
    Actions
  </DropdownMenuTrigger>
  <DropdownMenuContent label="File actions" align="end">
    <DropdownMenuItem onSelect={() => rename(file)}>Rename</DropdownMenuItem>
    <DropdownMenuItem disabled>Duplicate</DropdownMenuItem>
    <DropdownMenuSeparator />
    <DropdownMenuItem tone="destructive" onSelect={() => remove(file)}>
      Delete
    </DropdownMenuItem>
  </DropdownMenuContent>
</DropdownMenu>;
```

## Limitations

- `role="menu"` names the surface; rows are `menuitem` or `menuitemcheckbox`, the
  trigger carries `aria-expanded`, and one level of submenus is tested.
- **No `aria-haspopup`, `aria-controls`, `aria-checked` or `aria-activedescendant`** in `@gpuix/native@0.11.0` — `HostProps` publishes only `aria-label`, `aria-description`, `aria-expanded`, `aria-selected`, `aria-valuetext` and `aria-level`.
- **A dismissed menu is a ghost, not a target.** The surface stays painted for
  its **200 ms** exit and the seam's shield takes the presses, while every row
  inside it leaves the window's Tab order for that window: the runtime decides
  the order element by element, so the row drops its own stop. The trigger keeps
  its own; a control you compose inside the surface keeps its stop until the
  runtime publishes an inherited `inert`.

## Theming

The surface paints the theme's `elevation.lg` beside its 1px `foreground` ring,
so a brand's lift and edge both show. Its corner is the recipe's fixed **24px**
(`rounded-3xl`): the platform switch repaints the roles and leaves the corner
alone, while the preview follows the platform radius. The preview is the
approximation; the shipped box is the fixed one.
