## Usage

```tsx
import {
  ContextMenu,
  ContextMenuCheckboxItem,
  ContextMenuContent,
  ContextMenuItem,
  ContextMenuSeparator,
  ContextMenuSub,
  ContextMenuSubContent,
  ContextMenuSubTrigger,
  ContextMenuTrigger,
} from "@gpuixui/components/context-menu";

<ContextMenu>
  <ContextMenuTrigger>
    <text>release-notes.md</text>
  </ContextMenuTrigger>
  <ContextMenuContent label="Project actions">
    <ContextMenuItem onSelect={open}>Open</ContextMenuItem>
    <ContextMenuItem onSelect={rename}>Rename</ContextMenuItem>
    <ContextMenuItem disabled>Move to trash</ContextMenuItem>
    <ContextMenuSub>
      <ContextMenuSubTrigger>Share</ContextMenuSubTrigger>
      <ContextMenuSubContent label="Share">
        <ContextMenuItem onSelect={copyLink}>Copy link</ContextMenuItem>
        <ContextMenuItem onSelect={email}>Email</ContextMenuItem>
      </ContextMenuSubContent>
    </ContextMenuSub>
    <ContextMenuSeparator />
    <ContextMenuCheckboxItem
      checked={showHidden}
      onCheckedChange={setShowHidden}
    >
      Show hidden files
    </ContextMenuCheckboxItem>
  </ContextMenuContent>
</ContextMenu>;
```

## Pointer and keyboard

The pointer follows Base UI's menu rules: **hovering a submenu trigger opens it
after a 100 ms rest**, and the submenu closes 80 ms after the pointer leaves it,
so a diagonal trip from the row into the second level keeps it open. A pointer
that reaches a row which is not that submenu's trigger closes it at once, and one
that leaves the menu and every submenu closes the whole menu. A disabled trigger
opens nothing. Moving from the submenu back onto its trigger keeps it open.

The keyboard is the same set of rules: `ArrowDown`/`ArrowUp` move the highlight
and skip disabled rows, `Home`/`End` go to the ends, a typed prefix (500 ms
window) jumps to the row that starts with it, `Enter` acts on the press and
`Space` on the release, `ArrowRight` opens a submenu and `ArrowLeft` closes it,
and `Escape` closes only the innermost layer.

## API reference

### `ContextMenu`

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `open` | `boolean` | uncontrolled | controlled open state |
| `defaultOpen` | `boolean` | `false` | the initial state when uncontrolled |
| `onOpenChange` | `(open: boolean, details: { reason }) => void` | none | reports the next state and why it changed: `trigger-press`, `item-press`, `escape-key`, `outside-press`, `focus-out` or `pointer-leave`; a controlled menu waits for the caller |
| `children` | parts | none | `ContextMenuTrigger` and `ContextMenuContent` |

### `ContextMenuTrigger`

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `disabled` | `boolean` | `false` | no aux click, no `Shift+F10`, out of the tab order, dimmed |
| `children` | nodes | none | the area the reader presses |
| `style` | host style | none | merged last over the card-like box |

### `ContextMenuContent`

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `label` | `string` | `"Context menu"` | the surface's accessible name |
| `children` | parts | none | rows, groups, labels, separators and submenus |
| `className` | `string` | none | compiled through `@gpuixui/tw` and joined after the recipe |
| `style` | host style | none | merged last on the surface |

### `ContextMenuItem` and `ContextMenuCheckboxItem`

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `onSelect` | `() => void` | none | runs once when the row is activated |
| `disabled` | `boolean` | `false` | skipped by arrows and type-ahead; paints the measured disabled pair |
| `tone` | `"default" \| "destructive"` | `"default"` — a stored name the union does not carry | a destructive row paints the status tone's readable role |
| `leading` / `trailing` | `ReactNode` | none | slots before and after the label |
| `textValue` | `string` | the label | the text type-ahead searches |
| `closeOnSelect` | `boolean` | `true` | whether activation closes the menu |
| `checked` | `boolean` | none | the checkbox row's state (required on `ContextMenuCheckboxItem`) |
| `onCheckedChange` | `(checked: boolean) => void` | none | reported when the checkbox row toggles (required) |
| `className` | `string` | none | compiled through `@gpuixui/tw` and joined after the recipe |
| `style` | `MenuItemState` callback | none | `{ disabled, highlighted }`, merged after the row's roles |

### `ContextMenuRadioGroup` and `ContextMenuRadioItem`

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `value` | `string` | none | the chosen row's value (required on the group) |
| `onValueChange` | `(value: string) => void` | none | reported with a row's value when it is chosen, never the current one (required) |
| `label` | `string` | none | the choice's accessible name; a painted `ContextMenuLabel` does not name the group |
| `className` | `string` | none | compiled through `@gpuixui/tw`, joined after the recipe |
| `children` | parts | none | the group's `ContextMenuRadioItem` rows |
| `value` | `string` | none | this row's value inside the group (required on `ContextMenuRadioItem`) |
| `closeOnSelect` / `disabled` / `tone` / `leading` / `trailing` / `textValue` | as the action row | — | the row's own slots, tone and type-ahead key |
| `style` | `MenuRadioItemState` callback | none | `{ checked, disabled, highlighted }`, merged after the row's roles |

## Limitations

- The runtime role is `menu`, with `menuitem` and `menuitemcheckbox` on rows; no
  `aria-haspopup` on the trigger and no `aria-activedescendant`, so the keyboard
  route is documented here rather than announced.
- The surface is **not portalled**: it is an anchored layer at window coordinates, so it paints correctly but is not clipped by a scroll container. It is also **out of the layout flow** — opening it moves nothing behind it, and the trigger keeps its own box.
- **A dismissed menu is a ghost, not a target.** The surface stays painted for
  its **200 ms** exit and the seam's shield takes the presses, while every row
  inside it leaves the window's Tab order for that window: the runtime decides
  the order element by element, so the row drops its own stop. A control you
  compose inside the surface keeps its stop until the runtime publishes an
  inherited `inert`.

## Theming

The surface paints the theme's `elevation.lg` beside its 1px `foreground` ring,
so a brand's lift and edge both show. Its corner is the recipe's fixed **24px**
(`rounded-3xl`): the platform switch repaints the roles and leaves the corner
alone, while the preview follows the platform radius. The preview is the
approximation; the shipped box is the fixed one.
