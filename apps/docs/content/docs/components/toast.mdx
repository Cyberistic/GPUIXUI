`ToastProvider` creates one Effect runtime and one toast store; `useToast()`
pushes and dismisses; `ToastViewport` paints the stack. The queue is a
`SubscriptionRef`, the auto-dismiss timers are a `FiberMap`, and React only sees
the resulting array.

## Usage

```tsx
import {
  ToastProvider, ToastViewport, useToast,
} from "@gpuixui/components/toast";

<ToastProvider>
  <App />
  <ToastViewport />
</ToastProvider>;

const toast = useToast();
toast.push({
  title: "Changes published",
  description: "The site rebuilds in about a minute.",
  tone: "success",
});
```

## Variants

`tone` is `info` (default), `success`, `warning` or `danger`; each paints a 3px
left bar and a text glyph (`i`, `✓`, `!`, `✕`). The glyph stays text until the
icon set's marks replace it.

## Sizes

The stack holds 3 cards by default (`max`); a fourth drops the oldest. Cards are
380px wide with `spacing.lg` padding; there is no size prop.

## States

Auto-dismiss is 5 seconds by default, configurable per toast with
`duration: Duration.seconds(6)`. A zero or infinite duration never dismisses.
Hovering a card pauses its clock, and so does keyboard focus anywhere inside it;
neither resumes until both the pointer and focus have left, and the remaining
time is kept across the pause. Ids are monotonic (`"1"`, `"2"`, …) and never
reused; a dismissed toast cancels its timer so a stale one cannot remove its
successor.

## Actions

A toast may carry one action, such as Undo. The label is data in the draft and
the handler is passed beside it, so a toast never holds a closure in the store:

```tsx
toast.push(
  { title: "Message archived", action: { label: "Undo" } },
  { onAction: () => restore() },
);
```

Pressing the action runs `onAction` once and dismisses the toast. A label with no
handler draws nothing — never a dead control. A toast has at most one action; more
than one is a composition decision.

## State and ownership

`ToastProvider` owns the Effect runtime, the store and the auto-dismiss timers;
`ToastViewport` only paints the queue. A provider is not a singleton — two
providers are two stores — so mount one above everything that pushes and render
the viewport last. The consumer owns the push decision and any action handler it
attaches; a toast never navigates or calls the network itself.

## Keyboard and focus

Each card's dismiss control is a labelled, focusable button. The viewport itself
is `pointerEvents: "none"`, so it never blocks the page; each card turns pointer
events back on.

## Theming

Cards paint `colors.popover`/`popoverForeground`, a thin `colors.border`,
`radius.md`, the `md` elevation and `spacing.lg` padding. The bar and glyph take
the tone's colour from the shared status palette.

## Accessibility and limitations

- The viewport is `role="status"` named "Notifications"; each dismiss control is
  a labelled button.
- **No `aria-live` and no `aria-atomic`** in 0.10.0 — a status region is the
  supported announcement.
- **No progress indicator** for remaining time; the card does not animate the
  deadline.
- No portal: render the viewport last at the app root (GPUix has no `zIndex`).
- One action per toast; an action label without a handler renders no control.
- No live scene ships for this component yet; the example and source are real.
