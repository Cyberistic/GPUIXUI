`Popover` floats a surface next to its trigger without making the rest of the
window modal. Positioning is GPUix's own anchored layer; the component owns the
open state, the dismissal rules and the measured placement correction.

## Usage

```tsx
import {
  Popover,
  PopoverContent,
  PopoverTrigger,
} from "@gpuixui/components/popover";

<Popover>
  <PopoverTrigger variant="secondary">Columns</PopoverTrigger>
  <PopoverContent side="bottom" align="start">
    <ColumnToggles />
  </PopoverContent>
</Popover>;
```

## Composition

| Part | Responsibility |
| ---- | -------------- |
| `Popover` | open state and the positioning root the anchored layer measures |
| `PopoverTrigger` | a button that toggles the popover, with `aria-expanded` |
| `PopoverContent` | the floating surface, rendered only while open |

`PopoverContent` accepts `side`, `align`, `sideOffset`, `collisionPadding` and
`alignOffset`. The trigger is an ordinary button, so it takes the button
`variant` and `size`.

## Placement

| Prop | Type | Default | Meaning |
| ---- | ---- | ------- | ------- |
| `side` | `"top" \| "right" \| "bottom" \| "left"` | `"bottom"` | preferred side |
| `align` | `"start" \| "center" \| "end"` | `"start"` | alignment along that side |
| `sideOffset` | `number` | `6` | gap between trigger and surface |
| `collisionPadding` | `number` | `8` | margin kept from the window edge |
| `alignOffset` | `number` | `0` | extra shift after the centre correction |

The runtime snaps a surface inside the window but does not continuously flip it,
and its `center` alignment centres on the trigger's containing block. The
component therefore flips a snapped surface back off its trigger and converts
`align="center"` into a measured centre.

## Dismissal

| Action | Result |
| ------ | ------ |
| `Escape` | closes and returns focus to the trigger |
| `Tab` | closes and lets focus move on — a popover is not modal |
| press outside | closes without moving focus; the press already gave it |
| press inside | does nothing |
| click the trigger while open | closes it |

The popover shares the dismiss stack with `Dialog`, so pressing outside both
closes the popover first and leaves the dialog open. The trigger records whether
it was open at mouse-down, which stops a press from closing and immediately
re-opening the surface on the following click.

## Keyboard

Focus moves into the surface on open, so keys reach its content without a click.
The surface is a tab stop but not a trap: `Tab` leaves and closes it. The trigger
is an ordinary button — `Enter` and `Space` toggle it.

## API reference

### Popover

| Prop | Type | Default |
| ---- | ---- | ------- |
| `open` | `boolean` | uncontrolled |
| `defaultOpen` | `boolean` | `false` |
| `onOpenChange` | `(open: boolean) => void` | none |

### PopoverContent

| Prop | Type | Default |
| ---- | ---- | ------- |
| `side` | `"top" \| "right" \| "bottom" \| "left"` | `"bottom"` |
| `align` | `"start" \| "center" \| "end"` | `"start"` |
| `sideOffset` | `number` | `6` |
| `collisionPadding` | `number` | `8` |
| `alignOffset` | `number` | `0` |

### PopoverTrigger

| Prop | Type | Default |
| ---- | ---- | ------- |
| `onActivate` | `(event) => void` | — |
| `onClick` | `(event) => void` | — |

`onActivate` is the action's one handler — it toggles the popover after the
caller's own work; `onClick` is the deprecated alias and only runs when
`onActivate` is absent.

## Theming

| Part | Reads |
| ---- | ----- |
| surface | `popover` and `popoverForeground` |
| edge and lift | two shadows: the theme's `elevation.lg` lift beneath the recipe's 1px `foreground` ring at 5% (`ring-1`). The ring is the recipe's only shadow utility — its `shadow-lg` is superseded — so `overlaySurfaceStyle` restores the level the slot had swallowed |
| corners | 24px — the recipe's `rounded-3xl`, a fixed shadcn metric rather than the theme's radius scale |
| trigger | the button roles, plus `keyboardRing(theme)` — the `focusVisible` outline, so a press paints none |

The ring is 5% of `foreground` in both modes: the recipe's
`dark:ring-foreground/10` is skipped, because the theme owns the mode rather
than a `dark:` variant.

## Accessibility and limitations

- `aria-expanded` is on the trigger.
- **No `aria-haspopup`, `aria-controls` or `aria-labelledby`** in
  `@gpuix/native@0.11.0`; the link between trigger and surface is positional,
  not semantic.
- Positioning is the runtime's anchored layer: no arrow, no custom anchor
  element, no backdrop.
- It does not do continuous collision-aware placement while the window resizes.
  Keep a popover short; for a form that must block the window, use **Dialog**.
- `align="center"` cannot centre a surface that would leave the window; the
  snap margin wins at the edges.
- An outside press hands focus to whatever was pressed, so focus is not restored
  to the trigger on that path. Escape is the keyboard path that restores it.
- A `side` or `align` restored from persisted state that the union does not name
  opens the house `bottom`/`start`; it never throws out of the render.

## Status

`done`, with the runtime support marked `partial` in `COMPONENTS.md`: 14 native
behaviour tests, both themes. The runtime snaps a surface but does not flip it
and centres `align="center"` on the containing block, so the component flips a
snapped surface back off its trigger and measures the centre itself. It paints
an anchored surface rather than a portalled one, and there is no
`aria-haspopup`.
