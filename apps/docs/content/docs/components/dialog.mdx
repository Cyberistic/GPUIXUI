## Usage

```tsx
import {
  Dialog,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogFooter,
  DialogHeader,
  DialogTitle,
  DialogTrigger,
} from "@gpuixui/components/dialog";
import { Button } from "@gpuixui/primitives";

<Dialog>
  <DialogTrigger>Delete workspace</DialogTrigger>
  <DialogContent label="Delete workspace">
    <DialogHeader>
      <DialogTitle>Delete this workspace?</DialogTitle>
      <DialogDescription>
        The workspace and its 42 files are removed for everyone.
      </DialogDescription>
    </DialogHeader>
    <DialogFooter>
      <DialogClose>Cancel</DialogClose>
      <Button variant="destructive">Delete workspace</Button>
    </DialogFooter>
  </DialogContent>
</Dialog>;
```

## Composition

```text
Dialog
├── DialogTrigger
└── DialogContent
    ├── DialogHeader
    │   ├── DialogTitle
    │   └── DialogDescription
    ├── DialogFooter
    │   └── DialogClose
    └── (close control)
```

The close control is painted in the box around the surface's own scroller, not
inside it, so a body longer than the dialog scrolls under the control instead of
carrying the one visible way out of the surface. The Tab trap, Escape and an
outside press read that same box
(`packages/components/src/behaviour/dialog.test.tsx` holds the scroll case).

## API reference

### Dialog

| Prop | Type | Default |
| ---- | ---- | ------- |
| `open` | `boolean` | uncontrolled |
| `defaultOpen` | `boolean` | `false` |
| `onOpenChange` | `(open: boolean) => void` | none |
| `dismissible` | `boolean` | `true` |
| `children` | parts — `DialogTrigger`, `DialogContent`, `DialogClose` | — |

### DialogContent

| Prop | Type | Default |
| ---- | ---- | ------- |
| `label` | `string` (required) | none |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` — a stored name the union does not carry |
| `showClose` | `boolean` | `true` |
| `initialFocus` | `() => number \| null` | none |
| `className` | `string` — joined after the surface recipe | — |
| `children` | `ReactNode` — the surface's content | — |

### DialogTrigger and DialogClose

| Prop | Type | Default |
| ---- | ---- | ------- |
| `disabled` | `boolean` | `false` |
| `onClick` | `(event: EventPayload) => void` | none |
| `variant` | `"primary" \| "secondary" \| "ghost" \| "danger"` | `"secondary"` |
| `size` | `"sm" \| "md" \| "lg"` | `"md"` |
| `className` | `string` — joined after the button recipe | none |

## Limitations

- `role="dialog"` named by the required `label`; focus enters the surface on
  open and returns to the opener on close.
- **A dismissed dialog is a ghost, not a target.** It stays painted for its
  **320 ms** exit and the seam's shield takes the presses, while its own close
  control leaves the window's Tab order for that window: the runtime decides the
  order element by element, so a control the library paints has to drop its own
  stop. A control you compose inside the body keeps its stop until the runtime
  publishes an inherited `inert`.
- **No `aria-modal` and no `aria-labelledby`** in `@gpuix/native@0.11.0`; a
  `size` restored from persisted state that the union does not name paints the
  house `md` width (480px) instead of shrinking the surface to its content.

## Theming

The box paints the theme's `elevation.lg` beside its 1px `foreground` ring, so a
brand's lift and edge both show. Its corner is the recipe's fixed **32px**
(`rounded-4xl`): the platform switch repaints the roles and leaves the corner
alone, while the preview draws the platform radius plus 8px. The preview is the
approximation; the shipped box is the fixed one.
