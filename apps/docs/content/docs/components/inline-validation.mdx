`Field` is the structure around one control: label, input and one message slot.
The package's internal `src/validation/logic.ts` turns a `Schema` into a
user-facing message; the caller decides **when** to run it. It is not exported
from the package entry yet (a tracked package task), so the example below shows
the `Field` contract rather than an import a consumer cannot resolve. There is
no auto-validate per keystroke and no form library.

## Usage

```tsx
import { Field, FieldInput } from "@gpuixui/components/field";

<Field
  label="Workspace URL"
  description="Lowercase words joined by hyphens."
  error={error}
  required
>
  <FieldInput value={slug} onChange={(event) => setSlug(event.value ?? "")} />
</Field>;
```

The parts are `Field`, `FieldLabel`, `FieldDescription`, `FieldError` and
`FieldInput`. The error **replaces** the description rather than stacking under
it, so the row never shifts twice.

## Variants

No visual variant. `required` appends a destructive `*` and `Required` to the
control's `aria-description`; `error` swaps the description for a destructive
`role="alert"` message and the input border to the destructive role.

## Sizes

No size prop. Type, spacing and radius come from the theme.

## States

The field owns no value and no submit; the caller owns the value and when
validation runs. `validate(schema)` returns the first message or `None`;
`validateAll(schema)` returns every distinct message in issue order. Both live
in `src/validation/logic.ts` and are not exported from the package entry yet, so
call `Schema` at your boundary (or copy that module) until the export lands.
Running the Effect is an application-boundary decision.

## Keyboard and focus

The input is the GPUix text field; typing is native and focus follows the form's
order. The field itself adds no key handling.

## Theming

Labels use the `label` role in `colors.foreground`; descriptions the `caption`
role in `colors.mutedForeground`; errors the `caption` role in
`colors.destructive`. The input uses `colors.input`/`inputForeground`, a thin
`colors.border`, `radius.md`, and the destructive border when invalid.

## Accessibility and limitations

- The input's accessible name is the field's label; the message is its
  `aria-description`.
- **No `aria-describedby`, `aria-invalid` or `aria-required`** in
  `@gpuix/native@0.10.0`: the association is a description and validity is
  carried by colour and the alert message. This is a real screen-reader
  limitation.
- `FieldInput` is the stand-in for the primitive text input.
- Not a form library: no submit, cross-field rules or async validation.
