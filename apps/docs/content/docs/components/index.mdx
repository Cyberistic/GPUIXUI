The composed layer: dialogs, menus, pickers, tables and the rest, built from the
[primitives](/docs/primitives). Every card below is a page — its own browser
rendering, install block, API table and the real source. The filter matches a
page's name, its purpose, **the parts it documents**, **the props and prop
types its API table declares**, **the limits it records** and **its inventory
verdict**. So `DialogFooter` finds the dialog, `onCheckedChange` finds the
switch, `StateStyle` finds every page whose props take it, `aria-orientation`
finds the tabs, `preview` finds the pages that open with a browser rendering,
and `partial` finds every component the runtime supports only in part. The lower
lanes have their own maps: [Primitives](/docs/primitives), and the
`@gpuixui/data` lane at [Data display](/docs/data-display). A filter that finds
nothing here names the lower lane that does hold the query, so searching for a
primitive from this page is a link rather than a dead end.

The filter travels in the URL (`?q=partial`), the way the platform switch
carries `?platform=win32`: a filtered view can be linked, and a reload opens the
same cards. Clear the box and the parameter leaves the address bar.

The grid holds every composed component. Each tile renders the demo the page
mounts and links to the page itself; a component with no demo says so rather
than showing an empty frame.

The pages come from two places:

- **A curated page** for the components documented here in depth — Accordion,
  Alert, Avatar, Badge, Breadcrumb, Button, Card, Carousel, Checkbox,
  Collapsible, Combobox, Command menu, Confirmation dialog, Context menu, Date
  picker, Dialog, Drawer, Dropdown menu, Empty state, Field and inline
  validation, Form, Inline edit, List, Navigation menu, Pagination, Popover,
  Search input, Select, Stepper, Switch, Color picker, Table, Tag input, Tabs,
  Time picker, Timeline, Tooltip and Toast — with browser previews, an install
  block and the copyable source. A page that mounts a preview renders it in its grid tile.
- **The package's own page** for every other component, rendered from
  `packages/components/docs/`. That file is what the component ships with, so
  the page and the package cannot disagree. A component or primitive page mounts
  its own preview too — a browser approximation, labelled as one — while a page
  with no demo opens with a note naming the command that opens the companion
  playground.

**What the mark means.** A **partial** mark is about the component:
`COMPONENTS.md` records that the pinned runtime supports only part of it, and
the page's own Status section names the missing part. The same rule names a
`todo` status or an unmeasured `?` if one ever lands on a page, so a mark never
means "shipped whole" when the inventory says otherwise.

The mark is not written by hand: the verdict comes from the `COMPONENTS.md` row the status strip already joins, so a component that moves to `done` loses its mark in the same commit.

## How to read a page

| Section | What it answers |
| ------- | --------------- |
| preview | the states at a glance — a browser drawing, labelled as one |
| Installation | the `nub` and manual install, and the copyable source |
| Usage | a realistic snippet, not a prop dump |
| Composition | the parts, which are required, and what to use instead |
| API reference | every prop, its type, its default and its consequence |
| Limitations | the role and name it publishes, and what the runtime does not provide |
| Status | `done` or `partial`, with the runtime evidence (generated) |
| Dependencies | the workspace packages the component imports (generated) |
| Related | what to use instead, or alongside (generated) |

A section that does not apply is left out rather than faked: a leaf component has
no Composition, and a page whose runtime facts are all measured elsewhere still
states its own limits. The facts a page does not repeat are shared:
[Accessibility](/docs/accessibility) carries the runtime's ARIA budget and the
pressable-target floors, and [Theming](/docs/theming) carries the token roles and
the platform switch.

## The platform looks

Every preview on this site renders through the **Platform** switch at the foot
of the sidebar: macOS, Linux, Windows or Default. The switch resolves a real
`@gpuixui/tokens` theme, and the choice travels in the URL
(`?platform=win32`), so a link shows what you saw. [Theming](/docs/theming#platform-styles)
documents what each variant changes today.

## Previews are browser renderings

The components render through GPUix, not the DOM. A preview shows geometry,
palette and states in a browser and says so on the page; it is never the
authority. To run the real component, open the companion playground with
<code>{playgroundCommand}</code> — the [native playground
page](/docs/playground) lists what it mounts.

<Callout type="warn" title="Status is per component, not per page">
  A page existing does not mean the component is finished. `COMPONENTS.md` holds
  the status, the runtime evidence and the limitations for every row; where a
  page and that inventory disagree, the inventory wins.
</Callout>
