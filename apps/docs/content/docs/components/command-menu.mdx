## Usage

```tsx
import {
  CommandMenu,
  CommandMenuEmpty,
  CommandMenuInput,
  CommandMenuList,
} from "@gpuixui/components/command-menu";

const actions = [
  {
    id: "new-file",
    label: "New file",
    group: "File",
    shortcut: "⌘N",
    perform: newFile,
  },
  {
    id: "toggle-sidebar",
    label: "Toggle sidebar",
    group: "View",
    shortcut: "⌘B",
    perform: toggleSidebar,
  },
];

<CommandMenu open={open} onOpenChange={setOpen} actions={actions}>
  <CommandMenuInput placeholder="Type a command…" />
  <CommandMenuList />
  <CommandMenuEmpty>No matching commands</CommandMenuEmpty>
</CommandMenu>;
```

Typing filters; the field keeps the focus while `↓` / `Ctrl+N` and `↑` / `Ctrl+P`
move the highlight, `Home` and `End` jump to the first and last match, `Enter`
runs the active row, and `Escape` is offered to the topmost dismiss layer, which
closes the dialog. `CommandMenuList` paints the same keys as its hint.

## Composition

```text
CommandMenu
├── CommandMenuInput
├── CommandMenuList
│   └── CommandMenuItem
└── CommandMenuEmpty
```

## API reference

| Part | Renders | Props |
| ---- | ------- | ----- |
| `CommandMenu` | the composed `Dialog` surface | `open` (required), `onOpenChange` (required), `actions` (required; a stored value that is not a list paints the empty state), `recents` (a stored value that is not a list carries no recents), `filter`, `children` |
| `CommandMenuInput` | host `<input>` | `placeholder` (default `"Type a command…"`; an empty field announces it as `aria-description`), `label` (default `"Search commands"`), `className` |
| `CommandMenuList` | scrolling match column | `className`; the root's ranked matches are its content |
| `CommandMenuItem` | one runnable row | `action` (required), `className` |
| `CommandMenuEmpty` | the no-match message | `children` (default `No matching commands`), `className` |

## Limitations

- The dialog is named `Command menu`, the input `Search commands`; rows are `option` with `aria-selected`.
- **A dismissed palette is a ghost, not a target.** It stays painted for the
  dialog's **320 ms** exit (a fade and an 8 px rise) and the field the library
  paints leaves the window's Tab order for that window: the runtime decides the
  order element by element, so `Escape` then `Tab` walks past the field. Rows
  are highlighted, never focused, so they were never stops; a control you
  compose inside the palette keeps its stop until the runtime publishes an
  inherited `inert`.
- **No `aria-activedescendant` or `aria-controls`** in 0.11.0: the active row is visual only.
