## Usage

```tsx
import {
  Card,
  CardContent,
  CardDescription,
  CardFooter,
  CardHeader,
  CardTitle,
} from "@gpuixui/components/card";

<Card>
  <CardHeader>
    <CardTitle>Pro plan</CardTitle>
    <CardDescription>
      Everything in Starter, plus seats and invoicing.
    </CardDescription>
  </CardHeader>
  <CardContent>{rows}</CardContent>
  <CardFooter>{actions}</CardFooter>
</Card>;
```

## Composition

```text
Card
├── CardHeader
│   ├── CardTitle
│   └── CardDescription
├── CardContent
└── CardFooter
```

## API reference

| Prop | Type | Default | Consequence |
| ---- | ---- | ------- | ----------- |
| `variant` | `"outline" \| "elevated" \| "plain"` | `"outline"` — a stored name the union does not carry | the edge and lift in **Treatments** below |
| `className` | `string` | none | a recipe class string joined after the component's own, so it wins a conflict |
| `style` | `StyleDesc` | none | merged last, after the compiled recipe |
| `children` | `PartChildren` | none | the parts; text and numbers are rejected for every part that hosts parts |

**Treatments**

| Treatment | Edge | Lift |
| --------- | ---- | ---- |
| `outline` | 1px `border` | none |
| `elevated` | none | `elevation.sm` |
| `plain` | none | none |

All three paint the `card` fill and a fixed 8px corner; `outline` edges in
`border-input`, compiled to `border`.

## Notes
- `CardTitle` renders a `<text>` with `role="heading"` and `aria-level={3}`.
- A card is not a landmark: no role, name or `aria-*` state.
- The surface clips overflow: a scrolling body needs its own height in `CardContent`.
