GPUIXUI is a TypeScript-first monorepo. Every command runs through **nub** on
Node 24.18.0.

## Worktrees

Each workstream works in its own `git worktree` under `workspaces/` on branch
`agent/<workstream>`. One writer per tree. The shared checkout's `main` is the
integration branch.

## Issues and pull requests

The source lives at
[github.com/Cyberistic/GPUIXUI](https://github.com/Cyberistic/GPUIXUI). Report a
bug or ask for a change as a GitHub issue, and send a fix as a pull request.
Every pull request carries the checks in [Gates](#gates); a component change
also carries the docs page and inventory record described under
[Components](#components).

## Gates

A change is not done until these pass:

```sh
nub run check   # test-quality gate, lint, format, type-check
nub run lint
nub run test
```

## Tests

A test must be able to fail. `nub run check` rejects a test that asserts nothing,
compares a value with itself, or asserts back what the test itself stubbed. A
regression fix lands with a test that fails without it and passes with it.

The suites are vitest files beside the code (`src/**/*.test.ts`); `nub run test`
runs them.

## Components

Every component needs code, a test appropriate to its behaviour, a working
example, a docs page and an inventory record in `COMPONENTS.md`. An interaction
is not complete until it is verified in the real GPUix runtime. The record
fields, required sections, MDX blocks and guards a page owes are on
[Component pages](/docs/component-pages).

## Native runtime

A component's interaction is not verified by a browser test. Build the
playground and run the native smoke suite on a host with the GPUix binding:

```sh
nub run --filter playground smoke
```

Exit `0` means every scenario passed, `1` means one failed, and `2` means no
binding loaded, so nothing ran. `2` is not a pass. The harness, the scenario
model and the limits of what it proves are on
[Native smoke suite](/docs/native-testing).

## Docs site

`apps/docs` is a Fumadocs app. Its unit suite reads the content source and the
component registry; the smoke checks drive the built site in a real browser. Run
every check your change can affect:

| Command | What it proves | Exit codes |
| ------- | -------------- | ---------- |
| `nub run --filter docs test` | pages, registry, links, search, previews, copyable fence imports | `1` on a failure |
| `nub run --filter docs check-types` | the app, the preview document and MDX types | `1` on a type error |
| `nub run --filter docs build` | the production Worker bundle builds | `1` on a build error |
| `nub run --filter docs smoke:deploy` | the deployment artifact: the build succeeds, `wrangler deploy --dry-run` accepts the generated Worker config, and every file is inside Cloudflare's per-asset, file-count and Worker-size limits | `1` a config mismatch or an exceeded budget, `2` could not verify |
| `nub run --filter docs smoke:build` | every sitemap page renders in the production output, its document head carries the description, social card, icon and light/dark theme colour, every internal link and brand asset resolves, every `#fragment` lands on a heading, search answers, an unknown slug is a 404, and no page's headings skip a level | `1` broken, `2` could not verify |
| `nub run --filter docs smoke:browser` | the built site hydrates; every preview surface paints the theme and platform the toggles publish, and every code colour clears the 4.5:1 text floor in both schemes | `1` wrong paint, `2` could not verify |
| `nub run --filter docs smoke:console` | every sitemap page loads in the production build with no console error, uncaught exception or error-level log entry — the class a server-HTML crawl cannot see | `1` a page errored, `2` could not verify |
| `nub run --filter docs smoke:preview` | every live GPUix scene reaches the renderer in headless Chrome, and the page wiring passes the platform | `1` scene failure, `2` could not verify |
| `nub run --filter docs smoke:keyboard` | the skip link is the first tab stop, Enter moves focus into the page, and the focus ring is the theme's ring token | `1` wrong, `2` could not verify |
| `nub run --filter docs smoke:platform` | the platform toggle is one radio group on a tablet/desktop width — a click updates the URL, the stored choice survives a parameter-free load, every preview repaints, arrows move and apply, and Default removes the parameter — and the phone-width select does the same at 390 px | `1` wrong, `2` could not verify |
| `nub run --filter docs smoke:search` | ⌘K opens the search palette with its field focused, typing lists the real Installation page, Enter navigates and focuses the destination page, an unknown query says "No results found", Escape returns focus to the search trigger; the Components filter matches one card, shows its empty state and clears; and at 390 px the palette opens from the icon button and navigates | `1` wrong, `2` could not verify |
| `nub run --filter docs smoke:theme` | pressing the theme switch turns the document, the browser chrome and every preview surface dark, the choice survives a navigation and a parameter-free reload, a second press returns to light, and the landing page's compact switch does the same at 390 px | `1` wrong, `2` could not verify |
| `nub run --filter docs smoke:theme-editor` | setting a role's colour and the density preset repaints the library's token surface, updates the copied module and writes the shareable `?theme=` value; the shared URL restores the edit and Reset removes it | `1` wrong, `2` could not verify |
| `nub run --filter docs smoke:responsive` | at a 390 px viewport no page scrolls sideways and no content column clips its content, the mobile sidebar opens and navigates, both phone-width controls are visible inside the viewport, and the docs sidebar exposes the theme switch | `1` wrong, `2` could not verify |
| `nub run --filter docs smoke:a11y` | axe-core over every sitemap page in light and dark finds no WCAG 2.1 A/AA violation: list semantics, focusable scroll regions and text contrast included | `1` a violation, `2` could not verify |

The smokes exit `2` when Chrome or the server is missing. An unverified site is
not a passing one: treat `2` as "run it where the check can run", never as a
pass.

### Site output

The site publishes its own discovery documents from the modules its pages read,
so a route cannot describe a page the sitemap does not serve:

| Route | What it serves | Source |
| ----- | -------------- | ------ |
| `/sitemap.xml` | every page URL the site serves | `apps/docs/src/lib/sitemap.ts` |
| `/robots.txt` | crawlers, naming the sitemap | `apps/docs/src/routes/robots[.]txt.ts` |
| `/llms.txt` | every page, absolutely linked, for an LLM crawler | `apps/docs/src/lib/llms.ts` |
| `/llms-full.txt` | every page as processed Markdown | `apps/docs/src/lib/llms.ts` |
| `/docs/<slug>.md` | one page as the processed Markdown `llms-full.txt` carries | `apps/docs/src/routes/docs/{$}[.]md.ts` |
| `/site.webmanifest` | the install document: name, start URL, palette colours and both icons | `apps/docs/src/lib/site-manifest.ts` |

Every page carries a **Copy Markdown** button and a **View as Markdown** link,
both addressing the page's `/docs/<slug>.md` route, so a reader or an agent can
take one page away without the full manual.

Every page inherits the favicon (the SVG mark `/brand/mark.svg` plus a 32 px
`/brand/favicon-32.png`), the apple-touch icon
(`/brand/apple-touch-icon.png`) and the 1200×630 social card
(`/brand/og.png`), a canonical URL and OpenGraph/Twitter tags from
`apps/docs/src/lib/site-head.ts`. The manifest declares `display: "browser"` and
there is **no service worker**, so the site makes no PWA or offline claim. The
maintainer detail, including how the raster icons were made, is in
`apps/docs/README.md`.

### Authoring

The pages are plain MDX. Fumadocs Studio edits them in place without rewriting
untouched blocks; it is a dev-only command and is never part of the built site:

```sh
nub run --filter docs studio
```

`apps/docs/README.md` carries the editor's contract and the round-trip guard.

### Generated pages

[Values API](/docs/api-values) is generated from the packages' real entry
points, not written by hand. After an export, its doc comment or a
classification changes:

```sh
nub run --filter docs api:values
```

The command refuses to write an export with no summary, or a package that is
neither indexed nor excluded. `nub run --filter docs test` then fails while the
committed index is stale, so the generated file is never the only copy of the
truth.

[Icons](/docs/components/icon) lists every name the icon set ships, generated
from the package's own registry:

```sh
nub run --filter docs icons
```

The generated catalogue is committed, and the same suite fails while it is
stale, so adding an icon cannot ship a page that is one icon short.

[Roadmap](/docs/roadmap) renders every Tier 3–5 target from `COMPONENTS.md`,
with its inventory status, GPUix support and note:

```sh
nub run --filter docs roadmap
```

The command refuses to write an empty cell, a duplicate target or a missing
tier; the same suite fails while the committed module is stale, so an inventory
change cannot ship a page that is one target behind.
